 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are two essential security features in Kubernetes that help secure your cluster. RBAC allows you to manage access control for various Kubernetes resources, while network policies enable you to control incoming and outgoing traffic.

# Key Technical Points
- RBAC enables you to assign roles and permissions to users, service accounts, and groups, ensuring only authorized entities can access specific resources.
- Network policies enable you to define rules for inbound and outbound traffic based on labels, pod selectors, and IP addresses.
- Combining RBAC and network policies provides a multi-layered security approach, securing access to your Kubernetes resources and the network traffic between them.

# Real-World Example
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx
  labels:
    app: nginx
spec:
  containers:
  - name: nginx
    image: nginx:1.19.5

---

apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: nginx-reader
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get"]

---

apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: nginx-reader-binding
subjects:
- kind: User
  name: alice
roleRef:
  kind: Role
  name: nginx-reader
  apiGroup: rbac.authorization.k8s.io

---

apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: nginx-policy
spec:
  podSelector:
    matchLabels:
      app: nginx
  ingress:
  - ports:
    - protocol: TCP
      port: 80
      from:
      - ipBlock:
          cidr: 10.0.0.0/16
  egress:
  - to:
    - ipBlock:
        cidr: 0.0.0.0/0
```
In this example, a pod named `nginx` is defined, and access control is managed using RBAC. A user named `alice` is granted the `nginx-reader` role, which allows her to only get information about pods. Network policies are then applied to restrict the traffic to and from the `nginx` pod, allowing traffic from `10.0.0.0/16` subnet for incoming traffic and permitting all outgoing traffic to any destination.
