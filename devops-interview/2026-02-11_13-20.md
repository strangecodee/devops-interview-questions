 # Interview Question
Can you explain how you would securely configure an Amazon Elastic Container Service (ECS) cluster using IAM roles and task definitions?

# Answer
In order to securely configure an Amazon Elastic Container Service (ECS) cluster, we will create and utilize IAM roles for tasks and task definitions, ensuring proper access control, and minimize the use of hardcoded credentials. The process begins by creating a new IAM role for ECS tasks, which defines the necessary permissions for container instances to run tasks. We will then apply the role to the task definition, thereby linking it to the container instances. This setup prevents the need for hardcoded credentials and enhances the overall security posture of the ECS cluster.

# Key Technical Points
- By using IAM roles for tasks, we eliminate the need for hardcoding credentials directly in container images or task definitions
- Access control is more granular as we can specify exact permissions for the ECS tasks
- Creating an IAM role for tasks reduces the potential attack surface, as the role can be revoked or modified quickly if necessary

# Real-World Example
```yaml
# IAM Role for ECS tasks
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ecs:ListClusters",
        "ecs:DescribeClusters",
        "ecs:ListTasks",
        "ecs:DescribeTasks",
        "ecs:RegisterContainerInstances",
        "ecs:DeregisterContainerInstances",
        "ecs:StartTask",
        "ecs:StopTask"
      ],
      "Resource": "*"
    }
  ]
}

# Task Definition
{
  "containerDefinitions": [
    {
      "name": "my-container",
      "image": "my-docker-image",
      "memory": 128,
      "cpu": 256,
      "portMappings": [
        {
          "containerPort": 80,
          "hostPort": 80,
          "protocol": "tcp"
        }
      ],
      "essential": true,
      "roleArn": "arn:aws:iam::1770796202:role/service-role/my-ecs-role-v1_0-1"
    }
  ],
  "family": "my-container-family",
  "networkConfiguration": {
    "awsElasticNetworkInterfaceConfiguration": {
      "subnets": [
        {
          "subnetId": "subnet-12345678901234567"
        },
        {
          "subnetId": "subnet-23456789012345678"
        }
      ]
    }
  }
}
```
In this example, an IAM role with necessary permissions for ECS tasks is created, and the role is assigned to a task definition. The role ARN is specified in the task definition under the container definition, ensuring the correct IAM role is assigned when the task is executed. This setup provides a more secure alternative to hardcoding credentials and offers better access control for the ECS cluster.
