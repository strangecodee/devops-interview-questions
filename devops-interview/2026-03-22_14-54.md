 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and explain the key differences between Role and ClusterRole?

# Answer
Kubernetes Role-Based Access Control (RBAC) is a security feature that allows you to control access to Kubernetes resources based on roles and permissions. In Kubernetes, there are two types of roles: Role and ClusterRole. A Role defines permissions for a specific Namespace, while a ClusterRole defines permissions across all Namespaces in a cluster. Both Role and ClusterRole can be granted to users, service accounts, or groups.

# Key Technical Points
- Role: Defines permissions for a specific Namespace. Can be used to grant access to specific resources within a Namespace.
- ClusterRole: Defines permissions across all Namespaces in a cluster. Can be used to grant access to resources in multiple Namespaces or to grant cluster-wide permissions.
- RBAC provides a fine-grained access control mechanism for Kubernetes resources, allowing you to define and manage permissions at a granular level.

# Real-World Example
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: my-namespace-reader
  namespace: my-namespace
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: my-namespace-editor
  namespace: my-namespace
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "list", "watch", "create", "update", "delete"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: cluster-admin
rules:
- apiGroups: [""]
  resources: ["nodes"]
  verbs: ["get", "list", "watch", "create", "update", "delete"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: eclipse-cluster-admin
subjects:
- kind: User
  name: eclipse
roleRef:
  kind: ClusterRole
  name: cluster-admin
```
In this example, we define a Role and a ClusterRole, each with specific permissions, and then bind a user named "eclipse" to the ClusterRole using a ClusterRoleBinding. This allows the user "eclipse" to have administrative access to all nodes in the cluster.
