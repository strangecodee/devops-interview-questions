 # Interview Question
Can you explain how to use IAM roles for cross-account access in an AWS multi-account setup?

# Answer
In an AWS multi-account setup, IAM roles can be used to grant permissions for cross-account access between different AWS accounts. This is particularly useful when sharing resources or services between multiple teams or departments. The IAM role acts as a trust relationship, allowing the assumed role to access resources in the source account while keeping the underlying credentials hidden.

# Key Technical Points
- IAM roles enable cross-account access by defining trust relationships between AWS accounts.
- Trust relationships are used to grant permissions from one account to another.
- The source account grants permissions to the role in the target account, and the role assumes those permissions to access the resources.

# Real-World Example
```yaml
# Trust relationship in the source account (account A)
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:role/TargetAccountRole"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}

# Role definition in the target account (account B)
{
  "Version": "2012-10-17",
  "StatementID": "Stmt123456789012",
  "Effect": "Allow",
  "Principal": {
    "AWS": "arn:aws:iam::123456789012:root"
  },
  "Action": "sts:AssumeRole",
  "Condition": {
    "StringEquals": {
      "aws:PrincipalTag/Environment": "Production"
    }
  }
}

# Assume role using the STS API
$ aws sts assume-role --role-arn arn:aws:iam::123456789012:role/TargetAccountRole --account-id 111111111111
```
In this example, account A (source account) creates a trust relationship for the role in account B (target account), which allows account B to assume the role and access the resources in account A. The role definition in account B includes conditions, such as the `PrincipalTag/Environment` condition, to control which principals (in this case, the root user of account A) can assume the role. The `assume-role` command is used to assume the role and receive temporary credentials to access the resources in account A.
