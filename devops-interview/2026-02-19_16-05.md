 # Interview Question
Can you explain how you have implemented an on-call rotation system using SRE principles in a previous project?

# Answer
In my previous role as a DevOps Engineer, I designed and implemented an on-call rotation system using Site Reliability Engineering (SRE) principles. This system ensured that team members were adequately covered for incident response and allowed for even distribution of on-call duties. The system utilized a combination of automated notifications and a custom web application for scheduling.

# Key Technical Points
- Implemented an automated notification system using PagerDuty for incident alerts.
- Developed a custom web application using Django for managing on-call schedules and rotations.
- Integrated the web application with GitHub Actions for continuous deployment and testing.

# Real-World Example
To implement the automated notification system, I utilized PagerDuty's API to create and update incident alerts. The API call is as follows:

```bash
curl -X POST \
  https://events.pagerduty.com/v2/enqueue.json \
  -H 'Authorization: Bearer <API_KEY>' \
  -H 'Content-Type: application/json' \
  -d '{
        "type": "incident_request",
        "configuration_version": 3,
        "details": {
          "summary": "Database connection issue",
          "description": "Database connection to the production environment is down.",
          "source": "Monitoring system"
        },
        "incident": {
          "source_type": "application",
          "source_id": "<APP_ID>",
          "service_key": "<SERVICE_KEY>"
        }
      }'
```

The custom web application was developed using Django, a popular Python web framework. The application allowed team members to view current on-call schedules, sign up for open slots, and request time off. The application was integrated with GitHub Actions for continuous deployment and testing using the following YAML configuration:

```yaml
name: CI
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Set up Django
        uses: actions/setup-python@v3
        with:
          python-version: 3.9
      - name: Install dependencies
        run: |
          pip install django
          pip install djangorestframework
          pip install psycopg2-binary
      - name: Build and test
        run: |
          python manage.py test
          python manage.py migrate --noinput
          python manage.py collectstatic --noinput
```
