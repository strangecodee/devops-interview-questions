 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are two essential security features in Kubernetes. RBAC helps manage access control for users and processes within a Kubernetes environment, while network policies provide a way to define and enforce communication rules between pods.

# Key Technical Points
- RBAC allows defining roles and bindings for users, groups, and service accounts to control their access to Kubernetes API resources.
- Network policies enable defining rules for ingress and egress traffic to and from pods based on source/destination, ports, and protocols.
- When combined, RBAC and network policies ensure a more secure Kubernetes environment by controlling access to resources and enforcing communication policies.

# Real-World Example
Consider an enterprise scenario where you need to secure a Kubernetes cluster named phoenix. To implement RBAC:
1. Define a Role for the 'developers' group:
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: developer-role
  labels:
    app: phoenix
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "watch", "list"]
```
2. Create a RoleBinding for the 'developers' group:
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: developer-role-binding
  labels:
    app: phoenix
subjects:
- kind: Group
  name: developers
roleRef:
  kind: Role
  name: developer-role
  apiGroup: rbac.authorization.k8s.io
```
To define network policies for pod communication, create a NetworkPolicy object:
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: phoenix-network-policy
spec:
  podSelector:
    matchLabels:
      app: phoenix
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: allowed-app
```
This network policy example allows ingress traffic only from pods with the label 'app: allowed-app'.
