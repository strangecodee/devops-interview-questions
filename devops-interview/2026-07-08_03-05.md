 # Interview Question
What are the steps to secure a Kubernetes cluster using RBAC and network policies?

# Answer
To secure a Kubernetes cluster, we can implement Role-Based Access Control (RBAC) and network policies. RBAC allows defining and managing access to Kubernetes resources based on roles and permissions. Network policies control the traffic between pods and services within the cluster.

# Key Technical Points
- Assign appropriate roles and permissions to users or services using RBAC.
- Define and apply network policies to restrict traffic flow based on pod labels, source and destination ports, and protocols.

# Real-World Example
Let's consider an example where we want to allow traffic from pods with label `app:web` to access a MySQL database pod. We create a YAML file defining a network policy:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: db-access
spec:
  podSelector:
    matchLabels:
      app: db
  ingress:
  - ports:
    - protocol: TCP
      port: 3306
  sources:
  - selector:
      matchLabels:
        app: web
```

This policy allows traffic only from pods labeled `app:web` to the MySQL pod labeled `app:db` on port 3306. By configuring RBAC and network policies, we enhance the security of our Kubernetes cluster.
