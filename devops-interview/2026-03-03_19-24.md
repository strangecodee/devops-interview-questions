 # Interview Question
Can you explain how you have implemented and configured a high availability load balancer using AWS Elastic Load Balancer (ELB)?

# Answer
In my previous role at XYZ Corporation, I was responsible for designing and implementing a scalable and highly available web application infrastructure using AWS Elastic Load Balancer (ELB). To achieve this, I configured ELB to distribute incoming application traffic across multiple Amazon Elastic Compute Cloud (EC2) instances. This ensured that the application remained available even if one or more instances went down, providing a seamless user experience.

# Key Technical Points
- ELB automatically distributes incoming application traffic across multiple EC2 instances using a configured load balancing algorithm.
- Health checks are performed by ELB to monitor the status of each EC2 instance, and instances are removed from the load balancing rotation if they fail the health check.
- ELB supports both HTTP and HTTPS protocols, and allows for SSL termination and SSL offloading.

# Real-World Example
```yaml
Resources:
  ElasticLoadBalancer:
    Type: AWS::ElasticLoadBalancing::LoadBalancer
    Properties:
      LoadBalancerName: my-load-balancer
      Scheme: internet-facing
      Listeners:
        - Protocol: HTTP
          LoadBalancerPort: 80
          InstanceProtocol: HTTP
          InstancePort: 80
      AvailabilityZones:
        - us-west-2a
        - us-west-2b
      HealthCheck:
        TargetGroupArn: !Ref TargetGroup
        Interval: 30
        Timeout: 2
        UnhealthyThreshold: 3
        HealthyThreshold: 2
      Subnets:
        - !Ref PublicSubnet1
        - !Ref PublicSubnet2
  AutoScalingGroup:
    Type: AWS::AutoScaling::AutoScalingGroup
    Properties:
      LaunchConfigurationName: !Ref LaunchConfiguration
      AvailabilityZones:
        - us-west-2a
        - us-west-2b
      MinSize: 2
      MaxSize: 5
      DesiredCapacity: 3
      Metrics:
        - Add:
            MetricStat:
              Name: ELB_Instances_Running
              Period: 300
              Statistic: Average
            ReturnData: false
            MetricName: ELBInstancesRunning
            Period: 60
            Statistic: Average
            ReturnData: false
            MetricName: ELB_Instances_InService
            Period: 60
            Statistic: Average
            ReturnData: false
            MetricName: ELB_Instance_Availability
            Period: 60
            Statistic: Average
            ReturnData: false
      HealthCheckType: ELB
      LoadBalancerDNSName: !Ref ElasticLoadBalancer
```
In this example, I have configured an Elastic Load Balancer with two Availability Zones, and an AutoScalingGroup with an ELB health check, ensuring both high availability and scalability for my web application.
