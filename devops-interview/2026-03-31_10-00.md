# Interview Question
Please explain how you would implement a zero-downtime deploy using Ansible and Docker in an enterprise environment.

# Answer
A zero-downtime deploy strategy ensures minimum disruption to production services during upgrades or deployments. In an enterprise scenario where we use Ansible for orchestration and Docker for containerization, we can implement a zero-downtime deploy by following these steps:

1. Create and test a new container image with the updated application code in a staging environment.
2. Use Ansible to update the Docker configuration on the production servers to point to the new container image.
3. Run the new container image in parallel with the old one, using Docker's built-in load balancer or a reverse proxy like NGINX.
4. Verify that the new container is functioning correctly and servicing traffic.
5. Once satisfied, update the DNS records to point to the new container, and remove the old one.

# Key Technical Points
- Use Ansible to manage Docker configurations on production servers.
- Run new container in parallel with old one during deploy.
- Use Docker's built-in load balancer or reverse proxy to distribute traffic.

# Real-World Example (YAML)
```yaml
---
- name: Zero-Downtime Deploy
  hosts: production
  become: yes

  tasks:
  - name: Update Docker config
    template:
      src: templates/docker-compose.yml.j2
      dest: /etc/docker-compose.yml

  - name: Restart services
    ansible.builtin.restart:
      name: my_service
      state: graceful

  - name: Verify new container is running
    ansible.builtin.container:
      name: my_service
      state: started
```
In this example, we use Ansible to update the Docker configuration and restart services gracefully, while keeping the new container running in parallel with the old one. Once the new container is confirmed to be functioning correctly, we update DNS records to point to the new container and remove the old one.
