 # Interview Question
Can you explain how you would secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are essential components of securing a Kubernetes cluster. RBAC allows defining and managing access control for different users and services, while network policies enable controlling the traffic between pods and services. By combining both mechanisms, we can ensure that only authorized entities can access specific resources within the cluster, and network traffic is restricted according to our security policies.

# Key Technical Points
- RBAC allows defining roles and permissions for different users, services, and groups, ensuring access control at a granular level.
- Network policies enable controlling the traffic between pods and services based on labels, IP addresses, and ports.
- By combining RBAC and network policies, we can implement multi-layered security, mitigating potential risks and threats.

# Real-World Example
Suppose you are working on an enterprise project where we use Kubernetes to manage various applications. To secure our cluster, we implement the following steps:

1. Define roles and permissions for different users and services using RBAC:
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: deployer
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["create", "get", "watch", "delete"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: editor
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["create", "get", "update", "patch", "delete"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: viewer
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get"]
```

2. Create a service account and bind it to the roles:
```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: deployer-sa
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: deployer-role-binding
subjects:
- kind: ServiceAccount
  name: deployer-sa
roleRef:
  kind: Role
  name: deployer
  apiGroup: rbac.authorization.k8s.io
```

3. Configure network policies to restrict traffic between specific pods:
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: pod-policy
spec:
  podSelector:
    matchLabels:
      app: my-app
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          team: dev
    ports:
    - protocol: TCP
      port: 80
```

By implementing these security measures, we ensure that only authorized users and services can access specific resources within our Kubernetes cluster, and network traffic is restricted according to our security policies. This approach helps us maintain a secure and compliant environment, reducing potential risks and threats.
