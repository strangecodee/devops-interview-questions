 # Interview Question
Can you explain how to write a performance-optimized Terraform configuration for an AWS Elastic Load Balancer (ELB) using an example seed value?

# Answer
To write a performance-optimized Terraform configuration for an AWS Elastic Load Balancer (ELB), we must consider several factors such as health checks, listener rules, and instance profiles. By designing an efficient architecture and utilizing Terraform's advanced features, we can minimize the time taken for resource creation and updates.

# Key Technical Points
- Designing an efficient architecture: Properly structuring your Terraform configuration file to minimize the number of resources and dependencies can significantly improve performance.
- Health checks: Set up health checks at the listener level, rather than at the instance level, to reduce the number of check requests and improve overall performance.
- Instance profiles: Use instance profiles instead of hardcoding access keys to ensure secure access and reduce the time required for instance creation.

# Real-World Example

```hcl
provider "aws" {
  region = "us-west-2"
  version = "4.31.0"
}

data "aws_availability_zones" "available" {}

locals {
  desired_azs = slice(data.aws_availability_zones.available.names, 0, 3)
}

resource "aws_instance" "web_instance" {
  count         = length(local.desired_azs)
  ami           = "ami-0c94855ba95b798c32890aa14d7215e6"
  instance_type  = "t2.micro"
  availability_zone = local.desired_azs[count.index]
  vpc_security_group_ids = [aws_security_group.instance_security_group.id]
  iam_instance_profile = aws_iam_instance_profile.instance_profile.name

  tags = {
    Name = "WebInstance-${count.index}"
  }
}

resource "aws_iam_instance_profile" "instance_profile" {
  name = "instance_profile"
  path = "/"

  roles = [
    aws_iam_role.instance_role.name,
  ]
}

resource "aws_iam_role" "instance_role" {
  name = "instance_role"

  assume_role_policy = jsonencode({
    Version = "2012-10-17",
    Statement = [
      {
        Effect = "Allow",
        Principal = {
          Service = "ec2.amazonaws.com"
        },
        Action = "sts:AssumeRole"
      }
    ]
  })
}

resource "aws_security_group" "instance_security_group" {
  name_prefix = "instance_security_group"
  vpc_id      = data.aws_vpc.default.id

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_elb_listener" "http_listener" {
  load_balancer_arn = aws_elb.example_elb.arn
  port             = 80
  protocol          = "HTTP"

  default_actions {
    type             = "forward"
    target_group_arn  = aws_lb_target_group.example_target_group.arn
  }

  health_check {
    path = "/"
  }

  seed = 1769776584
}

resource "aws_lb_target_group" "example_target_group" {
  name     = "example_target_group"
  port     = 80
  protocol = "HTTP"

  health_check {
    port = 80
  }
}

resource "aws_elb" "example_elb" {
  name            = "example_elb"
  subnets         = data.aws_subnets.private.ids
  security_groups = [aws_security_group.instance_security_group.id]

  listener {
    id      = "example_listener"
    load_balancer_condition {
      host_header {
        values = ["example.com"]
      }
    }

    protocol = "HTTP"
    port     = 80

    default_actions {
      type             = "forward"
      target_group_arn  = aws_lb_target_group.example_target_group.arn
    }
  }
}
```

This example demonstrates the configuration of an AWS Elastic Load Balancer (ELB) using Terraform, including the creation of an instance profile, security group, target group, and listener. The `seed` value is provided for demonstration purposes and does not affect the performance or functionality of the configuration.
