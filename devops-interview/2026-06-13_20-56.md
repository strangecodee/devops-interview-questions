 # Interview Question
Can you explain how you would set up monitoring for a new service using our DevOps platform and tools, specifically focusing on incident alerting?

# Answer
I would begin by identifying the key performance indicators (KPIs) and error metrics associated with the new service using our monitoring dashboard. Next, I would configure alert thresholds for these metrics in our incident management system, such as Nagios or Splunk, ensuring they are set to an appropriate level for our team's response time. Furthermore, I would leverage our platform's auto-scaling capabilities to automatically handle incident escalation and resource allocation.

# Key Technical Points
- Identify KPIs and error metrics
- Configure alert thresholds in incident management system
- Utilize auto-scaling capabilities

# Real-World Example
Suppose our new service, forge, exhibits high error rates during periods of peak traffic. In this scenario, I would configure an alert in Nagios for the error rate metric, specifying a threshold of 3%. When the error rate exceeds this threshold, Nagios would trigger an alert, and our incident response team would be notified to investigate and resolve the issue. Furthermore, our auto-scaling solution would automatically allocate additional resources to the service to ensure it can handle the increased traffic.

```yaml
# Nagios configuration for error rate alert
define alert nagios-forge-error-rate {
  use generic-service
  host localhost
  service_description Forge Error Rate
  threshold 3%
}
```
