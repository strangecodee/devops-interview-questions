 # Interview Question
Can you explain the concept of Docker layers and how they contribute to efficient container image building?

# Answer
Docker layers represent the different components that make up a container image. When building an image, each instruction in the Dockerfile creates a new layer on top of the previous one. This approach allows for efficient image creation as only the changes made by each instruction are saved, rather than the entire image. This results in smaller image sizes and faster build times.

# Key Technical Points
- Each instruction in a Dockerfile creates a new layer, with the exception of the `FROM` instruction which establishes the base image.
- Only the differences between layers are saved, reducing image size and build time.
- Layers are read-only, and any writable data or modifications are stored in a separate overlay file system when the container is run.

# Real-World Example
Imagine building an image using the `alpine` base image and installing `apache`. The first instruction is `FROM alpine:latest`, creating the base layer. The subsequent instruction is `RUN apk update && apk add apache`, which installs `apache` and creates a new layer. When this image is deployed, the writable data and modifications will be stored in an overlay file system on top of these two layers.

```yaml
# Dockerfile
FROM alpine:latest
RUN apk update && apk add apache
```
