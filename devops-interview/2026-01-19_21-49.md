 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are essential security features in Kubernetes that help restrict access to clusters and enforce network security rules. RBAC allows defining roles and their associated permissions, while network policies enable configuring egress and ingress traffic based on labels and IP addresses. By using these features, you can ensure that only authorized traffic is allowed in and out of your Kubernetes cluster.

# Key Technical Points
- Utilize RBAC to define roles and their corresponding permissions, such as creating, modifying, and deleting deployments.
- Set up network policies to control traffic flow based on labels, IP addresses, and ports.
- Configure egress rules to restrict outbound traffic from your Kubernetes cluster to specific IP addresses or domains.

# Real-World Example
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: my-deployment-editor
rules:
- apiGroups: [""]
  resources: ["deployments"]
  verbs: ["create", "get", "update", "patch", "delete"]

---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: my-user-to-editor
subjects:
- kind: User
  name: my-user
roleRef:
  kind: Role
  name: my-deployment-editor
  apiGroup: rbac.authorization.k8s.io

---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: my-policy
spec:
  podSelector:
    matchLabels:
      app: my-app
  policyTypes:
  - Egress
  egress:
  - to:
    - ipBlock:
        cidr: 10.0.0.0/8
    ports:
    - protocol: TCP
      port: 80
    - protocol: UDP
      port: 53
```
In this example, we create an RBAC role for editing deployments and bind it to a specific user. Then, we define a network policy allowing egress traffic to IP addresses within the 10.0.0.0/8 CIDR block on ports 80 (TCP) and 53 (UDP).
