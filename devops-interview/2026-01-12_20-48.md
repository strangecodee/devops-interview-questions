 # Interview Question
Can you explain how you have implemented and configured a high-availability load balancer using Amazon Elastic Load Balancer (ELB) in a DevOps context?

# Answer
In my previous role as a Senior DevOps Engineer, I was responsible for ensuring the availability and scalability of critical applications. To accomplish this, I implemented and configured Amazon Elastic Load Balancer (ELB) to distribute incoming application traffic across multiple Amazon Elastic Compute Cloud (EC2) instances. This setup allowed for automatic failover and scaling based on traffic demand.

# Key Technical Points
- Amazon ELB is a fully managed service that automatically distributes incoming application traffic across multiple EC2 instances to ensure high availability and scalability.
- ELB uses a load balancing algorithm to distribute traffic evenly and automatically scales up or down based on traffic demand to maintain optimal performance.
- I configured ELB to use health checks to monitor the health of instances and automatically route traffic to healthy instances, improving application availability and reliability.

# Real-World Example
```yaml
Resources:
  LoadBalancer:
    Type: AWS::ElasticLoadBalancing::LoadBalancer
    Properties:
      Listeners:
        - Protocol: HTTP
          LoadBalancerPort: 80
          InstanceProtocol: HTTP
          InstancePort: 80
      HealthCheck:
        Type: ELB_BLACK_LIST
        TargetGroups:
          - Name: my-target-group
    DependsOn:
      - my-autoscaling-group
```
In this example, ELB is configured to use a health check that monitors the target group "my-target-group" for unhealthy instances. If an instance becomes unhealthy, ELB will automatically route traffic to healthy instances to maintain application availability.
