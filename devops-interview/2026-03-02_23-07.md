 # Interview Question
Can you explain your experience with securing Kubernetes clusters using RBAC and network policies?

# Answer
I have extensive experience in implementing and configuring Role-Based Access Control (RBAC) and network policies for securing Kubernetes clusters. RBAC allows you to manage access to Kubernetes resources based on roles and permissions. Network policies help control the flow of traffic between pods and services within the cluster.

# Key Technical Points
- RBAC is used to manage access to Kubernetes resources based on roles and permissions.
- Network policies control the flow of traffic between pods and services in the cluster using labels and selectors.
- Both RBAC and network policies are essential components of Kubernetes security.

# Real-World Example
Here's an example of creating a YAML file for an RBAC role and a network policy:

```yaml
# Role: my-app-reader.yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: my-app-reader
  namespace: default
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get"]

---

# Role binding: my-app-reader-binding.yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: my-app-reader-binding
  namespace: default
subjects:
- kind: User
  name: alice
roleRef:
  kind: Role
  name: my-app-reader
  apiGroup: rbac.authorization.k8s.io

---

# Network policy: my-app-network-policy.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: my-app-network-policy
spec:
  podSelector:
    matchLabels:
      app: my-app
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          team: frontend
      ports:
      - protocol: TCP
        port: 80
```

This example demonstrates creating an RBAC role and role binding for a user "alice" to access pods, and a network policy allowing ingress traffic from pods with the label "team: frontend" to the "my-app" pod on port 80.
