 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are essential security features in Kubernetes for managing access to resources and controlling network traffic respectively. RBAC allows defining and managing access control rules based on roles and users, while network policies enable configuring the network traffic between different pods and services in a cluster.

# Key Technical Points
- Using RBAC, you can define and manage roles and bind them to specific users, groups, or service accounts, ensuring that only authorized entities can access specific resources.
- Network policies enable creating rules to control the flow of traffic between pods and services based on source, destination, labels, and ports.
- This combination of RBAC and network policies provides a robust security model for controlling access to Kubernetes resources and ensuring communication between pods and services is secured.

# Real-World Example
Here's an example of creating an RBAC role and a network policy in YAML format:

```yaml
# RBAC Role
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: sample-role
  labels:
    app: sample-app
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "watch", "list"]

# RBAC Role binding
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: sample-role-binding
roleRef:
  kind: Role
  name: sample-role
  apiGroup: rbac.authorization.k8s.io
subjects:
- kind: User
  name: user1

# Network Policy
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: sample-network-policy
spec:
  podSelector:
    matchLabels:
      app: sample-app
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: allow-app
```

In this example, we create a role called `sample-role` that allows users to get, watch, and list pods. Then, we create a role binding named `sample-role-binding` that associates the `sample-role` with the user `user1`. Lastly, we create a network policy named `sample-network-policy`, which allows only traffic from pods with the label `app: allow-app` to access the pods with the label `app: sample-app`.
