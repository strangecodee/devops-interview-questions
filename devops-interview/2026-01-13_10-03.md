 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are crucial components of Kubernetes security. RBAC allows for managing access to Kubernetes resources based on roles and permissions. Network policies enable defining and enforcing traffic rules between pods and services inside a Kubernetes cluster.

# Key Technical Points
- RBAC: Manages access to Kubernetes resources based on roles and permissions, securing the cluster against unauthorized access.
- Network policies: Define and enforce traffic rules between pods and services, isolating traffic and securing the cluster against potential attacks.
- Combining RBAC and network policies: Enhances overall cluster security by controlling access to resources and managing network traffic.

# Real-World Example
Consider a scenario where you need to allow traffic from a specific pod to access another pod within your Kubernetes cluster. You can create a YAML file defining a network policy using the `networking.k8s.io/v1` API:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-traffic-between-pods
spec:
  podSelector:
    matchLabels:
      app: my-app
  ingress:
  - ports:
    - protocol: TCP
      port: 80
    from:
    - podSelector:
        matchLabels:
          app: other-app
    source:
      selector:
        matchLabels:
          app: other-app
```

This network policy allows traffic from pods with `app: my-app` label to access ports 80 on pods with the `app: other-app` label. Additionally, you would create RBAC roles and bindings to ensure only authorized users can modify or delete the network policy.
