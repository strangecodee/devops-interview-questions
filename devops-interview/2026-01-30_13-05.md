 # Interview Question
Can you explain how you have implemented and configured a high availability load balancer using Amazon Elastic Load Balancer (ALB) in a DevOps environment?

# Answer
In my previous role as a Senior DevOps Engineer, I was responsible for designing and implementing a scalable and highly available infrastructure for an enterprise application. To ensure optimal performance and availability, I utilized Amazon Elastic Load Balancer (ALB) to distribute incoming application traffic across multiple Amazon Elastic Compute Cloud (EC2) instances.

# Key Technical Points
- I configured the ALB listener to use a specific protocol and port for incoming application traffic, allowing for seamless integration with the application servers.
- To increase availability, I set up multiple EC2 instances in different Availability Zones (AZs) and registered each instance with the ALB. The ALB automatically distributes traffic among the registered instances, minimizing the risk of downtime due to instance failure.
- I implemented health checks to automatically detect and remove unhealthy instances from the load balancer rotation, ensuring that only healthy instances handle application traffic.

# Real-World Example
```yaml
Resources:
  MyALB:
    Type: AWS::ElasticLoadBalancingV2::LoadBalancer
    Properties:
      Listeners:
        - Protocol: HTTP
          Port: 80
          DefaultActions:
            - Type: Forward
              TargetGroupArn: !Ref MyTargetGroup

  MyTargetGroup:
    Type: AWS::ElasticLoadBalancingV2::TargetGroup
    Properties:
      TargetType: instance
      VpcId: !Ref MyVpc
      Protocol: HTTP
      HealthCheck:
        HealthyThreshold: 3
        UnhealthyThreshold: 2
        Interval: 30
        Timeout: 5
      Targets:
        - Id: !Ref MyInstance1
          Port: 80
        - Id: !Ref MyInstance2
          Port: 80
```
In this example, I create an ALB named "MyALB" and configure it with a listener that listens for HTTP traffic on port 80. I also define a target group named "MyTargetGroup" that contains two target instances, "MyInstance1" and "MyInstance2," both listening for HTTP traffic on port 80. The health check is set up to check for a successful HTTP response and will mark the instances as unhealthy if they fail to respond within the specified timeframe. The ALB is designed to automatically distribute traffic among healthy instances and remove unhealthy instances from the rotation.
