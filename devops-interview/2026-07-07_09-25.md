 # Interview Question
Please describe your experience with configuring and managing load balancing using Amazon Elastic Load Balancer (ALB) in a DevOps context.

# Answer
I've extensively worked with configuring and managing Amazon Elastic Load Balancer (ALB) to ensure optimal application performance, availability, and scalability in enterprise environments. ALB is a critical component of DevOps practices as it automatically distributes incoming application traffic across multiple Amazon EC2 instances, allowing automatic scaling and failover.

# Key Technical Points
- Configure and manage ALB listener protocols, ports, and security settings.
- Implement ALB target groups and register Amazon EC2 instances.
- Utilize ALB access logs and CloudWatch metrics for monitoring and troubleshooting.
- Set up health checks to automatically detect and register/deregister unhealthy instances.

# Real-World Example
```yaml
Resources:
  LoadBalancer:
    Type: "AWS::ElasticLoadBalancingV2::LoadBalancer"
    Properties:
      Name: "my-load-balancer"
      Subnets: ["subnet-abc123", "subnet-xyz456"]
      SecurityGroups: ["sg-def789"]
      Scheme: "internet-facing"
      Listeners:
        - Protocol: "HTTP"
          Port: "80"
          DefaultActions:
            - Type: "Forward"
              TargetGroupArn: "arn:aws:elasticloadbalancing:region:account-id:targetgroup/my-target-group/xxxxxxxxxxxx"

  TargetGroup:
    Type: "AWS::ElasticLoadBalancingV2::TargetGroup"
    Properties:
      Name: "my-target-group"
      Protocol: "HTTP"
      VpcId: "vpc-abc123"
      TargetType: "instance"
      HealthCheck:
        HealthCheckArn: "arn:aws:elasticloadbalancing:region:account-id:healthcheck/my-health-check/xxxxxxxxxxxx"
      BackendArns:
        - "arn:aws:ec2:region:account-id:instance/i-abc12345678:0"
        - "arn:aws:ec2:region:account-id:instance/i-def45678901:1"
```
