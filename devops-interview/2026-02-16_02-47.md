 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are two essential security mechanisms in Kubernetes that help in securing a cluster by controlling access to resources and limiting the communication between pods. RBAC allows defining roles and binding them to users or service accounts to manage access to Kubernetes resources, while network policies enable defining rules to control the communication between pods based on their labels and selectors.

# Key Technical Points
- RBAC is used to manage access to Kubernetes resources, including pods, services, and secrets, based on roles and permissions assigned to users or service accounts.
- Network policies allow defining rules to control the communication between pods based on their labels, selectors, and IP addresses.
- RBAC and network policies can be configured using YAML manifests or the Kubernetes web console.

# Real-World Example
Consider a scenario where we have a Kubernetes cluster with two namespaces, "dev" and "prod," and we want to grant read-only access to the "dev" namespace to a specific user "devuser" and deny all incoming traffic from the internet to the "prod" namespace. We can achieve this by creating the following resources:

1. RBAC Role and Role Binding for the "devuser" in the "dev" namespace:

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: dev-reader
  namespace: dev
rules:
- apiGroups: [""]
  resources: ["pods", "services"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: devuser-reader
  namespace: dev
subjects:
- kind: User
  name: devuser
roleRef:
  kind: Role
  name: dev-reader
```

2. Network Policy to deny all incoming traffic to the "prod" namespace:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: prod-deny-all
  namespace: prod
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
```

This example demonstrates how to use RBAC and network policies to secure a Kubernetes cluster by granting read-only access to a specific user in a namespace and denying all incoming traffic to another namespace.
