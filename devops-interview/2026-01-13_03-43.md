 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are essential security features in Kubernetes that help secure the cluster by controlling access to resources and enforcing network traffic rules, respectively. RBAC allows defining roles and assigning permissions to users or services based on their requirements, while network policies enable controlling the ingress and egress traffic between pods and external endpoints.

# Key Technical Points
- RBAC defines roles and assigns permissions to users or services based on their requirements, ensuring that only authorized entities can access specific resources.
- Network policies enable controlling the ingress and egress traffic between pods and external endpoints, isolating the communication between them and enforcing security rules.
- Kubernetes provides several predefined roles and role bindings, such as the 'cluster-admin' role, which grants complete cluster-wide access.

# Real-World Example
To create an RBAC role and role binding, you can use the following YAML manifest:
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: my-role
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "watch", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: my-role-binding
subjects:
- kind: User
  name: my-user
roleRef:
  kind: Role
  name: my-role
  apiGroup: rbac.authorization.k8s.io
```
This example creates a role named 'my-role' that grants read-only access to all pods, and a role binding named 'my-role-binding' that binds the role to a user named 'my-user'. Similar steps can be followed to create network policies using Kubernetes NetworkPolicy resources.
