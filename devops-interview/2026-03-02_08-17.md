 # Interview Question
Can you explain your experience with implementing Chaos Engineering practices using Eclipse Chaos Toolkit and describe key technical points and a real-world example?

# Answer
Chaos Engineering is a disciplined approach to testing the resilience and reliability of distributed systems by intentionally injecting failures and observing the system's response. Eclipse Chaos Toolkit is an open-source toolkit that enables the execution of chaos experiments for various systems.

Key Technical Points:
1. Chaos Engineering using Eclipse Chaos Toolkit involves defining experiments, creating test scripts, and executing them against your system to identify potential weaknesses and improve overall system resilience.
2. Experiments can be categorized into various types like network latency, resource availability, application failure injection, and more.
3. Eclipse Chaos Toolkit requires Java 8 or higher to run and supports different execution modes, including local and cloud-based execution.

# Real-World Example
Assume you have a microservices-based application deployed on AWS. To test its resilience against network latency, we can create a Chaos Engineering experiment using Eclipse Chaos Toolkit.

1. Define the experiment:
```yaml
{
  "name": "Test Microservices App with Network Latency",
  "description": "Test the behaviour of our microservices application under network latency",
  "version": "1.0.0",
  "run": {
    "input": {},
    "action": {
      "class": "org.chaostools.actions.network.NetworkLatencyAction",
      "arguments": {
        "host": "api.example.com",
        "port": 80,
        "latency": 300
      }
    },
    "output": {
      "class": "org.chaostools.reporter.report.SlackReporter",
      "arguments": {
        "webhookUrl": "https://hooks.slack.com/services/X/Y/Z"
      }
    }
  }
}
```

2. Execute the experiment:
```bash
java -jar chaos-toolkit-0.12.0-all.jar \
--manifest-file chaos.yaml \
--seed 1772419667
```

3. Monitor the results:
The experiment injects network latency between the microservices application and the specified API host (api.example.com) by introducing a delay of 300ms (latency). The output is reported via Slack to keep track of the experiment's status and results.
