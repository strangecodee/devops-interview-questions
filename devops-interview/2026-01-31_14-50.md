 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are key security features in Kubernetes that help you manage access to your cluster and enforce network traffic policies. RBAC allows you to define roles and assign permissions to users, while network policies help you control the flow of network traffic within your cluster.

# Key Technical Points
- Define roles and bind them to users or service accounts, granting them specific permissions
- Create role bindings to associate roles with users or service accounts
- Use network policies to define rules that allow or deny traffic based on source and destination IP addresses, ports, protocols, and labels
- Use labels to select and target specific pods or services

# Real-World Example
Let's consider a use case where we want to allow traffic only from trusted sources to our database pods. We'll create a network policy that denies all incoming traffic by default and allows traffic only from a specific IP address.

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: db-policy
spec:
  podSelector:
    matchLabels:
      app: db
  policyTypes:
  - Ingress
  ingress:
  - from:
    - ipBlocks:
      cidr: 10.0.0.0/16
    ports:
    - protocol: TCP
      port: 3306
```

In this example, we allow incoming traffic to port 3306 (MySQL) only from the IP range 10.0.0.0/16. All other traffic is denied. This policy is applied to all pods with the label `app: db`.
