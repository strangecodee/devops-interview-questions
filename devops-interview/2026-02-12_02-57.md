 # Interview Question
Can you explain how to implement zero-downtime deployments using Kubernetes?

# Answer
Zero-downtime deployments in Kubernetes can be achieved by utilizing Rollouts and Rollbacks. Rollouts progressively replace instances of a deployment with new versions, while Rollbacks revert to previous versions if necessary. This approach ensures availability and minimal disruption to the application's users.

# Key Technical Points
- Kubernetes Rollouts and Rollbacks are part of the Deployment feature, which automates application updates and manages the lifecycle of containers.
- Rollouts gradually replace old replicas with new replicas, allowing for controlled and stable updates.
- Rollbacks can be triggered if an update fails or causes issues, reverting the application back to the previous version.

# Real-World Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-repo:v1.0
        ports:
        - containerPort: 80
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-repo:v2.0
        ports:
        - containerPort: 80

# To deploy the new version
$ kubectl apply -f deployment-v2.yaml

# To check the deployment status
$ kubectl get deployment my-app

# To rollback to the previous version
$ kubectl rollout undo deployment my-app
```
