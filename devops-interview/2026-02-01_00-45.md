 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are two essential security features of Kubernetes that help secure a cluster by managing access to resources and controlling the network traffic flow respectively.

Firstly, RBAC allows defining roles and role bindings to ensure that only authorized users, services, and processes have access to the Kubernetes API and its resources. This can be achieved by creating ClusterRoles and RoleBindings using YAML manifests that define the allowed permissions.

Secondly, network policies help restrict network traffic between pods and services based on specific rules. These rules can be defined using YAML manifests to allow or deny traffic based on source and destination pods, ports, and protocols.

# Key Technical Points
- Define roles and role bindings to control access to Kubernetes API and resources using RBAC.
- Use YAML manifests to create ClusterRoles, RoleBindings, and NetworkPolicies.
- RBAC provides fine-grained access control while network policies help in enforcing network security rules.

# Real-World Example
```yaml
# Create a Role for a developer
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: developer
  namespace: default
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "watch", "list"]

# Create a RoleBinding for a user
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: developer-binding
  namespace: default
subjects:
- kind: User
  name: john.doe@example.com
  apiGroup: rbac.authorization.k8s.io
  roleRef:
    kind: Role
    name: developer
    apiGroup: rbac.authorization.k8s.io

# Create a NetworkPolicy to allow traffic from one pod to another
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: AllowTraffic
spec:
  podSelector:
    matchLabels:
      app: my-app
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: allowed-app
  egress:
  - to:
    - ipBlock:
        cidr: 0.0.0.0/0
```
This example demonstrates how to define a Role for a developer, create a RoleBinding for a user, and create a NetworkPolicy to allow traffic between specific pods. This setup ensures that the developer can access the required pods and that network traffic is restricted as per the defined rules.
