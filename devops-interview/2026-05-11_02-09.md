# Interview Question
Please explain how you would secure a Kubernetes deployment on AWS using RBAC and Secrets Manager.

# Answer
RBAC (Role-Based Access Control) and AWS Secrets Manager are essential security components when deploying applications on Kubernetes in the AWS environment. RBAC is used to control access to Kubernetes resources based on roles and permissions, while AWS Secrets Manager is a service that protects access to sensitive data such as API keys and passwords.

To secure a Kubernetes deployment, first, we need to create an IAM role for the Kubernetes cluster that has access to the AWS Secrets Manager. This role will be assumed by the Kubernetes control plane components, allowing them to retrieve secrets stored in AWS Secrets Manager.

Next, configure your Kubernetes manifests to use Secrets Manager to store and retrieve sensitive information. We can create a Kubernetes secret using the `kubectl create secret` command with the `--from-aws-secrets` flag to reference the secret in AWS Secrets Manager.

```
apiVersion: v1
kind: Secret
metadata:
  name: my-secret
type: Opaque
data:
  password: <base64-encoded-secret-value>
stringData:
  accessKey: my-access-key
stringData:
  secretAccessKey: my-secret-access-key
---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: my-role
rules:
- apiGroups: [""]
  resources: ["secrets"]
  verbs: ["get"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: my-binding
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: my-role
subjects:
- kind: ServiceAccount
  name: default
```

Key Technical Points:
- Create an IAM role for the Kubernetes cluster to access AWS Secrets Manager.
- Configure your Kubernetes manifests to use Secrets Manager for sensitive data.
- Use RBAC to control access to the Kubernetes secrets.

# Real-World Example
Assuming you have created an IAM role named `k8s-role` for your Kubernetes cluster, and an AWS Secrets Manager secret named `my-secret` containing a password.

First, create a Kubernetes secret using the following command:

```
kubectl create secret generic my-secret \
  --from-aws-secrets secret-name \
  --dry-run=client -o yaml > my-secret.yaml
```

Replace `secret-name` with the name of the secret in AWS Secrets Manager. This command creates a Kubernetes secret named `my-secret` in the `my-secret.yaml` file.

Next, apply the RBAC configuration to enable the default service account to access the secret:

```
kubectl apply -f my-secret-rbac.yaml
```

Replace `my-secret-rbac.yaml` with the name of the RBAC configuration file. This file should include the `Role` and `RoleBinding` definitions shown above. Finally, apply the Kubernetes secret using `kubectl apply -f my-secret.yaml`. Now, your application can access the secret using the `my-secret` Kubernetes secret.
