 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and network policies?

# Answer
RBAC (Role-Based Access Control) and network policies are essential security components in a Kubernetes environment. RBAC allows fine-grained access control based on roles and permissions, while network policies manage traffic between pods and services.

# Key Technical Points
- RBAC allows defining granular access control rules for users, service accounts, and groups. For example, you can create a custom role with specific permissions for deploying applications, managing infrastructure, or monitoring logs.
- Network policies use labels and selectors to define security rules for pods and services. You can allow or deny traffic based on source and destination pods, ports, and protocols.
- A best practice is to apply the least privilege principle and minimize the attack surface by defining the most restrictive RBAC rules and network policies possible.

# Real-World Example
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: my-app-deployer
rules:
- apiGroups: ["apps"]
  resources: ["deployments"]
  verbs: ["create", "get", "update", "patch", "delete"]

---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: my-app-deployer-binding
subjects:
- kind: User
  name: john.doe@example.com
roleRef:
  kind: Role
  name: my-app-deployer
  apiGroup: rbac.authorization.k8s.io

---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: my-app-network-policy
spec:
  podSelector:
    matchLabels:
      app: my-app
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          team: network-team
    ports:
    - protocol: TCP
      port: 80
```
In this example, we create a Role called 'my-app-deployer' that allows a user to create, manage, and delete deployments for applications with the 'my-app' label. We then bind this role to a user. Additionally, we define a NetworkPolicy to allow incoming traffic only from the 'network-team' pods on port 80.
