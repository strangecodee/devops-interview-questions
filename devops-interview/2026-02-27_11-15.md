 # Interview Question
Can you explain how Terraform's "matrix" feature is used to apply infrastructure changes in a more efficient manner?

# Answer
Terraform's "matrix" feature is a powerful capability that allows for the execution of multiple application of resource configurations with distinct input variables in a single run. By leveraging matrices, we can streamline the process of testing various combinations of input variables or performing parallel infrastructure deployments. This results in reduced time and effort required for testing and deployment.

# Key Technical Points
- Matrices enable the execution of multiple combinations of input variables in a single Terraform apply command.
- This functionality helps to minimize the time and effort needed for testing and deployment of infrastructure changes.
- Matrices also improve the efficiency of the infrastructure management process by reducing the number of individual apply commands that would otherwise be required.

# Real-World Example
Consider a scenario where you need to deploy multiple instances of an application with different configurations (e.g., different instance sizes or regions). Without using matrices, you would need to run the Terraform apply command separately for each combination. By utilizing a matrix, you can perform all the deployments in a single run:

```hcl
provider "aws" {
 region = "us-west-2"
}

resource "aws_instance" "example" {
 count = length(var.sizes)
 ami           = "ami-0c55b159cbfafe1f0"
 instance_type = var.sizes[count.index] # matrix column
 subnet_id     = aws_subnet.example.id

 connection {
   type        = "ssh"
   user        = "ec2-user"
   host        = self.public_ip
   timeout     = "2m"
 }
}

variable "sizes" {
 type        = list(string)
 default     = ["t2.micro", "t2.small"]
 description = "List of instance sizes"
}

output "instance_ips" {
 value = aws_instance.example.*.public_ip
}

locals {
 matrix = [for size in var.sizes : { size = size }]
}

provider "aws" {
 aliyun   = true
 region   = "cn-north-1" # matrix row
}

resource "aws_instance" "example_aliyun" {
 count = length(local.matrix)
 ami           = "ami-12345678"
 instance_type = local.matrix[count.index].size # matrix index
 subnet_id     = aws_subnet.example.id

 connection {
   type        = "ssh"
   user        = "root"
   host        = self.public_ip
   timeout     = "2m"
 }
}

output "instance_ips_aliyun" {
 value = aws_instance.example_aliyun.*.public_ip
}

# Run Terraform apply with matrix
$ terraform apply -input=false -var "sizes=[$aws_instance.example.*.instance_type, $aws_instance.example_aliyun.*.instance_type]" -var "regions=[us-west-2, cn-north-1]"
```

In this example, we define a matrix by combining two variables: `sizes` and `regions`. The `aws_instance` resource is defined twice, once for AWS and once for Alibaba Cloud. The matrix allows us to apply the configurations of both instances with different sizes and regions in parallel, reducing the overall time and effort required.
