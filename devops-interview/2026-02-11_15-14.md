 # Interview Question
Can you explain how to implement auto-scaling using AWS Elastic Container Service (ECS) Fargate and Application Load Balancer (ALB)?

# Answer
Auto-scaling in AWS ECS Fargate and ALB involves configuring the application load balancer to automatically adjust the number of backends based on traffic demands, and using Amazon ECS service auto-scaling to adjust the number of tasks in response to traffic changes.

# Key Technical Points
- Configure the Application Load Balancer (ALB) to automatically adjust the number of backends based on traffic. This can be done using the ALB's built-in scaling policies, such as target tracking, or using Amazon CloudWatch alarms.
- Set up Amazon ECS service auto-scaling to adjust the number of tasks based on the desired CPU utilization. This can be done using the Amazon ECS service auto-scaling feature, which allows you to define a minimum and maximum number of tasks, as well as a scaling policy based on CPU utilization.
- Use Amazon CloudWatch to monitor the system and provide feedback to the auto-scaling policies. This includes monitoring the ALB's target group metrics and the ECS service metrics.

# Real-World Example
```yaml
# Application Load Balancer configuration for auto-scaling
Resources:
  ALB:
    Type: AWS::ElasticLoadBalancingV2::ApplicationLoadBalancer
    Properties:
      # ...
      ScalingPolicies:
        - PolicyName: ALBAutoscalePolicy
          PolicyType: TargetTrackingScaling
          TargetTrackingScalingPolicyConfiguration:
            TargetTrackingScalingMetric:
              MetricName: AverageUtilities
              PredefinedMetricName: ELBApplicationAccessLogs
              PredefinedMetricStat:
                Metric: AverageUtilities
                Period: 60
                Statistic: Average
              TargetValue: 50
            ScalingPolicyMetrics:
              - MetricName: AverageUtilities
              Cooldown: 300
              AdjustmentType: ChangeInCapacity
              AdjustmentValue: 1

# ECS service configuration for auto-scaling
Resources:
  Service:
    Type: AWS::ECS::Service
    Properties:
      # ...
      ServiceName: my-service
      Cluster: !Ref ECSCluster
      DesiredCount: 1
      LaunchTemplate:
        # ...
      ServiceAutoscaling:
        MinimumHealthyPercentage: 100
        MaximumPercent: 200
        ScalingPolicies:
          - PolicyName: ECSAutoscalePolicy
            PolicyType: ScheduledScaling
            ScheduledScalingPolicyConfiguration:
              ScheduledActions:
                - Type: AddCapacity
                  CapacityProviderStrategy:
                    Type: Fargate
                    CapacityProvider: <MyCapacityProvider>
                    Weight: 1
                  DesiredCapacity: 2
                  Metrics:
                    - MetricName: CPUUtilization
                      Period: 120
                      Statistic: Average
                      Unit: Percent
                  ScalingAdjustment: 1
              ScheduleExpression: rate(1 hour)
```
In this example, the Application Load Balancer (ALB) is configured to use target tracking scaling, which automatically adjusts the number of backends based on the average utilization of the target group. The ECS service is configured to use scheduled scaling, which adjusts the number of tasks based on the average CPU utilization. Both the ALB and ECS service are monitored using Amazon CloudWatch, which provides the feedback needed for the auto-scaling policies to make adjustments.
