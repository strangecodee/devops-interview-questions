 # Interview Question
Can you explain how to configure a high availability load balancer using vector-based weighting in Kubernetes?

# Answer
In Kubernetes, to configure a high availability load balancer with vector-based weighting, you need to utilize the MetalLB or Nginx Ingress Controller. Vector-based weighting allows assigning weights to individual services, which can be used to distribute traffic based on specific requirements. Kubernetes does not natively support vector-based weighting for load balancing, which is why you need to deploy an appropriate Ingress Controller.

# Key Technical Points
- You can use MetalLB or Nginx Ingress Controller to implement vector-based weighting in Kubernetes.
- Vector-based weighting allows assigning weights to individual services, which affects the traffic distribution.
- Properly configuring the Ingress Controller ensures high availability of the load balancer and application traffic.

# Real-World Example
To configure MetalLB with vector-based weighting, follow these steps:

1. Install MetalLB using the official Helm chart: `helm install metal-lb stable/metallb --namespace metallb-system`.
2. Create a YAML file for a MetalLB Ingress:
```yaml
apiVersion: v1
kind: Service
metadata:
  annotations:
    metallb.config.k8s.io/config: |
      apiVersion: v3
      kind: LoadBalancer
      metadata:
        name: my-service
      spec:
        selector:
          app: my-app
        ports:
        - name: http
          port: 80
          protocol: TCP
          targetPort: 80
        - name: https
          port: 443
          protocol: TCP
          targetPort: 443
        listeners:
        - address: 0.0.0.0
          name: http
          protocol: HTTP
          defaultBackends:
          - serviceName: my-service
            servicePort: 80
        - address: 0.0.0.0
          name: https
          protocol: HTTPS
          defaultBackends:
          - serviceName: my-service
            servicePort: 443
          tls:
            cert: /path/to/cert.pem
            key: /path/to/key.pem
            caCerts: /path/to/ca.pem
        providers:
        - type: k8s
          ipAddresses:
          - 172.31.21.142
          - 172.31.22.142
          - 172.31.23.142
          - 172.31.24.142
          id: my-provider
          iPAddressType: v4
      ---
      apiVersion: v1
      kind: Ingress
      metadata:
        annotations:
          kubernetes.io/ingress.global-static-ip-name: my-ip
          kubernetes.io/ingress.enable-cname: "true"
          nginx.ingress.kubernetes.io/rewrite-target: /
        name: my-ingress
        namespace: my-namespace
      spec:
        rules:
        - host: example.com
          http:
            paths:
            - path: /service1
              pathType: Prefix
              backend:
                service:
                  name: service1
                  port:
                    number: 80
                    name: http
                weight: 50
            - path: /service2
              pathType: Prefix
              backend:
                service:
                  name: service2
                  port:
                    number: 80
                    name: http
                weight: 50
            - path: /service3
              pathType: Prefix
              backend:
                service:
                  name: service3
                  port:
                    number: 80
                    name: http
                weight: 10
```
3. Apply the YAML file using `kubectl apply -f my-file.yaml`. This configuration sets up an Ingress with three services, each having a specific weight for traffic distribution.
