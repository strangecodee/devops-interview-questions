 # Interview Question
Can you explain how to secure a Kubernetes cluster using RBAC and explain some key concepts?

# Answer
Role-Based Access Control (RBAC) in Kubernetes is a built-in authorization system that helps manage access to Kubernetes resources. It uses a fine-grained access control model based on roles and permissions. RBAC defines who can perform which actions on which resources in the cluster based on their assigned roles.

Key Technical Points:
- RBAC consists of three main components: Roles, RoleBindings, and ClusterRoles/ClusterRoleBindings.
- Roles define the permissions for a single Kubernetes resource.
- RoleBindings associate a role with a user, group, or service account.
- ClusterRoles provide permissions across all namespaces in a cluster, while ClusterRoleBindings associate a ClusterRole with a user, group, or service account.

# Real-World Example
To create an RBAC Role that allows deploying pods, edit the kube-system namespace's `rbac-manager` Role, which is an example role for deploying applications.

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: my-deployer
  namespace: kube-system
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["create", "get", "update", "patch", "delete"]
```

Create a RoleBinding for an existing user to bind them to the new Role:

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: my-deployer-binding
  namespace: kube-system
subjects:
- kind: User
  name: my-user
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: my-deployer
  apiGroup: rbac.authorization.k8s.io
```

With these configurations, the user `my-user` now has the ability to create, get, update, patch, and delete pods in the `kube-system` namespace.
