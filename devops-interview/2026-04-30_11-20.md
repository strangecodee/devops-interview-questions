# Real-World Example
In a previous enterprise deployment, I integrated Vector into our Kubernetes security stack. By creating a YAML configuration file, we were able to deploy the Vector DaemonSet:

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: vector-kube
spec:
  selector:
    matchLabels:
      app: vector
  template:
    metadata:
      labels:
        app: vector
    spec:
      containers:
      - name: vector
        image: vector/vector:v2.17.0
        ports:
        - containerPort: 1514
        env:
        - name: VECTOR_LOG_LEVEL
          value: INFO
        volumeMounts:
        - name: vector-data
          mountPath: /data
      volumes:
      - name: vector-data
        persistentVolumeClaim:
          claimName: vector-data
```

The Vector DaemonSet was configured to run in the background and scan all containers in the Kubernetes cluster for potential threats, while observing log data and applying countermeasures as necessary. By utilizing GitOps, we were able to continuously update and manage the Vector DaemonSet configuration, ensuring our security posture remained up-to-date.
