# Real-World Example
Consider a scenario where we need to restrict access to a specific Kubernetes deployment for only certain users within our organization. I would implement RBAC rules to define the required roles and permissions for accessing the deployment. Here's a snippet of a YAML configuration for defining a custom role:

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: myapp-deployer
rules:
- apiGroups: [""]
  resources: ["deployments"]
  verbs: ["get", "watch", "list", "create"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: myapp-user-binding
subjects:
- kind: User
  name: myuser
roleRef:
  kind: Role
  name: myapp-deployer
  apiGroup: rbac.authorization.k8s.io
```

This configuration defines a custom role named `myapp-deployer` with read access to all deployments. A role binding for the user named `myuser` is then created, allowing them to assume the `myapp-deployer` role and access the specified deployments.
