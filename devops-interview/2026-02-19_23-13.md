 # Interview Question
Can you explain your experience with implementing an on-call rotation system using a configuration management tool in an SRE context?

# Answer
An on-call rotation system is a crucial element of Site Reliability Engineering (SRE) practices, ensuring that team members are available to handle incidents and maintain system stability. I have experience implementing such a system using the Ansible configuration management tool.

# Key Technical Points
- Ansible is an open-source automation engine that simplifies application deployment, configuration management, and task automation.
- I created a playbook that manages on-call rotations by generating a dynamic list of team members and their assignments for a given week.
- This playbook uses Ansible's variables, templates, and loops, enabling automatic generation of the on-call schedule without manual intervention.

# Real-World Example
```yaml
---
- hosts: localhost
  tasks:
    - name: Define list of team members
      set_fact:
        team_members:
          - john.doe@example.com
          - jane.doe@example.com
          - jim.brown@example.com
          - jack.green@example.com

    - name: Generate on-call schedule
      set_fact:
        on_call_schedule: {}

      loop: "{{ range(1, 7) | int + 1 | map(string) | join('') }}"
        loop_var: week_number
      vars:
        start_day: Monday
        end_day: Sunday
      tasks:
        - name: Assign team member for week number {{ week_number }}
          set_fact:
            on_call_schedule:
              "{{ week_number }}" : "{{ item }}"
          loop: "{{ team_members }}"
          vars:
            day: "{{ item }}"
            start_day: "{{ start_day }}"
            end_day: "{{ end_day }}"
          when: "{{ week_number }} <= 7 and day != {{ ansible_loop_index }}"

      register: on_call_rotation

    - debug:
        msg: "On Call Schedule for week: {{ on_call_rotation.iter.index0 }}: "
        var: on_call_schedule
```
This example demonstrates the creation of an on-call rotation schedule for a week using Ansible. The playbook defines a list of team members and assigns a rotating on-call duty based on their availability each week. The first team member is on-call during the first week, the second team member during the second week, and so on. The playbook ensures that no team member is on-call for more than one week in a row, providing a fair and effective on-call rotation.
