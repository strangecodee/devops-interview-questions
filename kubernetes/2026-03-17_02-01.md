 # Kubernetes Concept
This example introduces a Kubernetes DaemonSet for running a logging agent, such as Fluentd or ELK Stack, ensuring that at least one instance is running on every node in the cluster.

# Explanation
DaemonSets ensure that a specified number of replicas of a container run on each node in the cluster, maintaining a consistent logging agent fleet for centralized logging. This configuration is ideal for services that require system-level visibility, such as monitoring CPU, memory usage, and network activity.

# Best Practices
- Ensure the logging agent container image is lightweight and consumes minimal resources.
- Configure the logging agent DaemonSet to use appropriate resource requests and limits.
- Set up a separate logging namespace for the DaemonSet to maintain a clear namespace hierarchy.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: phoenix-logging-agent
  namespace: logging
  labels:
    app: phoenix-logging-agent
spec:
  selector:
    matchLabels:
      app: phoenix-logging-agent
  template:
    metadata:
      labels:
        app: phoenix-logging-agent
    spec:
      containers:
      - name: phoenix-logging-agent
        image: logging-agent:v1.0.0
        ports:
        - containerPort: 25220
          protocol: TCP
        resources:
          limits:
            cpu: "0.5"
            memory: "512Mi"
          requests:
            cpu: "100m"
            memory: "256Mi"
        lifecycle:
          preStart:
            exec:
              command: ["/usr/bin/setup.sh"]
          postStart:
            exec:
              command: ["/usr/bin/start.sh"]
          preStop:
            exec:
              command: ["/usr/bin/stop.sh"]
          failureProbes:
            - failureThreshold: 3
              periodSeconds: 5
              timeoutSeconds: 5
              probe:
                exec:
                  command: ["/usr/bin/healthcheck.sh"]
          imageRestartPolicy: Always
```
In this example, we have defined a DaemonSet named `phoenix-logging-agent` with an appropriate label selector, container image, and resource requirements. We've also added `preStart`, `postStart`, `preStop`, and `failureProbes` configurations to ensure a smooth startup and shutdown process.
