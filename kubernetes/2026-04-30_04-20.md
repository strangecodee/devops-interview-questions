# Kubernetes Concept
Kubernetes DaemonSet is a way to ensure a copy of a pod runs on all nodes in a cluster.

# Explanation
DaemonSets create and manage a set ofpods across the nodes in a cluster. For each node, at most one instance of a pod is running, and it is scheduled to run on every node where the label selector matches. This ensures that a critical daemon or service is running on every node, which is essential for maintaining cluster health and availability.

# Best Practices
- Use DaemonSets for services that require a single instance per node, such as monitoring agents or logging daemons.
- Use health checks, such as readiness and liveness probes, to ensure the pods are running correctly and ready to serve traffic.
- Keep DaemonSet images up-to-date to ensure the latest security patches and features.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-daemonset
  labels:
    app: logging
spec:
  selector:
    matchLabels:
      app: logging
  template:
    metadata:
      labels:
        app: logging
    spec:
      containers:
      - name: logging-container
        image: logging-image:latest
        ports:
        - containerPort: 514
        - containerPort: 9001
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:514 || exit 1"]
            intervalSeconds: 5
            timeoutSeconds: 2
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:514 || exit 1"]
            intervalSeconds: 30
            timeoutSeconds: 5
```
This example creates a DaemonSet named 'logging-daemonset' that runs a logging container on each node. The container listens on ports 514 and 9001, and both readiness and liveness probes are defined to ensure the container is running and ready to serve traffic.
