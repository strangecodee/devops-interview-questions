 # Kubernetes Concept
Deployment is a Kubernetes object used to roll out and manage containerized applications.

# Explanation
A Deployment creates and manages a desired state for a set of replica Pods based on a container image, configuration, or revision. When a new version is released, Kubernetes creates new replicas with the updated container image and gradually rolls out the new version to traffic, ensuring zero downtime and minimal disruption.

# Best Practices
- Always use rolling updates to minimize downtime.
- Set up a strategy for updating your Deployment, such as Blue/Green or Canary.
- Monitor your application's health and readiness before and after updates.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-webapp
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: my-webapp
  template:
    metadata:
      labels:
        app: my-webapp
    spec:
      containers:
      - name: my-webapp
        image: my-webapp:1.0.0
        ports:
        - containerPort: 80
          name: http
        readinessProbe:
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 5
```
This example demonstrates a Deployment for a web application with three replicas, a rolling update strategy, and a readiness probe to ensure the application is ready before sending traffic.
