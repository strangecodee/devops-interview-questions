 # Kubernetes Concept
Deployment is a declarative way to create and manage containers in a Kubernetes cluster. A single Deployment can create, update, and scale multiple replicas of a container.

# Explanation
A Deployment in Kubernetes manages the lifecycle of a set of replicas of a container. It ensures that a specified number of replicas are running and available at any given time. It also performs rolling updates, which replace containers in a controlled manner to minimize downtime.

# Best Practices
- Use a rolling update strategy to minimize downtime when deploying new container versions.
- Set health checks to ensure that only healthy containers are serving traffic.
- Use labels to manage and select groups of containers.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-app
  labels:
    app: nebula
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
        - name: nebula
          image: nebula:v1
          ports:
            - containerPort: 80
          livenessProbe:
            httpGet:
              path: /healthz
              port: 80
          readinessProbe:
            httpGet:
              path: /ready
              port: 80
```
This example demonstrates a Deployment managing three replicas of a container named "nebula". The container is based on the image "nebula:v1" and listens on port 80. Liveness and readiness probes are defined to ensure container health.
