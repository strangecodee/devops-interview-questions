 # Kubernetes Concept
Deployment is a Kubernetes object used for managing containerized applications by creating, updating, and scaling replicas.

# Explanation
A Kubernetes Deployment defines the desired state for a set of replicas that run and maintain a specified number of updated instances of a containerized application. It handles the rolling update process by updating instances progressively while ensuring high availability and zero downtime.

# Best Practices
- Use rolling updates (update replicas incrementally) instead of recreating all of them at once.
- Use `readinessProbe` and `livenessProbe` to ensure the containers are running correctly.
- Use `rolling-update` strategy with `maxSurge` and `maxUnavailable` to control the number of new replicas and the minimum available instances during updates.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-app:latest
        ports:
        - containerPort: 80
      readinessProbes:
      - apiVersion: v1
        kind: Probe
        name: readiness
        exec:
          command: ["/bin/sh", "-c", "curl --fail --head --silent --connect-timeout 5 http://localhost || exit 1"]
        periodSeconds: 10
      livenessProbes:
      - apiVersion: v1
        kind: Probe
        name: liveness
        exec:
          command: ["/bin/sh", "-c", "curl --fail --head --silent --connect-timeout 5 http://localhost || exit 1"]
        periodSeconds: 30
  strategy:
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
```
