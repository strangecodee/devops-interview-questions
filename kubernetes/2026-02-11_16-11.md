 # Kubernetes Concept
Deployment is a Kubernetes resource for managing and creating containers. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
A Deployment creates and manages replicas of a container using a YAML manifest file. It provides updates and rollbacks and ensures availability and scalability. Kubernetes Continuously rolls out updates and monitors the health of the new replicas before marking the old ones as dead.

# Best Practices
- Use labels for easy identification and management of your deployment.
- Use rolling updates for minimal downtime and automatic rollbacks in case of failures.
- Use health checks and readiness probes to ensure that your containers are healthy and ready to serve traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-deployment
  labels:
    app: forge
spec:
  replicas: 3
  selector:
    matchLabels:
      app: forge
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: forge
        image: forge:latest
        ports:
        - containerPort: 80
      livenessProbe:
        httpGet:
          path: /healthz
          port: 80
      readinessProbe:
        httpGet:
          path: /readiness
          port: 80
```
This example creates a Deployment named 'forge-deployment' with three replicas running the 'forge:latest' container image. It uses labels for easy identification and management. The liveness and readiness probes ensure the containers are healthy and ready to serve traffic.
