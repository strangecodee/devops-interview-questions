 # Kubernetes Concept
This example introduces a Kubernetes Service of type LoadBalancer, which exposes a Kubernetes deployment to the external network using a cloud provider's load balancer.

# Explanation
A Kubernetes Service of type LoadBalancer creates a cloud provider's load balancer and distributes incoming traffic to the available pods in the deployment. It provides a single IP address for external traffic to reach the application. In this example, we'll expose an Nginx deployment.

# Best Practices
- Practice 1: Use a single Service per deployment rather than exposing multiple deployments using a single Service. This simplifies management and provides better network security.
- Practice 2: Use a ClusterIP Service for internal services and a LoadBalancer or NodePort Service for external traffic.
- Practice 3: Use an Ingress Controller instead of a LoadBalancer for more advanced routing and traffic management.

# YAML Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: nebula-loadbalancer
  labels:
    app: nebula
spec:
  type: LoadBalancer
  selector:
    app: nebula
  ports:
  - port: 80
    targetPort: 80
    protocol: TCP
  - port: 443
    targetPort: 443
    protocol: TCP
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nginx:1.22.1
        ports:
        - containerPort: 80
        - containerPort: 443
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula
  labels:
    app: nebula
spec:
  selector:
    matchLabels:
      app: nebula
  replicas: 3
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nginx:1.22.1
        ports:
        - containerPort: 80
        - containerPort: 443
```
