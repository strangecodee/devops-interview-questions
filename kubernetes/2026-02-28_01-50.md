 # Kubernetes Concept: Deployment
A Kubernetes Deployment manages the lifecycle of a set of replicas for a desired number of available instances of a Pod, ensuring availability and scalability.

# Explanation
A Deployment creates and manages the desired state for a Pod, including updates and rollbacks. When changes are made to the container image, the Deployment controller updates the Pods to the new version, ensuring zero downtime through rolling updates.

# Best Practices
- Use rolling updates for minimal downtime during Deployment updates.
- Use health checks and readiness probes to ensure new replicas are healthy before they are made available to traffic.
- Use Horizontal Pod Autoscaling in conjunction with Deployments to automatically scale the number of replicas based on resource utilization or custom metrics.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-deployment
spec:
  selector:
    matchLabels:
      app: nebula
  replicas: 3
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /
            port: 80
        readinessProbe:
          httpGet:
            path: /
            port: 80
---
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: nebula-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nebula-deployment
  minReplicas: 1
  maxReplicas: 5
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 80
```
