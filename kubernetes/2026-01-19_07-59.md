 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas of a container are running at any given time, and it can perform rolling updates and rollbacks.

# Explanation
A Deployment creates and manages the desired state of a group of containers, called replicas, running in the cluster. It keeps the desired number of replicas running at all times, and it can update the containers in a rolling fashion, minimizing downtime. It also provides a way to roll back to a previous version if necessary.

# Best Practices
- Use labels to uniquely identify and select your Deployments.
- Use RollingUpdate strategy to minimize downtime during updates.
- Use Health checks and Liveness probes to monitor the health of the containers and automatically restart them if necessary.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse-deployment
  labels:
    app: eclipse
spec:
  selector:
    matchLabels:
      app: eclipse
  replicas: 3
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
      - name: eclipse
        image: openjdk:latest
        ports:
        - containerPort: 8080
          protocol: TCP
      livenessProbe:
        httpGet:
          path: /healthz
          port: 8080
        initialDelaySeconds: 30
        periodSeconds: 5
```
This YAML example creates a Deployment named `eclipse-deployment` with three replicas of the `eclipse` container running on the `openjdk:latest` image. It also includes a liveness probe, which checks the container's health by sending an HTTP request to the `/healthz` endpoint on port `8080`. The probe waits for 30 seconds before the first check and then checks every 5 seconds thereafter.
