 # Kubernetes Concept
Kubernetes Deployment is a declarative way to manage the lifecycle of a set of replicas of a containerized application.

# Explanation
A Deployment creates or updates pods in a desired state and maintains the specified number of replicas using a rolling update strategy. It allows for seamless updates and rollbacks, and automatically replaces unhealthy replicas.

# Best Practices
- Use rolling updates to minimize downtime.
- Set up a liveness and readiness probe for your application.
- Use labels and selectors for easy management and scaling.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-image:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```
This YAML creates a Deployment named `my-app` with 3 replicas, using the container image `my-registry/my-image:latest`. The liveness and readiness probes are set up to check the `/healthz` and `/ready` endpoints respectively.
