 # Kubernetes Concept
This is an example of a Kubernetes Service and Ingress resource for load balancing and exposing a secure web application using TLS.

# Explanation
The Kubernetes Service resource is used to expose a stable IP address and DNS name for a set of Pods. In this example, we have defined a Service of type `LoadBalancer` for our web application. The Ingress resource acts as a reverse proxy and manages external access to the cluster, allowing inbound connections using HTTPS. TLS certificates are mounted as a secret, and the Ingress controller is responsible for terminating the SSL connection and passing the traffic to the backend Service.

# Best Practices
- Use a dedicated Ingress controller for handling TLS termination to maintain a clean and simple Service definition.
- Store and manage TLS certificates using a Kubernetes Secret.
- Use an external load balancer (e.g., GCE, AWS ELB) for better scalability and traffic distribution.

# YAML Example
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: tls-certs
data:
  tls.crt: <base64-encoded-cert-data>
  tls.key: <base64-encoded-key-data>
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: webapp-ingress
  annotations:
    nginx.ingress.kubernetes.io/proxy-body-size: 50m
    nginx.ingress.kubernetes.io/ssl-passthrough: "true"
spec:
  tls:
  - hosts:
    - example.com
    secretName: tls-certs
  rules:
  - host: example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: webapp-service
            port:
              name: http
---
apiVersion: v1
kind: Service
metadata:
  name: webapp-service
spec:
  selector:
    app: webapp
  ports:
    - name: http
      port: 80
      targetPort: 80
  type: LoadBalancer
```
