 # Kubernetes Concept: Deployment
A Kubernetes Deployment manages the rolling update and rollback of containerized applications. It creates and maintains a specified number of replicas and ensures their availability through automated rolling updates and self-healing.

# Explanation
Deployments in Kubernetes provide a declarative update mechanism for managing applications. When a Deployment is updated, Kubernetes performs a rolling update, updating the replicas one at a time while ensuring availability through readiness probes. If a new replica fails to start or fails the readiness probe, it is rolled back to the previous version.

# Best Practices
- Use Rolling Updates: Update your application gradually, with minimal downtime and rollback capability.
- Use Readiness Probes: Ensure that only healthy instances are serving traffic by utilizing readiness probes.
- Use Configuration Management Tools: Use tools like Helm or Kustomize for managing and deploying your applications.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: my-app
          image: my-registry/my-app:latest
          ports:
            - containerPort: 80
          readinessProbe:
            probeType: HTTP
            httpGet:
              path: /healthz
              port: 80
```
In this example, we have defined a Deployment named "my-app" with three replicas. The application is labeled with "app: my-app", and its container image is pulled from "my-registry/my-app:latest". The container exposes port 80 for both the application and the readiness probe. The readiness probe is set up as an HTTP GET request to the "/healthz" endpoint on port 80.
