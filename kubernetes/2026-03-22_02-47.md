 # Kubernetes Concept
This example introduces a Kubernetes DaemonSet, which ensures that a specified number of replicas of a Pod are running on each node in the cluster.

# Explanation
DaemonSets are particularly useful for deploying system daemons, such as monitoring agents or logging collectors, ensuring that they run on all nodes in a cluster. In this example, we will deploy a logging agent DaemonSet named "my-daemonset" using the Fluentd container image.

# Best Practices
- Ensure that the DaemonSet's container image is regularly updated to maintain security and stability.
- Implement resource requests and limits to ensure that the DaemonSet's resource usage is optimized and does not interfere with other workloads.
- Monitor the DaemonSet's logs to detect and address any issues proactively.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemonset
  template:
    metadata:
      labels:
        app: my-daemonset
    spec:
      containers:
      - name: my-daemonset-container
        image: fluent/fluentd:v1.14-1
        resources:
          requests:
            cpu: 100m
            memory: 128Mi
          limits:
            cpu: 200m
            memory: 256Mi
        volumeMounts:
        - name: var-log
          mountPath: /var/log
          readOnly: false
      volumes:
      - name: var-log
        hostPath:
          path: /var/log
```
This YAML example defines a DaemonSet named "my-daemonset" with a container running the Fluentd image, which is configured to consume logs from the host system. The container is assigned 100m CPU and 128Mi memory requests, with 200m CPU and 256Mi memory limits. The container is also mounted to the host's `/var/log` directory to access and collect logs.
