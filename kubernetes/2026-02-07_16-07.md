 # Kubernetes Concept
Deployment is a Kubernetes resource for managing and updating containerized applications. It ensures that a specified number of replicas of a container image are running at any given time.

# Explanation
A Kubernetes Deployment creates and manages the lifecycle of a set of replica Pods. When a new version of a container image is deployed, Kubernetes rolls out the new version and rolls back if necessary based on the user-defined strategy.

# Best Practices
- Use rolling updates for most use cases to minimize downtime.
- Set up resource limits and requests for optimal usage and stability.
- Monitor your application deployment and rollbacks using Kubernetes built-in metrics or external tools.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: quantum-tf-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: quantum
      environment: production
  template:
    metadata:
      labels:
        app: quantum
        environment: production
    spec:
      containers:
      - name: quantum
        image: 1770460584.dkr.ecr.region.amazonaws.com/quantum:latest
        ports:
        - containerPort: 80
          name: http
          protocol: TCP
        resources:
          limits:
            cpu: "1"
            memory: "512Mi"
          requests:
            cpu: "0.5"
            memory: "256Mi"
        readinessProbe:
          probes:
          - exec:
              command: ["/usr/local/bin/check-readiness.sh"]
          periodSeconds: 15
        livenessProbe:
          probes:
          - exec:
              command: ["/usr/local/bin/check-liveness.sh"]
          periodSeconds: 30
```
This YAML example defines a Kubernetes Deployment named `quantum-tf-deployment` with three replicas. It specifies the container image `1770460584.dkr.ecr.region.amazonaws.com/quantum:latest`, sets resource limits and requests, and includes readiness and liveness probes.
