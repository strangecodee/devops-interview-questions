 # Kubernetes Concept
Deployment is a method of updating and rolling back applications in a Declarative manner in the Kubernetes environment.

# Explanation
A Kubernetes Deployment manages the lifecycle of a set of replicas for a desired number of Pods, creating new ones to replace any that have crashed or been terminated, and scaling the number of replicas up or down based on defined conditions.

# Best Practices
- Use rolling updates for minimal downtime and smooth application upgrades.
- Set up self-healing for quick recovery of application crashes.
- Define readiness and liveness probes to ensure application availability and functionality.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-web-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: forge-web
  template:
    metadata:
      labels:
        app: forge-web
    spec:
      containers:
      - name: forge-web
        image: myregistry/forge-web:v1
        ports:
        - containerPort: 80
        readinessProbe:
          probes:
          - exec:
              command: ["sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 5
            timeoutSeconds: 1
        livenessProbe:
          probes:
          - exec:
              command: ["sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 15
            timeoutSeconds: 1
```
In this example, we create a Deployment named `forge-web-deployment` with three replicas for the application `forge-web`. The containers use the image `myregistry/forge-web:v1` and listen on port 80. We also set up readiness and liveness probes for monitoring application health and ensuring it is ready for traffic.
