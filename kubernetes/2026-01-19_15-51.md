 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas are running and ready to serve, automatically scaling up or down based on demand.

# Explanation
A Deployment is a declarative way to create and manage applications in a cluster. It provides rolling updates and automatic rollbacks, ensuring high availability and reliability. When a new version is deployed, Kubernetes updates the replicas sequentially, maintaining a stable state through the entire process.

# Best Practices
- Use rolling updates and blue-green deployments for minimal downtime.
- Define resource limits and requests to optimize resource usage and avoid contention.
- Use readiness and liveness probes to monitor application health and ensure they're serving traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-app-image:latest
        ports:
        - containerPort: 80
      imagePullSecrets:
      - name: my-registry-secret
      readinessProbes:
      - probe:
          exec:
            command: ["/usr/local/bin/readiness"]
        initialDelaySeconds: 5
        periodSeconds: 5
      livenessProbes:
      - probe:
          exec:
            command: ["/usr/local/bin/liveness"]
        initialDelaySeconds: 15
        periodSeconds: 10
```
This YAML example defines a Deployment with 3 replicas, a container named "my-app-container," and readiness and liveness probes. The deployment uses a secret for image registry authentication and updates the replicas with rolling updates to minimize downtime.
