# Kubernetes Concept: Deployment
A Kubernetes Deployment manages the rollout and scaling of Pods in a ReplicaSet.

# Explanation
A Deployment creates and updates ReplicaSets to manage the desired number of replicas, applying desired updates to new Pods in a controlled manner and rolling back changes if necessary. It maintains a specified number of replicas by creating a ReplicaSet and rolling out updates to it in batches.

# Best Practices
- Use rolled updates with `strategy.type: RollingUpdate` to ensure zero downtime when updating your application.
- Use `minReadySeconds` to ensure that a new pod is ready before it starts receiving traffic.
- Use `dryRun: - edit` with the kubectl command to review changes before applying them to the cluster.

# YAML Example - MongoDB Deployment
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mongodb
spec:
  replicas: 3
  selector:
    matchLabels:
      app: mongodb
  template:
    metadata:
      labels:
        app: mongodb
    spec:
      containers:
        - name: mongodb
          image: mongo:latest
          env:
            - name: MONGO_INITDB_ROOT_USERNAME
              value: root
            - name: MONGO_INITDB_ROOT_PASSWORD
              value: password
          ports:
            - containerPort: 27017
          imagePullPolicy: Always
          readinessProbe:
            tcpSocket:
              port: 27017
              probeTimeoutSeconds: 5
              failureThreshold: 3
          livenessProbe:
            tcpSocket:
              port: 27017
              probeTimeoutSeconds: 5
              failureThreshold: 3
```
This Deployment creates a MongoDB database instance with three replicas and manages the rollout and scaling of the replicas. The readiness and liveness probes are configured to monitor the connection status on port 27017.
