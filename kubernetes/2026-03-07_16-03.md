 # Kubernetes Concept
This is an example of a Kubernetes `Horizontally Scalable Deployment` using a `LoadBalancer Service` for external access.

# Explanation
A `Deployment` in Kubernetes manages the lifecycle of a set of replicas, ensuring that a specified number of instances of a containerized application are running at any given time. The `LoadBalancer Service` provides a stable IP to access the deployed application from outside the cluster.

# Best Practices
- Use `replica` counts in multiples of three for high availability.
- Apply security contexts to limit container capabilities.
- Set up resource limits and requests for efficient resource utilization.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: pulse-deployment
spec:
  selector:
    matchLabels:
      app: pulse
  replicas: 3
  template:
    metadata:
      labels:
        app: pulse
    spec:
      containers:
      - name: pulse
        image: pulse:latest
        ports:
        - containerPort: 80
      securityContext:
        runAsUser: 1001
      resources:
        requests:
          cpu: 10m
          memory: 50Mi
        limits:
          cpu: 20m
          memory: 100Mi
---
apiVersion: v1
kind: Service
metadata:
  name: pulse-service
spec:
  selector:
    app: pulse
  ports:
  - port: 80
    targetPort: 80
  type: LoadBalancer
```
