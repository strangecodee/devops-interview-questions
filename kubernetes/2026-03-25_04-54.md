# Kubernetes Concept
Kubernetes Deployment is a declarative way to create and update application containers. It ensures the desired state of a set of containers, rolling out updates and scaling as necessary.

# Explanation
A Kubernetes Deployment manages the lifecycle of a set of Pods, creating new ones when needed and removing old ones when they are no longer required. It also provides a way to update the containers in the Pods, rolling out new versions in a controlled manner.

# Best Practices
- Use rolling updates to minimize downtime when deploying new versions.
- Use health checks to ensure that new containers are ready before routing traffic to them.
- Use labels for selectors to make it easier to manage and scale your applications.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: my-app
          image: my-registry/my-app:v1
          ports:
            - containerPort: 80
          readinessProbe:
            probeType: HTTP
            path: /healthz
            port: 80
            initialDelaySeconds: 5
            periodSeconds: 10
      imagePullSecrets:
        - name: my-registry-secret
```
This YAML file defines a Kubernetes Deployment for an application named "my-app". It creates three replicas and sets up a readiness probe to check the health of the containers. The image is pulled from a registry using the "my-registry-secret" image pull secret.
