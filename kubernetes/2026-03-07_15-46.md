 # Kubernetes Concept
Kubernetes DaemonSet is a type of Kubernetes deployment that ensures a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
A DaemonSet guarantees that a specific number of replicas of a pod are spread across all nodes in the cluster. This is particularly useful for running system daemons, such as monitoring or logging agents, which are required on all nodes. In case of a node failure, newly added nodes will automatically receive the latest version of the DaemonSet. This ensures consistency across the entire cluster.

# Best Practices
- Use labels to select the nodes where your DaemonSet should be deployed.
- Monitor the health of DaemonSets using Kubernetes built-in liveness and readiness probes.
- Use rolling updates to minimize downtime and ensure smooth upgrades.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-logging-agent-ds
  labels:
    app: my-logging-agent
spec:
  selector:
    matchLabels:
      app: my-logging-agent
  template:
    metadata:
      labels:
        app: my-logging-agent
    spec:
      containers:
      - name: my-logging-agent
        image: my-logging-agent:latest
        ports:
        - containerPort: 514
        livenessProbe:
          exec:
            command: ["/usr/local/bin/check-agent.sh"]
          intervalSeconds: 60
        readinessProbe:
          exec:
            command: ["/usr/local/bin/check-agent-ready.sh"]
          intervalSeconds: 30
```
In this example, we create a DaemonSet named `my-logging-agent-ds` with a container `my-logging-agent` based on the image `my-logging-agent:latest`. The DaemonSet is configured to run on nodes labeled with `app: my-logging-agent`. Liveness and readiness probes are defined to ensure the container is healthy and ready, respectively. The containers expose port 514, which is commonly used for logging protocols like syslog.
