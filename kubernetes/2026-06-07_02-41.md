 # Kubernetes Concept
Kubernetes DaemonSet is a type of Kubernetes deployment that ensures a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
DaemonSets are useful for deploying processes that need to run as a single instance on each node in the cluster, such as monitoring agents or logging daemons. In case of a node failure, DaemonSets automatically place the pod on a new node.

# Best Practices
- Ensure that the DaemonSet pod has a small resource footprint and does not interfere with other workloads.
- Use labels to target specific nodes and ensure proper node selectors in your YAML file.
- Perform thorough testing and monitoring to ensure proper functioning of DaemonSet pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
  labels:
    app: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemonset
  template:
    metadata:
      labels:
        app: my-daemonset
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
          protocol: TCP
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 5
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 15
```
This DaemonSet defines a `my-daemonset` with a single container running on each node, using the image `my-image:latest`. The readiness and liveness probes are set up to check the availability of the container's endpoint on `localhost:80` to ensure proper functioning.
