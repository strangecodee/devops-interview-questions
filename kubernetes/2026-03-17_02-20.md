 # Kubernetes Concept
Kubernetes DaemonSet is a way to ensure that a specified number of replicas of a Pod are running on all nodes in a cluster.

# Explanation
DaemonSets maintain a consistent pod population across your nodes by managing and replacing containers that die or are terminated. This is particularly useful for running system daemons, such as monitoring agents or logging collectors, which need to be present on every node.

# Best Practices
- Use labels to target specific nodes or node selectors for your DaemonSet.
- Implement readiness and liveness probes for your containers to ensure they are running correctly.
- Use rolling updates to minimize downtime during DaemonSet updates.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-monitoring-daemon
  labels:
    app: my-monitoring
spec:
  selector:
    matchLabels:
      app: my-monitoring
  template:
    metadata:
      labels:
        app: my-monitoring
    spec:
      containers:
      - name: my-monitoring-container
        image: my-monitoring-image:latest
        ports:
        - containerPort: 2112
          name: monitoring-port
        livenessProbe:
          exec:
            command: ["/usr/local/bin/monitoring-check.sh"]
          periodSeconds: 15
        readinessProbe:
          exec:
            command: ["/usr/local/bin/monitoring-check.sh"]
            periodSeconds: 5
```
In this example, a DaemonSet named "my-monitoring-daemon" is created using the apps/v1 API version. The DaemonSet ensures that one instance of "my-monitoring-container" is running on all nodes with the label "app: my-monitoring". The container runs an image "my-monitoring-image:latest" and listens on port 2112. Liveness and readiness probes are defined to check the health of the container.
