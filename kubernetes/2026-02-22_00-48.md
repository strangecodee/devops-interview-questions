 # Kubernetes Concept
This example demonstrates a Kubernetes `Deployment` for a secure Phoenix application using a container image with known vulnerabilities scanned and mitigated by a `SecurityContext`.

# Explanation
A `Deployment` in Kubernetes is used to manage the lifecycle of a set of replica Pods, scaling them up or down based on demand. In this example, we create a secure `Deployment` for a Phoenix application by specifying a `SecurityContext` in the container definition that sets appropriate security labels and privileges.

# Best Practices
- Use a scanned and verified container image to minimize the risk of vulnerabilities
- Set the `SecurityContext.runAsUser` to a non-root user to limit container privileges
- Use a `ServiceAccount` with least-privilege permissions for the application

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-app
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: phoenix:secure-v1.0.0
        securityContext:
          runAsUser: 1001
          privileged: false
          seLinuxOptions:
            type: permissive
          readOnlyRootFilesystem: true
          fsGroup: 1001
      ports:
      - containerPort: 4000
        protocol: TCP
      imagePullSecrets:
      - name: my-registry
  serviceName: phoenix
```
This YAML file defines a `Deployment` named `phoenix-app` with a replica set of 3, and uses a container image with the tag `phoenix:secure-v1.0.0` that has been scanned and verified for vulnerabilities. The `SecurityContext` is set to run the container as user `1001`, with a non-privileged container, and with appropriate SELinux and filesystem settings for increased security. The container listens on port `4000` and uses an image pull secret named `my-registry` to access the container registry.
