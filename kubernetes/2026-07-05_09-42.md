 # Kubernetes Concept
Deployment is a kind of Kubernetes resource that creates and manages a set of Pods, providing declarative updates.

# Explanation
A Kubernetes Deployment ensures that a desired number of replicas of a Pod are running at any given time. It provides declarative updates: if you change the container image or configuration, the Deployment will update the Pods without requiring manual intervention. This is particularly useful for applications that need to be updated frequently.

# Best Practices
- Use a rolling update strategy for minimal downtime.
- Set up a Deployment strategy (like RollingUpdate or Recreate) to manage updates gracefully.
- Create a Deployment object for each application.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: pulse-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: pulse
  template:
    metadata:
      labels:
        app: pulse
    spec:
      containers:
      - name: pulse
        image: aws_account_id.dkr.ecr.region.amazonaws.com/pulse:v1
        ports:
        - containerPort: 80
          protocol: TCP
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```
In this example, we create a Deployment named `pulse-deployment` with three replicas. The containers in the template have a label `app: pulse` that matches the selector. The container image is pulled from an Amazon Elastic Container Registry (ECR) using the account ID and region. The liveness and readiness probes are used to check the health and readiness of the containers.
