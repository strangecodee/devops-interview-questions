 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications. It creates and updates containers in a pod, ensuring a desired state by rolling out new versions and rolling back if necessary.

# Explanation
A Deployment creates and manages the lifecycle of a set of replicas of a container, ensuring high availability and scalability of the application. It keeps the desired number of replicas running, rolling out updates and rolling back if necessary.

# Best Practices
- Define resource limits to prevent containers from consuming excessive resources.
- Use rolling updates with a gradual rollout strategy to minimize downtime and ensure smooth upgrades.
- Monitor and configure application readiness and liveness probes to ensure the desired state and restart containers if necessary.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-app:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```
This YAML defines a Kubernetes Deployment with 3 replicas of the "my-app" container, which listens on port 80 and runs the image "my-app:latest". Liveness and readiness probes are configured to check the health of the container and ensure it's ready to serve traffic.
