# Kubernetes Concept
Deployment is a Kubernetes object used for updating and rolling back applications. It maintains a specified number of replicas of a container, ensuring high availability and scalability.

# Explanation
A Kubernetes Deployment creates and manages a desired state for a set of Pods, handling rolling updates and rolling back to previous versions if necessary. It enables zero-downtime deployment strategies, as new replicas are created before the old ones are terminated. This minimizes downtime and provides a more stable deployment experience.

# Best Practices
- Use `rolling-update` strategy for minimal downtime when deploying new versions.
- Use `readinessProbe` and `livenessProbe` for Health checks to ensure containers are running as expected.
- Use `strategy.blueGreen` for deploying new versions in parallel and swapping traffic between them for a seamless rollout.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-registry/my-app:v1.0.0
        ports:
        - containerPort: 80
      readinessProbes:
      - apiVersion: v1
        kind: Probe
        name: readiness
        exec:
          command: ["/usr/local/bin/check-readiness"]
      livenessProbes:
      - apiVersion: v1
        kind: Probe
        name: liveness
        exec:
          command: ["/usr/local/bin/check-liveness"]
strategy:
  rollingUpdate:
    maxSurge: 1
    maxUnavailable: 0
```
In this example, a Deployment named `my-app` is created with 3 replicas and a container named `my-app-container` running version `v1.0.0`. The `rollingUpdate` strategy allows for rolling updates with a maximum surge (new replicas) of 1 and zero unavailable replicas. The readiness and liveness probes are used to check the container's health before and during runtime.
