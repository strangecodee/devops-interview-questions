 # Kubernetes Concept
This example demonstrates a Kubernetes Deployment for a scalable web application using a replica set and a horizontal pod autoscaler (HPA).

# Explanation
The following YAML manifest defines a Kubernetes Deployment named `my-web-app` that creates a replica set, manages the rollout of updates, and sets up an HPA to scale the number of replicas based on CPU utilization.

# Best Practices
- Use a rolling update strategy to minimize downtime during deployment.
- Set up resource limits and requests to ensure efficient use of Kubernetes resources.
- Monitor application metrics to effectively set the HPA targets.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-web-app
  labels:
    app: my-web-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-web-app
  template:
    metadata:
      labels:
        app: my-web-app
    spec:
      containers:
      - name: my-web-container
        image: my-web-image:latest
        ports:
        - containerPort: 80
          name: http
        resources:
          limits:
            cpu: "1"
            memory: 128Mi
          requests:
            cpu: "0.5"
            memory: 64Mi
          livenessProbe:
            httpGet:
              path: /healthz
              port: 80
          readinessProbe:
            httpGet:
              path: /ready
              port: 80
---
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: my-web-app-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: my-web-app
  minReplicas: 3
  maxReplicas: 5
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
```
