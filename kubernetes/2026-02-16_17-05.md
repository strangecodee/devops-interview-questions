 # Kubernetes Concept
Deployment is a Kubernetes object used for updating and rolling out new container images for a desired number of replicas.

# Explanation
Deployments in Kubernetes manage the lifecycle of a set of replicas and ensure that the desired number of replicas is running at any given time. When a new image is tagged, a new deployment can be created to update the running replicas. Kubernetes handles the rolling update and rolling back processes, allowing for zero-downtime deployments.

# Best Practices
- Use rolling updates with a small number of replicas updated at a time to minimize the impact on users.
- Monitor your application's health during the deployment process using the `readinessProbe` and `livenessProbe`.
- Set up automatic rollbacks in case of deployment failure.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-deployment
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
      readinessProbe:
        probe:
          tcpSocket:
            port: 80
        intervalSeconds: 5
      livenessProbe:
        probe:
          httpGet:
            path: /healthz
            port: 80
        intervalSeconds: 15
        failureThreshold: 3
```
This YAML creates a new deployment called `my-app-deployment` with three replicas of the container `my-app-container`. The `readinessProbe` and `livenessProbe` are set up to monitor the container's health during the deployment process.
