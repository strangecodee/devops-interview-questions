 # Kubernetes Concept
Deployment is a Kubernetes object used for updating and rolling back applications. It manages the availability of new releases and ensures zero-downtime deployments.

# Explanation
A Deployment creates and manages ReplicaSets, which maintain a specified number of replicas of a Pod. When a new release is deployed, Kubernetes gradually rolls out the update by creating new replicas and routing traffic to them. If an issue arises, traffic can be rolled back to the previous release, ensuring availability and minimal disruption.

# Best Practices
- Use Rolling Updates for minimal disruption.
- Apply the Progressive Delivery strategy, where new releases are gradually rolled-out to different segments of users or nodes.
- Monitor the status of the deployment using the `kubectl get deployments` command.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula/image:latest
        ports:
        - containerPort: 80
        readinessProbe:
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 5
          failureThreshold: 3
```
This Deployment creates a new `nebula-app` with three replicas running the container `nebula`. It uses a readiness probe to ensure the container is ready before traffic is sent to the Pod. Rolling updates can be performed using the `kubectl set image` command or by updating the container image in the YAML file and applying it with `kubectl apply`.
