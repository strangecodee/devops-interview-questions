 # Kubernetes Concept
This is an example of a Kubernetes DaemonSet, which ensures that a copy of the specified Pod is running on all nodes in the cluster.

# Explanation
A DaemonSet maintains a specified number of replicas of a Pod on each node in a cluster. It’s especially useful for deploying system daemons or components that require direct access to the node's hardware, such as monitoring agents or log collectors.

# Best Practices
- Use labels to select nodes based on specific criteria and deploy the DaemonSet accordingly.
- Set the desired number of replicas to ensure sufficient coverage per node.
- Define readiness and liveness probes to ensure the DaemonSet remains functional and can be automatically restarted if necessary.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-log-agent
spec:
  selector:
    matchLabels:
      app: my-log-agent
      tier: node
  template:
    metadata:
      labels:
        app: my-log-agent
    spec:
      containers:
      - name: my-log-agent
        image: my-log-agent:latest
        ports:
        - containerPort: 514
      readinessProbes:
      - exec:
          command: ["/usr/bin/check-ready"]
      livenessProbes:
      - exec:
          command: ["/usr/bin/check-liveness"]
```
In this example, a DaemonSet named "my-log-agent" is defined to deploy a single instance of the "my-log-agent" container on each node in the cluster. The container runs on port 514 and includes readiness and liveness probes to ensure its availability and functionality.
