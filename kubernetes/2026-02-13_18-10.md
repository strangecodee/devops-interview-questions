 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications by creating and updating the desired state of a set of replicas.

# Explanation
Deployments manage the lifecycle of containerized applications in a Kubernetes cluster by creating and updating the desired number of replicas and ensuring availability and rollbacks. They provide declarative updates, rolling updates, and rollbacks.

# Best Practices
- Use labels and selectors for efficient management of deployments.
- Consider using rolling updates for minimal downtime.
- Monitor the health of your applications using liveness and readiness probes.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
  labels:
    app: phoenix
    environment: production
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
      environment: production
  template:
    metadata:
      labels:
        app: phoenix
        environment: production
    spec:
      containers:
      - name: phoenix
        image: aws_account_id.dkr.ecr.region.amazonaws.com/phoenix:latest
        ports:
        - containerPort: 8080
          name: http
          protocol: TCP
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 5
          timeoutSeconds: 2
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 5
          timeoutSeconds: 2
```
Replace `aws_account_id` with your actual AWS account ID. This example creates a Deployment named `phoenix-deployment` with 3 replicas and manages a container image running the `phoenix` application. The liveness and readiness probes are used to monitor the application's health.
