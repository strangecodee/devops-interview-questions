 # Kubernetes Concept
This example demonstrates a Kubernetes Horizontal Pod Autoscaler (HPA) for a Node.js application to ensure optimal resource utilization and maintain a target CPU utilization.

# Explanation
The Kubernetes Horizontal Pod Autoscaler (HPA) automatically scales the number of replicas of a Pod, based on observed CPU utilization. In this example, the HPA ensures the desired state of the Node.js application by adjusting the number of replicas and maintaining a target CPU utilization level.

# Best Practices
- Set a reasonable initial number of replicas and target CPU utilization percentage for the HPA.
- Monitor and adjust the target CPU utilization percentage based on application requirements and infrastructure capacity.
- Configure the HPA to scale based on a metric other than CPU if the application's resource demands are not CPU-bound.

# YAML Example
```yaml
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: nodejs-app-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nodejs-app
  minReplicas: 3
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: UtilizationPercent
        averageUtilization: 50
        averageUtilizationSource:
          metric:
            type: Resource
            resource:
              name: cpu
              container: nodejs-container
```
In this example, we create a HorizontalPodAutoscaler (HPA) for a Node.js application named "nodejs-app". The HPA maintains a target CPU utilization of 50% and scales the number of replicas of the "nodejs-app" deployment between 3 and 10 based on observed CPU utilization.
