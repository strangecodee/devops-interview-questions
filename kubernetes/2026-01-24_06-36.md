 # Kubernetes Concept: Deployment
A Kubernetes Deployment manages the rollout and rollback of containerized applications. It ensures that a specified number of replicas of a container image are running at any given time.

# Explanation
Deployments maintain availability and progressively roll out new versions of containerized applications while ensuring that a certain number of replicas are available to keep the application running. This process is known as rolling update. In case of a failed update, Kubernetes can rollback to the previous version.

# Best Practices
- Use rollouts with multiple replicas to minimize downtime.
- Configure automatic rollbacks to the previous version in case of failures.
- Use the `readinessProbe` and `livenessProbe` to monitor the application's readiness and restart containers if needed.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-app-image:latest
        ports:
        - containerPort: 80
      readinessProbes:
      - apiVersion: v1
        kind: Probe
        name: readiness-probe
        tcpSocket:
          port: 80
        initialDelaySeconds: 5
        periodSeconds: 5
      livenessProbes:
      - apiVersion: v1
        kind: Probe
        name: liveness-probe
        httpGet:
          path: /healthz
          port: 80
        initialDelaySeconds: 15
        periodSeconds: 10
```
This YAML example demonstrates a Kubernetes Deployment named `my-app` with 3 replicas, a container image, readiness and liveness probes. The rolling update process ensures high availability while monitoring the application's readiness and restarting containers if necessary.
