 # Kubernetes DaemonSet
A DaemonSet ensures that a specified number of replicas for a pod are running on each node in the cluster.

# Explanation
DaemonSets are used to deploy and manage a daemon process on each node in a cluster. This is particularly useful for services like logging agents or network proxies, which require a single instance per node. DaemonSets ensure that these instances are running and available on every node, maintaining a consistent and reliable infrastructure.

# Best Practices
- Define resource limits and requests for the DaemonSet to ensure proper resource allocation.
- Use labels to target specific nodes when deploying DaemonSets.
- Use rolling updates to minimize downtime and ensure smooth transitions between versions.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
  labels:
    app: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemonset
  template:
    metadata:
      labels:
        app: my-daemonset
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
          name: http
        resources:
          limits:
            cpu: "1"
            memory: "512Mi"
          requests:
            cpu: "500m"
            memory: "256Mi"
          volumeMounts:
          - mountPath: /var/run/docker.sock
            name: dockersock
      volumes:
      - name: dockersock
        hostPath:
          path: /var/run/docker.sock
```
This YAML file defines a DaemonSet named "my-daemonset" with a single container named "my-container" that runs the image "my-image:latest" on every node in the cluster. The container listens on port 80 for HTTP requests, and it has CPU and memory limits and requests defined. Additionally, it mounts the Docker socket for container communication.
