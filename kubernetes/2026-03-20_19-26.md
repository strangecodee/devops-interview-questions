 # Kubernetes Deployment
Creates and manages containerized applications in a Kubernetes environment.

# Explanation
A Deployment in Kubernetes ensures that a specified number of replicas of a containerized application are running at any given time. It automates the process of updating and rolling back applications.

# Best Practices
- Use rolling updates and blue-green deployments for minimal downtime and zero-downtime updates.
- Define container images using a registry and store the configuration in a version control system for GitOps.
- Set up resource limits and requests to ensure optimal resource utilization and efficient pod scheduling.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: my-app-container
          image: registry.example.com/my-app:v1.0.0
          ports:
            - containerPort: 80
          resources:
            limits:
              cpu: 1
              memory: 128Mi
            requests:
              cpu: 0.5
              memory: 64Mi
          livenessProbe:
            httpGet:
              path: /healthz
              port: 80
          readinessProbe:
            httpGet:
              path: /ready
              port: 80
```
This YAML example demonstrates a Deployment with 3 replicas, a container running on image `registry.example.com/my-app:v1.0.0`, and probes for liveness and readiness checks. Resource limits and requests are defined for efficient scheduling and utilization.
