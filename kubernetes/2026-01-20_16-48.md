 # Kubernetes Concept
This example demonstrates a Kubernetes `HorizontalPodAutoscaler` (HPA) for a Deployment named `atlas-monitoring`. The HPA automatically scales the number of pods based on observed CPU utilization.

# Explanation
The Horizontal Pod Autoscaler (HPA) is a Kubernetes component that maintains the desired number of replicas for a Deployment, StatefulSet, or ReplicaSet by monitoring the metrics and adjusting the size of the fleet accordingly. In this case, we'll configure an HPA for the `atlas-monitoring` Deployment, which will scale based on observed CPU utilization.

# Best Practices
- Use the `--min` and `--max` options in the HPA to set the desired minimum and maximum number of replicas.
- Set up proper limits and requests for the container to ensure resource usage is efficient and predictable.
- Monitor CPU usage and other metrics in the Prometheus/Grafana stack for effective capacity planning and proactive scaling.

# YAML Example
```yaml
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: atlas-monitoring-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: atlas-monitoring
  minReplicas: 1
  maxReplicas: 5
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
```
This YAML example defines an HPA named `atlas-monitoring-hpa` that will adjust the number of replicas for the `atlas-monitoring` Deployment based on the average CPU utilization. The `minReplicas` is set to 1, and the `maxReplicas` is set to 5. When the average CPU utilization reaches 50%, the HPA will start scaling up the number of replicas.
