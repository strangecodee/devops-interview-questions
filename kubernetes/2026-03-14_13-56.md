 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures a specified number of replicas are running and available, and can perform rolling updates or rollbacks.

# Explanation
A Deployment creates and manages the desired state of a group of replicas, updating them as new container images are tagged or as new configurations are released. Kubernetes rolls out updates in batches, ensuring high availability and minimizing downtime.

# Best Practices
- Use rolling updates to minimize downtime and maintain availability.
- Define readiness and liveness probes to determine when containers are ready to serve traffic and when they should be replaced.
- Implement rolling updates with a gradual rollout to test updates in development before they are rolled out to production.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-registry/my-image:latest
        ports:
        - containerPort: 80
          protocol: TCP
        readinessProbe:
          tcpSocket:
            port: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
---
apiVersion: v1
kind: Service
metadata:
  name: my-app
spec:
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```
This YAML file defines a Deployment with three replicas for an application named `my-app`. It specifies a container image and sets up readiness and liveness probes. The Service resource is used to expose the Deployment on a cluster-internal IP.
