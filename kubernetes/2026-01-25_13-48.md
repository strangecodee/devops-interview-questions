 # Kubernetes Concept
Deployment is a Kubernetes resource for managing and deploying containerized applications. It ensures that a specified number of replicas of a container image are running at any given time.

# Explanation
A Kubernetes Deployment creates and manages replicas of a container image, ensuring that the desired state of the application is maintained. It also provides a rollout feature for updating containers in a controlled manner, allowing for zero-downtime deployments. The Deployment controller continuously rolls out updates to the replicas and rolls back the update when necessary to maintain the desired state.

# Best Practices
- Use rolling updates for minimal downtime and graceful shutdown of old replicas.
- Define readiness and liveness probes to ensure that the containers are healthy and ready to serve traffic.
- Use labels to identify and manage deployments easily.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probes:
          - exec:
              command: ["/bin/sh", "-c", "curl --fail http://localhost:80 || exit 1"]
            initialDelaySeconds: 15
            periodSeconds: 5
        livenessProbe:
          probes:
          - exec:
              command: ["/bin/sh", "-c", "curl --fail http://localhost:80 || exit 1"]
            initialDelaySeconds: 15
            periodSeconds: 10
```
