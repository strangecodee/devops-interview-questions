 # Kubernetes Concept
Deployment is a type of Kubernetes object used for creating, updating, and managing containers. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
A Kubernetes Deployment creates and manages the lifecycle of a set of replicas of a container. When you create or update a Deployment, the system ensures that a specified number of replicas are available at any given time. If a replica goes down due to a failure, the system automatically creates a new one to maintain the desired state.

# Best Practices
- Use `rolling updates` for minimal downtime and gradual rollout of new container versions.
- Set up `horizontal pod autoscaling` to automatically scale the number of replicas based on resource usage or other metrics.
- Use `readinessProbes` and `livenessProbes` to monitor the health of your containers and ensure they are ready to serve traffic.

# YAML Example

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: example-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: example
  template:
    metadata:
      labels:
        app: example
    spec:
      containers:
      - name: example-container
        image: example-image:latest
        ports:
        - containerPort: 80
        readinessProbes:
        - probes:
          - exec:
              command: ["/usr/local/bin/check-readiness"]
            intervalSeconds: 5
            failureThreshold: 3
      livenessProbes:
      - probes:
        - exec:
            command: ["/usr/local/bin/check-liveness"]
          intervalSeconds: 30
          failureThreshold: 3
```
