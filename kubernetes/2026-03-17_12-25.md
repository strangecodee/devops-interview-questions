 # Kubernetes Concept
Kubernetes Ingress is a collection of rules that allow inbound connections to reach the cluster services. It acts as a reverse proxy and enables external access to the services in a cluster, typically via HTTP.

# Explanation
The Ingress resource in Kubernetes is used to manage external access to the services in a cluster. It defines rules that route incoming traffic based on specific conditions, such as the request hostname, path, or protocol. This enables external users to access specific services through a single, external IP address.

# Best Practices
- Use an Ingress Controller, such as Nginx or Traefik, to manage the Ingress rules.
- Implement SSL certificates for secure communication.
- Use Ingress rules to restrict access based on source IP addresses or paths.

# YAML Example
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-ingress
  annotations:
    kubernetes.io/ingress.global: "true"
    nginx.ingress.kubernetes.io/ssl-pass-through: "true"
spec:
  tls:
  - hosts:
    - example.com
    secretName: example-tls
  rules:
  - host: example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: my-service
            port:
              name: http
```
This example defines an Ingress resource named `my-ingress` with SSL pass-through enabled and a single rule for the host `example.com`. The rule routes all traffic to the service named `my-service` listening on port `http`. The SSL certificate for the host is stored in the secret named `example-tls`.
