 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas for a pod are running on all nodes in a cluster.

# Explanation
DaemonSets are useful for deploying background services or system components that require a pod to run on every node in the cluster. This is typically used for services like logging agents, monitoring agents, and network proxies. By ensuring that a copy of the pod runs on every node, you can guarantee consistency across the cluster and maintain a uniform state.

# Best Practices
- Use labels to target specific node selectors.
- Configure health checks using Liveness and Readiness probes.
- Use rolling updates to minimize downtime.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: nebula-logging-agent
  labels:
    app: nebula
spec:
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula-container
        image: nebula/logging-agent:latest
        ports:
        - containerPort: 514
        livenessProbe:
          exec:
            command: ["/usr/bin/nebula-healthcheck.sh"]
          intervalSeconds: 60
        readinessProbe:
          exec:
            command: ["/usr/bin/nebula-readinesscheck.sh"]
            intervalSeconds: 15
```
This DaemonSet creates a logging agent named "nebula-logging-agent" that runs on every node in the cluster. The container uses the image "nebula/logging-agent:latest" and listens on port 514. Liveness and readiness probes are defined to check the health and readiness of the container.
