 # Kubernetes Deployment
Create and manage containerized applications in a cluster.

# Explanation
A Kubernetes Deployment is used to create, update, and manage applications in a Kubernetes cluster by maintaining a specified number of replicas and their availability. It ensures that a desired state is maintained by continuously rolling out updates and rolling back if necessary.

# Best Practices
- Define health checks for your containers using Liveness and Readiness probes.
- Use rolling updates to minimize downtime and ensure high availability.
- Set resource limits and requests in the container spec to maintain efficient use of cluster resources.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse
spec:
  replicas: 3
  selector:
    matchLabels:
      app: eclipse
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
      - name: eclipse
        image: openjdk:latest
        ports:
        - containerPort: 4500
          protocol: TCP
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 5
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 5
      resources:
        limits:
          cpu: "1"
          memory: "512Mi"
        requests:
          cpu: "0.5"
          memory: "256Mi"
```
This YAML example describes a deployment for an Eclipse application, which has three replicas, and uses OpenJDK as the container image. It sets up Liveness and Readiness probes to check the application's health and defines resource limits and requests.
