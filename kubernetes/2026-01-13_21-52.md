 # Kubernetes Concept
This is an example of a Kubernetes DaemonSet for running chaos engineering tests using the Litmus Chaos controller.

# Explanation
A DaemonSet ensures that all nodes in a cluster run a copy of the specified Pod. In this case, we will use it to install the Litmus Chaos controller and run chaos engineering tests on every node in the cluster. Chaos engineering is the discipline of deliberate system disruption to build confidence in system reliability.

# Best Practices
- Use Role-Based Access Control (RBAC) to secure the DaemonSet and its associated resources.
- Keep your Chaos Engineering controller and agents up-to-date with the latest versions.
- Regularly review and analyze chaos engineering test results to identify and address potential issues.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: chaos-daemonset
spec:
  selector:
    matchLabels:
      app: chaos
  template:
    metadata:
      labels:
        app: chaos
    spec:
      containers:
      - name: chaos-agent
        image: litmuschaos/chaos-agent:0.13.0
        securityContext:
          runAsUser: 1000
          capabilities:
            drop: ALL
        ports:
        - containerPort: 8080
      nodeselector:
        beta.kubernetes.io/os: linux
```
This example YAML creates a DaemonSet named `chaos-daemonset` that runs the Litmus Chaos agent container. It uses the `apps/v1` API version and sets the `selector` to target nodes with the `app: chaos` label. The `template` specifies the container image (`litmuschaos/chaos-agent:0.13.0`) and sets the `runAsUser` to `1000` for security purposes. The `drop: ALL` capability is set to prevent any unnecessary permissions for the container. Also, the `nodeselector` is set to target only Linux nodes.
