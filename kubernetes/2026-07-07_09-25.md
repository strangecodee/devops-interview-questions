 # Kubernetes Concept
This example demonstrates a Kubernetes Service and a Deployment for a simple Load Balancer using the Nginx Forge.

# Explanation
Services in Kubernetes provide a stable IP address and DNS name for a set of Pods, while the Deployment ensures the desired state of the application by creating and managing instances of the application. In this scenario, we use an Nginx Load Balancer from the Forge to distribute network traffic to our application instances.

# Best Practices
- Use a Deployment for managing and scaling your application instances.
- Ensure the `selector` in the Service and Deployment YAML files match to correctly associate the Service with the application Pods.
- Use `nodePort` or `loadBalancer` as the type in the Service YAML file to enable external access to the Service.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  selector:
    matchLabels:
      app: nginx
  replicas: 3
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.14.2
        ports:
        - containerPort: 80

---
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  type: LoadBalancer
  selector:
    app: nginx
  ports:
  - port: 80
    targetPort: 80
```
