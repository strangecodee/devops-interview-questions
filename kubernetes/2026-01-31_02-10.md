 # Kubernetes Concept
Deployment: A Kubernetes object used for creating and managing containers in a cluster.

# Explanation
Deployments manage the lifecycle of a set of replicas of a container or a set of containers, providing mechanisms for updates and rollbacks as well as self-healing. They ensure that a specified number of pods are running at any given time.

# Best Practices
- Use rolling updates for safe and controlled deployment.
- Set up resource limits and requests to optimize resource usage.
- Utilize readiness and liveness probes for efficient scaling.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
        - name: nebula
          image: aws_account_id.dkr.ecr.region.amazonaws.com/nebula:v1
          ports:
            - containerPort: 80
          resources:
            limits:
              cpu: "1"
              memory: "512Mi"
            requests:
              cpu: "0.5"
              memory: "256Mi"
          readinessProbe:
            probeType: HTTP
            httpGet:
              path: /healthz
              port: 80
          livenessProbe:
            probeType: HTTP
            httpGet:
              path: /liveness
              port: 80
```
In this YAML example, we create a Deployment named `nebula-deployment` with 3 replicas of the container `nebula`. The container uses an Amazon ECR image, listens on port 80, and sets resource limits and requests for CPU and memory. Readiness and liveness probes are also specified to ensure efficient scaling and self-healing.
