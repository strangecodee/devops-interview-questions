 # Kubernetes Concept
Kubernetes DaemonSet is a type of Kubernetes deployment that ensures a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
DaemonSets are useful for deploying system daemons, such as monitoring agents, logging agents, or network proxies, that need to be running on every node in the cluster. They maintain the desired state of the pods, even if the pods crash or are deleted.

# Best Practices
- Use a well-defined `securityContext` to restrict pod privileges, such as setting `runAsUser`, `runAsGroup`, and ` fsGroup`.
- Use the `nodeSelector` and `tolerations` fields to ensure the pods are scheduled on nodes with the desired labels and to tolerate node taints.
- Use `readinessProbes` and `livenessProbes` to ensure the containers in the pod are functioning correctly.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
  labels:
    app: my-daemon
    version: v1
spec:
  selector:
    matchLabels:
      app: my-daemon
      version: v1
  template:
    metadata:
      labels:
        app: my-daemon
        version: v1
    spec:
      securityContext:
        runAsUser: 1001
        runAsGroup: 1001
        fsGroup: 1001
      nodeSelector:
        beta.kubernetes.io/os: linux
      tolerations:
        - key: "node-role.kubernetes.io/master"
          operator: Exists
          effect: NoSchedule
      containers:
        - name: my-container
          image: my-image:latest
          ports:
            - containerPort: 80
          readinessProbes:
            - exec:
                command: ["/bin/sh", "-c", "curl --fail http://localhost:80/healthz || exit 1"]
          livenessProbes:
            - exec:
                command: ["/bin/sh", "-c", "curl --fail http://localhost:80/liveness || exit 1"]
```
