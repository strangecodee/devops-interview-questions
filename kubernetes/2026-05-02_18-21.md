# Kubernetes Concept
Kubernetes DaemonSet is a way to ensure a copy of a specified Pod runs on each node in the cluster.

# Explanation
DaemonSets maintain a consistent daemon-like process across the nodes in a cluster. They are useful for deploying and managing services that require a separate process per node, such as monitoring agents or edge nodes. DaemonSets ensure the availability of these processes by continuously creating and managing their replicas.

# Best Practices
- Use DaemonSets for applications that require a single instance per node, such as edge nodes or monitoring agents.
- Configure DaemonSets to use labels for node selectors to ensure the Pods are scheduled only on the desired nodes.
- Use rolling updates for DaemonSets to minimize downtime and ensure a smooth upgrade process.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemon
  template:
    metadata:
      labels:
        app: my-daemon
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 5
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 30
---
```
In this example, we define a DaemonSet named `my-daemonset` with a container named `my-container` that runs the image `my-image:latest`. The DaemonSet ensures that one instance of the container runs on each node in the cluster by using the `selector` field to match nodes with the label `app: my-daemon`. The `readinessProbes` and `livenessProbes` are used to check the container's health and availability.
