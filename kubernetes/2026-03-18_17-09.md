 # Kubernetes Concept
Kubernetes DaemonSet is a way to ensure a copy of a pod is running on each node in a cluster.

# Explanation
DaemonSets maintain a copy of a specified pod for each node in a cluster. This is useful for running system daemons or monitoring agents across the entire cluster. DaemonSets ensure availability and consistency of these applications by restarting or replacing containers that fail.

# Best Practices
- Use DaemonSets for applications that must run as a single instance per node.
- Use readiness and liveness probes to ensure the DaemonSet is running correctly.
- Use labels to select specific nodes for DaemonSets, and use node selectors to deploy DaemonSets to nodes based on labels.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: nebula-daemonset
spec:
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 12345
          name: nebula
        readinessProbes:
        - exec:
            command: ["/usr/local/bin/check-health.sh"]
          intervalSeconds: 5
          timeoutSeconds: 3
        livenessProbes:
        - exec:
            command: ["/usr/local/bin/check-liveness.sh"]
          intervalSeconds: 30
          timeoutSeconds: 15
```
This YAML creates a DaemonSet named "nebula-daemonset" with a container named "nebula". The container runs the image "nebula:latest" and listens on port 12345. The DaemonSet uses readiness and liveness probes to check the health of the container.
