 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
DaemonSets maintain a consistent daemon process across a cluster by managing and replacing the pods as needed. They are useful for deploying systems like logging agents, monitoring agents, or custom node components.

# Best Practices
- Label nodes and pods appropriately to ensure proper matching.
- Use the `replicas: 1` property to deploy a single instance of a daemon per node.
- Monitor the health of your DaemonSets using Kubernetes built-in monitoring tools.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-daemon
spec:
  selector:
    matchLabels:
      app: logging-daemon
  template:
    metadata:
      labels:
        app: logging-daemon
    spec:
      containers:
      - name: logging-container
        image: logging-image:latest
        ports:
        - containerPort: 514
          name: logging-port
          protocol: UDP
        readinessProbe:
          exec:
            command: ["/usr/local/bin/check-log-service"]
          intervalSeconds: 5
```
This YAML file defines a DaemonSet named `logging-daemon`, which deploys instances of the `logging-container` using the `logging-image:latest` image. The DaemonSet ensures that one instance of the container runs on each node, and the container's readiness probe is set to check the health of the logging service every 5 seconds.
