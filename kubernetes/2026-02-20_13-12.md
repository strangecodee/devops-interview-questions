 # Kubernetes Concept
Deployment is a Kubernetes object used for updating, scaling, and managing containers. It ensures availability and desired state of a set of replicas.

# Explanation
A Deployment creates and manages a set of replicas using a defined container image, and automatically scales the number of replicas based on statuses (e.g., `Available`, `Unavailable`, `WantedReplicas`). This ensures high availability and desired state of the application. The rolling update process is performant, as Kubernetes updates pods one at a time, maintaining availability.

# Best Practices
- Update the container image in a new Deployment before deleting the old one to minimize downtime.
- Use `readinessProbe` and `livenessProbe` to ensure that containers are ready to receive traffic and are still healthy.
- Set the `replicas` field to a number higher than the desired number of replicas for rollouts to work effectively.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-image:1.0.0
        ports:
        - containerPort: 80
        readinessProbes:
        - exec:
            command: ["/usr/local/bin/check-readiness"]
            intervalSeconds: 5
            failureThreshold: 3
        livenessProbes:
        - exec:
            command: ["/usr/local/bin/check-liveness"]
            intervalSeconds: 15
            failureThreshold: 3
```
