 # Kubernetes Concept
Deployment is a type of Kubernetes resource that creates and manages a desired state for a set of containers. It ensures that a specified number of replicas for an application are running at any given time.

# Explanation
A Kubernetes Deployment creates replicas of a container image based on a specified YAML manifest. The deployment controller continuously monitors the desired state and makes adjustments as needed to maintain the desired number of replicas. If a container crashes or becomes unresponsive, the deployment controller will automatically create a new replica to replace it. This ensures high availability and resilience for the application.

# Best Practices
- Use a rolling update strategy to minimize downtime when deploying new versions of your application.
- Set up a health check to ensure that the container is running properly and ready to receive traffic.
- Use labels to manage and select specific replicas based on their attributes.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
          name: http
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
      imagePullSecrets:
      - name: my-registry-secret
```
In this example, we define a Deployment called `my-app` that creates three replicas of a container with the image `my-registry/my-app:latest`. The container listens on port `80` and is monitored by a liveness probe that checks the `/healthz` endpoint. The Deployment is labeled `app: my-app`, and the container is labeled with the same value. We also use an image pull secret named `my-registry-secret` to securely pull the container image.
