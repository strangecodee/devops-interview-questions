 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications. It ensures availability, scalability, and rolling updates or rollbacks of an application.

# Explanation
A Deployment creates and manages replicas of a specified Docker container image. It continuously runs the latest version of the container, whileold replicas are updated or removed based on the update strategy. A Deployment can also trigger rolling updates and rollbacks, and it automatically restarts containers that fail.

# Best Practices
- Use a Deployment strategy of 'RollingUpdate' for the most common updates, which updates replicas gradually to minimize downtime.
- Set appropriate resource limits in the container spec to ensure resource utilization and container stability.
- Monitor the health of your containers using a Liveness and Readiness probe.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: quantum-sre-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: quantum-sre
  template:
    metadata:
      labels:
        app: quantum-sre
    spec:
      containers:
      - name: quantum-sre-container
        image: myregistry/quantum-sre:latest
        ports:
        - containerPort: 80
        - containerPort: 443
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 15
```
This YAML example creates a Deployment named "quantum-sre-app" with 3 replicas, each running the "quantum-sre" container from a specified registry. The containers listen on ports 80 and 443 and use an HTTP Liveness and Readiness probe.
