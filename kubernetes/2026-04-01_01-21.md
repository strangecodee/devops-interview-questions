# Kubernetes Concept
Kubernetes DaemonSet ensures that a specified number of replicas of a Pod are running on each node in the cluster.

# Explanation
DaemonSets create and manage a Pod on each node in the cluster based on label selectors. This is useful for deploying system daemons, logging agents, or network add-ons, as they need to run on every node. DaemonSets ensure that there's at least one replica running, and if a replica goes down, a new one is automatically created.

# Best Practices
- Use a unique and descriptive name for your DaemonSet.
- Apply the latest security patches to the container images used in your DaemonSet.
- Use Resource Requests and Limits to ensure pods get the resources they need without impacting other pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: phoenix-logging-agent
  labels:
    app: logging-agent
spec:
  selector:
    matchLabels:
      app: logging-agent
  template:
    metadata:
      labels:
        app: logging-agent
    spec:
      containers:
      - name: logging-agent
        image: logging-agent:latest
        ports:
        - containerPort: 514
          name: udp
      imagePullSecrets:
      - name: registry-secret
      securityContext:
        privileged: false
        seLinuxOptions:
          type: SELinux
          role: runasuser
        runAsUser: 1001
        capabilities: ["NET_ADMIN"]
  nodeSelector:
    beta.kubernetes.io/os: linux
  updateStrategy:
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
```
This YAML creates a DaemonSet named "phoenix-logging-agent" that runs a logging agent container on every node in the cluster. It uses an image with the tag "latest", sets container port 514 for UDP traffic, and applies the specified security context to secure the container. The DaemonSet uses an update strategy that ensures zero downtime during updates.
