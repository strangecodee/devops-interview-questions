 # Kubernetes Concept
Deployment is a Kubernetes resource for updating and rolling back containers. It creates and manages the desired state for a set of Pods, providing declarative updates and rollbacks.

# Explanation
A Kubernetes Deployment creates and manages replicas of a specified container image and ensures a desired number of instances are running at any given time. When a new version is deployed, it is rolled out gradually to minimize downtime. Old replicas are progressively terminated as new ones come online.

# Best Practices
- Use `rollout` strategies like `RollingUpdate` or `Recreate` to minimize downtime.
- Set up an appropriate `replica count` for your application to ensure availability and scalability.
- Use `readiness` and `liveness` probes to determine when a container is ready to receive traffic and when it should be restarted.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```
