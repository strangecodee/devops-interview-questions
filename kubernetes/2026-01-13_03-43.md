 # Kubernetes Concept
Kubernetes Secret is a container object used to store and manage sensitive information such as passwords, OAuth tokens, and SSH keys.

# Explanation
Secrets in Kubernetes are encrypted at rest and decrypted on the container runtime to be accessible as environment variables or as files in a volume. This ensures that sensitive data is not exposed in plaintext in the container image or in the Kubernetes manifests.

# Best Practices
- Create a separate namespace for storing secrets.
- Use Kubernetes Secret for storing sensitive information instead of hardcoding it in container images or manifest files.
- Use the Kubernetes Secret Rotator to automatically rotate and manage secrets.

# YAML Example
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: my-app-credentials
  namespace: my-namespace
type: Opaque
stringData:
  username: bWlzdHJlc3M=
  password: cGFzc3dvcmQ=
binaryData:
  ssh-key: iVBORw0KGgoAAAANSUhEUgAAAT4AAACeCAMAAAD1SvhkAAAAMFBMVEX///...
```
In this example, we have created a Kubernetes Secret named `my-app-credentials` with a `username` and `password` as base64 encoded strings and an SSH key as binary data. The `type: Opaque` indicates that the data is not encoded in any special way and is to be treated as raw data. The Secret is stored in the `my-namespace` namespace.
