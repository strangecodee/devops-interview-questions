 # Kubernetes Service
A Kubernetes Service is an API object that provides a stable IP address and DNS name for accessing a set of pods.

# Explanation
Services in Kubernetes abstract the underlying infrastructure and provide a single entry point to a set of pods. They utilize a ClusterIP to provide stable networking for the pods and support for multiple selectors to manage multiple versions of an application.

# Best Practices
- Use a Service for each unique application, or set of microservices, to create a single entry point and provide stable networking.
- Use the correct service type based on your requirements, like ClusterIP, NodePort, LoadBalancer or ExternalName.
- Set up the appropriate selectors and labels for your pods when creating a Service, to ensure the correct pods are targeted.

# YAML Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: quantum-sre-app
spec:
  selector:
    app: quantum
  type: ClusterIP
  ports:
  - name: http
    port: 80
    targetPort: 8080
```
This example creates a Kubernetes Service with the name `quantum-sre-app` using the ClusterIP type. The Service selects pods with the label `app: quantum` and listens on port 80, forwarding traffic to the target port 8080 within the pods.
