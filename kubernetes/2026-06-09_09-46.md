 # Kubernetes Concept
This is an example of a Kubernetes DaemonSet, which ensures that a copy of a specified Pod runs on all nodes in a cluster.

# Explanation
DaemonSets are useful for running processes that require access to the node's resources, such as monitoring agents or logging daemons. They are designed to maintain a consistent state across a cluster by replacing unavailable Pods with new ones.

# Best Practices
- Use labels to select the nodes where the DaemonSet should run.
- Define readiness and liveness probes to check the health of the Pods.
- Use rolling updates for minimal downtime during updates.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
  labels:
    app: my-daemon
spec:
  selector:
    matchLabels:
      app: my-daemon
  template:
    metadata:
      labels:
        app: my-daemon
    spec:
      containers:
      - name: my-daemon-container
        image: my-registry/my-image:latest
        ports:
        - containerPort: 80
        - containerPort: 443
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 5
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 30
```
This DaemonSet uses labels to select all nodes and runs a container named "my-daemon-container" on each node with ports 80 and 443. The readiness and liveness probes are defined using the `exec` method to check the reachability of the container's endpoint on localhost.
