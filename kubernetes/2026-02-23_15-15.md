 # Kubernetes Concept
A Kubernetes Deployment is a desired state for a set of containers, including replicas, updates, and rollbacks.

# Explanation
A Deployment in Kubernetes manages the lifecycle of a set of replica Pods, ensuring high availability and scalability by creating new replicas if old ones fail, and rolling out updates with minimal downtime. It also provides the ability to roll back to previous versions if needed.

# Best Practices
- Use rolling updates for minimal downtime during deployments.
- Use `readinessProbes` and `livenessProbes` to ensure your containers are healthy and ready to serve.
- Use `replicas` to set the desired number of container instances for your application.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse-deployment
spec:
  selector:
    matchLabels:
      app: eclipse
  replicas: 3
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
      - name: eclipse
        image: eclipse:latest
        ports:
        - containerPort: 8443
        readinessProbes:
        - exec:
            command: ["/usr/bin/curl", "--fail", "--silent", "http://localhost:8443"]
            intervalSeconds: 5
        livenessProbes:
        - exec:
            command: ["/usr/bin/curl", "--fail", "--silent", "http://localhost:8443"]
            intervalSeconds: 30
```
In this example, we define a Deployment named `eclipse-deployment` with 3 replicas, each containing a container named `eclipse` based on the latest `eclipse` image. The readiness and liveness probes are set to check the availability of the eclipse web server at `http://localhost:8443`.
