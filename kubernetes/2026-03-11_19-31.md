 # Kubernetes Concept
This example demonstrates a Kubernetes Service and a corresponding Deployment for creating a simple load balancer using the `Clustered IP` load balancing mode.

# Explanation
A Kubernetes Service provides stable DNS names and IP addresses, which allow for intra-cluster communication between pods. In this case, the Service acts as a reverse proxy and distributes traffic to the available replicas of the application. The `Clustered IP` load balancing mode utilizes the Kubernetes API to route traffic to the pods.

# Best Practices
- Ensure proper `labels` are set on your pods for Selectors, and keep them consistent with your Service definition.
- Configure `livenessProbes` and `readinessProbes` for your application to ensure optimal performance and reliability.
- Use `replicas` and `replicaSets` to maintain a desired number of running instances for your application.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-deployment
  labels:
    app: nebula
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbes:
        - httpGet:
            path: /
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 5
---
apiVersion: v1
kind: Service
metadata:
  name: nebula
spec:
  selector:
    app: nebula
  type: ClusterIP
  ports:
  - name: http
    port: 80
    targetPort: 80
  clusterIP: None # Kubernetes will automatically assign a private IP address
```
