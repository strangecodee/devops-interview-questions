# Kubernetes Concept
Deployment is a Kubernetes object used for creating and updating replicas of a desired state for a set of pods.

# Explanation
A Deployment creates and manages a set of replicas of a desired Pod definition. If a new version of the Pod definition is created, the Deployment controller can update the replicas to the new version in a controlled way. This ensures that the desired state of the application is maintained.

# Best Practices
- Use rollouts to update Pods gradually to minimize the risk of downtime.
- Use rolling updates to update Pods in batches to ensure availability and prevent the risk of downtime.
- Use readiness and liveness probes to ensure that the Pods are healthy and ready to serve traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.14.2
        ports:
        - containerPort: 80
        readinessProbes:
        - probeName: ReadinessProbe
          exec:
            command: ["nc", "-z", "0.0.0.0", "80"]
            initialDelaySeconds: 5
            periodSeconds: 5
        livenessProbes:
        - probeName: LivenessProbe
          exec:
            command: ["nc", "-z", "0.0.0.0", "80"]
            initialDelaySeconds: 15
            periodSeconds: 10
```
This YAML file defines a Kubernetes Deployment named `nginx-deployment` with three replicas. It uses a container image of `nginx:1.14.2` with a readiness and liveness probe to ensure the health of the Pods. The rolling update strategy is not explicitly defined in this example, but it is a recommended best practice to use it for controlled updates.
