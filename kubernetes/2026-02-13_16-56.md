 # Kubernetes Concept
Kubernetes Secret is an object used to store and manage sensitive information, such as passwords, OAuth tokens, and SSL certificates.

# Explanation
Secrets in Kubernetes are encrypted at rest and decrypted on-the-fly when they are used by container pods. By using Secrets, you can avoid hard-coding sensitive information directly in your container images, configuration files, or as environment variables. This approach enhances application security and reduces the risk of exposing sensitive data.

# Best Practices
- Create and manage Secrets using Kubernetes Secrets Manager or an external Secret Manager like Hashicorp Vault or AWS Secrets Manager.
- Store sensitive information in encrypted form within the Secret.
- Set appropriate access control policies for Secrets to ensure that only authorized users and components have access.

# YAML Example
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: nebula-db-password
  namespace: default
type: Opaque
data:
  password: cGFzc3dvcmQ=
  username: c29tZSBzdGF0ZW1lbnQ=
```
In this example, we create a Secret named "nebula-db-password" in the "default" namespace. The Secret contains two encrypted key-value pairs, "password" and "username". The data for these values is encoded in base64. After creating the Secret, you can use Kubernetes Kubectl command or other tools to reference the Secret in container configuration files or as environment variables.
