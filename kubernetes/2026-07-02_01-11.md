 # Kubernetes Concept
This is an example of a Kubernetes `HorizontalPodAutoscaler` (HPA) for monitoring and scaling a Deployment based on CPU utilization.

# Explanation
The Horizontal Pod Autoscaler (HPA) is a Kubernetes component that automatically scales the number of replicas of a Deployment, StatefulSet, or ReplicaSet based on observed CPU utilization. In this example, we will create an HPA that maintains the desired number of replicas for the "atlas" Deployment by monitoring the CPU utilization of its pods.

# Best Practices
- Ensure that your Deployment is properly labeled (metadata.labels) for effective resource management and selectivity.
- Use CPU or memory metrics for scaling based on your application needs and available resources.
- Set minimum and maximum replica limits to prevent excessive scaling and ensure application availability.

# YAML Example
```yaml
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: atlas-hpa
  labels:
    app: atlas
spec:
  scaleTargetRef:
    kind: Deployment
    name: atlas
    apiVersion: apps/v1
  minReplicas: 3
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
        averageUtilizationSmoothingPeriodSeconds: 60
```
In this YAML example, we create an HPA named "atlas-hpa" that scales the number of replicas for the "atlas" Deployment based on CPU utilization. The minimum and maximum number of replicas are set to 3 and 10, respectively. The HPA will maintain the desired number of replicas by monitoring the average CPU utilization of the pods and adjusting the number of replicas when the average utilization exceeds or falls below 50%.
