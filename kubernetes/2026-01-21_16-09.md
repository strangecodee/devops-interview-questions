 # Kubernetes Concept
This example demonstrates a Kubernetes Service and Deployment for load balancing and scaling a Phoenix application.

# Explanation
A Kubernetes Service provides a stable IP and DNS name for a set of Pods, while a Deployment manages the rollout and scaling of containers within the Pods. Here, we deploy a Phoenix application using a Deployment and expose it via a Service for load balancing.

# Best Practices
- Use labels to identify and manage your Deployments and Services.
- Use ConfigMaps or Secrets for managing and storing sensitive application data.
- Monitor your application performance and use Horizontal Pod Autoscaling to ensure optimal resource usage.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
  labels:
    app: phoenix
spec:
  selector:
    matchLabels:
      app: phoenix
  replicas: 3
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: phoenix:latest
        ports:
        - containerPort: 4000
---
apiVersion: v1
kind: Service
metadata:
  name: phoenix-service
spec:
  type: LoadBalancer
  selector:
    app: phoenix
  ports:
  - port: 80
    targetPort: 4000
```
