 # Kubernetes Concept
This example demonstrates a Kubernetes Deployment for an ArgoCD application using a GitRepository source. ArgoCD is a popular continuous delivery tool for Kubernetes that syncs application definitions between Git repositories and Kubernetes clusters.

# Explanation
In this YAML example, we create a Kubernetes Deployment named "eclipse-app" that pulls the container image from a Git repository, managed by ArgoCD. The Deployment uses a single replica and starts the container when it's ready. The image is pulled whenever there's a change in the Git repository, ensuring automatic updates.

# Best Practices
- Ensure the Git repository is properly secured and has access control in place.
- Use ArgoCD's automated rollouts and validation features to minimize downtime and risk.
- Keep the container image base small and up-to-date to reduce the security risk.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse-app
spec:
  replicas: 1
  selector:
    matchLabels:
      app: eclipse
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
      - name: eclipse
        image: "<IMAGE_REGISTRY>/<IMAGE_NAME>:<TAG>"
        ports:
        - containerPort: 8080
---
apiVersion: sourcecontrollab.toolkit.fluxcd.io/v1beta2
kind: GitRepository
metadata:
  name: eclipse-repo
spec:
  url: "<GIT_REPO_URL>"
  branch: "<BRANCH_NAME>"
  path: "path/to/app/"
  interval:
    minutes: 5
```
Replace `<IMAGE_REGISTRY>/<IMAGE_NAME>:<TAG>` with the container image details, `<GIT_REPO_URL>` with the Git repository URL, and `<BRANCH_NAME>` and `path/to/app/` with the Git branch name and the application path, respectively. The `interval` in the GitRepository spec is set to update the repository every 5 minutes.
