 # Kubernetes Concept: Daemonset
A DaemonSet ensures that a specified number of replicas of a Pod run on as many nodes as possible in the cluster.

# Explanation
DaemonSets are useful for deploying processes that require special access to the node, such as monitoring agents, logging daemons, or container runtimes. They are designed to maintain the desired state of a set of daemon processes running on each node in the cluster.

# Best Practices
- Define resource limits and requests for the daemon processes in the DaemonSet.
- Use labels and selectors properly to ensure the DaemonSet targets the correct nodes.
- Use rolling updates for DaemonSets to minimize downtime.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: quantum-logs
  labels:
    app: quantum
spec:
  replicas: 3
  selector:
    matchLabels:
      app: quantum
  template:
    metadata:
      labels:
        app: quantum
    spec:
      containers:
      - name: quantum-container
        image: quantum/logs:latest
        resources:
          limits:
            cpu: "100m"
            memory: "256Mi"
          requests:
            cpu: "50m"
            memory: "128Mi"
        ports:
        - containerPort: 80
        livenessProbe:
          exec:
            command: ["/bin/sh", "/usr/local/bin/quantum-check.sh"]
          intervalSeconds: 120
```
This DaemonSet ensures three replicas of the quantum-logs container run on each node, with proper resource management and a liveness probe for monitoring the container's health.
