 # Kubernetes Deployment
Create and manage containerized applications at scale.

# Explanation
A Kubernetes Deployment is used to describe and create a desired state for a set of containers or replicas, ensuring their availability and scalability. It continuously rolls out updates and manages their rollbacks if needed, following a process called Rolling Update or Rollback.

# Best Practices
- Use Label selectors to identify and manage a specific set of pods within the deployment.
- Implement Rolling Updates and Rollbacks to minimize downtime and ensure smooth application updates.
- Utilize ReplicaSets for high availability and scalability, as they maintain a desired number of replicas regardless of failures.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: example-deployment
  labels:
    app: example
spec:
  replicas: 3
  selector:
    matchLabels:
      app: example
  template:
    metadata:
      labels:
        app: example
    spec:
      containers:
      - name: example-container
        image: example-image:latest
        ports:
        - containerPort: 80
          name: http
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
          initialDelaySeconds: 15
```
This example demonstrates a simple Kubernetes Deployment for an application named "example" using an image named "example-image:latest". The Deployment runs three replicas, and each replica has a single container listening on port 80. The liveness and readiness probes are set up to monitor the health of the container, ensuring its availability and readiness to receive traffic.
