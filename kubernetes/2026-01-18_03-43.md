 # Kubernetes Concept
Deployment is a Kubernetes object used for updating and managing containerized applications. It keeps a specified number of replicas running and ensures the desired state of the application.

# Explanation
A Kubernetes Deployment creates or updates Pods in a cluster to run a new version of an application. It ensures that the specified number of replicas are running and creates new Pods as needed. The old Pods are gradually terminated, allowing for a controlled rollout and rollback.

# Best Practices
- Use a rolling update strategy to minimize downtime and ensure a smooth transition between versions.
- Define a readiness probe and a liveness probe for your containers to help Kubernetes determine when a container is ready to serve traffic and when it should be restarted.
- Set up a rolling update strategy using the `rolling-update` strategy (default) in the `.spec.strategy.type` field.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
        - name: phoenix
          image: myregistry/phoenix:v1
          ports:
            - containerPort: 8080
          readinessProbes:
            - apiVersion: v1
              kind: Probe
              name: readiness
              exec:
                command: ["/usr/bin/sh", "-c", "curl --fail http://localhost:8080/ || exit 1"]
              intervalSeconds: 5
              timeoutSeconds: 5
              successThreshold: 1
              failureThreshold: 3
          livenessProbes:
            - apiVersion: v1
              kind: Probe
              name: liveness
              exec:
                command: ["/usr/bin/sh", "-c", "curl --fail http://localhost:8080/ || exit 1"]
              intervalSeconds: 30
              timeoutSeconds: 5
              successThreshold: 1
              failureThreshold: 3
```
This example demonstrates a Deployment for a containerized application named Phoenix. The Deployment runs three replicas of the container and defines readiness and liveness probes. The rolling update strategy is used by default.
