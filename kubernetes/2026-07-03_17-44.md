 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures the desired number of replicas are running and available.

# Explanation
A Deployment creates and manages Pods based on a defined container image, provides a controlled way to update and rollback changes to an application. Its controller continually monitors the state of the application and automatically restarts Pods if they fail.

# Best Practices
- Use RollingUpdates to update your application, ensuring minimal downtime and smooth transitions.
- Use ReadinessProbes and LivenessProbes to ensure your application is running correctly and ready for traffic.
- Implement resource limits and requests for your containers to ensure efficient resource utilization and prevent noisy neighbors.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: example-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: example
  template:
    metadata:
      labels:
        app: example
    spec:
      containers:
      - name: example-container
        image: example-image:latest
        ports:
        - containerPort: 80
        resources:
          limits:
            cpu: "1"
            memory: "512Mi"
          requests:
            cpu: "500m"
            memory: "256Mi"
      readinessProbes:
      - apiVersion: v1
        kind: Probe
        name: readiness
        probeType: HttpGet
        httpGet:
          path: /healthz
          port: 80
          intervalSeconds: 5
        failureThreshold: 3
      livenessProbes:
      - apiVersion: v1
        kind: Probe
        name: liveness
        probeType: HttpGet
        httpGet:
          path: /liveness
          port: 80
          intervalSeconds: 15
```
