 # Kubernetes Concept
Deployment is a Kubernetes object used for creating and updating replicas of a desired state for a set of containers.

# Explanation
A Kubernetes Deployment creates and manages the availability of a specified number of replicas of a container image, ensuring the desired state is always running. It provides a way to progressively roll out updates to the container images, allowing for zero downtime deployments.

# Best Practices
- Use Rolling updates for zero downtime deployments.
- Use the latest stable Kubernetes version to ensure security and compatibility.
- Set up resource limits to ensure fair distribution of resources.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-registry/my-image:latest
        ports:
        - containerPort: 80
        readinessProbes:
        - apiVersion: v1
          probeType: HttpGet
          timeoutSeconds: 5
          path: /healthz
      imagePullSecrets:
      - name: my-registry-secret
```
This example demonstrates a Deployment for a simple containerized application named "my-app". The Deployment creates and manages three replicas of the container, ensuring the desired state is always available. The container image is pulled from a registry using the name "my-registry/my-image:latest". The readiness probe checks the HTTP endpoint at "/healthz" to determine if the container is ready to receive traffic. The image pull secret "my-registry-secret" is used for securely accessing the container registry.
