 # Kubernetes Concept
This is an example of a Kubernetes `Deployment` resource for a simple application named `atlas` with built-in readiness and liveness probes for monitoring its health.

# Explanation
A `Deployment` in Kubernetes is a declaration of desired state for a group of replicas of a containerized application. The controller ensures that the actual state matches the desired state by creating or updating replicas with the new image tag. In this example, we configure the `atlas` Deployment with readiness and liveness probes for monitoring its health and availability. The `readinessProbe` determines if the container is ready to start accepting traffic, while the `livenessProbe` checks if the container is running properly.

# Best Practices
- Use the `rollout` strategy `Recreate` for new versions of your application.
- Set the `imagePullPolicy` to `Always` to ensure that the latest image is always used.
- Use `replicas` instead of `replicaCount` for more flexibility.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: atlas
spec:
  selector:
    matchLabels:
      app: atlas
  replicas: 3
  template:
    metadata:
      labels:
        app: atlas
    spec:
      containers:
      - name: atlas
        image: my-registry/atlas:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probes:
          - exec:
              command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
          initialDelaySeconds: 5
          periodSeconds: 10
        livenessProbe:
          probes:
          - exec:
              command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
          initialDelaySeconds: 15
          periodSeconds: 20
```
