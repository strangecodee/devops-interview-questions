 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications and their rollouts. It ensures available deployments of an application, creates new replicas with updates, and scales according to the desired state.

# Explanation
A Kubernetes Deployment manages the lifecycle of a set of replicas of a container, ensuring availability and increasing progressively the number of available replicas as new versions are rolled out, while keeping the old versions available until they are completely replaced. This allows for seamless updates and minimizes downtime.

# Best Practices
- Use rolling updates to minimize downtime and ensure high availability.
- Set up a readiness probe to check if the container is ready to receive traffic.
- Use liveness probes to detect and recover containers that have failed but are still running.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: example-app
  labels:
    app: example
spec:
  replicas: 3
  selector:
    matchLabels:
      app: example
  template:
    metadata:
      labels:
        app: example
    spec:
      containers:
        - name: example-container
          image: example-registry/example-image:latest
          ports:
            - containerPort: 80
          livenessProbe:
            httpGet:
              path: /healthz
              port: 80
          readinessProbe:
            httpGet:
              path: /ready
              port: 80
```
In this example, a Deployment named "example-app" is created with 3 replicas, using the "example-registry/example-image:latest" image, and listening on port 80. Liveness and readiness probes are set up using `httpGet` to check the health of the container at the defined paths "/healthz" and "/ready" respectively.
