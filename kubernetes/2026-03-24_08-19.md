# Kubernetes Concept
Kubernetes Deployment is a declarative way to create and manage applications in a Kubernetes cluster. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
Deployments manage the lifecycle of containerized applications and handle rolling updates and rollbacks. They declare the desired state for a set of containers, including their images, memory, CPU, and other specifications. The Kubernetes controller maintains this desired state by creating or updating the required replicas, scaling them up or down as needed, and ensuring their availability and readiness.

# Best Practices
- Use `rollouts` with `rolling-updates` and `progressDeadlineSeconds` to minimize downtime and ensure smooth updates.
- Set up `readinessProbes` and `livenessProbes` to monitor the health and readiness of your containers.
- Use `replicas` and `strategy.type` to define the number of desired instances and the update strategy for your applications.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probe:
            exec:
              command: ["/usr/local/bin/my-readiness-check.sh"]
          initialDelaySeconds: 5
          periodSeconds: 5
        livenessProbe:
          probe:
            exec:
              command: ["/usr/local/bin/my-liveness-check.sh"]
            initialDelaySeconds: 15
            periodSeconds: 10
```
