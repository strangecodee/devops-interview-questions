 # Kubernetes Concept
Deployment is a Kubernetes object used to describe and create a desired state for a set of containers. It ensures that a specified number of replicas of a container image are running and available at any given time.

# Explanation
The Deployment resource type in Kubernetes manages the lifecycle of a set of pods, creating new instances when necessary and removing old ones that are no longer required. It also provides a way to roll out updates to the container image, performing rolling updates or blue/green deployments.

# Best Practices
- Use rolling updates to minimize downtime and ensure high availability.
- Set up readiness and liveness probes for the containers to determine their health and readiness to receive traffic.
- Set up resource limits for the containers to optimize cluster usage and prevent container starvation.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 8080
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
      resources:
        limits:
          cpu: "1"
          memory: "512Mi"
        requests:
          cpu: "0.5"
          memory: "256Mi"
```
This YAML file defines a Kubernetes Deployment named "nebula-deployment" with 3 replicas, a container named "nebula" using the image "nebula:latest", and sets up liveness and readiness probes for the container. The container is allocated 1 CPU and 512 MiB of memory, and 0.5 CPU and 256 MiB of memory is requested.
