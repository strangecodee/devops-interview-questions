 # Kubernetes Concept
This is an example of a Kubernetes DaemonSet, a way to ensure a copy of a pod runs on all nodes in a cluster.

# Explanation
A DaemonSet ensures that a specified number of replicas of a pod are running on all nodes in the cluster. This is useful for running system daemons, such as a logging agent or monitoring agent, on every node. The DaemonSet controller continuously creates and manages the daemon pods and restarts them if they fail.

# Best Practices
- Use labels to select the nodes where the DaemonSet should run.
- Use health checks and readiness probes to ensure the daemon is running correctly.
- Set the desired number of replicas appropriately to avoid overloading nodes with unnecessary daemons.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: nebula-logging-agent
spec:
  selector:
    matchLabels:
      app: nebula-logging-agent
  template:
    metadata:
      labels:
        app: nebula-logging-agent
    spec:
      containers:
      - name: nebula-logging-agent
        image: nebula/logging-agent:latest
        ports:
        - containerPort: 25826
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:25826/ || exit 1"]
            periodSeconds: 5
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:25826/ || exit 1"]
            periodSeconds: 10
---
```
In this example, the DaemonSet named `nebula-logging-agent` runs a logging agent container on all nodes in the cluster. The container image is `nebula/logging-agent:latest`, and the container has a readiness and a liveness probe to check the availability of the agent on the localhost at port 25826. The labels are used to select the nodes and manage the daemon.
