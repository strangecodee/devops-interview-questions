 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas of a container are running in the cluster at any given time.

# Explanation
Deployments manage the lifecycle of a set of replicas, creating new replicas with updates and scaling as needed. They provide a way to declaratively update or rollback applications with minimal downtime using the rolling update strategy. Additionally, they integrate with Kubernetes' readiness and liveness probes for advanced health checks.

# Best Practices
- Create immutable images and use Helm charts or Kustomize for declarative configuration management.
- Leverage rolling updates and set appropriate update strategies to minimize downtime.
- Implement health checks with readiness and liveness probes for each container in your application.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-registry.com/my-image:1.0.0
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 30
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 15
```
