 # Kubernetes Concept
Deployment is a Kubernetes object used for updating and rolling back applications. It ensures availability during updates.

# Explanation
A Deployment creates and manages replica sets to ensure that a specified number of replicas are running and available at any given time. It can perform rolling updates and rollbacks, ensuring zero downtime for applications.

# Best Practices
- Use labels for easy identification and management of Deployments.
- Use rolling updates to minimize downtime and maintain availability.
- Use readiness and liveness probes to monitor the health of your applications.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-app
  labels:
    app: nebula
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula-container
        image: nebula:latest
        ports:
        - containerPort: 80
      readinessProbes:
      - exec:
          command: ["/usr/bin/curl", "--fail", "--silent", "--head", "/"]
          intervalSeconds: 5
      livenessProbes:
      - exec:
          command: ["/usr/bin/curl", "--fail", "--silent", "--head", "/"]
          intervalSeconds: 15
```
This YAML defines a Deployment named `nebula-app` with three replicas. It uses readiness and liveness probes to monitor container health and ensures that only healthy containers are considered available. The container image is `nebula:latest` and listens on port 80.
