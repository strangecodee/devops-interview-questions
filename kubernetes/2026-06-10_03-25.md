 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage replicas of a container. It ensures the desired number of replicas are running at any given time, and can perform updates and rollbacks.

# Explanation
A Deployment creates and manages a set of replicas for a container, ensuring that a specified number of replicas are running at any given time. If the container image is updated, Deployments can perform rollouts and rollbacks, updating the replicas in batches to minimize downtime and risk.

# Best Practices
- Use rolling updates for minimal downtime during container image updates.
- Set up readiness and liveness probes to ensure containers are running correctly and ready to serve traffic.
- Use labels to organize and select sets of replicas for scaling and rolling updates.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: quantum-app
  labels:
    app: quantum
spec:
  replicas: 3
  selector:
    matchLabels:
      app: quantum
  template:
    metadata:
      labels:
        app: quantum
    spec:
      containers:
      - name: quantum
        image: gcr.io/project-123/quantum:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probe:
            exec:
              command: ["/usr/local/bin/readiness.sh"]
          periodSeconds: 10
          failureThreshold: 3
        livenessProbe:
          probe:
            exec:
              command: ["/usr/local/bin/liveness.sh"]
          periodSeconds: 30
          failureThreshold: 6
```
This example creates a Deployment named `quantum-app` for a container with the label `app: quantum`. The Deployment creates and manages three replicas, and sets up readiness and liveness probes to check the container's health. The container image is specified as `gcr.io/project-123/quantum:latest`.
