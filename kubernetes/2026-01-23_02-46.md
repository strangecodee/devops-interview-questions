 # Kubernetes Concept
Deployment is a Kubernetes object used to roll out and manage containerized applications. It ensures a specified number of replicas are running and available, and can perform rolling updates or rollbacks.

# Explanation
A Kubernetes Deployment creates and manages a set of replica Pods to ensure desired application availability through updates and failures. It maintains the desired state by creating new replicas if they are terminated and deleting unhealthy ones. The Deployment controller manages the lifecycle of the Pods, including updates and rollbacks.

# Best Practices
- Use rolling updates for minimal downtime during application upgrades.
- Use health checks to determine readiness and liveness of the application.
- Set appropriate resource limits and requests to ensure efficient resource utilization.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: example-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: example-app
  template:
    metadata:
      labels:
        app: example-app
    spec:
      containers:
      - name: example-container
        image: example/image:latest
        ports:
        - containerPort: 80
      imagePullSecrets:
      - name: example-registry
      readinessProbe:
        probe:
          exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
          intervalSeconds: 5
        timeoutSeconds: 5
      livenessProbe:
        probe:
          exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
          intervalSeconds: 30
          timeoutSeconds: 5
```
