 # Kubernetes Concept
Deployment is a Kubernetes object used for managing applications by creating and updating replicas.

# Explanation
A Deployment creates and manages instances of a desired Pod template using a declarative approach. It ensures that a specified number of replicas are running and replaces or updates instances as needed to maintain the desired state.

# Best Practices
- Use rolling updates for minimal downtime when updating Deployments.
- Use rolling updates with `maxSurge` and `maxUnavailable` to control the number of new and old replicas during updates.
- Use labels to select and manage a specific set of Pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: pulse-deployment
  labels:
    app: pulse
spec:
  replicas: 3
  selector:
    matchLabels:
      app: pulse
  template:
    metadata:
      labels:
        app: pulse
    spec:
      containers:
      - name: pulse-container
        image: aws_account_id.dkr.ecr.region.amazonaws.com/pulse:latest
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: pulse-service
spec:
  selector:
    app: pulse
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```
In this example, a Deployment named `pulse-deployment` is created to manage three replicas of the `pulse` container, with each replica running the Docker image `aws_account_id.dkr.ecr.region.amazonaws.com/pulse:latest`. A Service named `pulse-service` is created to expose the application on port 80 using the `ClusterIP` type.
