 # Kubernetes Concept
This YAML example demonstrates a Kubernetes `HorizontalPodAutoscaler` and `Service` for load balancing traffic to a replica set of `nginx` pods.

# Explanation
The `HorizontalPodAutoscaler` automatically adjusts the number of replica pods in a replica set based on CPU utilization. The `Service` provides a stable IP address and DNS name for accessing the application running on the pods. Together, these components enable automatic scaling and load balancing for the `nginx` application.

# Best Practices
- Set appropriate limits and requests for CPU and memory for your container to ensure efficient resource utilization.
- Use `readinessProbes` and `livenessProbes` to ensure your containers are running correctly and ready to accept traffic.
- Monitor your application's resource usage and adjust the `minReplicas` and `maxReplicas` accordingly.

# YAML Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
  - name: http
    port: 80
    targetPort: 80
  type: LoadBalancer
---
apiVersion: v1
kind: ReplicaSet
metadata:
  name: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.21.1
        ports:
        - containerPort: 80
---
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: nginx-autoscaler
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: ReplicaSet
    name: nginx
  minReplicas: 1
  maxReplicas: 5
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
```
In this example, we define a `Service` that exposes the `nginx` application on port 80 using a LoadBalancer type. We also create a `ReplicaSet` with three replicas running the `nginx` container. The `HorizontalPodAutoscaler` is used to automatically scale the number of replicas based on CPU utilization, with a minimum of one replica and a maximum of five replicas. This setup ensures high availability and efficient resource utilization for the `nginx` application.
