 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas of a pod are running on each node in a cluster.

# Explanation
DaemonSets are useful for deploying system services or agents that require to run on every node of the Kubernetes cluster. They help maintain a consistent state across the cluster, ensuring high availability and fault tolerance.

# Best Practices
- Use labels to select nodes and limit the DaemonSet scope to specific nodes as needed.
- Set resource requirements and limits to manage resources efficiently.
- Implement readiness and liveness probes to monitor the health and readiness of the DaemonSet pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
  labels:
    app: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemonset
  template:
    metadata:
      labels:
        app: my-daemonset
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
        - containerPort: 443
        resources:
          limits:
            cpu: "1"
            memory: "512Mi"
          requests:
            cpu: "0.5"
            memory: "256Mi"
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            periodSeconds: 5
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            periodSeconds: 15
```
This example demonstrates a DaemonSet named "my-daemonset" with a container named "my-container", which runs an image called "my-image:latest". The DaemonSet sets CPU and memory limits and requests, as well as readiness and liveness probes.
