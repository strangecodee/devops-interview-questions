 # Kubernetes Concept
This Kubernetes YAML example demonstrates a DaemonSet configuration for running an eclipse-jetty application with Chaos Engineering readiness and liveness probes.

# Explanation
A DaemonSet ensures all nodes in a cluster run a copy of the same pod. Here, we deploy an eclipse-jetty container with Chaos Engineering probes to ensure the application is running and ready to serve traffic.

# Best Practices
- Use appropriate labels for the DaemonSet to target nodes.
- Implement Chaos Engineering probes to increase application resilience.
- Regularly update the container image to maintain security and functionality.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: eclipse-jetty
  labels:
    app: eclipse-jetty
spec:
  selector:
    matchLabels:
      app: eclipse-jetty
  template:
    metadata:
      labels:
        app: eclipse-jetty
    spec:
      containers:
      - name: eclipse-jetty
        image: eclipse:jetty
        ports:
        - containerPort: 8080
          name: http
        readinessProbes:
        - exec:
            command: ["/usr/bin/nc", "-z", "--shutdown", "--timeout=5s", "localhost", "8080"]
            intervalSeconds: 15
        livenessProbes:
        - exec:
            command: ["/usr/bin/nc", "-z", "--shutdown", "--timeout=5s", "localhost", "8080"]
            intervalSeconds: 30
---
kind: ChaosEngine
apiVersion: chaos-mesh.org/v1alpha1
metadata:
  name: eclipse-jetty-chaos-engine
spec:
  rules:
  - type: HTTP
    targets:
    - service: eclipse-jetty
      port: 8080
```
This YAML file creates a DaemonSet named `eclipse-jetty`, which runs the `eclipse:jetty` container image. The `readinessProbes` and `livenessProbes` are used to ensure the container is ready and running. The ChaosEngine configuration is included to manage chaos experiments, and the rule specifies the type of chaos as HTTP and the targeted service and port.
