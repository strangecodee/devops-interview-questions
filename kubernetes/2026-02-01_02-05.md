 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
Deployments manage the lifecycle of a set of replicas, creating new ones when needed, and terminating unused ones. They also enable rolling updates and rollbacks. Using a Deployment, you can declare desired state, and Kubernetes will maintain that state by creating or terminating pods as needed.

# Best Practices
- Use `RollingUpdate` strategy to minimize downtime and maintain availability.
- Set `minReadySeconds` to ensure that your containers pass readiness checks before being considered available.
- Monitor your Deployments using Kubernetes metrics and logs.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-image:latest
        ports:
        - containerPort: 80
          protocol: TCP
      imagePullSecrets:
      - name: my-registry-secret
      readinessProbe:
        probes:
        - exec:
            command: ["curl", "--fail", "/healthz"]
            intervalSeconds: 5
            timeoutSeconds: 3
        initialDelaySeconds: 180
---
apiVersion: v1
kind: Service
metadata:
  name: my-app
spec:
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 80
```
In this example, we create a Deployment managing 3 replicas of the container `my-app`, which listens on port 80. The container's image is pulled using a secret `my-registry-secret`. The `readinessProbe` ensures that the application is ready before it is considered available by the Deployment. The `Service` exposes the Deployment on port 80.
