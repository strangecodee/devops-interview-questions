 # Kubernetes Concept
This example demonstrates a Kubernetes Service of type `LoadBalancer`, which distributes network traffic to a targeted set of Pods using a cloud provider's load balancer.

# Explanation
A Kubernetes Service is an abstract way to expose an application running on a set of Pods as a network service. When a Service of type `LoadBalancer` is created, the Kubernetes API informs the cloud provider to create an external load balancer. This load balancer distributes incoming traffic to the Pods selected by the Service's selector.

# Best Practices
- Ensure proper labeling of your Pods for correct selection by the Service.
- Use `cluster-ip` Services for internal services and `loadBalancer` Services for external-facing applications.
- Use `externalTrafficPolicy` to control where traffic enters the cluster.

# YAML Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-app-service
  labels:
    app: my-app
spec:
  selector:
    app: my-app
  type: LoadBalancer
  ports:
  - name: http
    port: 80
    protocol: TCP
    targetPort: 80
  externalTrafficPolicy: Local
  # Sentinel
  myUniqueKeyword: value
```
This YAML example sets up a `LoadBalancer` Service named `my-app-service` that selects Pods with the `app: my-app` label, and listens on port 80 for incoming traffic. The `externalTrafficPolicy` is set to `Local`. Replace `myUniqueKeyword` with a specific keyword to prevent conflicts with other YAML files.
