 # Kubernetes Concept
This Kubernetes YAML example demonstrates a Horizontal Pod Autoscaler (HPA) configuration for a deployment of an application using a LoadBalancer service for external access.

# Explanation
The Horizontal Pod Autoscaler (HPA) automatically scales the number of replicas in a deployment based on observed CPU utilization. Here, an HPA is used to manage the scaling of a deployment with an associated LoadBalancer service to distribute external network traffic to the pods. This configuration enables efficient resource utilization and improved application availability.

# Best Practices
- Set up appropriate resource limits and requests for the container to ensure optimal container performance and efficient resource usage.
- Monitor the application's performance metrics and adjust the HPA's minimum and maximum replica count based on the expected traffic and resource requirements.
- Use rolling updates with the HPA to minimize downtime when deploying new versions of your application.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-app
  labels:
    app: nebula
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula-container
        image: nebula:latest
        ports:
        - containerPort: 80
          protocol: TCP
        resources:
          limits:
            cpu: "1.0"
            memory: "512Mi"
          requests:
            cpu: "0.5"
            memory: "256Mi"
---
apiVersion: v1
kind: Service
metadata:
  name: nebula-service
  labels:
    app: nebula
spec:
  selector:
    app: nebula
  ports:
  - port: 80
    targetPort: 80
  type: LoadBalancer
---
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: nebula-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nebula-app
  minReplicas: 2
  maxReplicas: 5
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 80
```
This YAML example includes a Deployment, Service, and HorizontalPodAutoscaler configuration. The Deployment runs three replicas of the nebula-app container, while the Service, named nebula-service, is set up as a LoadBalancer to distribute external network traffic to the pods. The HPA, named nebula-hpa, is set up with a minimum of 2 replicas and a maximum of 5 replicas, with the autoscaling triggered when the average CPU utilization exceeds 80%.
