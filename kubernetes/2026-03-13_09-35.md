 # Kubernetes Concept
Deployment is a Kubernetes object used for creating and managing replicas of a container application. It ensures the desired state of a set of containers by creating and managing Pods.

# Explanation
A Deployment in Kubernetes maintains a specified number of replicas of a desired Pod template and creates new replicas if old ones fail. It uses selectors to match Pods and updates them based on the latest image or configuration changes. The rollout strategy determines how new replicas are created and old ones are replaced.

# Best Practices
- Use rolling updates for minimal downtime and smooth deployment of new versions.
- Perform updates during low traffic hours to minimize the impact on users.
- Implement readiness and liveness probes to ensure that only healthy containers are serving traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```
