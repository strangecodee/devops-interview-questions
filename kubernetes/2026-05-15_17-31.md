# Kubernetes Concept
Kubernetes Secret is a container object used to store and manage sensitive information, such as passwords, OAuth tokens, and SSL certificates.

# Explanation
Secrets in Kubernetes are encrypted at rest and decrypted only when they are used to fill environment variables, command-line arguments, or as configuration data for containers. This ensures that sensitive data is not exposed in the container image or as plaintext in the cluster.

# Best Practices
- Create a dedicated `kube-system` namespace for storing system-level secrets.
- Use Kubernetes RBAC to restrict access to secrets to specific users and groups.
- Store secrets as encrypted files instead of cleartext values when creating them.

# YAML Example
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: my-app-credentials
  namespace: my-application
  creationTimestamp: "2022-01-01T00:00:00Z"
data:
  username: cGFzc3dvcmQ=
  password: c29tMQ==
  apiKey: dGhlIHNlY3JldHk=
```
In this example, a Secret named `my-app-credentials` is created in the `my-application` namespace. The sensitive data, such as a username, password, and API key, are encoded in base64 and stored as data key-value pairs.
