 # Kubernetes Concept
Kubernetes DaemonSet is a type of Kubernetes deployment that ensures a copy of the specified Pod is running on each node in the cluster.

# Explanation
DaemonSets are used to manage system daemons or background services that need to be running on all nodes in a cluster. They ensure that a specified number of replicas of the daemon are running and available, even if the pods are terminated or crashed. This is useful for services like logging, monitoring, and network proxies that need to be present on every node.

# Best Practices
- Use a unique and descriptive name for the DaemonSet.
- Define the desired number of replicas in the DaemonSet.
- Use labels to select the nodes where the DaemonSet should be deployed.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-logging-daemonset
spec:
  selector:
    matchLabels:
      app: my-logging
      tier: daemon
  template:
    metadata:
      labels:
        app: my-logging
        tier: daemon
    spec:
      containers:
      - name: my-logging-container
        image: my-logging-image:latest
        ports:
        - containerPort: 514
          name: udp
          protocol: UDP
        volumeMounts:
        - mountPath: /var/log
          name: var-log
      volumes:
      - name: var-log
        emptyDir: {}
---
kind: Service
apiVersion: v1
metadata:
  name: my-logging-service
spec:
  selector:
    app: my-logging
  ports:
  - port: 514
    name: udp
    protocol: UDP
  type: ClusterIP
```
This DaemonSet deploys a logging agent container on all nodes in the cluster, listens on UDP port 514, and mounts a emptyDir volume for storing logs. The corresponding Service creates a ClusterIP service to enable communication between the logging daemon and other services in the cluster.
