 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications. It creates and updates containers using replicas, maintaining a desired state.

# Explanation
Kubernetes Deployment ensures a specified number of replicas for an application are running at any given time. It handles rolling updates and rollbacks, making it an essential component to run and manage containers in a cluster.

# Best Practices
- Use rolling updates with a small number of replicas to update containers gradually.
- Set up a readiness probe to ensure the container is ready to serve traffic.
- Configure liveness probes for monitoring the container's health and restarting it if necessary.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: atlas-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: atlas
  template:
    metadata:
      labels:
        app: atlas
    spec:
      containers:
      - name: atlas
        image: myregistry/atlas:latest
        ports:
        - containerPort: 80
          protocol: TCP
      readinessProbe:
        probes:
        - exec:
            command: ["curl", "--fail", "/healthz"]
            intervalSeconds: 15
            timeoutSeconds: 5
      livenessProbe:
        probes:
        - exec:
            command: ["curl", "--fail", "/healthz"]
            intervalSeconds: 60
            timeoutSeconds: 5
```
This YAML file creates a Kubernetes Deployment named 'atlas-app' with 3 replicas. The containers in the replicas use the image 'myregistry/atlas:latest'. The readinessProbe and livenessProbe ensure that the container is ready and healthy. The readiness probe checks the health endpoint with a curl command every 15 seconds, and the liveness probe checks it every 60 seconds.
