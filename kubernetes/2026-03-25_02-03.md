# Kubernetes Concept
Deployment is a Kubernetes object used for updating and rolling out applications. It ensures that a specified number of replicas are running at any given time, providing a zero-downtime update mechanism.

# Explanation
A Kubernetes Deployment creates and manages replicas of a containerized application. It monitors the availability of the application, and if any replicas fail, it automatically restarts them or creates new ones to maintain the desired state. Deployments also perform rolling updates, allowing for seamless updates without disrupting end-users.

# Best Practices
- Use rolling updates to minimize downtime and maintain availability.
- Keep multiple replicas running to ensure high availability and distribute incoming requests evenly.
- Monitor your application's health and readiness with Probes.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-deployment
spec:
  selector:
    matchLabels:
      app: nebula
  replicas: 3
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 8080
        readinessProbe:
          probes:
          - exec:
              command: ["/usr/local/bin/check-readiness.sh"]
        livenessProbe:
          probes:
          - exec:
              command: ["/usr/local/bin/check-liveness.sh"]
```
This example creates a Deployment named `nebula-deployment` with 3 replicas, each running the `nebula:latest` container image. The Deployment uses both readiness and liveness probes to monitor the application's health and availability.
