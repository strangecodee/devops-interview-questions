# Kubernetes Concept
Deployment is a Kubernetes object used for creating, updating, and managing containers. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
A Deployment creates and manages containers by creating and updating Pods in a cluster. It maintains the desired state by rolling out updates and rolling back if necessary. This provides a declarative approach for application deployment and scaling.

# Best Practices
- Use rolling updates to minimize downtime when deploying new versions of your application.
- Use a readiness probe and a liveness probe to ensure that newly created containers are healthy and ready to serve traffic.
- Use a strategy of Type: RollingUpdate or Type: Recreate to define how updates should be performed.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-deployment
spec:
  selector:
    matchLabels:
      app: forge
  replicas: 3
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: forge
        image: forge:latest
        ports:
        - containerPort: 80
      readinessProbe:
        probe:
          exec:
            command: ["/app/health-check.sh"]
        periodSeconds: 5
      livenessProbe:
        probe:
          exec:
            command: ["/app/liveness-check.sh"]
        periodSeconds: 10
        failureThreshold: 3
strategy:
  type: RollingUpdate
  rollingUpdate:
    maxSurge: 1
    maxUnavailable: 0
```
This YAML example demonstrates a Deployment named "forge-deployment" with a replica count of 3. It uses rolling updates, and the readiness and liveness probes are defined to ensure that the containers are healthy and ready to serve traffic. The strategy of RollingUpdate is used here, with a maxSurge of 1 and maxUnavailable of 0.
