 # Kubernetes Concept
Deployment is a Kubernetes object used for updating and managing containerized applications. It ensures availability through progressively rolling out updates and maintaining a specified number of replicas.

# Explanation
A Deployment creates and manages replica sets and updates them in batches to minimize downtime. It keeps a desired number of replicas running by creating new pods, deleting old ones, and handling rolling updates.

# Best Practices
- Use rolling updates to minimize downtime and maintain availability during updates.
- Set up health checks with Liveness and Readiness probes to ensure pods are healthy and ready to serve.
- Use replica sets and replica controllers for maintaining a stable number of instances.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula-container
        image: nebula:latest
        ports:
        - containerPort: 80
      livenessProbe:
        httpGet:
          path: /healthz
          port: 80
      readinessProbe:
        httpGet:
          path: /ready
          port: 80
---
apiVersion: v1
kind: Service
metadata:
  name: nebula-service
spec:
  selector:
    app: nebula
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```
This Deployment example creates a nebula application with three replicas. It uses a ClusterIP service to expose the application internally within the cluster. Liveness and Readiness probes are set up to ensure the pod's status and availability.
