 # Kubernetes Concept
Introducing a Kubernetes `Deployment` for a Docker application, which ensures desired state and rolling updates.

# Explanation
A `Deployment` is a Kubernetes resource for managing containerized applications. It provides declarative updates for the containerized applications, rolling updates, and rolling back to previous versions if needed. It keeps a specified number of replicas running to ensure high availability and self-healing capabilities.

# Best Practices
- Use `rolling updates` to minimize disruptions and ensure application availability.
- Configure `readiness` and `liveness` probes to ensure the container is ready to receive traffic and functioning correctly.
- Use `resource limits` and `requests` to manage container resource usage and prioritize resources for other pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
        resources:
          limits:
            cpu: "1.0"
            memory: "512Mi"
          requests:
            cpu: "0.5"
            memory: "256Mi"
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 5
        readinessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 5
```
