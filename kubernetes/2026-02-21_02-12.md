 # Kubernetes Concept: Deployment with Liveness and Readiness Probes

This Kubernetes concept refers to creating and managing a replicaset using the Deployment resource, along with defining Liveness and Readiness probes to ensure the application's health and readiness.

# Explanation
Deployments in Kubernetes manage the lifecycle of a set of replicas, providing a declarative update mechanism for applications. The Liveness and Readiness probes are essential for monitoring application health and assessing whether new replicas should be introduced or existing ones replaced. Liveness probes help ensure the application is running properly and will be restarted if it fails, while Readiness probes determine whether a container is ready to start accepting traffic.

# Best Practices
- Set appropriate initial delays and period values for the probes to prevent unnecessary restarts or checks.
- Use probes that are specific to your application.
- Monitor and update the probes as your application changes.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse-deployment
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 1
  selector:
    matchLabels:
      app: eclipse
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
      - name: eclipse-container
        image: eclipse:latest
        ports:
        - containerPort: 8443
        livenessProbe:
          exec:
            command: ["/usr/bin/curl", "-f", "http://localhost:8080/healthz"]
            intervalSeconds: 30
            timeoutSeconds: 5
        readinessProbe:
          exec:
            command: ["/usr/bin/curl", "-f", "http://localhost:8080/ready"]
            intervalSeconds: 15
            timeoutSeconds: 3
```
In this example, the Deployment named 'eclipse-deployment' will manage three replicas of an eclipse container image (latest version). Liveness and Readiness probes have been defined to check the health and readiness of the containers, respectively. Liveness probe checks the 'http://localhost:8080/healthz' endpoint every 30 seconds, while the Readiness probe checks the 'http://localhost:8080/ready' endpoint every 15 seconds. The container's image is updated using a RollingUpdate strategy, allowing one new replica at a time and maintaining one old and one new replica available during the update process.
