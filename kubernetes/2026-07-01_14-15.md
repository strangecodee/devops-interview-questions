 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas of a container are running at all times.

# Explanation
A Deployment creates or updates Pods in a cluster to run a specific version of an application. It maintains the desired state of the application by managing the rolling updates and rollbacks of the Pods.

# Best Practices
- Use rolling updates to minimize downtime and improve availability.
- Use readinessProbes and livenessProbes to ensure the containers are healthy.
- Use a strategy of type "RollingUpdate" to make updates with zero downtime.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-registry/my-app:v1.0.0
        ports:
        - containerPort: 80
        readinessProbe:
          probes:
          - exec:
              command: ["/usr/local/bin/check-readiness"]
        livenessProbe:
          probes:
          - exec:
              command: ["/usr/local/bin/check-liveness"]
```
This example creates a Deployment named `my-app` with 3 replicas, using an image with the tag `v1.0.0`. It uses a rolling update strategy to minimize downtime and ensures that the containers are healthy using readiness and liveness probes.
