 # Kubernetes Concept
Deployment is a Kubernetes resource for managing the rollout and scaling of containerized applications.

# Explanation
A Deployment creates and manages replicas of a specified container image within a Pod. It also handles updates and rollbacks to ensure smooth application transitions.

# Best Practices
- Use rolling updates to minimize downtime when updating your application.
- Set appropriate resource limits and requests to ensure optimal performance and fair sharing.
- Monitor your deployment using Kubernetes built-in metrics and logging.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: registry.example.com/phoenix:v1
        ports:
        - containerPort: 8080
          protocol: TCP
        resources:
          limits:
            cpu: "1"
            memory: "512Mi"
          requests:
            cpu: "0.5"
            memory: "256Mi"
          livenessProbe:
            httpGet:
              path: /healthz
              port: 8080
          readinessProbe:
            httpGet:
              path: /ready
              port: 8080
```
This YAML file defines a Deployment named `phoenix-deployment` with 3 replicas. It uses a container image from `registry.example.com` with a tag `v1`. The container exposes port 8080, sets CPU and memory limits and requests, and includes both liveness and readiness probes.
