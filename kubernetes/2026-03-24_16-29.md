# Kubernetes Concept
Deployments in Kubernetes are used for updating and rolling out new versions of applications. They ensure that the desired state of the application is maintained by creating new replicas and gradually rolling out the updated version while ensuring zero-downtime.

# Explanation
Kubernetes Deployments manage the lifecycle of a set of replicas for an application. They provide options for rolling updates, rollbacks, and can be used to perform blue-green deployments. The updated version is rolled out gradually to a percentage of instances, and once it passes health checks, the old instances are drained and deleted.

# Best Practices
- Use `RollingUpdate` strategy with `MaxSurge` and `MaxUnavailable` set to ensure a smooth deployment process.
- Use `Readiness` and `Liveness` probes to ensure that the new pods are ready to serve traffic and to check the health of the application.
- Use `Rollback` to revert to the previous version in case of any issues with the new release.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-example
spec:
  selector:
    matchLabels:
      app: nebula
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
    blueGreenDeployment:
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 80
        readinessProbe:
          exec:
            command: ["/usr/local/bin/check-ready.sh"]
          intervalSeconds: 15
          failureThreshold: 3
        livenessProbe:
          exec:
            command: ["/usr/local/bin/check-health.sh"]
          intervalSeconds: 30
          failureThreshold: 6
```
This YAML file defines a Kubernetes Deployment named `nebula-example` with 3 replicas. It uses a RollingUpdate strategy with a max surge of 1 and max unavailable of 0, ensuring minimal downtime during the deployment process. It also includes readiness and liveness probes to ensure that the new pods are ready to serve traffic and to check the health of the application. Additionally, it uses the `blueGreenDeployment` field to perform a zero-downtime deployment.
