 # Kubernetes Concept
Kubernetes DaemonSet is a type of Kubernetes deployment that ensures a copy of a specified pod runs on every node in a cluster.

# Explanation
DaemonSets maintain a consistent state across a cluster by managing and Replacing pods on each node. This is useful for running system daemons, such as monitoring agents, that require one instance per node.

# Best Practices
- Define health checks using Kubernetes probes to ensure your daemonset's pods are always running and healthy.
- Use labels and selectors to target specific nodes or node labels when deploying your DaemonSet.
- Use rolling updates to minimize downtime and rollback to previous versions if needed.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: monitoring-daemonset
spec:
  selector:
    matchLabels:
      app: monitoring
  template:
    metadata:
      labels:
        app: monitoring
    spec:
      containers:
      - name: monitoring
        image: monitoring-image:latest
        ports:
        - containerPort: 80
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80 || exit 1"]
            intervalSeconds: 5
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80 || exit 1"]
            intervalSeconds: 15
```
In this example, we create a DaemonSet with a container running monitoring software. The readiness and liveness probes ensure that only healthy instances of the container are running.
