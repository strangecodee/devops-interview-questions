 # Kubernetes Concept
This is an example of a Helm chart for deploying a Phoenix application on Kubernetes.Helm is a popular package manager for deploying and managing applications on Kubernetes. Using Helm charts makes it easier to package, install, and upgrade applications on a Kubernetes cluster.

# Explanation
This Helm chart includes all the necessary configuration files to deploy a Phoenix application on a Kubernetes cluster. It manages the deployment of the application container, sets up persistent volumes for data storage, and includes probes for monitoring the health of the application.

# Best Practices
- Use Helm to manage the deployment and configuration of your Phoenix application.
- Set up persistent volumes to ensure data persistence for your application.
- Configure probes to monitor the health of your application.

# YAML Example
```yaml
apiVersion: v2
name: phoenix
version: 0.1.0

values:
  image:
    repository: myregistry/phoenix:latest
    tag: latest
    pullPolicy: IfNotPresent

  container:
    name: phoenix
    image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
    ports:
    - containerPort: 4000
    env:
    - name: PORT
      value: "4000"

  volume:
    name: phoenix-data
    persistentVolumeClaim:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 10Gi

  service:
    type: ClusterIP
    name: phoenix
    ports:
    - name: http
      port: 4000
      targetPort: 4000

  nodeSelector:
    app: phoenix

  tolerations:
  - key: app
    value: phoenix
    effect: PreferNoSchedule

  probes:
  - name: liveness
    exec:
      command: ["/bin/sh", "-c", "curl --fail --max-time 1 http://localhost:4000/ || exit 1"]
    initialDelaySeconds: 15
    periodSeconds: 10
    timeoutSeconds: 5

  - name: readiness
    exec:
      command: ["/bin/sh", "-c", "curl --fail --max-time 1 http://localhost:4000/ || exit 1"]
    initialDelaySeconds: 15
    periodSeconds: 10
    timeoutSeconds: 5
```
This Helm chart includes the definition of the Phoenix application container image, the creation of a persistent volume, the setup of a ClusterIP service, and the configuration of node selectors and tolerations. It also includes probes for monitoring the liveness and readiness of the application.
