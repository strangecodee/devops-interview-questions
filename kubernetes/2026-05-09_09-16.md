# Kubernetes Concept
This example introduces a Kubernetes DaemonSet for the eclipse-js-chaos project, which injects chaos agents for testing and improving resiliency of applications.

# Explanation
A DaemonSet ensures that all specified pods are running and maintained across the cluster, and that new nodes joining the cluster are populated with the specified pods. In this case, we use a DaemonSet to deploy the eclipse-js-chaos chaos agents as daemons in the cluster. These agents injection tests for various failure scenarios, such as network partitions, resource exhaustion, and pod deletion, helping to build fault-tolerant applications.

# Best Practices
- Keep the number of chaos agents per node minimal to avoid performance degradation.
- Configure the chaos agents to target specific applications or namespaces to minimize impact on non-targeted workloads.
- Regularly review the chaos engineering results and adjust the tests based on the application's design and requirements.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: eclipse-js-chaos
spec:
  selector:
    matchLabels:
      app: eclipse-js-chaos
  template:
    metadata:
      labels:
        app: eclipse-js-chaos
    spec:
      containers:
      - name: eclipse-js-chaos
        image: eclipse-foundation/chaos-js:0.11.0
        args:
          - run
          - --logtostderr
          - --restapi-port=8081
          - --webhook-port=8080
          - --namespace: <YOUR-NAMESPACE>
      restartPolicy: Always
```
Replace `<YOUR-NAMESPACE>` with the appropriate Kubernetes namespace for your application.
This DaemonSet uses the eclipse-foundation/chaos-js:0.11.0 container image and sets the container arguments and ports to the default values for the eclipse-js-chaos chaos agents.
