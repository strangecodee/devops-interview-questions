 # Kubernetes Concept
This is an example of a Kubernetes Deployment for a scalable application named "nebula" using ReplicaSets and RollingUpdate strategy.

# Explanation
The Kubernetes `Deployment` resource is used to manage the lifecycle of a set of replicas for an application. In this example, the `nebula` Deployment will ensure a specified number of replicas are running and available. The `RollingUpdate` strategy is used to perform updates for the application with minimal downtime, updating the replicas one at a time.

# Best Practices
- Use `RollingUpdate` strategy for updates to minimize downtime.
- Set appropriate resource limits and requests for the replicas to maintain optimal performance and prevent resource contention.
- Monitor the application's health and readiness using `Probes`.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula
spec:
  selector:
    matchLabels:
      app: nebula
  replicas: 3
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 80
        resources:
          limits:
            cpu: "1"
            memory: "512Mi"
          requests:
            cpu: "0.5"
            memory: "256Mi"
        readinessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 5
      terminationGracePeriodSeconds: 30
  strategy:
    type: RollingUpdate
---
apiVersion: v1
kind: Service
metadata:
  name: nebula
spec:
  selector:
    app: nebula
  ports:
  - port: 80
    targetPort: 80
```
