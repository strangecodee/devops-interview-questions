# Kubernetes Concept
Kubernetes DaemonSet ensures that a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
A DaemonSet is a type of Kubernetes deployment that ensures that a copy of the specified pod runs on all nodes of a cluster. This is useful for running system daemons, logging agents, or monitoring solutions. DaemonSets automatically replace or heal unavailable pods and maintain the desired state of the application across the entire cluster.

# Best Practices
- Apply the DaemonSet configuration via a GitOps workflow for version control and easy rollbacks.
- Use appropriate labels and selectors to target the nodes where the DaemonSet should run.
- Configure rolling updates carefully to minimize downtime and ensure data consistency.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-daemonset
spec:
  selector:
    matchLabels:
      app: logging-daemon
  template:
    metadata:
      labels:
        app: logging-daemon
    spec:
      containers:
      - name: logging-container
        image: logging-image:latest
        ports:
        - containerPort: 514
        readinessProbes:
        - exec:
            command: ["/usr/bin/logger", "--test"]
          intervalSeconds: 5
```
This YAML example defines a DaemonSet named `logging-daemonset` with a container named `logging-container` that runs the `logging-image:latest` image. The `readinessProbes` are used to verify that the container is ready to accept traffic from the cluster.
