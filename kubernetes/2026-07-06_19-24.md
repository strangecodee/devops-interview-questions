 # Kubernetes Concept
This example demonstrates a Kubernetes `HorizontalPodAutoscaler` (HPA) for monitoring and automatically adjusting the number of replicas in a Pod based on observed CPU utilization.

# Explanation
The Kubernetes HPA is a controller that automatically scales the number of replicas in a Pod based on observed metrics, such as CPU utilization. By setting up an HPA, you can ensure optimal resource utilization and maintain application availability.

# Best Practices
- Define specific target CPU thresholds to trigger scaling actions.
- Limit the minimum and maximum number of replicas to prevent unintended scaling.

# YAML Example
```yaml
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: my-app-hpa
spec:
  selector:
    matchLabels:
      app: my-app
      environment: production
  minReplicas: 3
  maxReplicas: 10
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: my-app-deployment
  metrics:
  - type: Resource
    resource:
      name: cpu
    target:
      type: Utilization
      averageUtilization: 50
      averageUtilizationPeriod: 300
```
This YAML example creates a Kubernetes HPA named `my-app-hpa`. It targets a deployment named `my-app-deployment`, and the HPA will scale based on observed CPU utilization, maintaining an average of 50% over a 5-minute period. The minimum and maximum number of replicas are set to 3 and 10, respectively.
