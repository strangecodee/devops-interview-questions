 # Kubernetes Concept
Deployment is a Kubernetes object used to create and update containerized applications. It ensures that a specified number of replicas of a container are running at any given time, maintaining availability and scalability.

# Explanation
A Deployment in Kubernetes manages the lifecycle of a set of replicas for a given application. It continuously ensures that the desired state of the application is maintained by creating new replicas if they are terminated, and scaling up or down based on the current workload. This way, the Deployment provides a rolled-out update mechanism for your applications, ensuring zero downtime.

# Best Practices
- Use `rollouts.strategy.type: RollingUpdate` to update your application with minimal downtime.
- Configure `minReadySeconds` to ensure that new containers are healthy before being considered ready and eligible to serve traffic.
- Use `horizontalPodAutoscaler` to scale the number of replicas based on the current resource usage.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
      readinessProbe:
        probe:
          exec:
            command: ["/usr/bin/curl", "--fail", "http://localhost:80/healthz"]
        initialDelaySeconds: 5
        periodSeconds: 10
      livenessProbe:
        probe:
          exec:
            command: ["/usr/bin/curl", "--fail", "http://localhost:80/liveness"]
        initialDelaySeconds: 30
        periodSeconds: 30
```
This example demonstrates a Deployment managing a containerized application called `my-app`. It sets the desired number of replicas to 3, and uses readiness and liveness probes to ensure the containers are healthy and ready to serve traffic. The container image is pulled from `my-registry/my-app:latest`.
