 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas of a Pod are running on each node in the cluster, maintaining a consistent daemon presence across the cluster.

# Explanation
DaemonSets are a type of Kubernetes deployment that creates and manages a set of Pods, ensuring that a copy runs on each node in the cluster. They are commonly used for deploying system daemons, such as monitoring agents or log collectors, as they ensure consistent availability and distribution across the cluster.

# Best Practices
- Use labels for targeting specific nodes or nodes with certain characteristics
- Use rolling updates with a small update size to minimize downtime
- Use health checks and liveness probes to ensure the daemon Pods are healthy and running correctly

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: monitoring-agent
  labels:
    app: monitoring
spec:
  selector:
    matchLabels:
      app: monitoring
  template:
    metadata:
      labels:
        app: monitoring
    spec:
      containers:
      - name: monitoring-agent
        image: monitoring/agent:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probeType: HTTP
          httpGet:
            path: /health
            port: 80
        livenessProbe:
          probeType: HTTP
          httpGet:
            path: /liveness
            port: 80
```
This DaemonSet example uses a monitoring agent container with the specified image, ports, readiness, and liveness probes. It also includes a label selector for the monitoring app, ensuring that the monitoring agent is deployed on each node with the app label `app: monitoring`.
