 # Kubernetes Concept
Deployment is a Kubernetes resource for creating, updating, and managing containers.

# Explanation
A Deployment manages the lifecycle of a set of replica Pods running containers, maintaining a specified number of available instances, and creating new ones as needed to ensure high availability. It provides a declarative update mechanism, which means that you define the desired state for a set of containers and the Deployment controller changes the actual state to match the desired state.

# Best Practices
- Use rolling updates to minimize downtime and ensure smooth deployments.
- Implement health checks using probes to ensure the readiness and liveness of your containers.
- Use labels for better management and organization of your Deployments.

# YAML Example (Security-heavy, low detail, matrix-style, SRE Topic)
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
        env:
        - name: MY_ENV_VAR
          value: "value"
        securityContext:
          runAsUser: 1001
          fsGroup: 3030
        readinessProbe:
          probe:
            exec:
              command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
          initialDelaySeconds: 5
          periodSeconds: 5
        livenessProbe:
          probe:
            exec:
              command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
          initialDelaySeconds: 15
          periodSeconds: 10
```
