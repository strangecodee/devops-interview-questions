 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications. It ensures that a specified number of replicas of a container image are running at any given time.

# Explanation
Deployments in Kubernetes provide declarative updates for containerized applications. This means that you define the desired state of the application in the YAML manifest file, and Kubernetes takes care of updating the containers to meet that state. Deployments provide rolling updates and rollbacks, which make it easy to update applications with minimal downtime.

# Best Practices
- Use labels and selectors to manage and identify deployments.
- Use rolling updates to minimize downtime and ensure zero-downtime deployments.
- Use replicas to provide availability and scalability for your applications.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: myregistry/phoenix:latest
        ports:
        - containerPort: 8080
        readinessProbe:
          probes:
          - httpGet:
              path: /healthz
              port: 8080
              httpHeaders:
              - name: X-Requested-With
                value: "xmlhttprequest"
          initialDelaySeconds: 5
          periodSeconds: 5
```
This YAML example defines a Deployment named `phoenix` with three replicas. The `replicas` field is used to ensure that at least three instances of the container are running. The `selector` field is used to identify the pods that belong to this deployment. The `template` field defines the container image, ports, and readiness probe for the container. The readiness probe checks the `/healthz` endpoint of the container every 5 seconds and sets the container as ready if the status code is 200. This ensures that only healthy containers are serving traffic.
