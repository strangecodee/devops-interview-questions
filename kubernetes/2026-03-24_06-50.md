# Kubernetes Concept
Kubernetes DaemonSet is a way to ensure that a copy of a specified Pod runs on all nodes in a cluster.

# Explanation
DaemonSets maintain a consistent number of replicas of a Pod on each node in a cluster. They are particularly useful for running system daemons, node agents, or monitoring tools where a single instance per node is desired. In this example, we will create a DaemonSet for a logging agent.

# Best Practices
- Declare necessary resource limits and requests in the DaemonSet configuration.
- Use labels and selectors to control which nodes the DaemonSet runs on.
- Use readiness and liveness probes to ensure the health of your DaemonSet.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-agent
  labels:
    app: logging-agent
spec:
  selector:
    matchLabels:
      app: logging-agent
  template:
    metadata:
      labels:
        app: logging-agent
    spec:
      containers:
      - name: logging-agent
        image: logging-agent:latest
        ports:
        - containerPort: 5000
          name: http
        - containerPort: 6000
          name: tcp
        resources:
          limits:
            cpu: "0.5"
            memory: "512Mi"
          requests:
            cpu: "0.2"
            memory: "256Mi"
        readinessProbes:
        - exec:
            command: ["/usr/local/bin/check-readiness.sh"]
            intervalSeconds: 15
          timeoutSeconds: 5
        livenessProbes:
        - exec:
            command: ["/usr/local/bin/check-liveness.sh"]
            intervalSeconds: 30
          timeoutSeconds: 10
```
This YAML configuration defines a DaemonSet named `logging-agent` that runs a logging agent container on each node in the cluster. The container uses the `logging-agent:latest` image and has a CPU limit of 0.5 and a memory limit of 512Mi. The readiness and liveness probes are defined to check the status of the container.
