 # Kubernetes Concept
Kubernetes ConfigMaps provide a way to inject configuration data into containers running in a Kubernetes cluster.

# Explanation
ConfigMaps allow you to decouple application configuration from container images and manage them separately. You can create and update ConfigMaps without rebuilding and redeploying your application images. The configuration data is mounted as files or environment variables in the containers.

# Best Practices
- Create ConfigMaps for non-sensitive data, such as application configuration files, property files, and XML/JSON files.
- Use Secrets for managing sensitive data, like passwords and API keys.
- Use environment variables or volume mounts to access ConfigMap data in your containers.

# YAML Example
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: configmap-example
data:
  app-config.properties: |
    property1=value1
    property2=value2
```
This ConfigMap named "configmap-example" contains a single data item "app-config.properties" with two key-value pairs. The data is defined using raw literals (the "|" symbol) and is base64 encoded in the actual YAML file.
