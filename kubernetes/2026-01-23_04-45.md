 # Kubernetes Concept: Deployment
A Kubernetes Deployment manages the rollout and scaling of containerized applications. It maintains a specified number of replicas and ensures their availability and readiness.

# Explanation
Deployments in Kubernetes are used to create and manage instances of applications and automatically replace unhealthy or outdated pods with new ones. It provides rollouts with zero downtime and can execute rolling updates or rollbacks.

# Best Practices
- Use rolling updates to minimize downtime.
- Set up a strategy for maxSurge and maxUnavailable to control the number of new and old replicas during updates.
- Monitor the health of your application using Kubernetes built-in probes or custom probes.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: forge
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: forge-container
        image: myregistry/forge:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 5
```
This YAML creates a Deployment named "forge-web" with 3 replicas, a container running the image "myregistry/forge:latest", and both liveness and readiness probes to monitor the application's health.
