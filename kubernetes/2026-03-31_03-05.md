# Kubernetes Concept
This YAML example demonstrates a Kubernetes Deployment for a simple application using a Docker image, hosted on Amazon Elastic Container Registry (ECR), and configured with readiness and liveness probes.

# Explanation
Deployments in Kubernetes manage the lifecycle of containerized applications by creating and updating replicas in the cluster. In this example, we create a Deployment for a container image hosted on Amazon ECR, and configure readiness and liveness probes to ensure the application is functioning correctly.

# Best Practices
- Use Helm or Kustomize for managing and deploying complex applications in a declarative and consistent manner.
- Set appropriate resource limits and requests to optimize container memory usage and CPU utilization.
- Use a multi-stage Dockerfile for building your image to reduce the image size and minimize attack surfaces.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-app
  labels:
    app: nebula
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula-container
        image: 123456789012.dkr.ecr.region.amazonaws.com/nebula:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probes:
          - exec:
              command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
          initialDelaySeconds: 15
          periodSeconds: 5
          timeoutSeconds: 1
        livenessProbe:
          probes:
          - exec:
              command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
          initialDelaySeconds: 15
          periodSeconds: 10
          timeoutSeconds: 1
  strategy:
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
```
This YAML example includes:

- The API version and kind for creating a Deployment
- Metadata for defining the Deployment name and labels
- Specifying the number of replicas, selector, and container template
- Container details, including image, ports, and probes
- Strategies for updating the deployment with rolling updates.
