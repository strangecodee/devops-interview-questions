 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures desired state by creating and updating pods.

# Explanation
A Deployment creates and manages a set of replicas of a Pod, maintaining a specified number of available instances at any given time. You can use rollouts to update the containers in the Pods while keeping a fixed number of available instances. When you create or update a Deployment, Kubernetes will create a new ReplicaSet to manage the deployment's Pods, and the old ReplicaSet will be automatically deleted once the new one is ready.

# Best Practices
- Use Rolling updates with a small update strategy to minimize downtime and ensure a seamless transition between versions.
- Use rolling updates with the maximum number of replicas possible to shorten update times.
- Monitor your application's health using Liveness and Readiness probes to ensure that the new pods are functioning correctly before marking them as healthy and ready to serve traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
          protocol: TCP
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```

This YAML example creates a Deployment with the name "my-app" and sets the desired number of replicas to 3. It uses a container labeled "my-container" with an image "my-image:latest" and exposes a single port. Additionally, it sets up both a Liveness and Readiness probe to ensure the application is healthy and ready.
