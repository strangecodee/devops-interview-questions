 # Kubernetes Deployment
Create and manage containers in a pod using Kubernetes Deployments.

# Explanation
A Deployment in Kubernetes manages the lifecycle of a set of replicas of a container or set of containers, creating new replicas with updated configurations and removing old ones. It maintains a specified number of replicas running to ensure high availability and rollbacks to previous configurations if needed.

# Best Practices
- Use replicas to ensure availability: Set the desired number of replicas to ensure availability and maintain the specified number of running containers in the cluster.
- Use rolling updates: Update container images incrementally to minimize downtime and maintain availability.
- Use readiness and liveness probes: Monitor the health and readiness of the containers to ensure they are running and serving traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
          protocol: TCP
        readinessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 10
        livenessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 10
```
In this example, a Deployment named `my-app` is created with 3 replicas. The container image `my-registry/my-app:latest` is used, and the container listens on port 80. A readiness and a liveness probe are configured to check the health and readiness of the container using an HTTP GET request on the `/healthz` endpoint. The initial delay and period for the probes are set to 15 seconds and 10 seconds, respectively.
