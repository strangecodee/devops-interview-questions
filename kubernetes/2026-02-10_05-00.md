 # Kubernetes Concept
This is an example of a Kubernetes Deployment for a microservice application using Istio as a service mesh for traffic management and observability.

# Explanation
A Deployment in Kubernetes is used for declaratively creating and managing a set of replicas of a container application. In this example, we will deploy a microservice application using Istio for service discovery, load balancing, and traffic management. Istio acts as a sidecar container injected into each pod, providing additional features like security, retries, and timeouts.

# Best Practices
- Use a single container per pod for better resource isolation and easier management.
- Use Istio's automated sidecar injection for seamless integration and easier management.
- Set up Istio's Envoy proxy as a sidecar container in the Deployment.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: myregistry/phoenix:latest
        ports:
        - containerPort: 8080
        env:
        - name: MY_VAR
          value: "somevalue"
      imagePullSecrets:
      - name: myregistry
      # Enable Istio's sidecar injection
      initContainers:
      - name: istio-init
        image: istio/proxyv2:latest
        command: ["/init"]
        volumeMounts:
        - mountPath: /var/run/secrets/istio
          readOnly: true
      containers:
      - name: phoenix
        image: myregistry/phoenix:latest
        ports:
        - containerPort: 8080
        env:
        - name: MY_VAR
          value: "somevalue"
        readinessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 5
          periodSeconds: 5
        livenessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 10
```
This YAML file describes a Kubernetes Deployment named "phoenix" with 3 replicas. The container runs the image "myregistry/phoenix:latest" and is labeled with "app: phoenix". An Istio sidecar container is added as an init container to initialize the Envoy proxy. The main container runs the phoenix application and listens on port 8080. The Deployment uses Istio's Envoy proxy for traffic management and observability, and both readiness and liveness probes are defined for the container.
