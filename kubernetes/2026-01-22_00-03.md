 # Kubernetes Concept
This is an example of a Kubernetes `Deployment` configuration for a simple application using a container image of the open-source Java EE application server, Eclipse GlassFish.

# Explanation
This YAML file defines a `Deployment` resource in Kubernetes, which creates and manages a set of replicas of a containerized application. In this case, the application is Eclipse GlassFish, which is configured to expose its admin port so that it can be monitored using Kubernetes' built-in metrics and health probes.

# Best Practices
- Use a `Deployment` instead of a `ReplicaSet` or `DaemonSet` for stateless applications, as it provides more advanced features like rollouts and rollbacks.
- Apply the principle of separation of concerns by keeping configuration and codebase separate, and use `ConfigMaps` or `Secrets` to inject configuration data into your containers.
- Consider using a container image scanner like Clair or Trivy to ensure that the base container image used in your deployment is secure and up-to-date.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: glassfish
  labels:
    app: glassfish
spec:
  replicas: 3
  selector:
    matchLabels:
      app: glassfish
  template:
    metadata:
      labels:
        app: glassfish
    spec:
      containers:
      - name: glassfish
        image: glassfish:latest
        imagePullPolicy: IfNotPresent
        ports:
        - containerPort: 4848
          protocol: TCP
          name: http-admin
        livenessProbe:
          httpGet:
            path: /admin/status/health-status
            port: http-admin
          initialDelaySeconds: 30
          periodSeconds: 30
```
This YAML file creates a `Deployment` with 3 replicas of the Eclipse GlassFish container image, and exposes the admin port for monitoring using a liveness probe.
