 # Kubernetes Concept
Kubernetes ConfigMap is a container object used to store and manage non-confidential data as key-value pairs.

# Explanation
ConfigMaps can be used to provide configuration data to containers, such as application properties, or environment variables. They can be mounted as files in containers or injected as environment variables, thus allowing decoupling of configuration data from container images. ConfigMaps are immutable, meaning that updating a ConfigMap creates a new one, and the old one is not affected.

# Best Practices
- Store sensitive configuration data in Kubernetes Secrets instead of ConfigMaps
- Use a single ConfigMap for a single purpose
- Use environment variables instead of mounting ConfigMap files directly into containers

# YAML Example
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-configmap
  labels:
    app: my-app
data:
  app.properties: |
    property1=value1
    property2=value2
  logs.conf: |
    property1=value1
    property2=value2
```
In this example, we create a ConfigMap named "my-configmap" with two data keys "app.properties" and "logs.conf", each containing some data in YAML format. The ConfigMap can be mounted into a container or injected as environment variables using Kubernetes manifests.
