 # Kubernetes Concept: Kubernetes DaemonSets

DaemonSets ensure that a specified number of replicas for a pod are running on all nodes in a cluster. This is useful for deploying system services that require a pod to be running on every node, such as monitoring agents or log collectors.

# Explanation

DaemonSets maintain a consistent state across a cluster by managing the lifecycle of the pods on each node. They ensure that the desired number of replicas are running and that any failures are automatically replaced. This guarantees that critical system services are always available on every node.

# Best Practices
- Define a `.spec.template.spec.containers[].image` field with a stable, tagged image to ensure consistency across nodes.
- Use `.spec.replicas` to specify the desired number of replicas per node.
- Set up proper resource limits and requests for the containers to prevent resource contention.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: monitoring-agent
spec:
  selector:
    matchLabels:
      app: monitoring-agent
  template:
    metadata:
      labels:
        app: monitoring-agent
    spec:
      containers:
        - name: monitoring-agent
          image: stable/monitoring:latest
          resources:
            limits:
              cpu: "100m"
              memory: "512Mi"
            requests:
              cpu: "50m"
              memory: "256Mi"
          ports:
            - containerPort: 8080
          livenessProbe:
            exec:
              command: ["/bin/sh", "/usr/local/bin/monitoring-agent --test"]
            intervalSeconds: 60
            timeoutSeconds: 30
```
This YAML example creates a DaemonSet named `monitoring-agent` that runs the `monitoring-agent` container on every node in the cluster with a stable image and resource limits. The liveness probe is used to ensure that the monitoring agent is running and responsive.
