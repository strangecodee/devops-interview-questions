 # Kubernetes Concept: Deployment
A Kubernetes Deployment manages the rollout and scaling of containerized applications. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
Deployments maintain availability and performance of applications by handling updates and rollbacks. They provide declarative updates for rolling out new container images, rolling out updates in batches, and performing automated rollbacks if an update fails.

# Best Practices
- Use Rolling Updates: Update containers in batches to minimize downtime, allowing for progressive rollouts and easy rollbacks.
- Implement Readiness and Liveness Probes: Ensure containers are functioning correctly and ready to receive traffic.
- Use Label Selectors: Consistently label and select pods for easy management and scaling.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse-demo
spec:
  replicas: 3
  selector:
    matchLabels:
      app: eclipse
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
        - name: eclipse
          image: eclipse-image:latest
          ports:
            - containerPort: 8181
          readinessProbe:
            probes:
              - exec:
                  command: ["/usr/bin/nc", "-z", "localhost", "8080", "--timeout=1"]
                intervalSeconds: 5
                failureThreshold: 3
          livenessProbe:
            probes:
              - exec:
                  command: ["/usr/bin/nc", "-z", "localhost", "8080", "--timeout=1"]
                intervalSeconds: 30
                failureThreshold: 3
```
This example demonstrates a Deployment managing three replicas of an eclipse application with readiness and liveness probes.
