# Kubernetes Concept
Deployment is a kind of Kubernetes resource that creates and manages a set of replicas of a containerized application.

# Explanation
A Kubernetes Deployment provides declarative updates for a specified number of replicas of a container, handling rolling updates and rollbacks with minimal downtime. It also ensures availability and scalability by automatically replacing unhealthy replicas.

# Best Practices
- Use rolling updates with a small percentage of replicas updated at a time to minimize application downtime.
- Define readiness and liveness probes to control container scaling and rolling updates based on health checks.
- Set up resource limits and requests to ensure proper resource allocation and avoid container contention.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-app
  labels:
    app: nebula
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
        - name: nebula
          image: nebula:latest
          ports:
            - containerPort: 80
          livenessProbe:
            httpGet:
              path: /live
              port: 80
          readinessProbe:
            httpGet:
              path: /ready
              port: 80
      resources:
        limits:
          cpu: "1"
          memory: "512Mi"
        requests:
          cpu: "500m"
          memory: "256Mi"
```
This example demonstrates a Deployment named `nebula-app` with three replicas. Containers use the `nebula:latest` image, and port `80` is exposed for liveness and readiness probes. Resource limits and requests are defined to manage container resource allocation.
