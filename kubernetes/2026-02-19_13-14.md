 # Kubernetes Concept
Kubernetes Role-Based Access Control (RBAC) is a security feature that helps manage access to Kubernetes resources.

# Explanation
Role-Based Access Control (RBAC) in Kubernetes allows defining and managing access to Kubernetes resources based on roles and permissions. RBAC uses the standard Kubernetes API to manage and assign roles, which can be granted based on users, groups, or service accounts. It provides a flexible and fine-grained access control mechanism to secure the Kubernetes cluster.

# Best Practices
- Implement the Principle of Least Privilege: Assign the minimum required permissions to each user, group, or service account.
- Enable RBAC: By default, Kubernetes is not enabled with RBAC. Enable RBAC and configure it to secure your cluster.
- Regularly review RBAC policies: Review RBAC policies to ensure they are up-to-date and necessary.

# YAML Example
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: nebula-reader
  namespace: default
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "watch", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: nebula-reader-binding
  namespace: default
subjects:
- kind: ServiceAccount
  name: nebula-reader-sa
  namespace: default
roleRef:
  kind: Role
  name: nebula-reader
  apiGroup: rbac.authorization.k8s.io
```
In the example, we define a `Role` named `nebula-reader` that grants read access to `Pods` in the `default` namespace. We then define a `RoleBinding` named `nebula-reader-binding` that binds the `nebula-reader` role to the `nebula-reader-sa` ServiceAccount in the `default` namespace. This allows the ServiceAccount to read Pods in the `default` namespace.
