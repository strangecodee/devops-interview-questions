 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications by creating, updating, and scaling replicas.

# Explanation
A Kubernetes Deployment ensures that a specified number of replicas for an application are running at any given time. It can create new replicas to replace unhealthy containers, and it can roll out updates to the application in a controlled manner.

# Best Practices
- Use rolling updates for minimal downtime when deploying new versions.
- Set up auto-scaling to handle traffic fluctuations.
- Use readiness and liveness probes to ensure the application is properly running.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  template:
    metadata:
      labels:
        app: my-app
    spec:
      serviceAccountName: my-service-account
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probes:
          - exec:
              command: ["/usr/bin/curl", "--fail", "http://localhost/healthz"]
              intervalSeconds: 5
              timeoutSeconds: 2
          initialDelaySeconds: 30
        livenessProbe:
          probes:
          - exec:
              command: ["/usr/bin/curl", "--fail", "http://localhost/healthz"]
              intervalSeconds: 15
              timeoutSeconds: 2
status:
  availableReplicas: 0
  replicas: 0
```
This example creates a deployment for an application called `my-app` with three replicas. It sets up a readiness and liveness probe for the container, using a `curl` command to check the application's healthz endpoint. It also uses a service account and sets container ports for the application.
