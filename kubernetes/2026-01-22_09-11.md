 # Kubernetes Concept
This example demonstrates a Kubernetes Deployment for a stateless application, focusing on zero-downtime deployments using rolling updates.

# Explanation
Kubernetes Deployments manage the lifecycle of a set of replicas for a container application. In this example, we'll use a Deployment to ensure zero-downtime deployments for our application by performing rolling updates. Rolling updates allow for new versions of the container to be introduced while maintaining availability of the application by updating replicas one at a time.

# Best Practices
- Use a `RollingUpdateStrategy` with `MaxSurge` and `MaxUnavailable` to control the number of new and old replicas during updates.
- Use `readinessProbes` and `livenessProbes` to ensure that your containers are ready and healthy.
- Use Kubernetes labels for easy management and selective scaling.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-zero-downtime
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: myregistry/phoenix:v1.0.0
        ports:
        - containerPort: 8080
        readinessProbes:
        - exec:
            command: ["/usr/bin/nc"]
            args: ["-z", "-w1", "localhost", "8080"]
        livenessProbes:
        - exec:
            command: ["/bin/sh"]
            args: ["-c", "while :; do sleep 60; done"]
      terminationGracePeriodSeconds: 30
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
```
This YAML defines a Kubernetes Deployment for a stateless application called `phoenix`. It sets up the desired number of replicas to be 3 and uses a `RollingUpdateStrategy` to ensure zero-downtime deployments. The `readinessProbes` and `livenessProbes` are configured to monitor the health and readiness of the containers.
