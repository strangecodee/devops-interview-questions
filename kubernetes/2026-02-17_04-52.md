 # Kubernetes Concept
This example demonstrates a Kubernetes Deployment for a monitoring application named "Atlas" using Horizontal Pod Autoscaling (HPA) and a readiness probe.

# Explanation
The Kubernetes Deployment defines the desired state for a set of Pods, ensuring that a specified number of replicas are running at any given time. HPA automatically scales the number of replicas based on observed CPU utilization. The readiness probe checks the status of the application, marking a Pod as ready when the probe succeeds.

# Best Practices
1. Use `stable/stable` as the base image and ensure it is regularly updated.
2. Set an appropriate limit and request for CPU and memory resources.
3. Monitor and adjust HPA metrics to maintain optimal resource usage.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: atlas
spec:
  selector:
    matchLabels:
      app: atlas
  replicas: 3
  template:
    metadata:
      labels:
        app: atlas
    spec:
      containers:
      - name: atlas
        image: stable/stable:latest
        ports:
        - containerPort: 80
        env:
        - name: APP_ENV
          value: production
        readinessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 5
      resources:
        limits:
          cpu: "1"
          memory: 512Mi
        requests:
          cpu: "0.5"
          memory: 256Mi
---
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: atlas-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: atlas
  minReplicas: 1
  maxReplicas: 5
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
```
