 # Kubernetes Concept
Deployment is a Kubernetes object used for updating and rolling back applications. It creates and manages replicas of a specified Pod template.

# Explanation
Deployments in Kubernetes handle updating and scaling of applications by creating new replicas with the latest configuration, rolling out the updates, and rolling back if necessary. This allows for zero-downtime deployments, ensuring high availability and minimal disruption to users.

# Best Practices
- Use Rolling Updates: Kubernetes performs updates in batches, replacing a certain percentage of replicas at a time. This ensures minimal downtime and smooth upgrades.
- Use Readiness and Liveness Probes: Probes help Deployments determine the health of the containers and automatically manage their lifecycle.
- Use Labels and Selectors: Labels and selectors help manage and identify the Pods in a Deployment.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: myregistry/phoenix:v1.0.0
        ports:
        - containerPort: 8080
        readinessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 5
          periodSeconds: 5
        livenessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 10
```
This Deployment example creates a new Phoenix application with 3 replicas, and uses Rolling Updates, Readiness, and Liveness probes. It also includes labels and selectors for easier management.
