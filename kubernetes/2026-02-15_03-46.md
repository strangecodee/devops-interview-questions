 # Kubernetes Deployment
Defines the desired state for a set of replicas of a containerized application.

# Explanation
A Kubernetes Deployment is used to create, configure, and manage replicas of a containerized application. It declares the desired state for a set of replicas, which can be scaled up or down based on demand using a RollingUpdate strategy. The Deployment controller ensures that a specified number of replicas are running at any given time and automatically restarts any containers that fail or become unresponsive.

# Best Practices
- Use RollingUpdates to minimize downtime and maintain availability during updates.
- Use ReadinessProbes and LivenessProbes to ensure that your containers are healthy and ready to serve traffic.
- Use labels to organize and select sets of pods based on common attributes.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-nginx
  labels:
    app: forge
spec:
  selector:
    matchLabels:
      app: forge
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 1
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: nginx
        image: nginx:1.14.2
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 5
        readinessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 5
```
This YAML defines a Kubernetes Deployment named "forge-nginx" with three replicas of an Nginx container. It uses a RollingUpdate strategy to minimize downtime, and includes both a LivenessProbe and a ReadinessProbe to ensure container health.
