 # Kubernetes Concept
This Kubernetes YAML example demonstrates a Deployment for a containerized application using Docker images, with a focus on managing multiple layers and ensuring a healthy application through liveness and readiness probes.

# Explanation
A Deployment in Kubernetes is used to create, manage, and update containers in a cluster. In this example, we will create a Deployment for an application using a multi-stage Docker image, which allows us to build the application with one set of instructions and then run it with another. This leads to smaller, more efficient containers. Liveness and readiness probes are used to ensure that the containers are running healthily, allowing Kubernetes to automatically restart or replace unhealthy containers.

# Best Practices
- Use multi-stage Docker images to reduce the size of your containers and improve security by removing unnecessary dependencies and build artifacts.
- Define both liveness and readiness probes for your containers to ensure their health and allow Kubernetes to automatically manage their lifecycle.
- Implement rolling updates and rollbacks to minimize downtime and maintain application availability during updates.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: myregistry/phoenix:latest
        imagePullPolicy: Always
        ports:
        - containerPort: 4000
        - containerPort: 8080
        livenessProbe:
          httpGet:
            path: /health
            port: 8080
        readinessProbe:
          httpGet:
            path: /health
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 5
```
In this example, we create a Deployment called "phoenix-deployment" that runs a container named "phoenix" with the image "myregistry/phoenix:latest". We use both liveness and readiness probes, checking the "/health" path on port 8080. The container exposes both ports 4000 and 8080. The container runs with 3 replicas, and Kubernetes will automatically update and manage these containers based on the defined Deployment strategy.
