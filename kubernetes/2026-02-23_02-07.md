 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications and their rolling updates and rollbacks.

# Explanation
A Deployment manages the lifecycle of a set of replicas, which are instances of your application running in the cluster. It ensures that the desired number of replicas are available at any given time, and allows for rolling updates to new versions of your application with minimal downtime.

# Best Practices
- Use labels for easy identification and management of pods.
- Use rolling updates for minimal downtime when updating applications.
- Use readiness and liveness probes for monitoring the health of your application.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-registry/my-image:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```
In this example, we create a Deployment named `my-app` with 3 replicas, each labeled `app: my-app`. The containers in the template are specified with an image from a registry, a label, and a port for listening to incoming requests. Liveness and readiness probes are also defined to monitor the health of the application.
