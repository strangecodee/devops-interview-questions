 # Kubernetes Concept
This YAML example demonstrates a Horizontal Pod Autoscaler (HPA) for a Kubernetes Deployment, which automatically scales the number of pods based on observed CPU utilization.

# Explanation
The Horizontal Pod Autoscaler (HPA) is a Kubernetes component that automatically scales the number of replicas (pods) in a Deployment based on observed CPU utilization. HPA allows for efficient resource utilization and improved application performance by allocating the required number of resources to handle incoming traffic.

# Best Practices
- Set appropriate initial pod count and minimum and maximum replicas based on expected traffic.
- Use predefined metrics like CPU utilization or custom metrics for scaling.
- Monitor HPA metrics and adjust scale targets accordingly to ensure optimal performance.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 80
---
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: nebula-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nebula-app
  minReplicas: 3
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
```
This YAML example includes a Deployment named `nebula-app` with 3 initial replicas and an HPA named `nebula-hpa` which will automatically scale the number of replicas based on average CPU utilization of 50%.
