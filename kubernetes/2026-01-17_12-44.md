 # Kubernetes Concept
Deployment is a Kubernetes object used for declaring and managing a set of replicas for a desired state of a group of containers.

# Explanation
A Kubernetes Deployment manages updates, rollouts, and automates rollbacks of containerized applications. It maintains the desired state by creating replacement instances with updated containers whenever a new image is tagged or when a user explicitly runs `kubectl apply`.

# Best Practices
- Use `kubectl set image` or Helm chart updates to minimize downtime during Deployment updates.
- Configure the `minReadySeconds` field to ensure containers are stable before being considered ready by the Deployment.
- Use `rollouts.strategy.type = RollingUpdate` for staggered updates and a controlled update pace.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-webapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: forge
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: forge-container
        image: forge/webapp:1.0.0
        ports:
        - containerPort: 80
          name: http
          protocol: TCP
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
      imagePullSecrets:
      - name: regcred
  strategy:
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
```
