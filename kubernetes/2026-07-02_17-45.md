 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
A Deployment creates and manages replicas of a containerized application. When you create or update a Deployment, Kubernetes ensures that a specified number of replicas are running at any given time. If a replica fails, Kubernetes automatically creates a new one or replaces the failed one to maintain the desired state of your application.

# Best Practices
- Use rolling updates to minimize downtime and maintain availability.
- Use labels for easy management and selective deletion.
- Set resource limits to avoid contention and ensure fair usage.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-registry/my-image:latest
        ports:
        - containerPort: 80
          name: http
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```
This Deployment ensures that three replicas of the container `my-app-container` are running, and automatically replaces any replicas that fail or become unhealthy. The `livenessProbe` and `readinessProbe` are used to check the container's health and readiness. The container image is pulled from the registry `my-registry` and has a port exposed at `80`.
