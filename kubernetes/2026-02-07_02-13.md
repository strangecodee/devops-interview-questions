 # Kubernetes Deployment
Create and manage containerized applications with Kubernetes Deployments.

# Explanation
A Kubernetes Deployment manages the lifecycle of a set of replicas for a desired application. It ensures that a specified number of replicas are running and available at any given time. The Deployment controller can create new replicas to replace any that fail, roll out updates, and roll back to previous versions if necessary.

# Best Practices
- Use rolling updates to minimize downtime and ensure a smooth upgrade process.
- Set up and use readiness and liveness probes to check the health of your containers.
- Use labels for easy identification and management of your deployments.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: my-registry.com/phoenix:latest
        ports:
        - containerPort: 8080
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 5
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 5
```
This YAML file creates a Kubernetes Deployment named `phoenix-deployment` with three replicas running an application called `phoenix`. The containers in the replicas listen on port 8080, and both the liveness and readiness probes check the `/healthz` and `/ready` endpoints, respectively. The initial delay is set to 15 seconds, and the probes are checked every 5 seconds.
