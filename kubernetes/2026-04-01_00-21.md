# Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications.

# Explanation
A Deployment maintains a specified number of replicas of a container image. When you change the container image, the Deployment controller changes the containers for new replicas, while it rolls out updates for existing replicas in batches. This ensures high availability and minimal downtime.

# Best Practices
- Use rolling updates to minimize downtime and ensure a smooth deployment process.
- Set up a strategy for your rollouts, like Progressive or Blue/Green.
- Use readiness and liveness probes to monitor your application's health.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: atlas
spec:
  replicas: 3
  selector:
    matchLabels:
      app: atlas
  template:
    metadata:
      labels:
        app: atlas
    spec:
      containers:
      - name: atlas
        image: registry.example.com/atlas:v1
        ports:
        - containerPort: 80
      readinessProbes:
      - exec:
          command: ["/usr/local/bin/check-readiness.sh"]
          intervalSeconds: 5
      livenessProbes:
      - exec:
          command: ["/usr/local/bin/check-liveness.sh"]
          intervalSeconds: 30
```
This example creates a Deployment named 'atlas' with three replicas and a container image from the registry 'registry.example.com/atlas:v1'. It also includes readiness and liveness probes.
