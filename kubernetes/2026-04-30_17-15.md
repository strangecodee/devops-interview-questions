# Kubernetes Concept
Deployment is a Kubernetes resource for describing and managing a set of replicas for a container application.

# Explanation
A Deployment manages the lifecycle of a set of Pods, creating new ones to replace old ones when necessary. In case of a failure, the Deployment controller restores the desired state by creating a new replica.

# Best Practices
- Use `strategy.type: RollingUpdate` to update containers in a controlled manner.
- Set `minReadySeconds` to ensure that newly created pods meet specific readiness conditions before they are considered ready.
- Use `imagePullSecrets` to securely pull container images from a registry.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: atlas-sre
  labels:
    app: atlas
    environment: sre
spec:
  replicas: 3
  selector:
    matchLabels:
      app: atlas
      environment: sre
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: atlas
        environment: sre
    spec:
      containers:
      - name: atlas
        image: registry.example.com/atlas:v1
        ports:
        - containerPort: 80
        imagePullSecrets:
        - name: docker-registry-secret
      readinessProbes:
      - exec:
          command: ["/usr/local/bin/check-health", "--grace-period=30s"]
        initialDelaySeconds: 15
        periodSeconds: 5
```
This YAML example defines a Deployment named `atlas-sre` with three replicas. The containers in each replica use an image from the `registry.example.com` registry and are labeled as `app: atlas` and `environment: sre`. The rolling update strategy is used with a max surge of one and zero max unavailable deployments. The container's readiness is checked using the `check-health` command and the image is pulled using the `docker-registry-secret` secret.
