 # Kubernetes Concept
This is an example of a Kubernetes ConfigMap resource, which is used to store and manage non-confidential data as key-value pairs.

# Explanation
ConfigMaps are used to store and manage non-confidential data such as application configuration files, property files, or environment variables. They can be mounted as volumes in containers or used as environment variables. ConfigMaps support rollouts, rollbacks, and can be updated without changing the container image.

# Best Practices
- Use ConfigMaps instead of hardcoding sensitive information in containers or in Kubernetes manifests.
- Use Kubernetes secrets for storing confidential information such as passwords or keys.
- Use ConfigMaps to store configuration files that change frequently, while use ConfigMaps or an external registry for large binary files.

# YAML Example
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: phoenix-config
data:
  application.properties: |
    server.port=8080
    spring.datasource.url=jdbc:mysql://database:3306/mydb
    spring.datasource.username=user
    spring.datasource.password=password
  logback.xml: |
    <appender name="FILE" class="ch.qos.logback.core.FileAppender">
      <file>${LOG_FILE}</file>
      <encoder>
        <pattern>%d{HH:mm:ss.SSS} [%thread] %-5level %logger{3} - %msg%n</pattern>
      </encoder>
    </appender>
```
In this example, a ConfigMap named "phoenix-config" is created with two data keys: "application.properties" and "logback.xml". The values for these keys are stored as multi-line strings using the pipe character "|" to indicate the start and end of the multi-line string. The "application.properties" key stores application configuration settings, and the "logback.xml" key stores the application's logging configuration.
