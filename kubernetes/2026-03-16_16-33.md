 # Kubernetes Concept
Kubernetes Secret is an object used to store and manage sensitive information such as passwords, OAuth tokens, and SSL certificates.

# Explanation
Secrets in Kubernetes are encrypted at rest and decrypted on-the-fly when needed. They can be mounted as environment variables, command-line arguments, or as files in a container. This helps to keep sensitive information out of your container image and configuration files.

Best Practices:
- Create a separate namespace for storing secrets to enforce access control.
- Use Kubernetes Role-Based Access Control (RBAC) to restrict access to secrets.
- Rotate secrets frequently to maintain security.

# YAML Example
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: my-database-password
  namespace: my-namespace
type: Opaque
data:
  password: cGFzc3dvcmQ=
```
In this example, a secret named `my-database-password` is created in the `my-namespace` namespace. The secret contains a single data item named `password` which is encoded in base64. The decoded value of `password` is "password123" in plain text. This secret can then be mounted as an environment variable or a file in a container to provide secure access to the database.
