 # Kubernetes Concept
This is an example of a Kubernetes DaemonSet for running a Chaos Agent called Chaos Mesh with the Phoenix project.

# Explanation
A DaemonSet ensures that all or a specific number of nodes in a cluster host the specified pod(s) and restarts them if they go down. In this scenario, we will deploy Chaos Mesh, an open-source Chaos Engineering platform, as a DaemonSet. Chaos Engineering is the discipline of intentionally injecting failure into a system to ensure it can withstand real-world conditions. The Phoenix project is a Chaos Engineering framework that enables the execution of chaos experiments.

# Best Practices
- Ensure proper label selectors are set in the YAML to target the appropriate nodes.
- Regularly update the Chaos Mesh DaemonSet to keep up with the latest releases and security patches.
- Monitor the Chaos Mesh metrics to identify and address any performance issues.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: chaos-mesh-phoenix
  labels:
    app: chaos-mesh
    seed: 1774263678
spec:
  selector:
    matchLabels:
      app: chaos-mesh
  template:
    metadata:
      labels:
        app: chaos-mesh
        seed: 1774263678
    spec:
      containers:
      - name: chaos-mesh
        image: chaosmesh/chaos-mesh:0.11.3
        env:
          - name: CHAOS_MESH_AGENT_LOG_LEVEL
            value: INFO
          - name: CHAOS_MESH_AGENT_LISTEN_ADDRESS
            value: "127.0.0.1:4747"
          - name: CHAOS_MESH_AGENT_WATCHER_POD_SELECTOR
            value: app=chaos-mesh
        ports:
        - containerPort: 4747
          name: chaos-mesh
          protocol: TCP
        livenessProbe:
          exec:
            command: ["/usr/local/bin/chaos-mesh", "agent", "--version"]
          intervalSeconds: 5
        readinessProbe:
          exec:
            command: ["/usr/local/bin/chaos-mesh", "agent", "--version"]
          initialDelaySeconds: 15
          intervalSeconds: 5
```
