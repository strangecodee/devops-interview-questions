 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage replicas of a containerized application.

# Explanation
Deployments maintain a specified number of replicas of a desired Pod and can perform rolling updates or rollbacks. Each Deployment has a controller that continuously reconciles the actual state of the application with the desired state, making it an important part of the Kubernetes infrastructure for managing stateless applications.

# Best Practices
- Use labels and selectors for efficient management of Deployments.
- Implement a rolling update strategy to minimize downtime and ensure high availability.
- Configure readiness and liveness probes to monitor the health of your application.

# YAML Example - AWS Elastic Container Service for Kubernetes (EKS)
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-deployment
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-container-image:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 30
          periodSeconds: 10
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
          initialDelaySeconds: 30
          periodSeconds: 5
securityContext:
  privilegeEscalation: false
  initContainers:
  - name: install-certs
    image: my-certs-repo:latest
    volumeMounts:
    - name: certs-volume
      mountPath: /etc/certs
    command: ['/bin/sh', '-c', 'echo "Install certs"']
  volumes:
  - name: certs-volume
    secret:
      secretName: my-certs-secret
```
This example demonstrates a Deployment with 3 replicas, container image `my-container-image:latest`, and the use of readiness and liveness probes. The Deployment also includes a rolling update strategy and a certificate volume using a Kubernetes Secret. The securityContext is set to disable privilege escalation. The `initContainers` section is used to install certificates before the application starts.
