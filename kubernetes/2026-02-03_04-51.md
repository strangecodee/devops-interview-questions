 # Kubernetes Concept
Kubernetes DaemonSet is a deployment type that ensures a specified number of replicas for each node in your cluster. It is commonly used for running system daemons or background processes that require access to the node's resources.

# Explanation
DaemonSets maintain a consistent state across a fleet of nodes by managing and replacing the specified number of instances. This is particularly useful for deploying system components such as networking or logging daemons, which should ideally be present on every node. DaemonSets ensure that the desired state is maintained, even if nodes are added or removed from the cluster.

# Best Practices
- Use DaemonSets for nodes and system components that need access to the node's resources.
- Use rolling updates with a small update strategy to minimize downtime.
- Ensure that containers in a DaemonSet have appropriate security contexts and run as non-root users.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: nebula-logging-daemonset
spec:
  selector:
    matchLabels:
      app: nebula-logging
      tier: node
  template:
    metadata:
      labels:
        app: nebula-logging
        tier: node
    spec:
      containers:
      - name: nebula-logging
        image: nebula/logging:latest
        securityContext:
          runAsUser: 1001
          allowPrivilegeEscalation: false
        ports:
        - containerPort: 514
          protocol: UDP
          name: udp
        livenessProbe:
          exec:
            command: ["/usr/local/bin/check-log-status.sh"]
            intervalSeconds: 30
        readinessProbe:
          exec:
            command: ["/usr/local/bin/check-log-readiness.sh"]
            intervalSeconds: 15
```
This DaemonSet ensures that the specified `nebula-logging` container is running on each node with the specified security contexts and probes. The container uses an UDP port for logging and includes liveness and readiness probes for monitoring its status.
