 # Kubernetes Concept
Kubernetes DaemonSet ensures that a specified number of replicas for a Pod are running on all nodes in the cluster.

# Explanation
DaemonSets maintain a consistent daemon process on each node in the cluster. This is useful for applications such as logging agents or monitoring tools that should run as a single instance per node. The DaemonSet controller guarantees that the desired number of replicas are running, and automatically replaces any failed or missing replicas.

# Best Practices
- Use labels to target specific nodes or node labels when creating DaemonSets.
- Run essential services as Daemons for high availability and consistency.
- Use readiness and liveness probes to ensure the Daemon is healthy and ready to accept traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: log-daemon
  labels:
    app: log
spec:
  selector:
    matchLabels:
      app: log
  template:
    metadata:
      labels:
        app: log
    spec:
      containers:
      - name: log-container
        image: log-image:latest
        ports:
        - containerPort: 514
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "tail -n 100 /var/log/app.log && exit 0"]
          initialDelaySeconds: 5
          periodSeconds: 5
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "tail -n 10 /var/log/app.log || exit 1"]
          initialDelaySeconds: 15
          periodSeconds: 10
```
This DaemonSet deploys a logging agent as a daemon process on each node, ensuring consistent logging across the cluster. Labels are used to target the daemon, and readiness and liveness probes are set up to ensure the agent is ready to accept traffic and remains healthy.
