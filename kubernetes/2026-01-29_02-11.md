 # Kubernetes Concept
Kubernetes Deployment is a declaration of desired state for a set of containers. It updates the containers when new images are available or when configuration changes are made.

# Explanation
A Kubernetes Deployment creates and manages replicas of a container image. It automatically rolls out updates and manages the rollbacks in case of failures. The Deployment controller ensures the desired state of the application by continuously creating new replicas and removing old ones.

# Best Practices
- Use rolling updates for minimal downtime.
- Utilize readiness and liveness probes to ensure container health.
- Use Helm charts or Kustomize for managing complex applications.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-registry/my-image:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```
This YAML file defines a Deployment named `my-app` with 3 replicas. It selects the containers with the label `app: my-app`. The container runs the image `my-registry/my-image:latest` and listens on port 80. Both a liveness and readiness probe are configured to check the `/healthz` and `/ready` endpoints respectively.
