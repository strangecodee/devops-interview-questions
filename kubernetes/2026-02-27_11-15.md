 # Kubernetes Concept: Deployment
Creates and manages containerized applications by maintaining a specified number of replicas and their availability.

# Explanation
Deployments manage the lifecycle of a set of Pods, creating new replicas with updated container images when specified, and ensuring a desired number of replicas are available at all times. They provide a declarative update mechanism for applications in a cluster.

# Best Practices
- Use rolling updates to minimize downtime when updating containers.
- Set up a strategy for handling updates to minimize disruption to users.
- Use labels for selective deployment management and scaling.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-nginx-deployment
  labels:
    app: nginx
spec:
  selector:
    matchLabels:
      app: nginx
  replicas: 3
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80
          name: http
        readinessProbe:
          tcpSocket:
            port: 80
          probeTimeoutSeconds: 5
```
This Deployment creates a new Nginx application with three replicas, updates them when a new image is available, and ensures that at least one replica is always available. The readinessProbe is used to determine when a container is ready to accept traffic.
