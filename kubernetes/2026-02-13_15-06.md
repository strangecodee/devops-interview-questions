 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications by creating, updating, and scaling replicas.

# Explanation
A Deployment creates and manages a set of replicas of a containerized application, ensuring availability and scaling. When a new version of the application is ready, a new Deployment can be created with that version, and Kubernetes gradually rolls out the new version to the cluster's nodes, ensuring a smooth transition without downtime.

# Best Practices
- Use rolling updates for new versions to maintain availability and allow for rollbacks if needed.
- Use readiness and liveness probes to ensure the container is running and healthy.
- Use labels to select and manage pods based on specific criteria.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 1
      preRollOutDelaySeconds: 30
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-app:1.0.0
        ports:
        - containerPort: 80
          name: http
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```
This Deployment manages three replicas of `my-app`, uses rolling updates for smooth version updates, and includes readiness and liveness probes to ensure the container is healthy and ready to serve.
