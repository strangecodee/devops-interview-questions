 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
DaemonSets are useful for deploying system services that should be running on every node in the cluster, such as monitoring agents or logging daemons. By managing the availability and health of these critical components, DaemonSets contribute to the overall reliability and observability of the Kubernetes infrastructure.

# Best Practices
- Use a well-defined and tested container image for your DaemonSet.
- Set the number of replicas to the desired number of nodes in your cluster.
- Utilize `node-selector` and `tolerations` to ensure that the DaemonSet only runs on specific nodes, as needed.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-monitoring-daemon
  labels:
    app: my-monitoring
spec:
  selector:
    matchLabels:
      app: my-monitoring
  template:
    metadata:
      labels:
        app: my-monitoring
    spec:
      containers:
      - name: my-monitoring-container
        image: my-monitoring-image:latest
        ports:
        - containerPort: 12345
        livenessProbe:
          exec:
            command: ["/healthcheck.sh"]
          intervalSeconds: 30
      nodeSelector:
        beta.kubernetes.io/os: linux
      tolerations:
      - key: "node-role.kubernetes.io/master"
        operator: Exists
        effect: "NoSchedule"
```
In this example, a DaemonSet named `my-monitoring-daemon` is configured with a container named `my-monitoring-container` that runs the image `my-monitoring-image:latest`. The DaemonSet ensures that one replica of the container is running on every node labeled with `os: linux`. The container is configured to listen on port `12345` and includes a liveness probe to check the health of the container. Additionally, the DaemonSet is set to not schedule pods on the master node due to the presence of a `toleration` with the key `node-role.kubernetes.io/master`.
