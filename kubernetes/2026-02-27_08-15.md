 # Kubernetes Deployment for a Node.js Application on AWS EKS

# Explanation
This Kubernetes YAML example demonstrates a `Deployment` configuration for a Node.js application running on Amazon Elastic Kubernetes Service (EKS). The configuration includes a `Container` definition for the application, `replicas`, `selector`, and `schedule` to ensure high availability and self-healing capabilities.

# Best Practices
1. Use `Labels` for the Deployment and `Selectors` for the Pods to maintain easy management and rolling updates.
2. Set up `Health Checks` using `Liveness Probes` and `Readiness Probes` to monitor application status and ensure a healthy pod in the cluster.
3. Configure `Rollouts and Rollbacks` to manage application updates and revert if needed.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nodejs-deployment
  labels:
    app: nodejs
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nodejs
  template:
    metadata:
      labels:
        app: nodejs
    spec:
      containers:
      - name: nodejs
        image: your-nodejs-image:latest
        ports:
        - containerPort: 8080
        env:
        - name: NODE_ENV
          value: production
        - name: PORT
          value: "8080"
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 15
        readinessProbes:
        - httpGet:
            path: /readiness
            port: 8080
            initialDelaySeconds: 15
            periodSeconds: 5
---
apiVersion: v1
kind: Service
metadata:
  name: nodejs-service
spec:
  selector:
    app: nodejs
  ports:
  - name: http
    port: 80
    targetPort: 8080
  type: ClusterIP
```
This YAML file sets up a `Deployment` named `nodejs-deployment`, which runs three replicas of a container based on a Node.js image. The container listens on port 8080 and uses a production environment. The `LivenessProbe` and `ReadinessProbe` are set up to monitor the application's health and availability. A corresponding `Service` is created to expose the application on port 80.
