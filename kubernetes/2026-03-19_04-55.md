 # Kubernetes Concept
Kubernetes DaemonSet is a way to ensure a copy of a pod runs on all nodes in a cluster.

# Explanation
A DaemonSet ensures that a specified number of replicas for a pod are running on each node in the cluster. This is useful for deploying system services that should be running on every node, such as a logging agent or a monitoring agent. DaemonSets automatically replace any dead pods and maintain the desired state of the cluster.

# Best Practices
- Use labels to select nodes for DaemonSets, and use the `nodeSelector` field to only place pods on nodes that meet certain criteria.
- Use health checks and readiness probes to ensure that DaemonSets are running correctly and can be rolled out and rolled back without affecting the application.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-agent
  labels:
    app: logging-agent
spec:
  selector:
    matchLabels:
      app: logging-agent
  template:
    metadata:
      labels:
        app: logging-agent
    spec:
      containers:
      - name: logging-agent
        image: logging-agent:latest
        ports:
        - containerPort: 514
          name: udp
          protocol: UDP
        - containerPort: 515
          name: tcp
          protocol: TCP
        livenessProbe:
          exec:
            command: ["/usr/local/bin/check-logging-agent.sh"]
          intervalSeconds: 30
        readinessProbe:
          exec:
            command: ["/usr/local/bin/check-logging-agent-ready.sh"]
            intervalSeconds: 15
```
This YAML defines a DaemonSet named `logging-agent` with two containers, one for UDP and one for TCP. It includes liveness and readiness probes to ensure the DaemonSet is running correctly. The `matchLabels` selector is used to ensure that the DaemonSet is placed on nodes with the label `app: logging-agent`.
