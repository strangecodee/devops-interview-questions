# Kubernetes Deployment
Create and manage containerized applications and their replicas in a cluster.

# Explanation
Deployments in Kubernetes manage the lifecycle of replicas of a container, ensuring availability and scaling of applications. They provide declarative updates and rollbacks, enabling easy rollouts and rollbacks of new versions.

# Best Practices
- Use helpful labels for easier management and selection of deployments.
- Implement rolling updates for minimal downtime and zero data loss.
- Implement automated rollbacks to restore applications to a previous working state.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-webapp
  labels:
    app: nebula
    version: v1
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
      version: v1
  template:
    metadata:
      labels:
        app: nebula
        version: v1
    spec:
      containers:
      - name: nebula-container
        image: nebula/webapp:v1
        ports:
        - containerPort: 80
        readinessProbe:
          probes:
          - exec:
              command: ["/app/healthcheck.sh"]
              intervalSeconds: 5
        livenessProbe:
          probes:
          - exec:
              command: ["/app/liveness.sh"]
              intervalSeconds: 30
```
This YAML example represents a Kubernetes Deployment named `nebula-webapp` with three replicas. It specifies a container image `nebula/webapp:v1`, and includes readiness and liveness probes to check the container's health and readiness. The `labels` are used for easier management and selection of the Deployment.
