 # Kubernetes Deployment
This Kubernetes resource is used for deploying and managing containerized applications at scale.

# Explanation
Deployments manage the lifecycle of a set of replica Pods, creating new replicas with updated container images when updates are pushed, and removing old replicas when they are no longer needed. This ensures that the desired state of the application is maintained.

# Best Practices
- Use labels for easy identification and management of your deployments.
- Use rolling updates to minimize downtime and ensure zero-downtime deployments.
- Use health checks to monitor the readiness and liveness of your applications.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
          protocol: TCP
        probes:
        - name: liveness
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 5
        - name: readiness
          httpGet:
            path: /ready
            port: 80
            initialDelaySeconds: 5
            periodSeconds: 5
```
This YAML file creates a deployment named `my-app` with three replicas, each labeled `app: my-app`. The container image for the deployment is `my-registry/my-app:latest`, and it exposes a single port (80) for both the liveness and readiness probes. The liveness probe checks the `/healthz` endpoint and the readiness probe checks the `/ready` endpoint every 5 seconds.
