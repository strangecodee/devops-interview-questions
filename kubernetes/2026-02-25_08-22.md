 # Kubernetes Concept
This is an example of a Kubernetes Service, which provides a stable IP address and DNS name for a set of Pods, enabling service discovery and load balancing.

# Explanation
A Kubernetes Service creates an abstract layer over a set of Pods, allowing access to them using a single DNS name or IP address. Services use selectors to identify which Pods to target and load balance traffic across them based on their health and readiness status. This provides a stable endpoint for clients to interact with, ensuring service continuity even as individual Pods are created, updated, or deleted.

# Best Practices
- Use `ClusterIP` type for services that should only be accessible within the cluster.
- Use `NodePort` or `LoadBalancer` for services meant to be accessible from outside the cluster.
- Set up health checks using the `livenessProbe` and `readinessProbe` to ensure the Service only routes traffic to healthy Pods.

# YAML Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-web-service
spec:
  selector:
    app: my-app
  type: ClusterIP
  ports:
  - name: http
    port: 80
    targetPort: 8080
  - name: https
    port: 443
    targetPort: 8443
  # Set up health checks
  # livenessProbe: ...
  # readinessProbe: ...
```
