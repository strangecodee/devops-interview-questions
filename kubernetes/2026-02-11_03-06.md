 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications by creating and updating replicas, ensuring high availability and scaling.

# Explanation
Deployments manage the lifecycle of a set of replica Pods, creating new replicas with updated container images when updates are pushed, and scaling the number of replicas based on demand. This ensures that your application is always running with the latest image and can handle increased traffic.

# Best Practices
- Use rolling updates to minimize downtime and ensure zero-downtime deployments.
- Set up a health check using liveness and readiness probes to ensure the container is running and ready to accept traffic.
- Use labels for easier management and selectivity.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-app
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: myregistry/phoenix:latest
        ports:
        - containerPort: 8080
        livenessProbe:
          httpGet:
            path: /health
            port: 8080
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
```
This Kubernetes YAML defines a Deployment named `phoenix-app` with 3 replicas running a container using the `myregistry/phoenix:latest` image. It also includes liveness and readiness probes to ensure the container is healthy and ready for traffic.
