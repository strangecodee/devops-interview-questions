 # Kubernetes Concept
Kubernetes Secret is an object used to store and manage sensitive information such as passwords, OAuth tokens, and SSL certificates.

# Explanation
Secrets in Kubernetes are encrypted at rest and decrypted on the container runtime when a container pulls an image and starts. They can be mounted as environment variables, command-line arguments, or as files in a container. This provides a secure way to store and manage sensitive information without hard-coding it in your applications or storing it in plain text files.

# Best Practices
- Create a separate namespace for storing secrets
- Use Kubernetes RBAC to control access to secrets
- Use long, random, and complex passwords and tokens for secrets
- Rotate secrets regularly

# YAML Example
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: atlas-db-password
  namespace: kube-security
type: Opaque
data:
  password: cGFzc3dvcmQ= # Base64 encoded "password123"
```
In this example, a new secret named `atlas-db-password` is created in the `kube-security` namespace with the type `Opaque`. The password is stored encrypted and can be decrypted and accessed as an environment variable or a file in a container. The password is base64 encoded and decoded in the example to show the actual value, but in practice, it should be generated randomly and securely.
