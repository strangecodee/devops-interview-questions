 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications. It ensures that a specified number of replicas of a container image are running and available.

# Explanation
A Kubernetes Deployment creates and manages the lifecycle of a set of replica Pods. It ensures that a specified number of replicas are running at any given time and replaces unhealthy or crashed Pods with new ones. Additionally, it can roll out updates to container images by creating new replicas with the latest image and gradually rolling traffic to them.

# Best Practices
- Use labels and selectors to manage and identify replicas for easy scaling and rolling updates.
- Set up resource limits and requests in the container definition to ensure efficient resource usage.
- Use readiness and liveness probes to determine the health of your containers and trigger restarts or replacement of unhealthy replicas.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse-deployment
  labels:
    app: eclipse
spec:
  replicas: 3
  selector:
    matchLabels:
      app: eclipse
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
      - name: eclipse
        image: eclipse:latest
        ports:
        - containerPort: 8443
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8001
        readinessProbe:
          httpGet:
            path: /
            port: 8443
      resources:
        limits:
          cpu: "1"
          memory: "512Mi"
        requests:
          cpu: "500m"
          memory: "256Mi"
```
This YAML defines a Kubernetes Deployment that manages three replicas of the Eclipse container. The container is labeled as "eclipse" and listens on ports 8001 (liveness probe) and 8443 (readiness probe and application port). The container has resource limits and requests set for CPU and memory.
