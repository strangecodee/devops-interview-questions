 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications. It ensures availability, scalability, and updates.

# Explanation
A Kubernetes Deployment manages the lifecycle of a set of replica Pods, creating new ones when necessary and scaling or rolling out updates as needed. It provides a declarative interface to define and manage the desired state of these applications.

# Best Practices
- Use `replicas` to define the number of desired instances of a Pod.
- Use `strategy.type` to define the update strategy (blue-green or rolling updates).
- Use `selector` to select the Pods to update, and `template` to define the desired Pod configuration.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: my-app
          image: my-registry/my-app:latest
          ports:
            - containerPort: 80
          livenessProbe:
            httpGet:
              path: /healthz
              port: 80
          readinessProbe:
            httpGet:
              path: /ready
              port: 80
status: {}
```
This example defines a Deployment named `my-app` with 3 replicas, using an image from a container registry and defining a liveness and readiness probe.
