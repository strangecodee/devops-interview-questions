 # Kubernetes Concept
Deployment is a Kubernetes object used for updating and rolling back containers in a replicas-managed environment. It ensures that the desired number of replicas are running and provides a declarative way to update the container image.

# Explanation
A Kubernetes Deployment maintains a specified number of replicas of a desired Pod. When a new deployment is created or updated, Kubernetes creates a new set of replicas from the new Pod template. The old replicas are not terminated immediately to ensure a zero-downtime update. Instead, the new replicas are created and drained old ones when they have finished serving all their requests.

# Best Practices
- Use Rolling Update strategy to ensure zero-downtime deployments.
- Set up a liveness probe to monitor the health of containers.
- Use a readiness probe to ensure that containers are ready to receive traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: atlas-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: atlas
  template:
    metadata:
      labels:
        app: atlas
    spec:
      containers:
      - name: atlas
        image: myregistry/atlas:v1.0.0
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
```
This example demonstrates a simple Deployment for an application named "atlas". The desired number of replicas is set to 3. The containers in the template are labeled with "app: atlas" and run the image "myregistry/atlas:v1.0.0". The containers listen on port 80 and have both liveness and readiness probes configured. The liveness probe checks the health of the container by sending an HTTP GET request to the "/healthz" endpoint on port 80, while the readiness probe checks the container's readiness by sending an HTTP GET request to the "/ready" endpoint.
