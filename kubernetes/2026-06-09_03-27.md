 # Kubernetes Concept
This is an example of a Deployment and a Service for creating and managing a monitoring daemon set called "Prometheus" in a Kubernetes cluster.

# Explanation
A Deployment in Kubernetes manages the lifecycle of a set of replicas, while a Service provides a stable IP address and DNS name for accessing a set of pods. In this case, we will create a Deployment for running Prometheus, a popular monitoring system, and a Service to access the created pods.

# Best Practices
- Run Prometheus as a DaemonSet to ensure monitoring is available on all nodes in the cluster.
- Use a dedicated namespace for monitoring applications.
- Monitor the state of the Prometheus pods using the Kubernetes dashboard or external monitoring tools.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: prometheus
  namespace: monitoring
  labels:
    app: prometheus
spec:
  replicas: 3
  selector:
    matchLabels:
      app: prometheus
  template:
    metadata:
      labels:
        app: prometheus
    spec:
      containers:
      - name: prometheus
        image: prom/prometheus:v2.32.0
        ports:
        - containerPort: 9090
          name: prom-http
        volumeMounts:
        - name: prometheus-config
          mountPath: /etc/prometheus/
          subPath: prometheus.yml
      volumes:
      - name: prometheus-config
        configMap:
          name: prometheus-config
          items:
          - key: prometheus.yml
            path: prometheus.yml
---
apiVersion: v1
kind: Service
metadata:
  name: prometheus
  namespace: monitoring
spec:
  selector:
    app: prometheus
  ports:
  - name: prom-http
    port: 9091
    targetPort: 9090
  type: ClusterIP
```
This example creates a Deployment with three replicas of the Prometheus container image and a Service to access the Prometheus pods using the stable IP address provided by the Service. The Prometheus configuration file is mounted as a configMap and is referenced in the container's volumeMounts.
