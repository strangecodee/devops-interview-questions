 # Kubernetes Concept
Deployment is a Kubernetes object used for updating and rolling back applications. It creates and manages replicas of a container or replica set, ensuring high availability and scalability.

# Explanation
The Deployment resource in Kubernetes automates application updates and provides a way to roll back to previous versions if needed. It keeps a specified number of replicas running at any given time. When a new version is deployed, Kubernetes updates the replicas gradually to minimize downtime. The old replicas are terminated only after all new replicas are healthy.

# Best Practices
- Use Rolling Updates to minimize downtime and ensure smooth transitions between versions.
- Use Scaling Strategies to manage the number of replicas based on load.
- Implement Health Checks to ensure that only healthy replicas are serving traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: forge
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: forge
        image: forge:latest
        ports:
        - containerPort: 80
          name: http
        readinessProbe:
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 5
```
This YAML example defines a Deployment called 'forge-deployment' with three replicas. It uses a container image called 'forge:latest' and sets up a readiness probe to ensure that only healthy replicas serve traffic. The container listens on port 80 for HTTP requests.
