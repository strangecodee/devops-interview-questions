 # Kubernetes Concept: Deployment with AWS Elastic Container Registry (ECR) and Ingress

This Kubernetes concept demonstrates a Deployment managing a container image stored in Amazon Elastic Container Registry (ECR), along with an Ingress for external access.

# Explanation

In this example, we configure a simple Kubernetes Deployment using an image from an Amazon Elastic Container Registry (ECR). The Deployment creates and manages the desired number of replicas, ensuring they are running and healthy. An Ingress controller is utilized to provide external access to the application by exposing the Kubernetes Service.

# Best Practices
- Practice 1: Use a GitOps workflow, such as GitOps Tools (FluxCD, ArgoCD, etc.), to manage your Kubernetes cluster and maintain a declarative configuration.
- Practice 2: Implement Role-Based Access Control (RBAC) to secure your cluster and ensure access control based on required roles.
- Practice 3: Regularly review and update images in your ECR repository to ensure they are secure and up-to-date.

# YAML Example

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: quantum-deployment
spec:
  selector:
    matchLabels:
      app: quantum
  replicas: 3
  template:
    metadata:
      labels:
        app: quantum
    spec:
      containers:
      - name: quantum
        image: 1773035548.dkr.ecr.region.amazonaws.com/quantum:latest
        ports:
        - containerPort: 80
---
apiVersion: networking.k8s.io/v1beta1
kind: Ingress
metadata:
  name: quantum-ingress
  annotations:
    kubernetes.io/ingress.global-static-ip-name: quantum-ip
spec:
  rules:
  - host: quantum.example.com
    http:
      paths:
      - path: /
        backend:
          serviceName: quantum-service
          servicePort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: quantum-service
spec:
  selector:
    app: quantum
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```

This YAML example includes a Kubernetes Deployment managing a container from an ECR repository, an Ingress resource for external access, and a Service to manage the internal communication between the replicas.
