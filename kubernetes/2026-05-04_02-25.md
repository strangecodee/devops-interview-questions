# Kubernetes Concept
Kubernetes DaemonSet is a way to ensure a copy of a pod runs on all nodes in a cluster.

# Explanation
A DaemonSet ensures that a specified number of replicas for a pod are running on all nodes in the cluster. This is useful for running system daemons, such as container network plugins or monitoring agents, which need to be available on every node. The DaemonSet controller continuously creates and manages the desired number of replicas on each node.

# Best Practices
- Use DaemonSets for system daemons or background services that need to be running on every node.
- Configure rolling updates with the maximumSurge and maximumUnavailable parameters to manage the number of new and old pods during updates.
- Use labels to select nodes and to differentiate between pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: atlas-daemonset
spec:
  selector:
    matchLabels:
      app: atlas
  template:
    metadata:
      labels:
        app: atlas
    spec:
      containers:
      - name: atlas
        image: atlas:latest
        ports:
        - containerPort: 3000
        securityContext:
          privileged: true
          readOnlyRootFilesystem: false
          allowPrivilegeEscalation: true
          runAsUser: 0
---
```
This DaemonSet example runs a container named `atlas` with the specified image, port, and security context. The privileged setting is used for this example, but it is not recommended for production use due to potential security risks. The security context can be adjusted based on the specific needs of the application.
