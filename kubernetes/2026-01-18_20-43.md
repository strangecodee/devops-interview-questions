 # Kubernetes Concept: Deploying a Node.js Application on AWS EKS using a DaemonSet

This concept outlines the process of deploying a Node.js application on Amazon Elastic Kubernetes Service (EKS) using a DaemonSet. DaemonSets ensure that a specified number of replicas of a pod run on each node in the cluster.

# Explanation
AWS EKS is a managed service that makes it easy to run Kubernetes clusters on AWS without needing to manage the underlying infrastructure. In this example, we'll use a DaemonSet to ensure that a specific number of instances of our Node.js application are running on each node in the cluster.

# Best Practices
- Define a `limitRange` to control the resource usage for your DaemonSet.
- Use `nodeSelector` to specify the nodes where your DaemonSet should run.
- Use `readinessProbes` and `livenessProbes` to ensure your application is running and ready to receive traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: nodejs-forge
spec:
  selector:
    matchLabels:
      app: nodejs-forge
  template:
    metadata:
      labels:
        app: nodejs-forge
    spec:
      containers:
      - name: nodejs-forge
        image: your-docker-image:latest
        ports:
        - containerPort: 80
        resources:
          limits:
            cpu: "500m"
            memory: "512Mi"
          requests:
            cpu: "250m"
            memory: "256Mi"
          limits.cpu: "1"
          limits.memory: "1Gi"
      terminationGracePeriodSeconds: 30
      imagePullSecrets:
      - name: your-image-secret
      nodeSelector:
        beta.kubernetes.io/os: linux
      tolerations:
      - key: Node.kubernetes.io/node-role.kubernetes.io/master
        effect: NoExecute
        operator: Exists
      - key: Node.kubernetes.io/node-role.kubernetes.io/worker
        effect: PreferNoSchedule
        operator: Exists
      - key: kubernetes.io/hostname
        effect: NoSchedule
        operator: Exists
      - key: beta.kubernetes.io/osd.label.kops.k8s.io/zone
        effect: Prefer scheduling on nodes with matching labels
        operator: In
        value: "your-zone"
      - key: beta.kubernetes.io/osd.label.kops.k8s.io/instance-type
        effect: Prefer scheduling on nodes with matching labels
        operator: In
        value: "your-instance-type"
      - key: kubernetes.io/ephemeral
        effect: PreferNoSchedule
      - key: kubernetes.io/dedicated
        effect: NoSchedule
      - key: beta.kubernetes.io/osd.type
        effect: Prefer scheduling on nodes with matching labels
        operator: In
        value: "gp2"
      - key: kubernetes.io/metadata.kops.k8s.io/instance-id
        effect: NoSchedule
      - key: kubernetes.io/metadata.kops.k8s.io/spot-instance
        effect: NoSchedule
      - key: kubernetes.io/metadata.kops.k8s.io/launch-type
        effect: PreferNoSchedule
        operator: NotIn
        value: "spot"
      - key: beta.kubernetes.io/osd.label.aws.com/instance-type
        effect: Prefer scheduling on nodes with matching labels
        operator: In
        value: "your-instance-type"
      - key: beta.kubernetes.io/osd.label.aws.com/availability-zone
        effect: Prefer scheduling on nodes with matching labels
        operator: In
        value: "your-availability-zone"
      - key: beta.kubernetes.io/osd.label.kops.k8s.io/provider
        effect: Prefer scheduling on nodes with matching labels
        operator: In
        value: "aws"
      - key: beta.kubernetes.io/osd.label.kops.k8s.io/cloud-provider
        effect: Prefer scheduling on nodes with matching labels
        operator: In
        value: "aws"
      - key: beta.kubernetes.io/osd.label.kops.k8s.io/region
        effect: Prefer scheduling on nodes with matching labels
        operator: In
        value: "your-region"
      restartPolicy: OnFailure
      terminationGracePeriodSeconds: 300
      volumes:
      - name: app-volume
        awsElasticBlockStore:
          accessModes: [ "ReadWriteOnce" ]
          fsType: ext4
          volumeID: your-volume-id
      terminationGracePeriodSeconds: 300
      affinity:
        podAntiAffinity:
        requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchExpressions:
            - key: app
              operator: In
              values:
              - nodejs-forge
          topologyKey: kubernetes.io/host
        podAffinity:
        requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchExpressions:
            - key: app
              operator: In
              values:
              - nodejs-forge
          topologyKey: kubernetes.io/hostname
      containers:
      - name: nodejs-forge
        image: your-docker-image:latest
        ports:
        - containerPort: 80
        env:
        - name: NODE_ENV
          value: production
        - name: TZ
          value: "America/Los_Angeles"
        readinessProbes:
        - exec:
            command: ["/usr/bin/npm", "test"]
            intervalSeconds: 5
            failureThreshold: 5
        livenessProbes:
        - exec:
            command: ["/usr/bin/npm", "--version"]
            periodSeconds: 10
            failureThreshold: 3
        volumes:
        - name: app-volume
          mountPath: /var/www/html
      imagePullSecrets:
      - name: your-image-secret
      terminationGracePeriodSeconds: 30
```
Replace `your-docker-image`, `your-image-secret`, `your-volume-id`, `your-zone`, `your-instance-type`, `your-availability-zone`, `your-region`, and `your-instance-id` with your actual values. This YAML configures a DaemonSet to deploy a Node.js application on AWS EKS and sets up probes, labels, and resource limits.
