 # Kubernetes Concept
This example demonstrates a Kubernetes Service and Deployment for a simple web application using the Phoenix web framework, which will be load-balanced using the Kubernetes Service.

# Explanation
A Kubernetes Service provides a stable IP address and DNS name for a set of pods, enabling network services to connect to the application running inside the cluster. In this configuration, a Deployment is used to manage the rolling update and scaling of the Phoenix application's pods, while the Service handles load balancing and routing traffic to the available pods.

# Best Practices
- Use labels to identify the application and environment for easier management.
- Set up a `livenessProbe` and `readinessProbe` for the application to ensure proper functioning and availability.
- Use `selector` in Deployment and Service configurations for matching the labels.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
  labels:
    app: phoenix
    environment: production
spec:
  selector:
    matchLabels:
      app: phoenix
      environment: production
  replicas: 3
  template:
    metadata:
      labels:
        app: phoenix
        environment: production
    spec:
      containers:
      - name: phoenix
        image: phx:1.4.21
        ports:
        - containerPort: 4000
        livenessProbe:
          httpGet:
            path: /admin/health_check
            port: 4000
        readinessProbe:
          httpGet:
            path: /
            port: 4000
          initialDelaySeconds: 5
          periodSeconds: 10
---
apiVersion: v1
kind: Service
metadata:
  name: phoenix-service
spec:
  selector:
    app: phoenix
    environment: production
  ports:
  - name: http
    port: 80
    targetPort: 4000
  type: LoadBalancer
```
