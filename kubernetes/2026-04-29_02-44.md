# Kubernetes Concept
Deployment is a Kubernetes resource for describing and managing a set of replicated pods. It ensures availability of the application by creating new replicas if any pod goes down.

# Explanation
A Deployment creates a desired state for a set of replicas, specifying the number of replicas and the desired container images. Kubernetes continuously attempts to maintain the desired state by creating new replicas if old ones are terminated or fail, and removing unnecessary replicas as they are replaced. This is known as a rolling update.

# Best Practices
- Use `rolling-update` strategy to minimize downtime and ensure a smooth transition between versions.
- Use `readinessProbes` and `livenessProbes` to ensure containers are running correctly before serving traffic and to automatically restart containers that fail.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-app:latest
        ports:
        - containerPort: 80
          protocol: TCP
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 30
          periodSeconds: 10
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
          initialDelaySeconds: 30
          periodSeconds: 10
```
