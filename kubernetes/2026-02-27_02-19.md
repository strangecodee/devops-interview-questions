 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
DaemonSets are used to deploy and manage background services, such as monitoring and logging agents, across a Kubernetes cluster. By defining a DaemonSet, you ensure that an instance of the pod is running on each node in the cluster. This can help improve consistency and reliability, as well as reduce the overhead of manually deploying and managing these services.

# Best Practices
- Use labels to target specific nodes or node selectors to ensure that the DaemonSet is only deployed to the appropriate nodes.
- Use rolling updates to minimize downtime and ensure that new versions of the pod are gradually rolled out across the cluster.
- Use health checks and liveness probes to monitor the health of the DaemonSet pods and ensure that they are correctly serving their intended purpose.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemonset
  template:
    metadata:
      labels:
        app: my-daemonset
    spec:
      containers:
      - name: my-daemonset-container
        image: my-container-image:latest
        ports:
        - containerPort: 80
        readinessProbes:
        - probe:
            exec:
              command: ["/usr/local/bin/check-readiness.sh"]
            intervalSeconds: 5
            timeoutSeconds: 3
        livenessProbes:
        - probe:
            exec:
              command: ["/usr/local/bin/check-liveness.sh"]
            intervalSeconds: 30
            timeoutSeconds: 10
```
In this YAML example, we define a DaemonSet named "my-daemonset" with a container named "my-daemonset-container" running the image "my-container-image:latest". The DaemonSet uses labels to select nodes and the container runs on port 80. We also define readiness and liveness probes to check the health of the pods.
