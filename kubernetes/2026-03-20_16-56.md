 # Kubernetes Concept
This is an example of a Kubernetes DaemonSet for running chaos engineering tests using the Chaos Toolkit and Chaos Mesh in a Kubernetes cluster.

# Explanation
A DaemonSet ensures that a copy of the specified Pod template is running on all nodes in the cluster. In this case, we will use it to run chaos engineering tests using the Chaos Toolkit and Chaos Mesh on every node. By performing chaos engineering tests regularly, we can proactively identify and mitigate potential failures in our system.

# Best Practices
- Use resource limits and requests to ensure that the chaos engineering tests do not consume excessive resources on each node.
- Implement chaos engineering tests in a controlled and measured manner to minimize the impact on production workloads.
- Regularly review and update the chaos engineering tests to ensure they remain relevant and effective.

# YAML Example

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: chaos-daemonset
spec:
  selector:
    matchLabels:
      app: chaos
  template:
    metadata:
      labels:
        app: chaos
    spec:
      containers:
      - name: chaos-agent
        image: nebulaedge/chaos-agent:0.10.0
        resources:
          limits:
            cpu: "0.1"
            memory: "128Mi"
          requests:
            cpu: "50m"
            memory: "64Mi"
        ports:
        - name: chaos-agent
          containerPort: 8080
          protocol: TCP
        livenessProbe:
          exec:
            command:
            - "/bin/sh"
            - "/usr/local/bin/chaos agent check-agent-health"
          intervalSeconds: 15
          failureThreshold: 3
```

This YAML file defines a DaemonSet named "chaos-daemonset" that runs the Chaos Agent container on every node in the cluster. The container image is based on the `nebulaedge/chaos-agent` image with the tag `0.10.0`. The container is given a CPU limit of 0.1 and a memory limit of 128Mi, with corresponding requests of 50m CPU and 64Mi memory. The container listens on port 8080 for the Chaos Agent API. The liveness probe is set up to check the Chaos Agent's health every 15 seconds, with a failure threshold of 3.
