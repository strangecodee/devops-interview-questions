 # Kubernetes Deployment
A Kubernetes Deployment manages the creation and updating of replicas of a desired Pod definition.

# Explanation
Deployments maintain availability of an application by creating new replicas for updates and removing old ones. It ensures that a specified number of replicas are running and ready to serve. The updates are performed in a controlled manner, allowing for rollbacks to a previous version if necessary.

# Best Practices
- Use Rolling Updates: Update Pods one at a time to minimize disruption.
- Use Readiness Probes: Ensure that only healthy Pods are serving traffic.
- Use Liveness Probes: Automatically restart unhealthy Pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse
spec:
  replicas: 3
  selector:
    matchLabels:
      app: eclipse
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
      - name: eclipse
        image: eclipse:latest
        ports:
        - containerPort: 8443
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --output /dev/null --silent --head --fail http://localhost:8080/ || exit 1"]
            intervalSeconds: 5
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --output /dev/null --silent --head --fail http://localhost:8080/ || exit 1"]
            intervalSeconds: 15
---
kind: Service
apiVersion: v1
metadata:
  name: eclipse
spec:
  selector:
    app: eclipse
  ports:
  - port: 80
    targetPort: 8443
```
This example demonstrates a Deployment managing three replicas of an Eclipse container with readiness and liveness probes defined. The Service exposes the application on port 80, routing traffic to the available Pods.
