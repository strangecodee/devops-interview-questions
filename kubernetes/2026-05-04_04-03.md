# Kubernetes Concept
Deployment is a type of Kubernetes resource that creates and manages containers. It ensures that a specified number of replicas of a container are running at any given time, and it can perform updates or rollbacks as needed.

# Explanation
A Kubernetes Deployment creates and maintains a desired state for a set of containers, known as replicas. It keeps track of the current number of replicas and can perform rolling updates or rollbacks to ensure high availability and minimal downtime. The Deployment controller also provides self-healing capabilities by restarting containers that fail.

# Best Practices
- Use a rolling update strategy for minimal downtime and to ensure that new containers are healthy before old containers are terminated.
- Use labels and selectors to manage replicas based on specific conditions or requirements.
- Use a liveness probe to determine when a container is no longer responsive and should be restarted.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-app
  labels:
    app: nebula
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 80
        readinessProbes:
        - probe:
            exec:
              command: ["/usr/local/bin/check-readiness.sh"]
        livenessProbes:
        - probe:
            exec:
              command: ["/usr/local/bin/check-liveness.sh"]
```
This YAML file creates a Deployment named `nebula-app` with three replicas running the container image `nebula:latest`. It uses labels for selection and management, and includes readiness and liveness probes for self-healing capabilities. The container runs on port 80 and the script `check-readiness.sh` and `check-liveness.sh` are used to determine container readiness and liveness, respectively.
