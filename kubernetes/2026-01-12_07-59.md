 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures a desired number of replicas are running and maintains availability and scale.

# Explanation
A Deployment creates and manages the lifecycle of containers within a set of Pods. It can perform rolling updates and rollbacks, ensuring zero downtime and minimal disruption to the application. It also supports the automatic creation of a ReplicaSet, which ensures availability and replaces failed Pods.

# Best Practices
- Use labels for easier management and selection of Pods.
- Use a rolling update strategy for minimal downtime when updating Deployments.
- Monitor Deployments with Kubernetes built-in metrics and external monitoring tools.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-web
  labels:
    app: nebula
    environment: production
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:v1
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
---
apiVersion: v1
kind: Service
metadata:
  name: nebula-service
spec:
  selector:
    app: nebula
  ports:
  - port: 80
    targetPort: 80
  type: LoadBalancer
```
This YAML defines a Deployment named `nebula-web` with three replicas and a Service named `nebula-service` for external access to the application. The containers in the Deployment run the image `nebula:v1` and expose port 80. The liveness and readiness probes help ensure the health of the containers.
