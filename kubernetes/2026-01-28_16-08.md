 # Kubernetes Concept
Kubernetes DaemonSet ensures that a specified number of replicas of a pod are running on all nodes in the cluster.

# Explanation
A DaemonSet maintains a consistent daemon process on all nodes in a cluster, ensuring high availability and fault tolerance. This is particularly useful for running system services, such as logging and monitoring. In case a node is drained or a pod is crashing, DaemonSet will automatically restart the pod on a new node.

# Best Practices
- Use labels to select nodes based on their role or labels.
- Use health checks and liveness probes to ensure pods are running correctly.
- Use replicas to maintain a backup of daemon pods, in case of failure.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-daemonset
spec:
  selector:
    matchLabels:
      app: logging
  template:
    metadata:
      labels:
        app: logging
    spec:
      containers:
      - name: logging-container
        image: logging-image:latest
        ports:
        - containerPort: 514
        livenessProbe:
          exec:
            command: ["/usr/local/bin/check-logs.sh"]
            intervalSeconds: 5
      nodeSelector:
        beta.kubernetes.io/os: linux
```
This DaemonSet named `logging-daemonset` ensures that a logging container running image `logging-image:latest` is deployed on all nodes labeled with `beta.kubernetes.io/os: linux`. The container listens on port `514` and runs a custom script `/usr/local/bin/check-logs.sh` every 5 seconds as a liveness probe to ensure the container is healthy.
