 # Kubernetes Concept
This example introduces a Kubernetes `HorizontalPodAutoscaler` (HPA) for monitoring and scaling a deployment based on CPU utilization.

# Explanation
The Horizontal Pod Autoscaler (HPA) is a Kubernetes controller that automatically adjusts the number of replicas of a deployment based on observed CPU utilization. This is useful for ensuring optimal resource usage by automatically scaling applications based on the current workload.

# Best Practices
- Set a minimum and maximum number of replicas.
- Monitor both CPU and memory usage for effective resource management.
- Configure HPA with a cooldown period for stable scaling.

# YAML Example
```yaml
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: eclipse-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: eclipse
  minReplicas: 3
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
        averageUtilizationTarget: 70
    pods:
      metricName: "container:eclipse:container:cpu-percent"
      containerPort: 80
  external:
    name: my-metrics-service
  cooldownPeriod: 300
```
In this example, an HPA named `eclipse-hpa` is created to target the `eclipse` deployment. The HPA will maintain a minimum of 3 replicas and a maximum of 10 replicas. The HPA scales based on the average CPU utilization, which is set to 50% with a target of 70%. The HPA uses a custom metrics service `my-metrics-service` to calculate the CPU utilization. The cooldown period is set to 300 seconds to provide stability during scaling.
