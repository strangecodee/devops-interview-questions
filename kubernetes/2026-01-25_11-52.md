 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas of a pod run on each node in a cluster.

# Explanation
DaemonSets are useful for deploying system daemons, such as monitoring agents or log collectors, as they ensure that each node in the cluster has an instance of the daemon running. This ensures consistency across the cluster and simplifies management.

# Best Practices
- Use labels to target specific nodes or node labels when defining the DaemonSet.
- Use the rollout strategy to update the DaemonSet gradually, minimizing downtime and ensuring stability.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemon
  template:
    metadata:
      labels:
        app: my-daemon
    spec:
      containers:
      - name: my-daemon-container
        image: my-daemon-image:latest
        ports:
        - containerPort: 1234
          name: my-daemon-port
        readinessProbes:
        - exec:
            command: ["/usr/local/bin/my-daemon", "check-ready"]
            intervalSeconds: 5
            failureThreshold: 3
        livenessProbes:
        - exec:
            command: ["/usr/local/bin/my-daemon", "check-liveness"]
            intervalSeconds: 30
            failureThreshold: 3
```
This YAML defines a DaemonSet named `my-daemonset` that deploys a container named `my-daemon-container` using the image `my-daemon-image:latest`. The container exposes a port named `my-daemon-port` on containerPort 1234. The `readinessProbes` and `livenessProbes` are used to check the container's readiness and liveness, respectively.
