 # Kubernetes Concept
This is an example of a Kubernetes Service, which provides stable IP addresses and DNS names for accessing applications running on a set of Pods.

# Explanation
A Kubernetes Service is an abstraction layer that enables accessing a logical set of Pods as a single network service. It provides a stable IP address and DNS name, allowing the application to be accessed from outside the cluster. Services can also distribute incoming traffic across the Pods using load balancing.

# Best Practices
- Use `ClusterIP` type for services that are only meant to be accessed from within the cluster.
- Use `NodePort` type for services that need to be accessible from outside the cluster on specific node ports.
- Use `LoadBalancer` type for services that need to be accessible from outside the cluster via a cloud provider's load balancer.

# YAML Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: atlas-service
spec:
  selector:
    app: atlas
  ports:
  - name: http
    port: 80
    targetPort: 80
  - name: https
    port: 443
    targetPort: 443
  type: LoadBalancer
```
This YAML example defines a Kubernetes Service named `atlas-service` that uses a `LoadBalancer` type to expose the application to the outside world. It selects Pods with the label `app: atlas` and listens on ports 80 and 443, mapping them to the target ports 80 and 443 respectively.
