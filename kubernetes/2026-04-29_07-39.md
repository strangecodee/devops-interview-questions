# Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas of a container are running at any given time, and it can perform rolling updates and rollbacks.

# Explanation
A Kubernetes Deployment manages the lifecycle of a set of Pods, creating new ones when necessary and removing old ones that are no longer needed. It provides declarative updates, ensuring that the desired state is maintained, as well as self-healing capabilities through rolling updates and rolling restarts.

# Best Practices
- Use labels to select and manage multiple deployments at once.
- Use rolling updates for minimum downtime and maximum availability.
- Monitor the health and performance of your deployments using liveness and readiness probes.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /
            port: 80
        readinessProbe:
          httpGet:
            path: /
            port: 80
```
This YAML defines a Deployment named `nginx-deployment` with three replicas, each running the `nginx:latest` container image. The Deployment uses labels for both the metadata and the container's template, ensuring that they match for proper selection and management. The liveness and readiness probes are defined to monitor the health and readiness of the containers, allowing for self-healing and automated rollouts and rollbacks.
