 # Kubernetes Concept
 Deployment is a type of Kubernetes resource for creating and managing containerized applications. It ensures that a specified number of replicas of a container are running at any given time.

 # Explanation
 In this example, we will create a Kubernetes Deployment for an application running on an Nginx container. The Deployment controller will manage the desired state of the application by creating and removing replicas as needed to maintain the desired number of available instances.

 # Best Practices
- Use a rolling update strategy to minimize downtime and ensure that new replicas are healthy before old ones are removed.
- Use labels and selectors to manage and identify Deployments easily.
- Use readiness and liveness probes to determine whether a container is ready to receive traffic and whether it's still running.

 # YAML Example
 ```yaml
 apiVersion: apps/v1
 kind: Deployment
 metadata:
   name: atlas-deployment
   labels:
     app: atlas
 spec:
   replicas: 3
   selector:
     matchLabels:
       app: atlas
   template:
     metadata:
       labels:
         app: atlas
     spec:
       containers:
       - name: atlas
         image: nginx:latest
         ports:
         - containerPort: 80
         readinessProbe:
           probes:
           - exec:
              command: ["/usr/bin/nc", "-z", "--wunresolved", "localhost", "80"]
           initialDelaySeconds: 5
           periodSeconds: 10
         livenessProbe:
           probes:
           - exec:
              command: ["/usr/bin/nc", "-z", "--wunresolved", "localhost", "80"]
           initialDelaySeconds: 15
           periodSeconds: 20
 ```
 In this YAML example, we create a Kubernetes Deployment for an Nginx container named 'atlas-deployment'. We set the desired number of replicas to 3 and use labels for easy identification. The container listens on port 80, and we define both readiness and liveness probes to ensure that the container is ready to receive traffic and is still running.
