 # Kubernetes Concept: Deployment
A Kubernetes Deployment manages the rollout and scaling of containerized applications. It creates and updates Pods in a ReplicaSet, maintaining a specified number of replicas.

# Explanation
Deployments ensure availability and progressively roll out new versions of an application while maintaining continuity through traffic management and rollback. They manage the updating process using strategies like RollingUpdate or Recreate.

# Best Practices
- Use `RollingUpdate` strategy to minimize downtime and maximize availability.
- Implement `readinessProbes` and `livenessProbes` for early detection and recovery of unhealthy containers.
- Set up `resource limitations` to prevent container resource exhaustion and ensure fair sharing.

# YAML Example - Forge Deployment with Security Probes
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-app
spec:
  selector:
    matchLabels:
      app: forge
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: forge-container
        image: forge/forge:latest
        ports:
        - containerPort: 80
        readinessProbes:
        - exec:
            command: ["/usr/local/bin/check-readiness"]
          intervalSeconds: 5
          timeoutSeconds: 3
        livenessProbes:
        - exec:
            command: ["/usr/local/bin/check-liveness"]
          intervalSeconds: 30
          timeoutSeconds: 15
      imagePullSecrets:
      - name: regcred
```
