 # Kubernetes Concept
Deployment is a Kubernetes object used for creating and updating replicas of a container application.

# Explanation
A Deployment ensures that a specified number of replicas of a container image are running at any given time. It creates a desired state for the application and automatically creates and manages the corresponding ReplicaSets and Pods.

# Best Practices
- Use Rolling Updates to minimize downtime by updating pods one at a time.
- Set appropriate resource limits.
- Use readiness and liveness probes for efficient scaling and management.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
          name: http
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
---
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```
This YAML example defines a Kubernetes Deployment named 'my-deployment' with 3 replicas, running the container image 'my-image:latest' and listening on port 80. The liveness and readiness probes are set up to monitor the health of the container. A Service named 'my-service' is created to expose the deployment on port 80.
