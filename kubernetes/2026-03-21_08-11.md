 # Kubernetes Deployment
A Kubernetes Deployment is used to create, update, and manage replicas of a containerized application.

# Explanation
Deployments maintain a specified number of replicas for an application, performing updates and rolling back to ensure high availability and automated scaling. They support various strategies like blue-green, rolling update, and rolling update with recreate.

# Best Practices
- Use rolling updates to minimize downtime and maintain availability.
- Set appropriate resource requests and limits to ensure fair sharing and prevent container contention.
- Implement readiness and liveness probes to monitor container health and automatically restart unhealthy replicas.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: quantum-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: quantum
  template:
    metadata:
      labels:
        app: quantum
    spec:
      containers:
      - name: quantum
        image: myregistry/quantum:v1
        ports:
        - containerPort: 80
          name: http
        readinessProbe:
          probe:
            exec:
              command: ["/usr/bin/nc", "-z", "127.0.0.1", "80", "--timeout=1s"]
              intervalSeconds: 30
          failureThreshold: 3
          gracePeriodSeconds: 60
        livenessProbe:
          probe:
            exec:
              command: ["/usr/bin/nc", "-z", "127.0.0.1", "80", "--timeout=1s"]
              intervalSeconds: 30
          failureThreshold: 3
          gracePeriodSeconds: 60
      resources:
        requests:
          cpu: "0.5"
          memory: "512Mi"
        limits:
          cpu: "1"
          memory: "1Gi"
```
