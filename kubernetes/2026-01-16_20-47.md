 # Kubernetes Concept
This example demonstrates a Kubernetes Service of type LoadBalancer, which provides an external IP to access a running application.

# Explanation
A Kubernetes Service is an abstraction that defines a policy for accessing a set of Pods. The `type: LoadBalancer` attribute requests a cloud provider's load balancer to distribute traffic to the Pods. This configuration ensures that the external IP address remains stable even if the underlying Pods change.

# Best Practices
- Use the appropriate labels on your Pods to ensure they are properly targeted by the Service.
- Use `selector: {}` in the Service definition if you want all running Pods in the namespace to be targeted.
- Update your DNS records whenever you create or delete a Service.

# YAML Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-app-service
  labels:
    app: my-app
spec:
  selector:
    app: my-app
  ports:
  - name: http
    port: 80
    targetPort: 8080
  - name: https
    port: 443
    targetPort: 8443
  type: LoadBalancer
```
This Service definition targets Pods with the label `app: my-app` and exposes ports 80 and 443 for HTTP and HTTPS traffic, respectively. The `type: LoadBalancer` attribute ensures that an external IP address is created for accessing the application.
