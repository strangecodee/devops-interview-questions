 # Kubernetes Concept
This example demonstrates a Kubernetes Service and Ingress resource for load balancing traffic to a pair of replicas running in a Deployment called "nebula-backend".

# Explanation
The Kubernetes Service abstracts an application running on a set of Pods, assigning a virtual IP (VIP) and managing service discovery and load balancing between the replicas. The Ingress resource, on the other hand, manages external access to the service. In this configuration, the Ingress controller distributes incoming requests to the Service using round-robin balancing.

# Best Practices
- Ensure that the desired number of replicas is set appropriately in the Deployment to maintain high availability and scalability.
- Implement a health check using the Deployment's `livenessProbe` or an external monitoring solution to ensure that the application is running correctly.
- Use an Ingress controller with SSL termination to secure communication between the client and backend services.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-backend
  labels:
    app: nebula
spec:
  replicas: 2
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 8080
          name: http
---
apiVersion: v1
kind: Service
metadata:
  name: nebula-backend
spec:
  selector:
    app: nebula
  ports:
  - port: 80
    targetPort: 8080
  type: ClusterIP
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: nebula-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  rules:
  - host: nebula.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: nebula-backend
            port:
              number: 80
```
