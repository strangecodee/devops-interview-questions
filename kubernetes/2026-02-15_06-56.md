 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures availability, scalability, and rollouts.

# Explanation
A Deployment manages the lifecycle of a set of replicas for a desired number of Pods. When a new version of an application is released, a new Deployment can be created to roll out the update in a controlled manner. Rollouts can be gradual, and the progress can be monitored for stability before completing the update.

# Best Practices
- Use rolling updates to minimize downtime.
- Configure readiness and liveness probes for automated rollbacks and updates.
- Use labels for selectors to manage multiple replicas.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-image:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probeType: HttpGet
          httpGet:
            path: /healthz
            port: 80
        livenessProbe:
          probeType: HttpGet
          httpGet:
            path: /liveness
            port: 80
---
apiVersion: v1
kind: Service
metadata:
  name: my-app-service
spec:
  selector:
    app: my-app
  ports:
  - name: http
    port: 80
    targetPort: 80
  type: ClusterIP
```
This YAML example declares a Deployment named `my-app` with three replicas, each running a container named `my-app-container` with image `my-image:latest`. The `readinessProbe` and `livenessProbe` ensure the container is ready and running, respectively, and ready for traffic. A Service named `my-app-service` is created to provide a stable IP address and distribute traffic to the Pods.
