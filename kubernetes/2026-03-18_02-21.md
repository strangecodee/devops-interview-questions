 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas are running and ready to serve.

# Explanation
A Deployment creates or updates Pods in a cluster using a predefined container image and configuration. It provides a declaration of desired state for a set of containers, including updates and scaling. Kubernetes controller continually checks the actual state against the desired state and makes adjustments as necessary.

# Best Practices
- Use Rolling Updates for minimal downtime.
- Set up Readiness and Liveness probes to ensure containers are healthy.
- Use Labels for selectors and efficient management of your resources.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: atlas-deployment
  labels:
    app: atlas
spec:
  selector:
    matchLabels:
      app: atlas
  replicas: 3
  template:
    metadata:
      labels:
        app: atlas
    spec:
      containers:
      - name: atlas
        image: atlas:latest
        ports:
        - containerPort: 12345
          protocol: TCP
        livenessProbe:
          exec:
            command: ["/usr/local/bin/check-health.sh"]
          initialDelaySeconds: 15
          periodSeconds: 5
        readinessProbe:
          exec:
            command: ["/usr/local/bin/check-readiness.sh"]
          initialDelaySeconds: 15
          periodSeconds: 5
```
This YAML file describes a Kubernetes Deployment called "atlas-deployment" with three replicas, each containing an "atlas" container. The containers run the "atlas:latest" image and listen on port 12345. Liveness and readiness probes are set using the exec method, checking the health of the application with custom scripts.
