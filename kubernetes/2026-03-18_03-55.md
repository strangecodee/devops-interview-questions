 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas for a pod are running on each node in the cluster.

# Explanation
DaemonSets are useful for deploying and managing background services or system components, such as logging agents or monitoring tools, that need to run on every node in the cluster. They maintain a consistent state across the cluster by creating and managing replicas of the pods.

# Best Practices
- Use appropriate labels for your DaemonSet to ensure it targets the correct nodes in your cluster.
- Use health checks and liveness probes to monitor the status of your DaemonSet pods and automatically restart failing pods.
- Use resource limits and requests to ensure that your DaemonSet pods do not consume excessive resources.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-logging-daemonset
spec:
  selector:
    matchLabels:
      app: my-logging-daemon
  template:
    metadata:
      labels:
        app: my-logging-daemon
    spec:
      containers:
      - name: my-logging-container
        image: my-logging-image:latest
        ports:
        - containerPort: 514
          name: udp
          protocol: UDP
        livenessProbe:
          exec:
            command: ["/healthz"]
          initialDelaySeconds: 15
          periodSeconds: 5
---
```
This DaemonSet ensures that one instance of the "my-logging-daemon" is running on each node in the cluster, with the container image "my-logging-image:latest" and label "app: my-logging-daemon". The container listens on UDP port 514 and includes a liveness probe to ensure the container is running and healthy.
