 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas of a pod are running on each node in the cluster, maintaining a consistent daemon on every node.

# Explanation
DaemonSets are used for running processes that require privileged access to the host or persistent storage, such as monitoring agents, log collectors, or database nodes. They simplify the management of these daemons by ensuring consistent deployment across the cluster, and rolling out updates or rollbacks in a controlled manner.

# Best Practices
- Use labels to target nodes with specific requirements or constraints.
- Limit the number of DaemonSets running on a single node to prevent resource contention.
- Keep DaemonSet containers updated to maintain the latest versions and security patches.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemon
  template:
    metadata:
      labels:
        app: my-daemon
    spec:
      containers:
      - name: my-container
        image: my-container-image:latest
        ports:
        - containerPort: 12345
          name: my-container-port
        securityContext:
          privileged: true
          capabilities:
            add:
            - NET_ADMIN
          seLinuxOptions:
            type:RuntimeAppSVirt
          labels:
            app.kubernetes.io/security-policy: restricted
          readOnlyRootFilesystem: false
      restartPolicy: Always
```
