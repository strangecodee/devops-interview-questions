 # Kubernetes Concept
This is an example of a Kubernetes Deployment configuration for a simple Java application using Eclipse OpenJDK, managed by Terraform.

# Explanation
A Kubernetes Deployment creates and manages a set of replica Pods with a specified number of availability and places them behind a Kubernetes Service. In this example, we configure a Deployment for a Java application using Eclipse OpenJDK as the base image. Terraform is used to manage and automate the deployment.

# Best Practices
- Use a rolling update strategy for minimal downtime during deployment.
- Configure resource limits and requests to ensure optimal resource utilization.
- Enable readiness and liveness probes to monitor the health of your application and automatically restart unhealthy containers.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-java-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-java-app
  template:
    metadata:
      labels:
        app: my-java-app
    spec:
      containers:
      - name: my-java-container
        image: openjdk:8-jdk-alpine
        ports:
        - containerPort: 8080
          name: http
        resources:
          limits:
            cpu: "0.5"
            memory: "512Mi"
          requests:
            cpu: "250m"
            memory: "256Mi"
        readinessProbe:
          probes:
          - exec:
              command: ["sh", "-c", "curl --fail http://localhost:8080/ || exit 1"]
              intervalSeconds: 5
              timeoutSeconds: 3
          initialDelaySeconds: 30
          failureThreshold: 3
        livenessProbe:
          probes:
          - exec:
              command: ["sh", "-c", "curl --fail http://localhost:8080/ || exit 1"]
              intervalSeconds: 5
              timeoutSeconds: 3
          initialDelaySeconds: 30
          failureThreshold: 3
```
This example creates a Deployment named `my-java-app` with 3 replicas, using the Eclipse OpenJDK image `openjdk:8-jdk-alpine`. The container listens on port `8080` and has resource limits and requests set for CPU and memory. Readiness and liveness probes are configured to monitor the application using a health check on the `/` endpoint.
