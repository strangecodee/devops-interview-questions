 # Kubernetes Concept
Deployment is a Kubernetes object used for updating and rolling back applications. It ensures availability during updates and provides a way to roll back to a previous version if necessary.

# Explanation
A Deployment creates and manages ReplicaSets, which maintain a specified number of replicas of a desired Pod. When a new version of the application is deployed, Kubernetes creates new replicas, and gradually transitions traffic to them using a rolling update strategy. This allows for a smooth transition and minimal downtime.

# Best Practices
- Use rolling updates with a small update percentage to minimize downtime and allow for easier rollbacks.
- Use `readinessProbes` and `livenessProbes` to ensure that the application is fully operational before sending traffic to it.
- Use labels for selectors to manage and update multiple replicas of an application at once.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-app
  labels:
    app: forge
spec:
  replicas: 3
  selector:
    matchLabels:
      app: forge
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: forge-container
        image: forge:1.0.0
        ports:
        - containerPort: 80
      readinessProbes:
      - exec:
          command: ["/usr/bin/curl", "--fail", "/"]
          intervalSeconds: 5
      livenessProbes:
      - exec:
          command: ["/usr/bin/curl", "--fail", "/"]
          intervalSeconds: 30
```
