# Kubernetes Concept
Kubernetes DaemonSet is a type of Kubernetes deployment that ensures a specified number of replicas of a pod are running on all nodes in a cluster.

# Explanation
DaemonSets run a user-defined number of pods on each node in the cluster, making it perfect for running system daemons, background workers, or other services that need to be available on every node. This ensures high availability and consistency across the cluster.

# Best Practices
- Use labels to target specific nodes or node labels when creating a DaemonSet.
- Use `restartPolicy: OnFailure` to ensure the pods are restarted when they fail.
- Use liveness and readiness probes to monitor the health and readiness of the pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
  labels:
    app: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemonset
  template:
    metadata:
      labels:
        app: my-daemonset
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
        livenessProbe:
          exec:
            command: ["/usr/local/bin/check-liveness.sh"]
        readinessProbe:
          exec:
            command: ["/usr/local/bin/check-readiness.sh"]
```
This example creates a DaemonSet named `my-daemonset` with a single container named `my-container`. The container is labeled with `app: my-daemonset` and runs on port 80. The DaemonSet uses liveness and readiness probes to check the health and readiness of the container using the scripts located at `/usr/local/bin/check-liveness.sh` and `/usr/local/bin/check-readiness.sh`, respectively.
