 # Kubernetes Concept
Deployment is a type of Kubernetes resource for describing and managing a set of replicas for a desired application. It ensures a specified number of replicas are running at any given time and creates or updates containers based on a container image.

# Explanation
A Deployment creates or updates Pods in the cluster to match the desired state, as defined in the manifest. If a new version of an application is released, a new Deployment can be created with the updated container image, and Kubernetes will create new replicas with the new image while keeping the old ones running until they are all replaced. This ensures minimal downtime during updates.

# Best Practices
- Use rolling updates to minimize downtime by updating Pods one at a time.
- Define readiness and liveness probes to ensure the application is functioning correctly and ready to serve traffic before marking it as available.
- Use labels for selectors to manage and identify the Pods within a Deployment.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-deployment
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-app:latest
        ports:
        - containerPort: 80
          protocol: TCP
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 5
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 5
```
