 # Kubernetes Concept
Deployment is a Kubernetes object used for managing containerized applications. It creates and updates instances of replicas as needed, ensuring availability and scalability.

# Explanation
A Kubernetes Deployment manages the lifecycle of a set of replica Pods, creating new ones as necessary to maintain the desired number, and deleting old ones when they are no longer needed. It also automatically rolls out updates to the application, performing rolling updates and rolling back if necessary, ensuring high availability and minimal downtime.

# Best Practices
- Use `RollingUpdate` strategy with `MaxSurge` and `MaxUnavailable` to minimize downtime during updates.
- Use `Readiness` and `Liveness` probes to check application health and automatically manage the deployment accordingly.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse
spec:
  replicas: 3
  selector:
    matchLabels:
      app: eclipse
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
        - name: eclipse
          image: eclipse:latest
          ports:
            - containerPort: 8182
          readinessProbe:
            probe:
              exec:
                command: ["/usr/bin/nc", "-z", "-w1", "127.0.0.1", "8182"]
              initialDelaySeconds: 5
              periodSeconds: 10
          livenessProbe:
            probe:
              exec:
                command: ["/usr/bin/nc", "-z", "-w1", "127.0.0.1", "8182"]
              initialDelaySeconds: 15
              periodSeconds: 20
```
This YAML file defines a Kubernetes Deployment named `eclipse`, which creates 3 replicas of the eclipse container, with a readiness and liveness probe. The probes check the connection to port 8182, ensuring that the container is running and ready to serve requests.
