# Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas of a container image are running and available.

# Explanation
A Deployment creates and manages the lifecycle of a set of replicas of a container. When a new version of the container image is available, the Deployment can roll out the new version in a controlled manner, updating a percentage of the replicas at a time and rolling back if necessary. It also includes a rolling update strategy and can perform automated rollouts and rollbacks.

# Best Practices
- Use strategic rollouts for major updates to minimize downtime and mitigate risk.
- Use a rolling update strategy to update pods one at a time, allowing for continuous availability.
- Use a readiness probe and a liveness probe to ensure that the containers are running correctly and ready to receive traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: forge
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: forge-container
        image: forge:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
---
apiVersion: v1
kind: Service
metadata:
  name: forge-service
spec:
  selector:
    app: forge
  ports:
  - port: 80
  type: ClusterIP
```
This YAML file defines a Deployment named `forge-deployment` with three replicas running the container image `forge:latest`. It uses labels for both the Deployment and the container to allow for easy management. The container listens on port 80 and includes a liveness probe and a readiness probe. The container is exposed through a Service named `forge-service`.
