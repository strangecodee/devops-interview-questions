 # Kubernetes Concept
Deployment is a Kubernetes object used for deploying and updating applications. It creates and manages replicas of a container image.

# Explanation
Deployments manage the lifecycle of a set of identical pods, creating new replicas whenever a change is pushed to the container image, and ensuring a specified number of replicas are running at any given time. This provides a simple way to perform updates and rollbacks, as well as the ability to automatically replace unhealthy pods.

# Best Practices
- Use rolling updates with a small percentage of the total number of replicas updated at a time to minimize disruptions.
- Set up a readiness and liveness probe to ensure that the container is running correctly and ready to serve traffic.
- Use labels for easy identification and selection of pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-deployment
  labels:
    app: nebula
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:v1
        ports:
        - containerPort: 80
        readinessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 80
      terminationGracePeriodSeconds: 30
```
This YAML file defines a Deployment named "nebula-deployment" with three replicas and a container named "nebula" running on port 80. It sets up a readiness probe to check the application's health at the path "/healthz". The deployment also includes a termination GracePeriod to allow containers to gracefully shut down before being terminated.
