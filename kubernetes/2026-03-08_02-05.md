 # Kubernetes Concept
Deployment is a kind of Kubernetes resource for managing containers' lifecycle and maintaining a desired state. It creates and updates Pods in a cluster according to the definition in the manifest file.

# Explanation
A Deployment creates and manages replicas of a specified container image, ensuring the desired number of instances is running at any given time. It uses rolling updates to replace old replicas with new ones, minimizing downtime. Rollbacks are also supported, allowing you to revert to a previous version of the Deployment.

# Best Practices
- Use rolling updates with a percentage-based strategy (e.g., 10%) for minimal downtime.
- Set up readiness and liveness probes to ensure containers are running correctly and ready to serve traffic.
- Use labels for easier filtering and organization of your Kubernetes resources.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: atlas
  labels:
    app: atlas
spec:
  replicas: 3
  selector:
    matchLabels:
      app: atlas
  template:
    metadata:
      labels:
        app: atlas
    spec:
      containers:
      - name: atlas
        image: myregistry/atlas:v1
        ports:
        - containerPort: 8080
          name: http
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 10
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 10
```
This example defines a Deployment named `atlas` with three replicas, running the container image `myregistry/atlas:v1`. It includes both liveness and readiness probes to ensure the containers are running correctly and ready to serve traffic.
