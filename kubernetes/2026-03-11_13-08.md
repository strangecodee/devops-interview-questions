 # Kubernetes Concept
Deployment is a Kubernetes object used for creating and managing containers. It ensures a specified number of replicas are running at any given time and can perform rolling updates and rollbacks.

# Explanation
A Deployment in Kubernetes manages the lifecycle of a set of replicas for a desired state defined by a container image, number of replicas, and other desired state configurations. When a new version is released, Kubernetes can perform a rolling update, updating the replicas one at a time to minimize downtime.

# Best Practices
- Use labels for selectors to make Deployments manageable and scalable.
- Use RollingUpdateStrategy for minimal downtime during updates.
- Use rolling updates in smaller batches for better control.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-docker-image:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 60
          periodSeconds: 30
          timeoutSeconds: 5
```
This example creates a Deployment named `my-app` that manages three replicas of a container with image `my-docker-image:latest`. The container listens on port 80 and has a liveness probe that checks the `/healthz` endpoint every 30 seconds.
