# Kubernetes Concept
Deployment is a Kubernetes resource for describing and creating a set of replicas for a desired state of a containerized application.

# Explanation
A Deployment manifests the desired state for a set of containers, including replicas, updates, and rollbacks. It ensures that a specified number of replicas are running and available at any given time. If a new container image is deployed, Kubernetes will update the replicas in a controlled and gradual manner, minimizing downtime.

# Best Practices
- Use rolling updates (default strategy) to minimize downtime and ensure smooth deployments.
- Set up a minimum number of desired replicas to maintain availability.
- Use a strategy like `RollingUpdate` with `maxSurge` and `maxUnavailable` to control the number of new and old pods during an update.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: atlas-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: atlas
  template:
    metadata:
      labels:
        app: atlas
    spec:
      containers:
      - name: atlas
        image: myregistry/atlas:v1.2.3
        ports:
        - containerPort: 80
        readinessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 80
        livenessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 80
```
