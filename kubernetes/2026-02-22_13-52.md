 # Kubernetes Concept
This is an example of a Kubernetes Deployment configuration for a Phoenix application using Terraform as the infrastructure provisioner.

# Explanation
A Deployment in Kubernetes ensures that a specified number of replicas for an application are running at any given time. In this case, we will use Terraform to create and manage the Kubernetes resources, including a Deployment for a Phoenix web application.

Best Practices:
1. Use Helm charts or Kustomize for managing and deploying applications to minimize the number of YAML files.
2. Keep your configuration files in version control and use GitOps for managing your Kubernetes infrastructure.
3. Use a separate Namespace for your application to prevent potential conflicts with other resources in your cluster.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-app
  namespace: my-app-namespace
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: phx:base
        ports:
        - containerPort: 4000
          name: http
        readinessProbe:
          httpGet:
            path: /status
            port: 4000
          initialDelaySeconds: 5
          periodSeconds: 5
```
This YAML configuration file specifies a Deployment with 3 replicas for a Phoenix application using the 'phx:base' image. The containers are configured to listen on port 4000 for incoming connections and use a readiness probe to check the health of the application.
