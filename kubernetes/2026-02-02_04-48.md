 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
A Deployment in Kubernetes manages the lifecycle of a set of replica Pods. It ensures that a specified number of replicas are running and creates new replicas if any fail. It also performs rolling updates of the containers, which minimizes downtime by updating pods one at a time.

# Best Practices
- Use rolling updates when deploying new versions of your application to minimize downtime.
- Set the desired number of replicas to ensure high availability.
- Use readiness and liveness probes to check the health of your containers.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: atlas-deployment
spec:
  selector:
    matchLabels:
      app: atlas
  replicas: 3
  template:
    metadata:
      labels:
        app: atlas
    spec:
      containers:
      - name: atlas
        image: amazon/amazon-mariadb:10.4
        ports:
        - containerPort: 3306
          name: mysql
        readinessProbe:
          tcpSocket:
            port: 3306
        livenessProbe:
          exec:
            command: ["mysqladmin", "ping", "--connect-timeout=5"]
```
This YAML file creates a Deployment named `atlas-deployment` that manages three replicas of the `atlas` container. The container runs the Amazon MariaDB image and exposes port 3306. The deployment also sets up readiness and liveness probes to check the health of the container.
