 # Kubernetes Deployment
Create and manage containerized applications in a Kubernetes cluster.

# Explanation
A Kubernetes Deployment is a declarative way to create and manage a desired state for a set of containers. It handles the rolling updates and rollbacks of containerized applications, ensuring high availability, scalability, and resilience.

# Best Practices
- Use rolling updates with a controlled update strategy to minimize downtime and ensure graceful transitions.
- Set up resource limits and requests to prevent container misbehavior and improve overall cluster performance.
- Implement readiness and liveness probes to monitor container health and readiness.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-webapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-webapp
  template:
    metadata:
      labels:
        app: my-webapp
    spec:
      containers:
      - name: my-webapp
        image: my-webapp:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probes:
          - exec:
              command: ["curl", "--fail", "/"]
              intervalSeconds: 5
          timeoutSeconds: 5
        livenessProbe:
          probes:
          - exec:
              command: ["curl", "--fail", "/"]
              intervalSeconds: 15
          timeoutSeconds: 3
```
This example defines a Deployment named `my-webapp` that runs 3 replicas of the `my-webapp:latest` container image. It includes readiness and liveness probes to check the container's health and readiness. The readiness probe checks for the presence of the application's root page, while the liveness probe checks the same condition but with a longer timeout and interval for increased resilience.
