 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures a specified number of replicas of a container are running at any given time.

# Explanation
A Deployment creates and manages the lifecycle of a set of replicas of a container image. It can perform rolling updates and rollbacks, and it ensures that a desired number of replicas are available at all times.

# Best Practices
- Use Rolling Updates to minimize downtime and maintain availability.
- Set up a Health Check to ensure that the containers are running correctly.
- Use Labels for easier management and selectivity.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
  labels:
    app: phoenix
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: myregistry/phoenix:latest
        ports:
        - containerPort: 8080
        livenessProbe:
          httpGet:
            path: /health-check
            port: 8080
          initialDelaySeconds: 5
          periodSeconds: 10
```
This YAML example defines a Deployment named `phoenix-deployment` with three replicas. It uses a RollingUpdate strategy to update containers without downtime. The container image being used is `myregistry/phoenix:latest`, and the container exposes port 8080. The liveness probe is set up to check the `/health-check` endpoint every 10 seconds.
