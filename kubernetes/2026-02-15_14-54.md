 # Kubernetes Concept
Deployment is a Kubernetes object used for creating, updating, and managing containerized applications.

# Explanation
A Deployment creates and manages ReplicaSets, which ensure a specified number of replicas are running and available. It also provides options for updating the application with zero downtime through rolling updates and rollbacks.

# Best Practices
- Use rolling updates to minimize downtime and ensure a smooth deployment process.
- Monitor the health of your application using Liveness and Readiness probes.
- Use resource limits and requests to ensure the efficient use of cluster resources.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 80
      livenessProbe:
        httpGet:
          path: /healthz
          port: 80
      readinessProbe:
        httpGet:
          path: /ready
          port: 80
      resources:
        limits:
          cpu: "1"
          memory: "512Mi"
        requests:
          cpu: "500m"
          memory: "256Mi"
---
```
This example demonstrates a Deployment managing a containerized application called `nebula`, with three replicas, Liveness and Readiness probes, and resource requests and limits.
