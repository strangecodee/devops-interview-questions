 # Kubernetes Concept: Deployment
Creates and manages containerized applications by controlling updates, rollouts, and scaling.

# Explanation
A Kubernetes Deployment is an abstraction that provides declarative updates for a set of Pods. It allows you to define the desired state for your application, and Kubernetes will maintain that state by managing the creation and deletion of Pods and their containers.

# Best Practices
- Use rolling updates to minimize downtime.
- Define readiness and liveness probes to ensure containers are healthy.
- Use labels for easy identification and management of your deployments.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
          name: http
      imagePullSecrets:
      - name: my-secret
      readinessProbes:
      - exec:
          command: ["/usr/local/bin/check-readiness"]
          intervalSeconds: 5
          failureThreshold: 3
      livenessProbes:
      - exec:
          command: ["/usr/local/bin/check-liveness"]
          intervalSeconds: 15
          failureThreshold: 3
```
This YAML file describes a Kubernetes Deployment that manages a containerized application with the name "my-app". It sets up the desired state for three replicas, with containers running the image "my-image:latest". Rolling updates can be performed with the `kubectl set image` command. The readiness and liveness probes are defined to check the container's health, and imagePullSecrets are utilized for secure image pulling.
