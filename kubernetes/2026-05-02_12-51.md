# Kubernetes Concept
This YAML example demonstrates a `Deployment` and corresponding `Service` for a simple monitoring application using an eclipse-jetty container, which logs and exposes metrics via Prometheus.

# Explanation
The Deployment manages the creation, scaling, and updates of replicas, while the Service provides a stable IP address and DNS name to access the application. Here, we configure the monitoring application to use containers with eclipse-jetty, expose metrics using Prometheus, and handle container restarts and updates using Rolling Updates.

# Best Practices
1. Use a configuration management tool like Helm or Kustomize for managing your Kubernetes manifests.
2. Apply the `readinessProbe` and `livenessProbe` to your containers to ensure they're ready for traffic and healthy, respectively.
3. Configure your Service with a `clusterIP` and `type: ClusterIP` to keep the monitoring application accessible within your cluster.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: monitoring-app
  labels:
    app: monitoring
spec:
  selector:
    matchLabels:
      app: monitoring
  replicas: 3
  template:
    metadata:
      labels:
        app: monitoring
    spec:
      containers:
      - name: eclipse-jetty
        image: eclipse:jetty.latest
        ports:
        - containerPort: 8080
          name: http
          protocol: TCP
        args:
        - run
        readinessProbe:
          httpGet:
            path: /actuator/health/ready
            port: 8080
        livenessProbe:
          httpGet:
            path: /actuator/health/liveness
            port: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: monitoring-app
spec:
  selector:
    app: monitoring
  ports:
  - name: http
    port: 80
    targetPort: 8080
  type: ClusterIP
```
