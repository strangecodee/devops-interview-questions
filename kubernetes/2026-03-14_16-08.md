 # Kubernetes Concept
Kubernetes ConfigMaps provide a way to inject configuration data into containers. They are used to store non-sensitive data that varies between environments, such as application properties files or environment variables.

# Explanation
ConfigMaps are created and managed outside of containers, allowing for easier management and separation of configuration data from application code. They can be mounted as files, environment variables, or as command-line arguments. ConfigMaps support multiple keys and values, which can be selected using environment variable or volume mount selectors.

# Best Practices
- Use ConfigMaps to store non-sensitive configuration data, such as application properties files or environment variables.
- Use Secrets for storing sensitive data, such as passwords or API keys.
- Use a unique name and appropriate labels for each ConfigMap.

# YAML Example
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-configmap
  labels:
    app: my-app
    environment: production
data:
  app-properties.properties: |
    property1=value1
    property2=value2
```
In this example, a ConfigMap named "my-configmap" is created, labeled with "app: my-app" and "environment: production". The "app-properties.properties" data key contains a multi-line YAML string representing the contents of a properties file. When mounted as a file in a container, this data can be accessed at "/etc/config/app-properties.properties".
