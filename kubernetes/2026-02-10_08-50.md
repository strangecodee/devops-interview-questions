 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas of a container image are running and replaces any instances that crash or become unavailable.

# Explanation
A Deployment in Kubernetes maintains a specified number of replicas of a container, updates them when new images are available, and ensures that they are running and healthy. It provides a declarative update mechanism for applications, allowing you to describe the desired state for your application and have Kubernetes manage it for you.

# Best Practices
- Use rolling updates to minimize downtime and ensure zero-downtime deployments.
- Use readiness and liveness probes to determine the health of your containers.
- Use labels and selectors to manage and identify your deployments easily.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-deployment
  labels:
    app: nebula
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probeType: HTTP
          httpGet:
            path: /healthz
            port: 80
        livenessProbe:
          probeType: HTTP
          httpGet:
            path: /liveness
            port: 80
```
This YAML defines a Deployment named "nebula-deployment" with three replicas, a container named "nebula" using the image "nebula:latest", and readiness and liveness probes to check the container's health.
