 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containers. It creates and updates containers in a desired state.

# Explanation
A Deployment creates or updates ReplicaSets, which ensure a specified number of replicas are running at any given time. Deployments can roll out updates, roll back to previous versions, and perform self-healing.

# Best Practices
- Use rolling updates for minimizing downtime during deployment.
- Configure health checks using Liveness and Readiness probes.
- Use labels and selectors to manage and identify pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
          name: http
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
          initialDelaySeconds: 30
          periodSeconds: 10
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
          initialDelaySeconds: 30
          periodSeconds: 10
```
This example demonstrates a Deployment creating and updating three replicas of an application container named "my-app". The containers listen on port 80 and have Liveness and Readiness probes configured to check the health of the application.
