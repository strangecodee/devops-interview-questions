# Kubernetes Concept
Deployment is a Kubernetes object used to create and manage replicas of a containerized application. It ensures availability and rollouts of new versions with minimal downtime.

# Explanation
A Deployment manages the lifecycle of a set of replica Pods. It creates new replicas based on updated container images, and removes old ones when it's safe to do so. This way, a Deployment ensures availability and progresses the application to the latest version with minimal downtime.

# Best Practices
- Use rolling updates to minimize downtime and maintain high availability
- Set up a strategy for rolling back to previous versions if needed
- Use health checks in your probes to control when new replicas are considered ready

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-registry/my-image:1.0.2
        ports:
        - containerPort: 80
        readinessProbes:
        - exec:
            command: ["/usr/local/bin/my-check"]
          intervalSeconds: 10
        livenessProbes:
        - exec:
            command: ["/usr/local/bin/my-check"]
          intervalSeconds: 30
```
This YAML defines a Deployment named `my-app` with three replicas. The containers in the template use the image `my-registry/my-image:1.0.2`. The readiness and liveness probes are defined using `exec` commands to check application health.
