 # Kubernetes Concept
Kubernetes Pod Security Policy is a way to restrict the capabilities of a container in a pod.

# Explanation
Pod Security Policies define the minimum security requirements a pod must satisfy before it can be admitted to the cluster. They control the levels of access that a container can have to the underlying host, such as the ability to drop capabilities, run as a privileged container, or mount host paths.

# Best Practices
- Create a PSP for each team or project and apply the least privileged policy possible.
- Regularly review and update the policies to reflect the current security needs.
- Use the `seccomp` profile to restrict system calls to minimize potential security risks.

# YAML Example
```yaml
apiVersion: security.openshift.io/v1
kind: PodSecurityPolicy
metadata:
  name: nebula-psp
spec:
  allowPrivileged: false
  seccompProfile:
  - type: RuntimeDefault
  runAsUser:
  - number: 65533
  seLinux:
    rule: RunAsAny
  supplementalGroups:
  - number: 65533
  fsGroup:
  - number: 65533
  readOnlyRootFilesystem: false
  volumes:
  - configMap
  - secret
  - emptyDir
  - projectHostPath
  hostPaths:
  - path: /data
    pathType: SubPathOrHostDir
  - path: /var/run
    pathType: HostPath
```
This YAML defines a Pod Security Policy named "nebula-psp". It allows the container to run as any user, group, and supplemental group with the specified numbers. The container can use `seccomp` profiles, access `configMap`, `secret`, `emptyDir`, and `projectHostPath` volumes, and mount host paths at `/data` and `/var/run`. The policy does not allow privileged containers or a read-only root filesystem.
