 # Kubernetes Concept
Deployment is a Kubernetes resource for managing and updating containers. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
A Kubernetes Deployment creates and manages replica sets and updates them with new container images when a change is pushed. This process is done in a rolling update fashion, minimizing downtime and maintaining availability.

# Best Practices
- Use rolling updates and set `updateStrategy.type: RollingUpdate` in your Deployment manifest
- Configure `minReadySeconds` and `maxUnavailable` in the Deployment to control the number of available replicas during an update
- Use `readinessProbe` and `livenessProbe` to ensure the container is ready to serve traffic and to automatically restart unhealthy containers

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: my-app-container
          image: my-registry/my-app:latest
          ports:
            - containerPort: 80
          readinessProbe:
            probes:
              - exec:
                  command: ["/usr/local/bin/check-readiness"]
          livenessProbe:
            probes:
              - exec:
                  command: ["/usr/local/bin/check-liveness"]
      imagePullSecrets:
        - name: my-registry-secret
      containers:
      - name: my-app-container
        image: my-registry/my-app:latest
        ports:
          - containerPort: 80
        readinessProbe:
          probes:
            - exec:
                command: ["/usr/local/bin/check-readiness"]
        livenessProbe:
          probes:
            - exec:
                command: ["/usr/local/bin/check-liveness"]
        env:
          - name: MY_APP_ENV_VAR
            value: "value"
        volumeMounts:
          - mountPath: "/var/app/my-app"
            name: my-app-volume
      volumes:
        - name: my-app-volume
          configMap:
            name: my-app-config
```
In this example, we have a Deployment named `my-app-deployment` with 3 replicas. The container is pulled from `my-registry/my-app:latest` image and listens on port 80. We have defined both readiness and liveness probes, which are used to determine if the container is ready to serve traffic and to automatically restart unhealthy containers. We also use an image pull secret named `my-registry-secret` for secure image pulls. The container's environment variable and volume mount are also configured.
