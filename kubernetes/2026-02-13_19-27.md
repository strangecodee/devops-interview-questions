 # Kubernetes Concept
Kubernetes Secret is an object used to store and manage sensitive information such as passwords, OAuth tokens, and SSH keys.

# Explanation
Secrets in Kubernetes are encrypted at rest and decrypted on the container runtime as an environment variable or as a file in the container. This ensures that sensitive data is not exposed in plaintext in the Kubernetes manifest files. The secret can be mounted as a volume in a container for usage.

# Best Practices
- Create a separate namespace for storing secrets.
- Use Kubernetes RBAC to control access to the secrets.
- Use Kubernetes Secret Encryption at Rest for added security.

# YAML Example
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: my-secret
  namespace: my-secret-namespace
  creationTimestamp: "{{ .Time.Now }}"
type: Opaque
data:
  user: {{ index .values "user.password" | b64enc }}
  apiKey: {{ index .values "api.key" | b64enc }}
```
In this example, we create a Kubernetes Secret named `my-secret` with two key-value pairs, `user` and `apiKey`, which are encrypted and stored in the Secret object. The namespace for the Secret is set to `my-secret-namespace`. This Secret can be mounted as a volume in a container and used as environment variables during container runtime.
