 # Kubernetes Concept
Kubernetes DaemonSet is a type of Kubernetes deployment that ensures a copy of the specified Pod is running on all nodes in the cluster.

# Explanation
DaemonSets are useful when running processes that require special access to the node, such as monitoring agents, logging agents, or storage nodes. They ensure that a specified number of replicas of a pod are running on every node in the cluster. If a node is added or removed from the cluster, the DaemonSet will automatically adjust the pods on that node.

# Best Practices
- Use DaemonSets for stateless applications or services that need to run on every node.
- Use the `replicas` field to specify the desired number of pods per node.
- Use labels to select specific nodes or pods.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
  labels:
    app: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
        - containerPort: 443
        nodeSelector:
          beta.kubernetes.io/os: linux
          kubernetes.io/arch: amd64
      tolerations:
      - key: NodeRole.kubernetes.io/master
        operator: Exists
        effect: NoSchedule
      - key: "com.example.toleration-key"
        operator: Exists
        effect: PreferNoSchedule
---
kind: Service
apiVersion: v1
metadata:
  name: my-daemonset-service
spec:
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 80
    name: http
  type: ClusterIP
```
This YAML defines a DaemonSet named `my-daemonset` with a container named `my-container` running image `my-image:latest`. The service associated with the DaemonSet is defined in the same file and listens on port 80. The DaemonSet includes labels for the app name and node selector for specific node types. The `tolerations` field specifies tolerations for the node roles and custom tolerations.
