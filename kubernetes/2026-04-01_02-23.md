# Kubernetes Concept
Kubernetes DaemonSet is a way to ensure that a specified number of replicas of a Pod are running in each node of the cluster, regardless of node label changes or node joins and leaves.

# Explanation
A DaemonSet ensures that a copy of the specified Pod is running on all nodes in the cluster, maintaining an equal distribution. It is useful when you have a sidecar container that needs to run on every node in the cluster, such as a logging agent or a monitoring agent.

# Best Practices
- Label the nodes to create affinity for the DaemonSet to run on specific nodes if needed.
- Use a rolling update strategy to minimize downtime during updates.
- Monitor the status of the DaemonSet to ensure the desired state is maintained.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: phoenix-logging-agent
spec:
  selector:
    matchLabels:
      app: phoenix-logging-agent
  template:
    metadata:
      labels:
        app: phoenix-logging-agent
    spec:
      containers:
      - name: logging-agent
        image: logging-agent:latest
        ports:
        - containerPort: 5000
        readinessProbes:
        - exec:
            command: ["/usr/local/bin/check-ready.sh"]
        - initialDelaySeconds: 5
          periodSeconds: 5
```
In this example, a DaemonSet named `phoenix-logging-agent` is defined. The DaemonSet ensures that a single instance of the `logging-agent` container is running on each node in the cluster, with the label `app: phoenix-logging-agent`. The container runs on port 5000, and its readiness is checked using the script `/usr/local/bin/check-ready.sh` with an initial delay of 5 seconds and a period of 5 seconds.
