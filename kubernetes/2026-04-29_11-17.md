# Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
A Deployment creates and manages replicas of a containerized application. It can perform rolling updates or rollbacks, and it includes a built-in self-healing mechanism that restarts containers that fail or become unresponsive.

# Best Practices
- Use labels to select and manage sets of pods.
- Define resource requests and limits to prevent noisy neighbor effect.
- Use rolling updates for minimal downtime.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-sre
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: myregistry/phoenix:latest
        ports:
        - containerPort: 8080
        readinessProbes:
        - httpGet:
            path: /health
            port: 8080
---
kind: Service
apiVersion: v1
metadata:
  name: phoenix-sre
spec:
  selector:
    app: phoenix
  ports:
  - port: 80
    targetPort: 8080
  type: LoadBalancer
```
This YAML file creates a Deployment with three replicas of a container named `phoenix`. The container is pulled from a registry and listens on port 8080. The readiness probe checks the health of the container by sending an HTTP request to the `/health` endpoint. The Service exposes the Deployment as a Kubernetes service with an external IP address.
