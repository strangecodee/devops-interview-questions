 # Kubernetes Concept
Kubernetes DaemonSet ensures that a specified number of replicas of a pod are running on all nodes in the cluster.

# Explanation
A DaemonSet runs a copy of the specified pod on each node in the cluster, maintaining a consistent set of pods across the nodes. This is useful for running services that require access to the node's local resources, such as a logging agent or a monitoring agent.

# Best Practices
- Use labels to select nodes where you want to run the DaemonSet.
- Use health checks and readiness probes to ensure the DaemonSet pods are running and ready.
- Use rolling updates to minimize downtime during DaemonSet updates.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-daemonset
  labels:
    app: logging
spec:
  selector:
    matchLabels:
      app: logging
  template:
    metadata:
      labels:
        app: logging
    spec:
      containers:
      - name: logging-container
        image: logging-image:latest
        ports:
        - containerPort: 514
          name: udp
        - containerPort: 5161
          name: tcp
        readinessProbes:
        - exec:
            command: ["/usr/bin/logger", "--test"]
            intervalSeconds: 5
        livenessProbes:
        - exec:
            command: ["/usr/bin/logger", "--test"]
            intervalSeconds: 15
```
This example creates a DaemonSet named `logging-daemonset` that runs a logging container on all nodes in the cluster. The container listens on UDP port 514 and TCP port 5161. The `readinessProbes` and `livenessProbes` are used to ensure that the container is running and ready.
