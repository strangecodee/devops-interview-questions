 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures availability, scalability, and rollbacks.

# Explanation
A Deployment creates and manages replicas of a desired Pod specification. When new replicas are created, Kubernetes rolls out updates in batches to minimize downtime. Rollbacks can be triggered if a new release fails.

# Best Practices
- Use `RollingUpdateStrategy` to minimize downtime during updates.
- Set up `HorizontalPodAutoscaler` for automatic scaling based on demand.
- Configure `LivenessProbe` and `ReadinessProbe` for health checks.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nebula-sre
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nebula
  template:
    metadata:
      labels:
        app: nebula
    spec:
      containers:
      - name: nebula
        image: nebula:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
---
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: nebula-sre
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nebula-sre
  minReplicas: 1
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
```
This YAML file defines a Deployment named `nebula-sre` with 3 replicas. It uses a container image named `nebula:latest` and sets up liveness and readiness probes. Additionally, there is a HorizontalPodAutoscaler to automatically scale the Deployment based on CPU utilization.
