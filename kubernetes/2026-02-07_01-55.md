 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas for a pod are running on all nodes in the cluster.

# Explanation
DaemonSets are useful for deploying processes that require access to a specific node label, such as a logging agent or a monitoring agent. By ensuring that a pod is running on every node in the cluster, DaemonSets can provide consistent and uniform behavior across the cluster.

# Best Practices
- Use labels to target specific nodes or node labels when creating a DaemonSet.
- Use read-only filesystems for containers in DaemonSets to prevent data loss and maintain consistency.
- Use health checks and probes to ensure that the containers in DaemonSets are running and healthy.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-agent
spec:
  selector:
    matchLabels:
      app: logging-agent
      node-role.kubernetes.io/worker: ""
  template:
    metadata:
      labels:
        app: logging-agent
    spec:
      containers:
      - name: logging-container
        image: logging-agent:latest
        volumeMounts:
        - mountPath: /var/log
          name: logging-volume
          readOnly: true
        ports:
        - containerPort: 514
          name: udp
          protocol: UDP
      nodeSelector:
        beta.kubernetes.io/os: linux
        beta.kubernetes.io/arch: amd64
status:
  updatedReplicas: 5
  availableReplicas: 5
  replicas: 5
```
In this example, we create a DaemonSet named "logging-agent" that runs a logging agent container on all nodes with the label "node-role.kubernetes.io/worker: """. The container is mounted to a read-only filesystem at the path "/var/log" to prevent data loss and maintain consistency. The container listens on UDP port 514 for log data. The DaemonSet is configured to maintain 5 replicas running at all times.
