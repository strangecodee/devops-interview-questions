 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications with desired state and rolling updates.

# Explanation
A Deployment creates and manages a set of replicas for an application, maintaining a desired state by creating new replicas when old ones die or are updated. Kubernetes continually rolls out updates to the replicas and rolls back if a problem occurs.

# Best Practices
- Use a single container per deployment.
- Use rolling updates with a small update size for minimal downtime.
- Configure rolling updates to update a percentage of the replicas at a time.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-webapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: forge-webapp
  template:
    metadata:
      labels:
        app: forge-webapp
    spec:
      containers:
      - name: forge-webapp
        image: forge/webapp:v1
        ports:
        - containerPort: 80
          name: http
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
---
apiVersion: v1
kind: Service
metadata:
  name: forge-webapp-service
spec:
  selector:
    app: forge-webapp
  ports:
  - port: 80
    targetPort: 80
```
This example demonstrates a simple Deployment with a replica set of 3, using a container image `forge/webapp:v1`, and exposes port 80 with the corresponding service. Liveness and readiness probes are configured to ensure the container is healthy and ready for traffic.
