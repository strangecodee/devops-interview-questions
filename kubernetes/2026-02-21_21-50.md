 # Kubernetes Concept
Kubernetes Secret is an object used to store and manage sensitive information such as passwords, OAuth tokens, and SSH keys.

# Explanation
Secrets in Kubernetes are encrypted at rest and decrypted on-the-fly when needed. They provide a secure way to store and manage sensitive data without exposing it in plain text in your configuration files. Kubernetes secrets can be mounted as files into containers, or used as an environment variable or a command-line argument.

# Best Practices
- Use long, complex passwords and rotate them regularly.
- Avoid storing sensitive data in plain text configuration files.
- Use Kubernetes secret management to store and manage sensitive data.
- Use a separate secret for each environment or application.

# YAML Example
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: my-app-db-password
  namespace: my-namespace
type: Opaque
data:
  password: cGFzc3dvcmQ= # Base64 encoded password: "my-secret-password"
```
In this example, we create a new Kubernetes secret named `my-app-db-password` in the `my-namespace` namespace. The secret type is set to `Opaque`, which means the data is encrypted and not human-readable. The `password` key contains the sensitive data, which is encoded in Base64. The actual password is "my-secret-password".
