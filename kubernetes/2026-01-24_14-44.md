 # Kubernetes Concept
Kubernetes DaemonSet is a type of Kubernetes deployment that ensures a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
DaemonSets are ideal for deploying processes that run as system daemons, such as monitoring agents, log collectors, or container runtimes. They ensure that every node in the cluster runs a specified number of replicas of the pod. This ensures that all nodes have the same daemon running and that if a pod crashes, a new one is automatically created to maintain the desired state.

# Best Practices
- Use `restartPolicy: OnFailure` to ensure that a new pod is only started when the previous one fails.
- Use `securityContext` to set the container security context to restrict the capabilities and permissions of the container.
- Use `nodeSelector` to target specific nodes in the cluster for the DaemonSet.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemon
  template:
    metadata:
      labels:
        app: my-daemon
    spec:
      containers:
        - name: my-daemon-container
          image: my-daemon-image:latest
          securityContext:
            privileged: false
            runAsUser: 1000
          restartPolicy: OnFailure
      nodeSelector:
        beta.kubernetes.io/os: linux
  updateStrategy:
    rollingUpdate:
      type: RollingUpdate
```
In this example, we create a DaemonSet named `my-daemonset` that runs a container named `my-daemon-container` using the image `my-daemon-image:latest`. The container runs with a non-privileged user (`runAsUser: 1000`) and is restarted only when it fails (`restartPolicy: OnFailure`). The DaemonSet is targeted to nodes running the Linux operating system (`nodeSelector: beta.kubernetes.io/os: linux`). The `updateStrategy` is set to perform a rolling update to minimize downtime.
