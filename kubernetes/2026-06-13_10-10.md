 # Kubernetes Concept
Deployment is a form of declarative updates for Pods and ReplicaSets in Kubernetes. It ensures that a specified number of replicas are running at any given time.

# Explanation
A Kubernetes Deployment creates or updates Pods in a cluster by controlling replicas, updating their containers, and rolling out new versions. It keeps a specified number of replicas running at any given time, ensuring high availability and scalability. Deployments also support rolling updates and can roll back to previous versions if necessary.

# Best Practices
- Use rolling updates to minimize downtime and ensure a smooth transition between versions.
- Set up health checks to monitor the readiness and liveness of your containers.
- Use labels for efficient management and organization of your deployments.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-deployment
  labels:
    app: forge
spec:
  selector:
    matchLabels:
      app: forge
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  replicas: 3
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: forge
        image: forge:latest
        ports:
        - containerPort: 8080
          protocol: TCP
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
```
This Deployment example named `forge-deployment` has three replicas, labels `app: forge`, and uses a RollingUpdate strategy for updating containers. It sets up both liveness and readiness probes and listens on port 8080.
