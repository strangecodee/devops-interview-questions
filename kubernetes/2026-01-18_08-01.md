 # Kubernetes Concept
Kubernetes DaemonSet is a deployment that ensures a copy of a specified Pod runs on all nodes in the cluster.

# Explanation
DaemonSets run a user-defined number of replicas of a Pod on each node in the cluster, ensuring that the same pod definition is running consistently across all nodes. This is particularly useful for running node daemons such as monitoring agents or logging collectors.

# Best Practices
- Define health checks via `livenessProbe` and `readinessProbe` to ensure container readiness and availability.
- Use `replicas` to define the desired state of the DaemonSet and `maxSurge` and `maxUnavailable` to control the update strategy.
- Keep container images up-to-date using continuous delivery pipelines or automatic updates.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemon
  template:
    metadata:
      labels:
        app: my-daemon
    spec:
      containers:
      - name: my-container
        image: forge/my-container:latest
        ports:
        - containerPort: 80
        livenessProbe:
          exec:
            command: ["/usr/local/bin/check-liveness.sh"]
          periodSeconds: 30
        readinessProbe:
          exec:
            command: ["/usr/local/bin/check-readiness.sh"]
          periodSeconds: 15
  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
```
This YAML defines a DaemonSet named `my-daemonset` that runs a container named `my-container` using the `forge/my-container:latest` image. It also includes `livenessProbe` and `readinessProbe` definitions and a `RollingUpdate` strategy with `maxSurge` and `maxUnavailable` limits.
