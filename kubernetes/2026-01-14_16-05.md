 # Kubernetes Concept
Deployment is a Kubernetes object used to create and manage containerized applications. It ensures the desired number of replicas are running and available, and can perform updates with minimal downtime.

# Explanation
A Kubernetes Deployment manages the lifecycle of a set of replica Pods. It creates new replicas and updates them with new container images, while also removing old replicas that have finished updating. This allows for rolling updates and progressive rollouts.

# Best Practices
- Use `strategy.type: RollingUpdate` to update replicas in batches.
- Set `maxSurge` and `maxUnavailable` to control the number of new and old replicas during updates.
- Use `readinessProbe` and `livenessProbe` to determine the health of the containers.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
spec:
  selector:
    matchLabels:
      app: phoenix
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: aws_account_id.dkr.ecr.region.amazonaws.com/my-image:latest
        ports:
        - containerPort: 8080
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "nc -z -w1 8080 < /dev/null || exit 1"]
            periodSeconds: 5
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "/usr/local/bin/check-health.sh"]
            periodSeconds: 15
```
This example creates a `Deployment` named `phoenix-deployment` with 3 replicas, using an Amazon Elastic Container Registry image. It sets the update strategy to `RollingUpdate`, with a maximum surge of 1 replica and no maximum unavailable replicas. The `Container` includes a `readinessProbe` and `livenessProbe` to monitor its health.
