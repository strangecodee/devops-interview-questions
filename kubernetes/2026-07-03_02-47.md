 # Kubernetes Concept
Deployment is a Kubernetes resource for describing and creating a set of replicas for a desired state of a containerized application.

# Explanation
A Deployment maintains a specified number of replicas for an application, creating new replicas if needed to maintain the desired state, and removing old replicas that have been terminated and are no longer needed. It also provides a way to update the application by creating a new ReplicaSet, which ensures a smooth upgrade with zero downtime.

# Best Practices
- Use rolling updates with `strategy.type: RollingUpdate` to minimize downtime.
- Set a proper number of replicas to ensure availability and scalability.
- Use a health check in the container's liveness and readiness probes.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  selector:
    matchLabels:
      app: nginx
  replicas: 3
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.14.2
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 10
        readinessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 15
          periodSeconds: 10
```
