 # Kubernetes Concept
Kubernetes ConfigMaps create and manage non-confidential data as key-value pairs. They decouple application configurations from container images.

# Explanation
ConfigMaps allow you to store and manage application configuration data outside of containers. Kubernetes can mount ConfigMaps as environment variables, command-line arguments, or as files in containers. This approach separates configuration data from container images, making it easier to manage, update, and deploy applications.

# Best Practices
- Store sensitive data in Kubernetes Secrets instead of ConfigMaps.
- Use ConfigMaps for non-sensitive data and application configurations.
- Update ConfigMaps to modify application configurations without redeploying containers.

# YAML Example
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: example-configmap
data:
  app_config.yaml: |-
    server:
      port: 8080
    database:
      user: user1
      password: password1
```
This ConfigMap named 'example-configmap' contains a single data item named 'app_config.yaml'. The value of 'app_config.yaml' is a YAML-formatted multiline string, defining application server and database configurations. These configurations can be consumed by containers using the ConfigMap name and key, such as 'app_config.yaml' or 'database.password'.
