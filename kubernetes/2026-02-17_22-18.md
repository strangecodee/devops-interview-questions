 # Kubernetes Concept
This example demonstrates a `Monitoring` DaemonSet configuration for a vector logging agent called `loki`. Loki is an open-source, horizontally-scalable, highly-available, multi-tenant log aggregation system.

# Explanation
The DaemonSet ensures that a specified number of replicas of a container are running on each node in the cluster. In this YAML, we set up a Loki DaemonSet to monitor and collect logs from all nodes in our Kubernetes cluster.

# Best Practices
- Use `Labels` for selectors to ensure that the DaemonSet deploys the containers to the desired nodes.
- Configure `Replicas` to match the number of nodes in the cluster to ensure full coverage for all logs.
- Use `Volumes` to persist Loki data for backups and data recovery.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: loki
  labels:
    app: loki
spec:
  selector:
    matchLabels:
      app: loki
  template:
    metadata:
      labels:
        app: loki
    spec:
      volumes:
      - name: loki-data
        persistentVolumeClaim:
          claimName: loki-pvc
      containers:
      - name: loki
        image: gcr.io/google-containers/loki:latest
        env:
        - name: LOG_LEVEL
          value: info
        ports:
        - containerPort: 3100
        volumeMounts:
        - mountPath: /mnt/data
          name: loki-data
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: loki-pvc
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
```
This YAML example creates a DaemonSet for Loki, sets up a PersistentVolumeClaim to ensure data persistency, and configures the container to run with the specified environment variables, ports, and volume mounts.
