 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications. It creates and maintains a specified number of replicas of a container image, ensuring high availability and scalability.

# Explanation
A Kubernetes Deployment creates and manages the desired state of a set of replicas for a containerized application. It provides rollouts, rollbacks, and self-healing capabilities, making it an essential building block for running applications in a production environment.

# Best Practices
- Use Helm charts or a GitOps tool like FluxCD for managing your Deployments.
- Set up automated CI/CD pipelines to ensure that your code is tested and deployed in a consistent and reliable manner.
- Use resource limits and requests to ensure that your application runs efficiently and doesn't consume unnecessary resources.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
        env:
        - name: ENV_VAR_1
          value: "value1"
        readinessProbe:
          httpGet:
            path: /healthz
            port: 80
        livenessProbe:
          httpGet:
            path: /liveness
            port: 80
---
apiVersion: v1
kind: Service
metadata:
  name: my-app
spec:
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```
This Deployment creates three replicas of a containerized application named `my-app` using the specified image. It sets up readiness and liveness probes to ensure that the application is healthy and ready to serve traffic. The associated Service exposes the application on port 80.
