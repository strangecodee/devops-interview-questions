 # Kubernetes Concept
Deployment is a Kubernetes object used for managing and updating containerized applications. It ensures the desired number of replicas are running, and it rolls out updates in a controlled manner.

# Explanation
A Deployment creates and manages the desired state of a set of replicas, updating them to a new version when a new image is tagged or the configuration is changed. Rollouts can be performed either in batches or all at once, and the application is rolled back if a new version fails.

# Best Practices
- Use `strategicRollout` with `type: RollingUpdate` for gradual updates.
- Set `imagePullPolicy: Always` to ensure the latest image is used.
- Use `readinessProbe` and `livenessProbe` to monitor the application's health and readiness.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: forge
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: forge
        image: forge:latest
        ports:
        - containerPort: 80
        readinessProbes:
        - exec:
            command: ["/usr/local/bin/healthcheck.sh"]
            intervalSeconds: 5
            timeoutSeconds: 3
        livenessProbes:
        - exec:
            command: ["/usr/local/bin/livenesscheck.sh"]
            intervalSeconds: 30
            timeoutSeconds: 5
          imagePullPolicy: Always
---
apiVersion: v1
kind: Service
metadata:
  name: forge-service
spec:
  selector:
    app: forge
  ports:
  - name: http
    port: 80
    targetPort: 80
  type: LoadBalancer
```
This YAML demonstrates a Deployment that manages three replicas of the `forge` application, using the `forge:latest` image. The readiness and liveness probes are defined to monitor the application's health and readiness. The image is pulled always to ensure the latest version is used. Additionally, a Service is created to expose the application on port 80 using a LoadBalancer.
