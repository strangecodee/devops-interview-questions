 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas of a Pod are running on all nodes in the cluster.

# Explanation
DaemonSets are useful for running processes that should be present on every node in a cluster, such as node exporters for monitoring or logging agents. The DaemonSet controller ensures that the specified number of replicas of the Pod are running and replaces any that may have been terminated due to node failure or eviction.

# Best Practices
- Use a DaemonSet for nodes that require specific daemons or agents to be running on every node in the cluster.
- Use labels to select the nodes where the DaemonSet should be applied.
- Use readiness and liveness probes to ensure that the DaemonSet is running correctly and ready to accept traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
  labels:
    app: my-daemon
spec:
  selector:
    matchLabels:
      app: my-daemon
  template:
    metadata:
      labels:
        app: my-daemon
    spec:
      containers:
      - name: my-daemon
        image: my-daemon:latest
        ports:
        - containerPort: 80
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 5
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 30
```
In this example, we define a DaemonSet named "my-daemonset" with a container named "my-daemon" that runs on every node in the cluster. The DaemonSet uses labels to select the nodes and the container runs on port 80 with readiness and liveness probes to ensure that it is running correctly.
