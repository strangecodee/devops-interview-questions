 # Kubernetes Concept: Deployment
Deployments in Kubernetes manage the lifecycle of containers by creating and updating replicas in a pod.

# Explanation
A Deployment creates and manages instances of a desired Pod template using replicas, updates, and self-healing. Replicas maintain availability and scale the application. Updates ensure the desired state of the application by replacing old replicas with new ones. Self-healing automatically restarts containers that fail or become unresponsive.

# Best Practices
- Use rolling updates to minimize downtime and maintain availability.
- Configure health checks and readiness probes for successful updates.
- Use labels for easy management and selective scaling.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse-deployment
  labels:
    app: eclipse
spec:
  selector:
    matchLabels:
      app: eclipse
  replicas: 3
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
      - name: eclipse
        image: eclipse:latest
        ports:
        - containerPort: 8443
          name: http
        livenessProbe:
          httpGet:
            path: /
            port: 8443
          initialDelaySeconds: 30
          periodSeconds: 10
```
This deployment creates a new eclipse application with three replicas. It sets labels for easy management, and the liveness probe checks the health of the application. Rolling updates can be done using kubectl without changing the YAML.
