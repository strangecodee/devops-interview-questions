 # Kubernetes Concept
This example demonstrates a Kubernetes `Deployment` with a `PodMonitor` for monitoring liveness and readiness probes using the `Prometheus` stack.

# Explanation
The `Deployment` creates and manages a set of replica `Pods` with a stable state. The `PodMonitor` is used to monitor the health of the `Pods` based on defined probes. In this case, we'll be monitoring both the liveness and readiness probes of the `Pods`. The `Prometheus` stack, consisting of a `Prometheus` server, a `ServiceMonitor`, and a `PrometheusAdapter`, is used to collect and store the monitoring data.

# Best Practices
- Ensure that the liveness and readiness probes are properly configured in the container's image or configuration files.
- Set the `initialDelaySeconds` and `periodSeconds` values appropriately for the `PodMonitor`.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-registry/my-app:latest
        ports:
        - containerPort: 80
        livenessProbe:
          httpGet:
            path: /healthz
            port: 80
        readinessProbe:
          httpGet:
            path: /ready
            port: 80
---
apiVersion: monitoring.coreos.com/v1
kind: PodMonitor
metadata:
  name: my-app-pod-monitor
spec:
  selector:
    matchLabels:
      app: my-app
  endpoints:
  - port: http
    path: /metrics
  interval: 15s
  scrapeTimeout: 5s
  timeout: 10s
---
apiVersion: v1
kind: Service
metadata:
  name: prometheus
spec:
  selector:
    app: prometheus
  ports:
  - name: web
    port: 9090
    targetPort: 9090
---
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: my-app-service-monitor
spec:
  selector:
    matchLabels:
      app: my-app
  endpoints:
  - port: http
    path: /metrics
  interval: 15s
---
apiVersion: configmaps/v1
kind: ConfigMap
metadata:
  name: prometheus-config
data:
  prometheus.yml: |
    # Prometheus configuration
    scrape_configs:
    - job_name: 'my-app'
      static_configs:
      - targets: ['my-service:9090']
```
In this example, the `Deployment` creates and manages three replicas of the `my-app` container. The `PodMonitor` is used to monitor the health of the `Pods` based on their liveness and readiness probes. The `Prometheus` server, configured in the `ConfigMap`, collects and stores the monitoring data using the defined `ServiceMonitor` and `Service`.
