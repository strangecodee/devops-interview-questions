 # Kubernetes Concept
This Kubernetes YAML example demonstrates a Horizontal Pod Autoscaler (HPA) for a deployment of Nginx pods, which is used for load balancing and automatic scaling based on CPU utilization.

# Explanation
The Kubernetes Horizontal Pod Autoscaler (HPA) is a built-in controller that automatically scales the number of replicas in a replication controller, deployment, replica set or statefulset based on observed CPU utilization. This example demonstrates how to set up an HPA for an Nginx deployment.

# Best Practices
1. Define appropriate metrics for scaling, such as CPU utilization, memory usage, or custom metrics.
2. Set a minimum and maximum number of replicas to prevent unwanted scaling.
3. Monitor and adjust scaling thresholds based on workload requirements.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80
---
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: nginx-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nginx-deployment
  minReplicas: 3
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      targetAverageUtilization: 50
```
In this example, a Deployment named `nginx-deployment` is created with three replicas. The HorizontalPodAutoscaler named `nginx-hpa` is then defined, which targets the `nginx-deployment` and sets the minimum and maximum number of replicas. The HPA is configured to scale based on observed CPU utilization, with a target average utilization of 50%.
