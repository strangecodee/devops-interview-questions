 # Kubernetes Concept
Deployment is a Kubernetes object used for updating and rolling out applications. It ensures the desired state of the application by creating or updating Pods.

# Explanation
The Deployment resource is used to declaratively create and manage replicas of a desired application. When you change the container image in the Deployment YAML file, Kubernetes will create a new version of the Pod, roll out the update, and roll back if necessary to ensure a zero-downtime deployment.

# Best Practices
- Use rolling updates with a small update strategy to minimize downtime and allow for progressive validation of changes.
- Set up a deployment strategy with a minimum number of replicas for availability and a maximum number to prevent overloading the cluster.
- Use Kubernetes labels and selectors to manage and scale applications based on specific criteria.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: registry.example.com/phoenix:v1.0.0
        ports:
        - containerPort: 8080
          name: http
        livenessProbe:
          httpGet:
            path: /health
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 5
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 5
```
In this example, a Deployment named 'phoenix' is defined. It has a desired state of three replicas and uses labels for easy management. The container uses an image from a registry, and liveness and readiness probes are set up to ensure the health of the application.
