 # Kubernetes Concept
Deployment is a kind of Kubernetes resource for describing and creating a set of replicas for a desired number of Pods.

# Explanation
A Deployment creates or updates Pods in a replicaset according to the defined template. It ensures availability of the application by creating new replicas if old ones fail. The controller continuously watches the desired state and makes adjustments to reach and maintain the desired pod count.

# Best Practices
- Use rolling updates to minimize downtime and ensure zero-downtime deployments.
- Set up a rolling update strategy with a percentage of new replicas in the initial batch to avoid unexpected errors.
- Use labels for selectors to manage multiple deployments for a single application version.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse
  labels:
    app: eclipse
spec:
  replicas: 3
  selector:
    matchLabels:
      app: eclipse
  template:
    metadata:
      labels:
        app: eclipse
    spec:
      containers:
      - name: eclipse
        image: openjdk:8-jre-alpine
        ports:
        - containerPort: 8080
          name: http
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 10
```
This example demonstrates a Deployment that manages 3 replicas of an OpenJDK container with a liveness probe set up. The rolling update strategy and percentage of new replicas can be configured using the `strategy` and `updateStrategy` sections.
