 # Kubernetes Deployment
Create and manage containerized applications at scale.

# Explanation
A Kubernetes Deployment is used to create and manage replicas of a containerized application. It maintains a specified number of replicas by making sure that the desired number is always running and replacing any unhealthy replicas.

# Best Practices
- Use Rolling updates to minimize downtime and ensure zero-downtime deployment.
- Set up automatic scaling based on CPU or memory usage to ensure optimal resource utilization.
- Use labels to manage and select sets of pods for easier deployment and scaling.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: forge-nginx
  labels:
    app: forge
spec:
  replicas: 3
  selector:
    matchLabels:
      app: forge
  template:
    metadata:
      labels:
        app: forge
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80
          name: http
        - containerPort: 443
          name: https
        livenessProbe:
          httpGet:
            path: /
            port: 80
        readinessProbe:
          httpGet:
            path: /
            port: 80
```
This example creates a Kubernetes Deployment named `forge-nginx` with 3 replicas running the latest Nginx image. It sets up a liveness probe and readiness probe to ensure the containers are healthy and ready to serve requests.
