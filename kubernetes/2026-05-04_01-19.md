# Kubernetes Concept
This is an example of a Kubernetes Service using a LoadBalancer type, providing external access to a Kubernetes application.

# Explanation
A Kubernetes Service is an abstract definition of a policy to access a set of Pods, using a specific network protocol and port. Services provide stable IP addresses and DNS names for a set of Pods, enabling communication between components within a cluster. In this example, we'll use a LoadBalancer Service to distribute incoming traffic evenly across available Pods.

# Best Practices
- Use `clusterIP` Service type for internal communication, and `LoadBalancer` or `NodePort` for external access.
- Label your Pods to select which pods to expose through a Service.
- Use `externalTrafficPolicy.local` to direct traffic to pods on the same node, if desired.

# YAML Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: nebula-app
  labels:
    app: nebula
spec:
  selector:
    app: nebula
  ports:
  - name: http
    port: 80
    targetPort: 8080
  type: LoadBalancer
  externalTrafficPolicy: Local
```
