 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
DaemonSets are used to manage background services that require a pod to be running on each node in the cluster. By defining a DaemonSet, Kubernetes ensures that the desired number of replicas are running and replaces any that may be terminated or crashed. This is especially useful for services like logging agents or monitoring agents that need to be present on all nodes.

# Best Practices
- Define a DaemonSet for critical services that require availability on all nodes.
- Use labels to select nodes or pods for a DaemonSet.
- Set the `replicas` field to the number of nodes in the cluster to ensure one pod per node.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-agent
spec:
  selector:
    matchLabels:
      app: logging-agent
  template:
    metadata:
      labels:
        app: logging-agent
    spec:
      containers:
      - name: logging-agent
        image: logging-agent:latest
        ports:
        - containerPort: 514
        readinessProbe:
          exec:
            command: ["/usr/local/bin/check-status.sh"]
          intervalSeconds: 5
          timeoutSeconds: 1
replicas: 5
```
In this example, a DaemonSet named `logging-agent` is defined with a single container running the logging agent image. The `replicas` field is set to 5, which will ensure that the logging agent is running on five nodes. The `readinessProbe` checks the status of the container every 5 seconds and considers it ready if the `check-status.sh` script returns a successful exit code.
