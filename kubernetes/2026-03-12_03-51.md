 # Kubernetes Concept
Kubernetes DaemonSet ensures that a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
DaemonSets are used to maintain a consistent daemon process running on all nodes in a cluster. This is particularly useful for system services, such as a logging agent or a monitoring agent, as they need to be running on every node to collect data. DaemonSets manage the lifecycle of these pods, including rolling updates and rolling back to a previous version if necessary.

# Best Practices
- Use resource limits and requests to ensure that the daemon processes do not consume an excessive amount of resources.
- Implement readiness and liveness probes to monitor the status of the daemon process and ensure that it is running correctly.
- Use labels to target specific nodes, such as node labels for different environments or node selectors based on specific features.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-agent
  labels:
    app: logging-agent
spec:
  selector:
    matchLabels:
      app: logging-agent
  template:
    metadata:
      labels:
        app: logging-agent
    spec:
      containers:
      - name: logging-agent
        image: logging-agent:latest
        resources:
          limits:
            cpu: "0.5"
            memory: "512Mi"
          requests:
            cpu: "0.2"
            memory: "256Mi"
        ports:
        - containerPort: 514
        - containerPort: 515
        livenessProbe:
          exec:
            command: ["/usr/local/bin/check-liveness.sh"]
          intervalSeconds: 60
          timeoutSeconds: 10
        readinessProbe:
          exec:
            command: ["/usr/local/bin/check-readiness.sh"]
          intervalSeconds: 30
          timeoutSeconds: 5
```
This YAML file defines a DaemonSet named `logging-agent` that runs a logging agent container on every node in the cluster. The container image is specified as `logging-agent:latest`, and it is configured with CPU and memory limits and requests. The container has two ports, one for the logging agent at port 514 and another for the agent's UI at port 515. Liveness and readiness probes are used to monitor the status of the container and ensure that it is running correctly.
