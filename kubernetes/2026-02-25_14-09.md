 # Kubernetes Concept
This YAML example demonstrates a Kubernetes `HorizontalPodAutoscaler` (HPA) for an Nginx deployment, which automatically scales the number of replicas based on observed CPU utilization.

# Explanation
The HorizontalPodAutoscaler is a Kubernetes autoscaling component that adjusts the number of replicas of a Pod (or a set of Pods), based on observed CPU utilization. In this example, we will demonstrate how to create an HPA for an Nginx deployment. The autoscaler maintains a stable number of replicas based on the defined minimum and maximum limits and the current CPU utilization of the Pods.

# Best Practices
- Set up appropriate limits and targets for CPU and memory usage.
- Use a `livenessProbe` and a `readinessProbe` to ensure the health and readiness of your application.
- Use `podAntiAffinity` and `podAffinity` to ensure that certain Pods are not scheduled together or close to each other.

# YAML Example
```yaml
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: nginx-hpa
spec:
  selector:
    matchLabels:
      app: nginx
  minReplicas: 2
  maxReplicas: 5
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nginx
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
```
This example uses a HorizontalPodAutoscaler named `nginx-hpa` that targets the `nginx` Deployment. The autoscaler maintains between 2 and 5 replicas, and scales based on an average CPU utilization of 50%.
