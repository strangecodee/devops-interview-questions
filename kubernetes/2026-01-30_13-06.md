 # Kubernetes Concept
This example demonstrates a Kubernetes `HorizontalPodAutoscaler` (HPA) for a `Deployment` that manages a load balancer using an `ExternalTrafficPolicy` of `Local`.

# Explanation
The HPA automatically adjusts the number of replicas of a `Deployment` based on observed CPU utilization, which is defined by the `metrics` field. The `ExternalTrafficPolicy` is set to `Local` to route traffic to pods on the same node.

# Best Practices
1. Use `ExternalTrafficPolicy` for global services to distribute traffic evenly across multiple nodes.
2. Set appropriate `minReplicas` and `maxReplicas` limits for your HPA.
3. Monitor your applications' resource usage to ensure the HPA scales effectively.

# YAML Example
```yaml
apiVersion: autoscaling/v2beta2
kind: HorizontalPodAutoscaler
metadata:
  name: forge-loadbalancer
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: forge
  minReplicas: 3
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
  externalTrafficPolicy: Local
```
Here's a brief explanation of the YAML:

- The `apiVersion` is set to `autoscaling/v2beta2` for the HorizontalPodAutoscaler.
- `kind` is set to `HorizontalPodAutoscaler`.
- `metadata.name` is set to `forge-loadbalancer` for the HPA's name.
- `spec.scaleTargetRef` refers to the target `Deployment` named `forge`.
- `minReplicas` and `maxReplicas` are set to 3 and 10, respectively.
- The `metrics` section sets the metric to be based on CPU utilization, with an average target utilization of 50%.
- `externalTrafficPolicy` is set to `Local`.
