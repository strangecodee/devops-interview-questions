 # Kubernetes Concept
Deployment is a Kubernetes object used for deploying and managing containerized applications. It ensures availability, scalability, and rolling updates or rollbacks of an application.

# Explanation
A Deployment creates and manages replicas of a specified container image. It ensures that a specified number of replicas are running at any given time. Kubernetes Deployments provide mechanisms for rolling updates and rolling back to previous versions.

# Best Practices
- Use a Deployment for each unique container image and application.
- Define a rolling update strategy for smooth application updates.
- Configure a readiness and liveness probe to ensure application availability and health.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app-container
        image: my-registry/my-app:v1
        ports:
        - containerPort: 80
        readinessProbe:
          probes:
          - exec:
              command: ["/usr/local/bin/check-readiness"]
            intervalSeconds: 15
            timeoutSeconds: 5
        livenessProbe:
          probes:
          - exec:
              command: ["/usr/local/bin/check-liveness"]
            intervalSeconds: 30
            timeoutSeconds: 5
```
This example demonstrates a Deployment with three replicas for the container image `my-registry/my-app:v1`. It includes a readiness and liveness probe for checking application availability and health. The Deployment ensures that the desired number of replicas is running while managing updates and rollbacks.
