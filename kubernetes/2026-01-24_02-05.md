 # Kubernetes Concept
Deployment is a Kubernetes object used for managing containerized applications. It ensures that a specified number of replicas of a containerized application are running in the cluster and automatically creates or updates the Pods as needed.

# Explanation
The Deployment resource in Kubernetes manages the lifecycle of a set of Pods, creating new ones when necessary and removing old ones when they are no longer needed. It offers features like rolling updates, rollbacks, and progressively deploying new versions of an application.

# Best Practices
- Use `strategy.type: RollingUpdate` to update new replicas gradually and ensure minimal downtime.
- Set `progressDeadlineSeconds` and `maxSurge` to manage the update process and maintain application availability.
- Use `readinessProbe` and `livenessProbe` to ensure that containers are running correctly and ready to serve traffic.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
        readinessProbe:
          probeType: HttpGet
          path: /healthz
          port: 80
        livenessProbe:
          probeType: HttpGet
          path: /liveness
          port: 80
```
