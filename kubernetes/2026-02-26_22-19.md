 # Kubernetes Concept: Deploying a Horizontally Scalable Pod using ReplicaSets and Deployments

This concept demonstrates how to deploy a horizontally scalable application in a Kubernetes cluster using ReplicaSets and Deployments.

# Explanation

ReplicaSets ensure a specified number of replicas of a pod are running at any given time. Deployments manage the rollout and rollback of updates to these replicas. By combining these two Kubernetes resources, you can create a scalable, self-healing application.

# Best Practices
- Use Health Checks and Liveness Probes to ensure your application is running correctly.
- Implement a rolling update strategy to minimize downtime during deployment.
- Monitor the resource usage of your application and adjust replicas accordingly to maintain optimal performance.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  selector:
    matchLabels:
      app: my-app
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: my-app
          image: my-registry/my-image:latest
          ports:
            - containerPort: 80
          livenessProbe:
            httpGet:
              path: /healthz
              port: 80
          readinessProbe:
            httpGet:
              path: /ready
              port: 80
---
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: my-app
          image: my-registry/my-image:latest
          ports:
            - containerPort: 80
```
