 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications. It ensures the desired number of replicas are running and maintains application availability through rolling updates and rolling back.

# Explanation
Deployments manage the lifecycle of containerized applications by creating and updating pods in a cluster. Kubernetes continuously monitors the desired state and attempts to maintain it by creating or removing pods as needed. Rolling updates allow for smooth application upgrades, while rolling back allows for easy reverting to a previous version if necessary.

# Best Practices
- Use rolling updates for minimal downtime during application upgrades.
- Set resource limits to ensure fair usage and prevent resource contention.
- Use replicas to maintain high availability and ensure application resilience.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: myregistry/phoenix:latest
        ports:
        - containerPort: 8080
          protocol: TCP
        resources:
          limits:
            cpu: "1"
            memory: "512Mi"
          requests:
            cpu: "0.5"
            memory: "256Mi"
        readinessProbe:
          probeType: HTTP
          httpGet:
            path: /health
            port: 8080/tcp
          initialDelaySeconds: 5
          periodSeconds: 5
```
This example demonstrates a Deployment managing a containerized application named "phoenix" with 3 replicas, resource limits, and a readiness probe.
