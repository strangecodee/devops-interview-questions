 # Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas for a pod are running on all nodes in the cluster, making it ideal for running system daemons.

# Explanation
DaemonSets in Kubernetes provide a mechanism to ensure that a certain number of replicas of a pod run on each node in the cluster. This is particularly useful for running critical system daemons, such as monitoring agents or log collectors, that need to be present on every node. By defining a DaemonSet, we ensure that these daemon processes are constantly running and available on all nodes.

# Best Practices
- Design your DaemonSet to be resilient and self-healing.
- Use appropriate labels to ensure that your Daemons are scheduled on the right nodes.
- Implement rolling updates for minimal downtime.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: phoenix-monitoring
spec:
  selector:
    matchLabels:
      app: phoenix
      role: monitor
  template:
    metadata:
      labels:
        app: phoenix
        role: monitor
    spec:
      containers:
        - name: phoenix-monitor
          image: monitoring/phoenix:latest
          ports:
            - containerPort: 80
          readinessProbe:
            exec:
              command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
          startupProbes:
            - exec:
                command: ["/bin/sh", "-c", "sleep 30"]
```
This YAML file creates a DaemonSet named `phoenix-monitoring` with a single container named `phoenix-monitor`. The DaemonSet is designed to run the `monitoring/phoenix:latest` image on all nodes in the cluster. The containers listen on port 80 for incoming connections and use a readiness and startup probe to ensure they are healthy and ready to receive traffic.
