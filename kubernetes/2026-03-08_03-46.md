 # Kubernetes Concept
Deployments in Kubernetes provide a declarative way to create and manage containerized applications with desired state.

# Explanation
A Kubernetes Deployment creates and manages a set of replicas of a container, ensuring a specified number of instances are running at all times. It supports rolling updates and rollbacks, making it an excellent choice for zero-downtime application deployments.

# Best Practices
- Use labels for Deployments and selectors to manage and identify your replicas effectively.
- Set up rolling updates with a sufficient number of replicas to ensure minimum downtime.
- Monitor your application's health using readiness and liveness probes.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix
        image: phoenix:latest
        ports:
        - containerPort: 48080
        readinessProbe:
          probes:
          - httpGet:
              path: /health-check
              port: 8080
            initialDelaySeconds: 5
            periodSeconds: 5
            timeoutSeconds: 1
        livenessProbe:
          probes:
          - httpGet:
              path: /health-check
              port: 8080
            initialDelaySeconds: 15
            periodSeconds: 10
            timeoutSeconds: 1
```
This YAML file demonstrates a Deployment managing the `phoenix` application with 3 replicas, rolling updates, and readiness and liveness probes.
