 # Kubernetes Concept
Kubernetes DaemonSet ensures that a specified number of replicas of a pod are running on all nodes in the cluster.

# Explanation
A DaemonSet runs a user-defined number of replicas of a pod on each node in the cluster. This is useful when you want to run a system daemon such as a monitoring agent, logging agent, or storage pod, that needs to be present on all nodes. DaemonSets manage the lifecycle of these pods, including restarting them if they fail.

# Best Practices
- Use DaemonSets for critical system components that need to run on every node.
- Use labels to target specific nodes or node selectors to target nodes based on labels.
- Use rolling updates for DaemonSets to minimize downtime.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-logging-agent
  labels:
    app: my-logging-agent
spec:
  selector:
    matchLabels:
      app: my-logging-agent
  template:
    metadata:
      labels:
        app: my-logging-agent
    spec:
      containers:
      - name: my-logging-agent
        image: logging-agent:latest
        ports:
        - containerPort: 514
        livenessProbe:
          exec:
            command: ["/usr/local/bin/check-logging-agent.sh"]
          intervalSeconds: 30
      tolerations:
      - key: NodeRole.kubernetes.io/master
        effect: PreferNoSchedule
---
apiVersion: v1
kind: Service
metadata:
  name: my-logging-agent
spec:
  selector:
    app: my-logging-agent
  ports:
  - name: grpc
    port: 514
    targetPort: 514
  type: ClusterIP
```
This YAML file defines a DaemonSet named "my-logging-agent" with a specification that matches nodes labeled "app: my-logging-agent". The template defines a container that runs the logging agent image and exposes port 514. The liveness probe ensures the container is running and restarts it if it's not. The Service creates a ClusterIP to enable communication between the logging agents on different nodes.
