 # Kubernetes Concept
Deployment is a Kubernetes resource for managing containerized applications by creating and updating their pods.

# Explanation
A Deployment creates and manages replicas of a containerized application. When you make changes to the container image or configuration, the Deployment will roll out the update to the replicas in batches, ensuring high availability and seamless scaling.

# Best Practices
- Use a rolling update strategy to minimize downtime.
- Set up resource limits and requests to ensure your application has the necessary resources.
- Monitor your Deployments to ensure they are running smoothly and respond promptly to any issues.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: example-vector-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: example-vector
  template:
    metadata:
      labels:
        app: example-vector
    spec:
      containers:
      - name: example-vector
        image: vector/vector:v1.11.1
        ports:
        - containerPort: 12345
          protocol: TCP
        resources:
          limits:
            cpu: "1"
            memory: "512Mi"
          requests:
            cpu: "0.5"
            memory: "256Mi"
        readinessProbes:
        - exec:
            command: ["curl", "--fail", "/healthz"]
            intervalSeconds: 5
            timeoutSeconds: 2
```
In this example, we create a Kubernetes Deployment named `example-vector-deployment` that runs the Vector search engine with three replicas. We set up resource limits and requests, and use a readiness probe to check the health of the container.
