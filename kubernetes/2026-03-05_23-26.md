 # Kubernetes Concept
This example demonstrates a Kubernetes DaemonSet for running a Chaos Engineering agent, `gremlin`, to inject controlled failures into a Kubernetes cluster for improved system resiliency.

# Explanation
DaemonSets ensure that a specified number of replicas of a pod run on all nodes in a cluster, providing consistent application availability and availability of system services. In this scenario, we use a DaemonSet to manage the `gremlin` Chaos Engineering agent for performing controlled experiments to test the cluster's readiness and responsiveness.

# Best Practices
- Run Chaos Engineering agents in separate namespaces or as DaemonSets to isolate their activities from production workloads.
- Regularly review and update your Chaos Engineering experiments to ensure they represent the current state of your applications and infrastructure.
- Monitor and log Chaos Engineering activities to quickly address any adverse effects on your cluster.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: gremlin-daemonset
  namespace: chaos-engineering
spec:
  selector:
    matchLabels:
      app: gremlin
  template:
    metadata:
      labels:
        app: gremlin
    spec:
      containers:
      - name: gremlin
        image: gremlin/gremlin:latest
        ports:
        - containerPort: 2182
          protocol: TCP
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "gremlin --version || exit 0"]
            intervalSeconds: 5
          failureThreshold: 3
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "gremlin --version || exit 0"]
            intervalSeconds: 15
      restartPolicy: Always
```
This YAML file defines a DaemonSet named `gremlin-daemonset` using version `v1` of the `apps` API. The DaemonSet's containers run the `gremlin:latest` image, which is responsible for performing Chaos Engineering experiments. The `readinessProbes` and `livenessProbes` ensure the containers are healthy and ready to accept traffic, respectively. The DaemonSet will automatically restart any containers that fail, ensuring high availability.
