 # Kubernetes Deployment
A Kubernetes Deployment creates and manages a set of replica Pods with a desired state.

# Explanation
Deployments in Kubernetes provide declarative updates for replicated stateful sets of containers. They automatically create new replicas with the latest container image version and remove old ones, ensuring a desired state for the application.

# Best Practices
- Use rolling updates for zero-downtime deployments.
- Set up a deployment strategy (RollingUpdate or Recreate) based on the application requirements.
- Use selectors to label and target the Pods to be updated.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: phoenix-deployment
  labels:
    app: phoenix
spec:
  replicas: 3
  selector:
    matchLabels:
      app: phoenix
  template:
    metadata:
      labels:
        app: phoenix
    spec:
      containers:
      - name: phoenix-container
        image: 1772861682/my-custom-image:latest
        ports:
        - containerPort: 8080
          name: http
      imagePullSecrets:
      - name: aws-secrets
```
In this example, we create a Deployment with the name `phoenix-deployment` that runs 3 replicas for a container called `phoenix-container`. The container uses the image `1772861682/my-custom-image:latest` and listens on the port `8080`. We use an `imagePullSecret` to securely pull the image from a private registry hosted on AWS Elastic Container Registry.
