# Kubernetes Concept: DaemonSet
A DaemonSet ensures that a specified number of replicas of a pod are running on each node in a cluster.

# Explanation
DaemonSets are used to manage background services that must run on every node in a cluster. They help in maintaining a consistent state across the cluster by managing and automatically replacing pods that may fail or get evicted.

# Best Practices
- Use labels to select the nodes where your DaemonSet should run.
- Use the `replicas` field to define the number of replicas per node.
- Use the `revisionHistoryMax` field to maintain a specific number of revisions.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: my-daemonset
  labels:
    app: my-daemonset
spec:
  selector:
    matchLabels:
      app: my-daemonset
  template:
    metadata:
      labels:
        app: my-daemonset
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
        securityContext:
          allowPrivilegeEscalation: false
          runAsUser: 65534
        readinessProbes:
        - exec:
            command:
            - /bin/sh
            args:
            - -c
            - "curl --fail http://localhost:80/ || exit 1"
          initialDelaySeconds: 15
          periodSeconds: 5
        livenessProbes:
        - exec:
            command:
            - /bin/sh
            args:
            - -c
            - "curl --fail http://localhost:80/ || exit 1"
          initialDelaySeconds: 15
          periodSeconds: 5
      replicas: 3
      revisionHistoryMax: 5
```
This YAML configuration defines a DaemonSet named `my-daemonset` that runs a container named `my-container` on each node in the cluster, ensuring a consistent state for the background service. The configuration includes best practices such as using labels, setting the number of replicas, maintaining a specific revision history, and securing the container by disabling privilege escalation and setting a non-root user.
