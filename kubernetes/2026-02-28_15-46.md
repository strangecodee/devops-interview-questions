 # Kubernetes Concept:
Kubernetes DaemonSet ensures that a specified number of replicas of a pod are running on each node in the cluster.

# Explanation
DaemonSets are used to deploy a pod of a specific label to each node in the cluster, ensuring consistent availability of a service or utility across nodes. This is particularly useful for services such as logging agents, monitoring agents, or network attachments.

# Best Practices
- Use labels to select nodes based on specific criteria, such as node role or labels.
- Use the `node-selector` field to place the daemonset on specific nodes and avoid scheduling conflicts.
- Use the `update-strategy` to manage rolling updates and minimize downtime.

# YAML Example
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: logging-daemonset
spec:
  selector:
    matchLabels:
      app: logging
  template:
    metadata:
      labels:
        app: logging
    spec:
      containers:
      - name: logging-container
        image: logging:latest
        ports:
        - containerPort: 514
      nodeSelector:
        beta.kubernetes.io/os: linux
      updateStrategy:
        type: RollingUpdate
```
This YAML defines a DaemonSet named `logging-daemonset` that deploys a container named `logging-container` with image `logging:latest` on nodes labeled with `os: linux`. The update strategy is set to `RollingUpdate` to minimize downtime during deployment updates.
