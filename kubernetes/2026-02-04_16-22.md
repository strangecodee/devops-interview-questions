 # Kubernetes Concept
This Kubernetes YAML example demonstrates a Deployment for a Node.js application using a ReplicaSet, rolling updates, and a readiness probe.

# Explanation
A Kubernetes Deployment manages the lifecycle of a set of replicas for a desired state of a containerized application. In this example, we will create a Deployment for a Node.js application using a ReplicaSet, rolling updates, and a readiness probe to ensure zero-downtime deployments.

# Best Practices
- Use `kubectl set image` to update the container image without changing the Deployment YAML file.
- Use Rolling Updates to minimize downtime when deploying new revisions.
- Monitor and ensure the readiness of your application using the readiness probe.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nodejs-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nodejs
  template:
    metadata:
      labels:
        app: nodejs
    spec:
      containers:
      - name: nodejs
        image: node:14-alpine
        ports:
        - containerPort: 8080
          protocol: TCP
        readinessProbe:
          probes:
          - exec:
              command: ["node", "--version"]
            intervalSeconds: 5
            failureThreshold: 3
        livenessProbe:
          probes:
          - httpGet:
              path: /healthz
              port: 8080
              httpHeaders:
              - name: X-Custom-Header
                value: "awesome-value"
          intervalSeconds: 30
          failureThreshold: 3
```
This Deployment creates 3 replicas of a Node.js application using the Node.js 14 Alpine image. The containers expose port 8080, and both readiness and liveness probes are defined to ensure the application is ready and healthy. The readiness probe checks the Node.js version, while the liveness probe checks the `/healthz` endpoint.
