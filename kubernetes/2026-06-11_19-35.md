 # Kubernetes Concept
Deployment is a type of Kubernetes object used to create and manage containerized applications. It ensures that a specified number of replicas of a container are running at any given time.

# Explanation
A Kubernetes Deployment creates or updates Pods in a declarative manner, applying the desired state and managing the lifecycle of the Pods. The Deployment controller manages the rolling update and rolling back of the application, allowing for seamless application updates and self-healing.

# Best Practices
- Use a rolling update strategy to minimize downtime during Deployment updates.
- Set up a readiness probe to ensure that the container is ready to receive traffic before it is exposed to the users.
- Use a liveness probe to detect and recover from container crashes and keep the container running.

# YAML Example
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-application
  labels:
    app: my-application
spec:
  selector:
    matchLabels:
      app: my-application
  replicas: 3
  template:
    metadata:
      labels:
        app: my-application
    spec:
      containers:
      - name: my-container
        image: my-container-registry:5000/my-container:latest
        ports:
        - containerPort: 80
        readinessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 5
            timeoutSeconds: 2
        livenessProbes:
        - exec:
            command: ["/bin/sh", "-c", "curl --fail http://localhost:80/ || exit 1"]
            intervalSeconds: 15
            timeoutSeconds: 2
```
In this example, a Deployment named 'my-application' is created with 3 replicas. The container image is specified as 'my-container-registry:5000/my-container:latest'. Readiness and liveness probes are set up to ensure that the container is ready and running before it is exposed to users. The rolling update strategy is not explicitly defined, but the Deployment controller applies it by default.
