 # Kubernetes Concept
This YAML example demonstrates a `Deployment` and associated `Service` for a simple Node.js application using the `eclipse-node-server` image, focusing on monitoring the application's health using Kubernetes built-in probes.

# Explanation
The `Deployment` defines the desired state for the running application instance(s). The `Service` abstracts and provides access to the running applications via a stable IP address. Kubernetes' built-in probes (`livenessProbe` and `readinessProbe`) are utilized to ensure the application is running correctly and ready to accept traffic.

# Best Practices
- Apply proper labels to the Deployment and Service resources for easy management and selectivity.
- Use rolling updates with `Deployment` to minimize downtime and ensure a smooth upgrade process.
- Monitor the metrics and logs of the deployed application to gain insights into its performance and health.

# YAML Example

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: eclipse-node-app
  labels:
    app: node
    version: v1
spec:
  replicas: 3
  selector:
    matchLabels:
      app: node
      version: v1
  template:
    metadata:
      labels:
        app: node
        version: v1
    spec:
      containers:
      - name: node
        image: eclipse:node-server
        ports:
        - containerPort: 8080
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
        readinessProbe:
          httpGet:
            path: /
            port: 8080
          initialDelaySeconds: 15
          periodSeconds: 5
---
apiVersion: v1
kind: Service
metadata:
  name: eclipse-node-app
  labels:
    app: node
spec:
  selector:
    app: node
    version: v1
  ports:
  - port: 80
    targetPort: 8080
  type: ClusterIP
```
