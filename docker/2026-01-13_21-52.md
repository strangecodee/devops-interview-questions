 # Best Practice: Use Multi-Stage Builds for Security and Size Optimization
Use multi-stage builds to keep your runtime image size minimal and enhance security by separating the build and runtime environments.

# Explanation
Multi-stage builds allow you to create a Dockerfile with multiple build stages, each producing an intermediate image that is not used as the final runtime image. This approach enables you to install development dependencies, compile code, and perform other build tasks in the first stage, while only copying the necessary files and dependencies to the final runtime image. Leaving out unnecessary build artifacts keeps your image size smaller and improves security by reducing the attack surface.

# Why It Matters
- Reduces the overall image size by excluding unnecessary build tools and libraries, which can help decrease bandwidth usage and save storage space.
- Minimizes the attack surface by keeping development dependencies and runtime dependencies separate, thus limiting potential vulnerabilities in the final image.
- Enhances security by allowing for easier updates to development tools and dependencies without affecting the runtime environment.

# Example
```Dockerfile
# Use a base image for the build environment (e.g., Ubuntu)
FROM ubuntu:latest as builder

# Install dependencies for the build stage
RUN apt-get update && apt-get install -y \
        build-essential \
        python3 \
        python3-dev \
        python3-pip \
        && \
        pip3 install --no-cache-dir \
        Pillow \
        && \
        rm -rf /var/lib/apt/lists/*

# Copy the application source code
COPY . /app

# Build the application
WORKDIR /app
RUN pip3 install -r requirements.txt

# Use an alpine-based image for the runtime environment
FROM alpine:latest

# Copy the compiled application
COPY --from=builder /app/ /app

# Expose the required port
EXPOSE 80

# Run the application
CMD ["python3", "/app/app.py"]
```
