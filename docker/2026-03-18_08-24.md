 # Use Multi-Stage Builds for Optimized Images
Build your Docker images using multi-stage builds to minimize image size and enhance security.

# Explanation
Multi-stage builds allow you to have multiple build stages in a single Dockerfile, each stage can build upon the previous one and discard unnecessary artifacts. This optimizes the final image size and reduces security vulnerabilities by eliminating unnecessary components.

# Why It Matters
- Smaller image sizes improve deployment times and reduce bandwidth usage.
- Eliminating unnecessary components reduces the attack surface and enhances security.
- This approach also makes it possible to build production-ready images without installing development tools in the final image.

# Example
```Dockerfile
# Build stage
FROM node:12-alpine as build-stage
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Run stage
FROM nginx:alpine
COPY --from=build-stage /app/node_modules ./
COPY . /usermap/app:/usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the `node:12-alpine` image is used for the build stage, which installs the dependencies and builds the application. The second stage uses the `nginx:alpine` image, which runs the application and serves it to the outside world. The unnecessary development tools installed during the build stage are discarded, resulting in a smaller and more secure image.
