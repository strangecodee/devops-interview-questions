# Best Practice: Use Multi-stage Builds for Security and Size Optimization
<Build your Docker image using multiple stages to minimize attack surface and reduce image size>

# Explanation
Multi-stage builds allow you to create a Docker image using multiple parent images, each containing only the necessary tools and dependencies required for specific build stages. Once a stage completes, the container is discarded, leaving only the resulting artifacts. This approach reduces the attack surface by eliminating unnecessary components and ensures a more secure base image for your application.

# Why It Matters
- Reduces the image size by eliminating unnecessary tools and libraries.
- Minimizes the attack surface by using a minimal base image and discarding temporary containers.
- Improves security by reducing the potential attack vector.

# Example
```Dockerfile
FROM node:14 as builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build
FROM nginx:latest
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
```
In this example, we use a multi-stage build to build our Node.js application using the Node.js base image (builder) and then copy the built application files to a new container using the Nginx base image to serve the application. The Node.js builder container is discarded after the build stage, minimizing the attack surface and reducing the image size.
