 # Use Multi-Stage Builds for Docker Images
Use multi-stage builds to minimize image size and improve security by separating build artifacts from the final runtime environment.

# Explanation
Multi-stage builds allow you to create Docker images with multiple stages. Each stage represents a different Dockerfile where you can install dependencies, compile code, or run tests. In the final stage, you copy only the required files to the output image, leaving unnecessary artifacts behind. This approach reduces image size, improves security, and accelerates build times.

# Why It Matters
- Reduces image size: Multi-stage builds help keep images lean by avoiding the need to install unnecessary dependencies or build tools in the final image.
- Enhances security: By separating build artifacts from the runtime environment, you limit the attack surface and minimize potential vulnerabilities in your Docker images.
- Improves build efficiency: Multi-stage builds can reduce build times by allowing you to install and cache dependencies in one stage and then build your application in another stage, rather than installing them twice.

# Example
```dockerfile
# Use an official base image for the first stage
FROM node:12.13.0-alpine as build

# Install dependencies and build the application
RUN apk add --no-cache \
    curl \
    git \
    make \
    gcc \
    && \
    echo "DEBIAN_FRONTEND=noninteractive" >> /etc/environment \
    && \
    runqoset -g sys.fs.tree_max 1000000 \
    && \
    addgroup -g 1001 appuser \
    && \
    adduser -S -g 1001 -D appuser

WORKDIR /app
COPY package.json .
RUN npm install

# Copy only the built application to the final image
FROM node:12.13.0-alpine
WORKDIR /app
COPY --from=build /app .
CMD ["npm", "start"]
```
In this example, the first stage (`node:12.13.0-alpine as build`) installs dependencies and builds the application. The second stage (`FROM node:12.13.0-alpine`) copies only the built application to the final image, leaving behind the build artifacts.
