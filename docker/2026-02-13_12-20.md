 # Use Multi-Stage Builds for Performance and Security
Build Docker images using multi-stage builds to minimize image size and enhance security by separating the build and runtime environments.

# Explanation
Multi-stage builds allow you to create multiple build stages in a single Dockerfile, each with its own set of instructions. The final image is built using the last stage, while the previous stages are discarded. This reduces the image size by eliminating unnecessary packages and libraries. Additionally, it improves security by keeping sensitive build tools and dependencies out of the final image.

# Why It Matters
- Smaller image sizes lead to faster download and deployment times, improving overall application performance.
- Separating the build and runtime environments reduces the attack surface and minimizes the potential impact of vulnerabilities.

# Example
```Dockerfile
# Base image for building
FROM node:14 as builder

# Install dependencies and build application
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Base image for running the application
FROM node:14
WORKDIR /app
COPY --from=builder /app /app
RUN chown -R node:node /app

# Expose and run the application
EXPOSE 3000
CMD ["node", "server.js"]
```
In this example, the first stage (`node:14 as builder`) installs dependencies and builds the application. The second stage (`node:14`) is used to run the application, copying only the built files from the first stage. This results in a smaller image size and a more secure runtime environment.
