 # Best Practice: Building Multi-Stage Docker Images
Use multiple stages in Dockerfile to separate the build and runtime environments.

# Explanation
Multi-stage builds in Docker allow us to create smaller, more efficient images by using one builder stage for compiling and installing dependencies, and then copying only the necessary files to a runtime stage. This approach reduces the final image size and minimizes attack surface by not carrying unnecessary artifacts.

# Why It Matters
- Reduces image size: By copying only the required files to the runtime stage, we avoid carrying unused artifacts and dependencies, thereby reducing image size and improving application startup time.
- Enhances security: Minimizing the attack surface by discarding unnecessary build artifacts and dependencies.
- Improves build and runtime performance: Building separate stages for different tasks allows for better resource utilization and faster build times.

# Example
```Dockerfile
FROM node:14 as builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build
FROM nginx:latest
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, we use two stages: 'builder' for building the application and 'nginx:latest' as the runtime stage for the web server. The `COPY --from=builder /app/dist /usr/share/nginx/html` command copies only the built application files to the runtime stage.
