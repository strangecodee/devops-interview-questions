 # Best Practice: Multistage Docker Builds
Build Docker images using multistage builds to minimize image size and improve security.

# Explanation
Multistage builds allow you to create multiple stages in a Dockerfile, each building on top of the previous one. The final image is built from the last stage, leaving out unnecessary artifacts from earlier stages. This results in smaller image sizes and improved security by reducing attack surface.

# Why It Matters
- Reduces image size: Multistage builds eliminate unnecessary packages and dependencies, keeping your images as minimal as possible.
- Enhances security: By keeping your images lightweight and only including essential components, you reduce the attack surface for potential vulnerabilities.
- Improves efficiency: By performing build steps only in the necessary stages, you save time and resources during the build process.

# Example
```Dockerfile
FROM eclipse:openj9-jre-alpine as builder
WORKDIR /app
COPY . .
RUN mvn clean install

FROM openjdk:8-jdk-alpine
ARG app
COPY --from=builder $app /app
RUN chmod +x /app/target/*.jar
ENTRYPOINT ["java","-jar","/app/target/*.jar"]
```
In this example, we use a multistage build to separate the build environment (Maven) from the runtime environment (OpenJDK). The first stage, `builder`, is used for building the application using Maven, while the second stage, `openjdk`, is used as the runtime environment. This results in a smaller image with only the required runtime components.
