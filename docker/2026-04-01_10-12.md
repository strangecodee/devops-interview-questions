# Best Practice: Docker Images Should Be Built Using Multi-Stage Builds

Building Docker images using multi-stage builds is a best practice to minimize image size and improve security.

## Explanation
Multi-stage builds allow you to create multiple build stages in a single Dockerfile. Each stage can have its own set of instructions for building, installing, or configuring applications. The final image is built using the last stage, while the intermediate images from the earlier stages are discarded. This results in a smaller image size and reduces the attack surface area by not carrying unnecessary runtime dependencies.

## Why It Matters
- **Reduced Image Size:** Multi-stage builds help to keep the final image size as small as possible by discarding the intermediate images that are not required in the runtime environment.
- **Improved Security:** By not carrying unnecessary dependencies, multi-stage builds help to minimize the attack surface area, making images more secure.
- **Faster Builds:** Multi-stage builds can lead to faster build times, as they avoid the need to copy large files multiple times during the build process.

## Example

``` Dockerfile
# Use an official base image
FROM node:14

# Install dependencies
WORKDIR /app
COPY package.json yarn.lock .
RUN yarn install

# Build the application
COPY . .
RUN yarn build

# Use an Alpine Linux image as the final stage for the production image
FROM alpine:3.13
COPY --from=0 /app/dist/. /
EXPOSE 80
CMD ["sh", "-c", "echo 'Hello World' > /app/dist/index.html && node /app/server.js"]
```

In this example, we use a multi-stage build to install dependencies on the Node.js base image and then build the application. The final image is built using an Alpine Linux image, which results in a smaller image size and improved security.
