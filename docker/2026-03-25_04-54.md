# Best Practice: Minimize the Number of Docker Layers
Use multi-stage builds to minimize the number of Docker layers and reduce image size.

# Explanation
Docker images are built using multiple layers, and each layer adds to the final image size. Multi-stage builds allow you to perform build stages that produce artifacts but do not include them in the final image. By separating the build and runtime environments, you can minimize the number of layers and reduce image size.

# Why It Matters
- Reducing the number of Docker layers leads to smaller image sizes, decreasing the time required to download and transfer images between hosts.
- Smaller images mean less storage space is needed, reducing the risk of running out of disk space on your containers.
- By using multi-stage builds, you maintain a clean build environment and isolate build artifacts from the final image.

# Example
```Dockerfile
# Dockerfile using multi-stage build
FROM node:12 as build

WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

COPY . .
RUN yarn build

FROM nginx:latest
COPY --from=build /app/build /usr/share/nginx/html
```
In this example, the first stage (`node:12 as build`) is used for building the application, and the second stage (`nginx:latest`) is used to run the application. The build stage creates the application and installs dependencies, while the runtime stage serves the application with Nginx. This approach minimizes the number of Docker layers in the final image.
