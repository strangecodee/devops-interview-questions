 # Docker Image Versioning Best Practice
Use semantic versioning for Docker images to ensure consistent and controlled evolution of container capabilities.

# Explanation
Semantic versioning is a method for specifying dependencies consisting of three numbers: major.minor.patch. Each part of the version number follows specific rules: major version when you make incompatible API changes, minor version when you add functionality in a backward-compatible manner, and patch version when you make backward-compatible bug fixes. This practice allows consumers to understand the impact of updates and manage dependencies effectively.

# Why It Matters
- Ensures consumers can manage dependencies and understand the impact of updates.
- Facilitates backward compatibility and consistency across multiple versions.
- Helps maintain and evolve the container image in a controlled and predictable manner.

# Example
```Dockerfile
# Use a semantic versioning scheme
VERSION: 1.0.0
...
# Update the version number in the Dockerfile whenever you make changes
# that may impact consumers
RUN sed -i "s/VERSION: \.*/VERSION: 1.1.0/" Dockerfile
```

```bash
# Build a new Docker image with the updated version number
$ docker build -t my-app:1.1.0 .
```
