 # Docker Image Versioning Best Practice
Use semantic versioning for Docker image tags to maintain a clear and consistent ordering of image changes.

# Explanation
Semantic versioning (MAJOR.MINOR.PATCH) allows for granular control over image changes, enabling easy identification of breaking changes and bug fixes. It ensures that new features do not unintentionally introduce backward-compatible issues.

# Why It Matters
- Enables developers to easily understand the implications of upgrading or downgrading Docker images
- Helps maintain a consistent and stable development environment
- Facilitates the creation of automated deployment pipelines based on version numbers

# Example
```bash
# Dockerfile
FROM phoenix AS base

# Building and tagging with semantic versioning
docker build -t mycompany/myapp:1.0.0 .
docker push mycompany/myapp:1.0.0

# Updating and tagging
docker pull mycompany/myapp:1.0.0
# Make changes...
docker build -t mycompany/myapp:1.1.0 .
docker push mycompany/myapp:1.1.0
```
