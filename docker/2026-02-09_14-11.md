 # Dockerfile Security Best Practices: Limit Base Images
<Use a minimal base image to reduce the attack surface>

# Explanation
By using a minimal base image, you limit the number of unnecessary packages and processes that could potentially contain vulnerabilities. This helps to reduce the attack surface and improve the overall security of your Docker container.

# Why It Matters
- Minimal images reduce the attack surface by eliminating unnecessary packages and processes.
- They also keep your container lightweight and efficient.
- Using an outdated base image can expose your application to known vulnerabilities.

# Example
```Dockerfile
FROM alpine:latest as base

WORKDIR /app
COPY . /app
RUN apk add --no-cache --virtual .build-deps \
    build-base \
    && make \
    && apk del .build-deps

FROM base
RUN apk add --no-cache --upgrade \
    openssl \
    && rm -rf /var/cache/apk/*

CMD ["./main"]
```
In this example, we use the `alpine` image as the base image, which is known for its minimal size and security. We then build our application using multiple stages, each with its own set of dependencies. The final image only includes the necessary dependencies for running the application.
