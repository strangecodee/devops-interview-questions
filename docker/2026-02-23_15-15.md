 # Use Multi-Stage Builds for Reducing Docker Image Size
Build Docker images using multi-stage builds to minimize image size by separating the build environment from the runtime environment.

# Explanation
Multi-stage builds allow creating a Docker image with multiple build stages. In each stage, a new Dockerfile is used, and the build artifacts from the previous stage can be copied to the next one. This approach reduces image size by eliminating unnecessary packages and tools used during the build process.

# Why It Matters
- Minimizing the Docker image size results in faster download and deployment times, reducing the overall infrastructure costs and improving application performance.
- Keeping the build environment and runtime environment separate ensures a cleaner image, free from unnecessary tools and libraries that are not required during runtime.
- Multi-stage builds improve container security by reducing the attack surface by removing unnecessary packages and libraries.

# Example
```Dockerfile
# Base image with development tools
FROM eclipse-openj9:openjdk-13-jdk-alpine as builder

# Install dependencies
RUN apk add --no-cache --update \
        curl \
        git \
        openjdk-11-jre-headless \
        && rm -rf /var/cache/apk/*

# Copy application source code and build it
COPY . /app
WORKDIR /app
RUN mvn clean install -Dmaven.test.skip=true

# Create runtime image using a smaller base image
FROM openjdk:11-jre-alpine as runtime

# Copy the application jar file and necessary dependencies
COPY --from=builder /app/target/*.jar app.jar

# Set entrypoint to run the application
ENTRYPOINT ["java","-jar","app.jar"]
```
This Dockerfile demonstrates a multi-stage build where the first stage, `builder`, installs the required development tools and builds the application. The second stage, `runtime`, is used to create the final runtime image, which uses a smaller base image and only includes the application jar file and necessary dependencies.
