# Best Practice: Use Multi-Stage Builds for Enhanced Security in Docker Images
<Build Docker images using multi-stage builds to minimize attack surface and improve security by separating the build environment from the runtime environment>

# Explanation
Multi-stage builds allow creating Docker images using multiple parent images, each with a specific purpose. The build process is performed in an initial, disposable parent image, while the final image only includes the application and its dependencies. This approach reduces the attack surface by removing unnecessary tools and libraries from the runtime image.

# Why It Matters
- Minimizes the attack surface: Multi-stage builds prevent potential vulnerabilities from being carried over to the final runtime image.
- Saves build time and image size: Since the build environment is discarded, resources are saved and the image size is reduced.
- Enhances security best practices: By maintaining a clean runtime environment, multi-stage builds align with security best practices for container images.

# Example
```Dockerfile
# Base image for building the application
FROM node:14 AS build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Final image with the application
FROM nginx:latest
COPY --from=build /app/build/production/ /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the Node.js application is built in the initial stage using `node:14`, and the final image is based on `nginx:latest`, ensuring the application runs in a lightweight and secure web server environment.
