# Best Practice: Use Multi-Stage Builds for Docker Images
Build Docker images using multi-stage builds to minimize image size and improve security.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple parent images, each containing only the necessary steps and dependencies for that stage. In the final image, only the output artifacts from the last stage are included, resulting in a smaller image size and reduced attack surface.

# Why It Matters
- Reduces image size: By only including the necessary dependencies and artifacts in the final image, multi-stage builds lead to smaller image sizes, which in turn leads to quicker download and build times.
- Enhances security: By minimizing the attack surface of your Docker images, you can reduce the potential vulnerabilities that could be exploited. Additionally, multi-stage builds enable you to separate your base image from your application code, which can help protect against known vulnerabilities in base images.
- Improves build performance: Multi-stage builds can also help improve build performance by allowing you to cache intermediate build steps across stages.

# Example
```Dockerfile
# Use an official base image as the first stage
FROM node:14 as build

# Install dependencies and build the application
WORKDIR /app
COPY package*.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Use an alpine-based image as the final stage
FROM alpine:latest

# Install the necessary dependencies for running the application
RUN apk add --no-cache --update ca-certificates

# Copy the application from the build stage
COPY --from=build /app/dist /app

# Set the working directory and the command for running the application
WORKDIR /app
CMD ["npm", "start"]
```
In this example, the first stage uses a Node.js base image for building the application, while the second stage uses an Alpine Linux image for running the application, resulting in a much smaller final image.
