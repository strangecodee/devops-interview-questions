 # Best Practice: Use Multi-Stage Builds for Docker Images
Build Docker images using multi-stage builds to reduce image size and improve security.

# Explanation
Multi-stage builds allow creating a Docker image with multiple FROM statements in the Dockerfile. Each stage can have its own set of instructions. The final image is made up of the last stage, discarding all intermediate containers. This results in smaller images as you only carry the necessary files from one stage to another. It also enhances security by limiting the number of layers exposed to the outside world.

# Why It Matters
- Reduces image size: Multi-stage builds eliminate the need to carry unnecessary files from one stage to another, leading to smaller images.
- Enhances security: By limiting the number of layers exposed to the outside world, multi-stage builds help to minimize the potential vulnerabilities in your images.
- Improves build time: By performing intermediate steps in separate stages, you offload the work from the final image, resulting in faster build times.

# Example
```Dockerfile
# First stage: Install dependencies
FROM node:14 AS setup
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Second stage: Build the application
FROM node:14
WORKDIR /app
COPY --from=setup . .
RUN yarn build

# Final stage: Serve the application
FROM nginx:latest
COPY --from=build /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
