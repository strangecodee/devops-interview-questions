 # Use Multi-Stage Builds for Performance Optimization
Use multi-stage builds to minimize image size and improve build performance by separating the build environment from the runtime environment.

# Explanation
Multi-stage builds allow you to define multiple build stages in a single Dockerfile, each with its own set of instructions. This means you can use one stage for building and another for running your application, which reduces the image size by eliminating unnecessary packages and tools. By using a clean runtime environment, you also ensure the security of your application.

# Why It Matters
- Reduces image size: Multi-stage builds can significantly decrease the image size by eliminating unnecessary tools and packages that are not required at runtime.
- Improves build performance: By separating the build and runtime environments, you can build your images more efficiently, as you no longer need to install and configure all the runtime dependencies during the build.
- Enhances security: Multi-stage builds ensure a clean runtime environment, as you are not shipping unnecessary tools and packages that could potentially introduce vulnerabilities to your application.

# Example
```bash
# Use a base image for building
FROM node:14 as builder

# Install dependencies
WORKDIR /app
COPY package*.json ./
RUN npm install

# Build the application
COPY . .
RUN npm run build

# Use a base image for running the application
FROM nginx:latest

# Copy the built application
COPY --from=builder /app/build /usr/share/nginx/html

# Expose port and start nginx
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, we use a multi-stage build with Node.js to minimize the image size and improve build performance. We use a Node.js base image to build the application and install dependencies, and then copy the built application to an Nginx base image for running it. This approach not only reduces the image size, but also ensures a clean runtime environment for improved security.
