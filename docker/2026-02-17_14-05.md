 # Use Multi-Stage Builds for Optimized Images
Build Docker images using multi-stage builds to minimize image size and maintain a clean runtime environment.

# Explanation
Multi-stage builds allow you to create a Docker image from multiple Dockerfiles, each of which can be used for a specific stage of the build process. This technique ensures that development dependencies do not end up in the final production image, reducing image size and improving security.

# Why It Matters
- Smaller image sizes lower bandwidth requirements during the deployment process and improve application start-up times.
- Maintaining a clean runtime environment ensures the production image is not contaminated with development dependencies, reducing potential security vulnerabilities.
- Multi-stage builds make it easier to manage multiple build stages, allowing for best practices such as caching build tools and automatically removing unnecessary files.

# Example
```Dockerfile
# Build stage
FROM node:14 AS build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Runtime stage
FROM node:14
WORKDIR /app
COPY --from=build /app .
RUN yarn global add serve
EXPOSE 3000
CMD ["serve", "-s", "out"]
```
In this example, the first Dockerfile is used for the build stage, and the second Dockerfile is used for the runtime stage. This allows the build stage to include the development dependencies, which are then removed during the build process, resulting in an optimized production image.
