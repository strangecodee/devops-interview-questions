 # Best Practice: Implementing Health Checks in Docker Containers
<Ensure each Docker container has a defined health check to allow for proper monitoring and container restart if necessary.>

# Explanation
Docker health checks are automated methods to assess the status of running containers. By defining a health check in the Dockerfile or using the `--health-check` flag during container run, Docker can periodically test the container's application or service to determine if it's functioning correctly. This feature is essential for maintaining the desired state of your containers and enabling zero-downtime deployments.

# Why It Matters
- Ensures container readiness and liveness: Health checks help determine if a container is ready to accept requests and if it is functioning correctly.
- Improves container availability: Automatic container restarts based on health check results minimize downtime and maintain high availability.
- Simplifies monitoring: Health checks provide an easy way to monitor the status of your containerized applications, reducing the need for manual checks.

# Example
```Dockerfile
FROM node:14

WORKDIR /usr/src/app

COPY package*.json ./
RUN npm install

COPY . .

EXPOSE 80

CMD ["npm", "start"]

# Health Check: Test application's response on port 80
HEALTHCHECK --interval=30s --timeout=5s --retries=3 CMD curl --fail http://localhost:80 || exit 1
```

```bash
# Running a container with a defined health check
docker run --name myapp -d --publish 80:80 -d --health-check myimage:latest
```
