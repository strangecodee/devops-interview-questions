 # Use Multi-stage Builds in Dockerfor Improved Image Size and Build Time
Use multi-stage builds to create Docker images with minimal attack surface and optimized build processes. This approach allows you to keep the runtime environment lean, while keeping development tools or other unnecessary artifacts only in the build stage.

# Explanation
Multi-stage builds enable you to create multiple build stages in a single Dockerfile. Each stage can be based on a different base image. Once a stage is complete, its container exits, and the next stage starts using a clean container. This allows you to separate the build and runtime environments, reducing the final image size and improving build times.

# Why It Matters
- Reduces the final image size by excluding unnecessary tools and libraries from the runtime environment
- Improves build times by not having to install the same tools in every build stage
- Enhances security by minimizing the attack surface area by not having development tools in the final image

# Example
```Dockerfile
FROM node:14 AS build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

FROM nginx:alpine
COPY --from=build /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, we use two stages: a `build` stage based on the Node.js image, and a `nginx` stage based on the Nginx image. The `build` stage installs Node.js dependencies and builds the app, while the `nginx` stage serves the built app. The final image will only contain Nginx and the built app, making it smaller and more secure.
