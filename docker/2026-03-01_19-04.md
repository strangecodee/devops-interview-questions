 # Best Practice: Use Docker Compose Files for Multi-container Applications
Create a separate `docker-compose.yml` file to define and manage multiple containers in a Docker application.

# Explanation
Docker Compose simplifies the process of defining and running multi-container Docker applications by using a YAML file to configure services, networks, and volumes. By separating container configurations into separate files, you can easily manage and update the configurations for each container in your application.

# Why It Matters
- **Easily manage multiple containers:** Docker Compose allows you to define and manage multiple containers as a single logical unit, making it simpler to run, scale, and maintain your application.
- **Consistency:** Using a `docker-compose.yml` file ensures consistency across your application by keeping all container configurations in one place and making it easier to apply changes to your entire application.
- **Portability:** Docker Compose files can be easily shared and used in different environments, allowing you to consistently deploy and run your application across development, testing, and production environments.

# Example
```
version: '3.9'

services:
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      - NODE_ENV=production
    depends_on:
      - db

  db:
    image: postgres:13
    environment:
      POSTGRES_PASSWORD: mysecretpassword
      POSTGRES_USER: myuser
      POSTGRES_DB: mydatabase
```
In this example, we define a simple Docker application with two containers: an `app` container that is built locally using a `Dockerfile`, and a `db` container that uses the official PostgreSQL image. The `app` container depends on the `db` container, meaning it will not start until the `db` container is running. The containers are configured to expose specific ports and environment variables, and the `app` container is built using the `.` shorthand for the current directory.
