 # Use Multi-Stage Builds for Production Docker Images
Create production Docker images using multi-stage builds to minimize image size and improve security by separating the build and runtime environments.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple parent images in the build process. The first parent image is used for building and installing dependencies, and the final parent image is used as the runtime image. This approach results in smaller images by eliminating unnecessary files and tools that are not required during the runtime. Additionally, multi-stage builds enhance security by reducing the attack surface by not carrying extra tools and dependencies.

# Why It Matters
- Reduces image size and improves performance by eliminating unnecessary files and tools.
- Enhances security by minimizing the attack surface.
- Allows for consistent and efficient builds across different environments.

# Example
```Dockerfile
FROM node:14 as builder
WORKDIR /app
COPY package*.json ./
RUN npm install

FROM nginx:alpine
COPY --from=builder /app/node_modules /userman/app/node_modules
COPY --from=builder /app/package*.json /userman/app/
COPY . /userman/app
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
