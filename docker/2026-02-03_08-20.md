 # Best Practice: Use Multi-stage Builds in Dockerfiles for Lean Images
<Use multi-stage builds in Dockerfiles to create lean images by separating the build and runtime environments, reducing image size and improving security>

# Explanation
Multi-stage builds allow you to have multiple build stages in a single Dockerfile. In the first stage, you can install dependencies and compile your code. In the second stage, you can copy only the required files from the first stage to a new image, leaving behind unnecessary build artifacts and dependencies. This results in smaller image sizes and improved security.

# Why It Matters
- Reducing image size: Multi-stage builds help maintain a lean image by eliminating unnecessary build artifacts and dependencies that are not required at runtime.
- Enhanced security: By separating the build and runtime environments, multi-stage builds help minimize the attack surface by reducing the number of unnecessary packages and configurations.
- Faster builds: Since you can build the application in one stage and copy it to the final image in the next stage, multi-stage builds can lead to faster and more efficient builds.

# Example
```Dockerfile
# Use an official base image for the build environment
FROM node:14 as builder

# Set the working directory and copy the application code
WORKDIR /usr/src/app
COPY package*.json ./

# Install dependencies
RUN npm install

# Set the build stage and copy the built application to the final image
FROM nginx:latest
WORKDIR /usr/share/nginx/html
COPY --from=builder /usr/src/app/build/ .
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, we use two stages: a Node.js build stage (builder) and an Nginx runtime stage. The build stage is used to install dependencies and compile the application, while the runtime stage serves the compiled application using Nginx. By using multi-stage builds, we create a lean image with only the required dependencies and configurations.
