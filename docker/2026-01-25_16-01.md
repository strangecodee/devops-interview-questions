 # Use Multi-Stage Builds for Performance and Security
Use multi-stage builds to minimize the size of the final Docker image and improve security by separating the build environment from the runtime environment.

# Explanation
Multi-stage builds allow you to have multiple `FROM` statements in a single Dockerfile. Each `FROM` statement starts a new build stage. You can use one stage for building and another stage for running the application. This way, you can install and run only the necessary packages without carrying unused dependencies from the build stage.

# Why It Matters
- **Reduced image size:** Multi-stage builds help maintain a smaller image size by eliminating unnecessary tools and packages that are only required during the build process.
- **Security:** By keeping the build and runtime environments separate, you minimize the attack surface and protect against potential vulnerabilities in your build tools.
- **Faster builds:** Multi-stage builds speed up the build process by avoiding unnecessary steps and reducing the amount of data that needs to be transferred between stages.

# Example
```Dockerfile
# Use an official base image for the build stage
FROM node:14 as build

# Set the working directory and copy the project files
WORKDIR /app
COPY . .

# Install dependencies
RUN npm install

# Use an official base image for the runtime environment
FROM node:14

# Copy the built application files
COPY --from=build /app/node_modules /app/node_modules
COPY --from=build /app/ /app

# Set the working directory and expose the application port
WORKDIR /app
EXPOSE 3000

# Start the application
CMD ["npm", "start"]
```
