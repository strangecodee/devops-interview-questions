 # Use Multi-Stage Builds for Reducing Image Size
Use multi-stage builds to create Docker images with minimal size by separating the build environment from the runtime environment.

# Explanation
Multi-stage builds allow you to define multiple build stages in a single Dockerfile, each one based on a different base image. The final image is built by copying only the necessary artifacts from the previous stages. This approach reduces the image size by eliminating unnecessary packages installed during the build process.

# Why It Matters
- Minimizing the image size leads to faster build and download times.
- Smaller images consume less storage space, making it easier to manage and scale your containers.
- Reducing the attack surface area by eliminating unnecessary packages.

# Example
```Dockerfile
FROM node:14 as builder
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .

FROM node:14-alpine as runtime
WORKDIR /app
COPY --from=builder /app .
RUN rm -rf /app/node_modules
```
In this example, the first stage (`builder`) is responsible for installing the dependencies, while the second stage (`runtime`) is used as the runtime environment. Only the necessary files (installed packages) are copied from the builder stage to the runtime stage, resulting in a smaller image.
