 # Use Multi-Stage Builds for Docker Images
Build Docker images using multi-stage builds to reduce image size and improve security.

# Explanation
Multi-stage builds allow you to create Docker images using multiple parent images, each with its specific purpose. This approach reduces the image size by eliminating unnecessary files and tools that are only required during the build process but not in the final image. Additionally, it enhances security by minimizing the attack surface of your container.

# Why It Matters
- Reduces image size: Multi-stage builds eliminate unnecessary files and tools, making your image smaller and faster to download and deploy.
- Improves security: By using only required tools and libraries, you minimize the attack surface of your container.
- Simplifies build process: Multi-stage builds help keep your Dockerfile clean and focused, making it easier to maintain and update.

# Example
```Dockerfile
# Use an official base image for building the application
FROM node:14-alpine AS build-stage

# Set environment variables and copy application code
WORKDIR /app
COPY package*.json ./
ENV NODE_ENV production

# Install dependencies
RUN npm install

# Use an official runtime image for the final image
FROM nginx:latest

# Copy the compiled application and the Nginx configuration file
COPY --from=build-stage /app/ /usrl/share/nginx/html
COPY nginx.conf /etc/nginx/nginx.conf

# Expose the container ports
EXPOSE 80
```
In this example, multi-stage builds are used to separate the build process from the runtime environment. The first stage (`build-stage`) uses a Node.js base image for installing dependencies and compiling the application, while the second stage (default stage) uses an Nginx base image to serve the compiled application. This approach keeps the final image lightweight and secure.
