 # Use Multi-Stage Builds for Performance and Reduced Image Size
Use multi-stage builds to minimize the size of your Docker images and improve build performance by separating the build environment from the runtime environment.

# Explanation
Multi-stage builds allow you to have multiple build stages in a single Dockerfile. Each stage can be used to install dependencies, compile code, or perform other build tasks. In the final stage, a clean and minimal runtime environment is used, reducing the image size and improving performance.

# Why It Matters
- Reduces image size: By keeping the runtime environment lean and only installing necessary packages, the image size is smaller, making it quicker to download and easier to manage.
- Improves build performance: By separating the build environment from the runtime environment, you can use one stage for building and another for running, improving the build speed and allowing you to use smaller-sized build images.
- Enhances security: By using multi-stage builds, you can minimize the attack surface area by keeping the build and runtime environments separate, reducing the risk of vulnerabilities.

# Example
```Dockerfile
# Use an official base image as the first stage
FROM node:14-alpine as builder

# Install dependencies and compile the code
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Use an Alpine-based image as the final stage
FROM alpine:3.13
COPY --from=builder /app/dist /app
RUN chmod -R 755 /app
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the first stage uses a Node.js base image to install dependencies and compile the code. The second stage uses an Alpine-based image to run the application. This results in a smaller image with only the necessary packages and a clean runtime environment.
