 # Best Practice: Maintain a Multi-Stage Dockerfile for Build and Runtime
Create a Dockerfile that consists of multiple stages to minimize image size and improve security by separating build-time and runtime dependencies.

# Explanation
A multi-stage Dockerfile utilizes multiple FROM statements to build an image in stages. The first stage is used for building the application, and the second stage is used for running the application. The build stage installs all the required dependencies and tools for building the application, while the runtime stage contains only the necessary dependencies and the application itself, keeping the image size small and reducing attack surface area.

# Why It Matters
- Reduces image size: By separating the build and runtime stages, you limit the size of the runtime image, making it easier to deploy and manage.
- Improves security: Minimizing the number of dependencies in the runtime image reduces the attack surface and potential vulnerabilities.
- Streamlines build process: With the build and runtime dependencies separated, the image is built more efficiently, as the build dependencies are not carried over to the runtime image.

# Example
```Dockerfile
# Stage 1: Build
FROM node:14 as builder

# Install dependencies
RUN apt-get update && apt-get install -y gcc
WORKDIR /app
COPY . .
RUN npm install

# Stage 2: Runtime
FROM node:14

# Copy the built application from the previous stage
COPY --from=builder /app/ /app/

# Run the application
CMD ["npm", "start"]
```
