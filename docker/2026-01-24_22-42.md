 # Best Practice: Maintain a Lean Docker Image by Using Multi-Stage Builds
<Use multi-stage builds to create production-ready images by separating build-time and run-time dependencies, minimizing image size and improving security>

# Explanation
Multi-stage builds allow you to define multiple build stages in a single Dockerfile. In the first stage, dependencies and build tools are installed, and the application is compiled or configured. In the second stage, the application is copied from the first stage into a new, clean image, and any post-processing steps are performed. This approach results in smaller images, as unnecessary build artifacts are not carried over to the final image. Additionally, it enhances security by reducing the attack surface area by not shipping unnecessary tools and libraries.

# Why It Matters
- Reduces image size: By separating build and runtime stages, you minimize the amount of unnecessary dependencies and build tools that are included in the final image.
- Improves security: By eliminating unused tools and libraries, you reduce the potential attack surface area and the likelihood of vulnerabilities being present in your images.
- Faster builds: By cleaning up the image after the build process, you significantly reduce the time it takes to build and distribute the image.

# Example
```Dockerfile
# Stage 1 - Build
FROM node:12 as build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm test

# Stage 2 - Production
FROM node:12-alpine
COPY --from=build /app/package*.json ./
COPY --from=build /app/node_modules/ ./
COPY --from=build /app .
RUN npm install --only=production
EXPOSE 80
CMD ["npm", "start"]
```
In this example, the first stage is used for building and testing the application, while the second stage is used for creating a production-ready image. This results in a smaller, more secure image with only the necessary dependencies and tools.
