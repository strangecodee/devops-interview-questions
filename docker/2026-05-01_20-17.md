# Best Practice: Least Privileged Container Run-time
<Containers should be run with the minimum necessary privileges to minimize potential security risks and attack surfaces>

# Explanation
Docker containers are designed to run applications in a lightweight and isolated environment. However, containers that are run with unnecessary privileges can create potential security risks and attack surfaces. To mitigate these risks, it is best practice to run containers with the least privileged user account. This can be achieved by creating a new user within the container and running the application with that user's privileges.

# Why It Matters
- Minimizing the attack surface of a container reduces the potential impact of a successful attack.
- Running containers with the least necessary privileges can prevent unintended or malicious changes to the host system.
- Containers that are run with elevated privileges create a larger attack surface for potential attackers.

# Example
Here is an example of a Dockerfile that creates a new user and runs the application using that user's privileges:

```Dockerfile
FROM alpine:latest

RUN addgroup -S app && adduser -S app -G app
RUN chown -R app:app /app
WORKDIR /app
COPY . /app
RUN apk add --no-cache --update --virtual .build-deps \
    python3-dev python3-pip \
    && pip install --no-cache-dir -r requirements.txt \
    && pip install --no-cache-dir -e . \
    && apk del .build-deps

CMD ["python3", "app.py"]
USER app
```

In this example, a new user named "app" is created, and the application is run using that user's privileges. This ensures that the container is running with the least necessary privileges to minimize potential security risks.
