# Best Practice: Multi-Stage Dockerfiles for Building and Running
Use multi-stage Dockerfiles for separating the build and run environments to reduce image size and improve security.

# Explanation
Multi-stage Dockerfiles allow creating a minimal runtime image by using multiple build stages. In each stage, you can install and configure dependencies, build the application, and remove unnecessary artifacts before moving to the next stage. The final image is based on the last stage, ensuring only the required components are present.

# Why It Matters
- Reduced image size: By removing build tools and other unnecessary artifacts from the final image, you can significantly decrease image size and improve deployment time.
- Enhanced security: Keeping sensitive build tools out of the final image reduces the attack surface and lessens potential vulnerabilities.
- Improved Dockerfile organization: Multi-stage Dockerfiles simplify the Dockerfile structure and help maintain a clean separation between different build and runtime stages.

# Example
```Dockerfile
# Use an official base image for building
FROM node:12.22-alpine as builder

# Install dependencies and build the app
RUN apk add --no-cache --update \
    python \
    curl \
    && pip install some_dependency
WORKDIR /app
COPY package.json .
RUN npm install
COPY . .

# Use an official base image for running the app
FROM node:12.22-alpine

# Copy the built app from the builder stage
COPY --from=builder /app .

# Remove unnecessary artifacts from the builder stage
FROM node:12.22-alpine as runtime
COPY --from=builder /app .
RUN apk del python cur
```
