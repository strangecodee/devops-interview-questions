 # Best Practice: Implementing Resource Limits in Docker Containers
<Implementing resource limits in Docker containers is essential to prevent container overconsumption and ensure optimal system performance>.

# Explanation
Docker provides various resource limiting options, such as CPU, memory, I/O, and network limits, which can be set at container runtime or defined in the Dockerfile. These limits help prevent container resource contention and ensure resource availability for other containers and the host system.

# Why It Matters
- Preventing container overconsumption: Resource limits prevent a single container from using excessive resources, ensuring other containers and host system processes have enough resources to operate correctly.
- Optimal system performance: Resource limits help prevent performance degradation by ensuring containers do not consume more resources than allocated.
- Resource fairness: Resource limits help maintain fairness between containers by preventing one container from consuming all available resources.

# Example
```bash
# Set CPU limit for a container
docker run --cpu-quota 500 --rm ubuntu:latest sleep 3600

# Set memory limit for a container in Dockerfile
FROM nginx:latest
RUN echo "memory.limit_memory=512m" >> /etc/docker/conf.d/nginx-limits.conf
```
