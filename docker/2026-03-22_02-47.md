 # Use Multi-stage Builds for Performance and Security
Use multi-stage builds to minimize the attack surface area and improve image size by separating the build process from the runtime environment.

# Explanation
Multi-stage builds allow you to define multiple build stages in a single Dockerfile. In each stage, you can install the necessary dependencies and compile the code, but only the final stage includes the runtime environment. This approach reduces the image size by avoiding the duplication of unnecessary components. Additionally, it enhances security by reducing the attack surface area by minimizing the number of components exposed.

# Why It Matters
- By using multi-stage builds, you can maintain a smaller image size, which results in faster build and deployment times.
- It helps to decrease the likelihood of vulnerabilities in the image by removing unused packages and components.
- Enhances the security posture by reducing the attack surface area, thereby minimizing the potential for successful attacks.

# Example
```Dockerfile
# Stage 1: Build
FROM node:14.17.3 AS build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Stage 2: Runtime
FROM node:14.17.3
WORKDIR /app
COPY --from=build /app/dist .
EXPOSE 3000
CMD ["node", "dist/index.js"]
```
In this example, we have two stages: Build (Stage 1) and Runtime (Stage 2). The build stage is used to install dependencies, compile the code, and copy the built artifacts, while the runtime stage runs the application using the minimal node image.
