 # Use Multi-Stage Builds for Optimized Docker Images
Build your Docker images using multi-stage builds to minimize image size and improve security.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple FROM statements in the Dockerfile. The build context is only passed to the last stage, meaning unnecessary tools and packages are not included in the final image. This results in smaller image sizes and enhanced security.

# Why It Matters
- Smaller image sizes reduce the time needed to download and transfer images between hosts, improving deployment efficiency.
- By excluding unused packages and tools, you can minimize the attack surface area, making your images more secure.
- Multi-stage builds enable you to maintain a cleaner image, as the build cache is not cluttered with unnecessary artifacts.

# Example
```Dockerfile
# Use an official base image for the first stage
FROM node:12.22-alpine as build

# Install dependencies and build the application in the first stage
WORKDIR /app
COPY package*.json .
RUN npm install
COPY . .
RUN npm run build

# Create a new stage for the production image, copying only the application files
FROM nginx:latest
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
