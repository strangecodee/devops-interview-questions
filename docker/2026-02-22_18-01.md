 # Docker Image Versioning best practice
Use semantic versioning to ensure consistent and manageable Docker image updates.

# Explanation
Semantic versioning is a method of labeling software releases with three numbers: major, minor, and patch. Major changes indicate backward incompatible updates, while minor changes represent new features or improvements, and patch versions are for bug fixes.

# Why It Matters
- Ensures compatibility and predictability in deployments
- Facilitates easy identification of updates and rollbacks if needed
- Enables better collaboration among teams working on the same project

# Example
```Dockerfile
FROM node:12.18.3
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
EXPOSE 8080
CMD ["yarn", "start"]

# Semver format: major.minor.patch
# 1.0.0 -> New major version (backward incompatible)
# 1.1.0 -> New feature or improvement
# 1.1.1 -> Bug fix
# Dockerfile name: Dockerfile.1.1.1
```

```bash
# Building Docker image with version 1.1.1
$ docker build -t myapp:1.1.1 .
```
