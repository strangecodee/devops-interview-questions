 # Use Multi-Stage Builds for Docker Images
Use multi-stage builds to keep runtime images lightweight and reduce the attack surface.

# Explanation
Multi-stage builds allow you to have multiple build stages in a single Dockerfile, each with its own set of instructions. In the final stage, only the necessary files for the runtime environment are copied to the output image. This approach reduces the size of the final image and eliminates unnecessary tools and libraries.

# Why It Matters
- Reduces image size: By eliminating unnecessary tools and libraries, you can significantly reduce the size of your Docker images. This can help improve your application's overall performance and decrease download times.
- Improves security: Smaller images have a reduced attack surface, making them less susceptible to vulnerabilities. Additionally, using multi-stage builds allows you to keep your base image up-to-date without affecting your application logic.
- Enhances build time: Multi-stage builds can also improve build times by allowing you to cache intermediate build steps across stages.

# Example
```Dockerfile
# Use an initial stage for building and caching dependencies
FROM node:14 AS build-env
WORKDIR /app
COPY package*.json ./
RUN npm install

# Use a second stage for building the application and creating the final image
FROM node:14-alpine AS runtime
WORKDIR /app
COPY --from=build-env /app .
RUN npm run build

# Expose the necessary port and set the entrypoint
EXPOSE 3000
ENTRYPOINT ["npm", "start"]
```
In this example, we use two stages to build and produce a Docker image. The first stage (`build-env`) sets up the development environment, installs dependencies, and runs `npm install`. The second stage (`runtime`) uses the cached build artifacts and runs the build and production commands, leaving only the required files for the runtime environment in the final image.
