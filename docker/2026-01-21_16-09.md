 # Best Practice: Use External Load Balancers with Docker Swarm Mode
Use external load balancers instead of relying on Docker Swarm's built-in load balancing for production workloads.

# Explanation
Docker Swarm's built-in load balancing may not provide the required scalability, reliability, or advanced features for production workloads. External load balancers offer superior traffic handling and distribution, health checking, and security features.

# Why It Matters
- Scalability: External load balancers can distribute traffic to a larger number of nodes and handle more traffic than Swarm's built-in load balancer.
- Reliability: External load balancers can provide high availability and failover capabilities, which are essential for mission-critical applications.
- Advanced features: External load balancers offer advanced features like SSL termination, session persistence, and traffic encryption.

# Example
To deploy a Docker application behind a load balancer, first create a Docker image:

```Dockerfile
FROM node:14
WORKDIR /app
COPY package.json .
RUN npm install
COPY . .
EXPOSE 8080
CMD ["npm", "start"]
```

Then, create a `docker-compose.yml` file:

```yaml
version: '3.7'
services:
  app:
    build: .
    ports:
      - 8080:8080
```

Finally, deploy the service to Swarm and configure the load balancer to distribute traffic to the Swarm nodes:

```bash
$ docker swarm init --advertise-addr 192.168.1.100
$ docker image build -t myimage .
$ docker service create --name myservice --publish 80:8080 myimage
$ docker service update --constraint "node.role == worker" myservice
```

Configure your load balancer to distribute traffic to the Swarm nodes on port 80.
