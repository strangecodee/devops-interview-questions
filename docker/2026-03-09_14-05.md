 # Use Multi-Stage Builds for Performance Optimization
Build Docker images using multi-stage builds to minimize image size and improve performance.

# Explanation
Multi-stage builds allow you to create an image from multiple Dockerfiles in a single build. Each stage can be used to install dependencies, compile code, or perform any other task, and the final image will only include the files from the last stage. This reduces the image size as unnecessary files from previous stages are not carried forward.

# Why It Matters
- Reduces image size: Multi-stage builds help you maintain smaller Docker images by eliminating unnecessary files and dependencies, which in turn speeds up the image download and runtime.
- Improves build time: As only the changes are propagated between stages, multi-stage builds significantly reduce the build time by avoiding rebuilding an entire image multiple times.
- Enhances security: By separating the development and runtime environments, multi-stage builds help to minimize the attack surface and improve the overall security of your Docker images.

# Example
```Dockerfile
# First stage - Install dependencies
FROM node:14 as build
WORKDIR /app
COPY package.json .
RUN npm install

# Second stage - Build the application
FROM node:14
WORKDIR /app
COPY --from=build /app .
RUN npm run build

# Third stage - Run the application
FROM nginx:latest
COPY --from=build /app/dist .
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
Here, we have a three-stage build: the first stage is used for installing dependencies, the second stage is for building the application, and the final stage runs the Nginx server to serve the application. By using multi-stage builds, only the necessary files from the application building stages are included in the final image, resulting in a reduced image size and improved performance.
