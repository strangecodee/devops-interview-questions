# Docker Image Base Best Practice
<Use a trusted base image with minimal modifications to build upon>

# Explanation
Using a trusted base image with minimal modifications ensures the security and stability of your Docker image. It reduces the attack surface by limiting the number of packages installed and the potential vulnerabilities present. Moreover, it allows for easier updates and maintenance of the image.

# Why It Matters
- Reduces the attack surface by limiting the number of packages and potential vulnerabilities
- Allows for easier updates and maintenance
- Enhances security and stability by using a trusted base image

# Example
```dockerfile
FROM library/alpine:latest as base

# Build application
WORKDIR /app
COPY . .
RUN apk add --no-cache --update build-base
RUN apk add --no-cache --virtual .build-deps gcc musl-dev cmake
RUN pip install --no-cache-dir -r requirements.txt

# Production image
FROM base as final
RUN apk del build-base .build-deps
COPY --from=base /etc/passwd /etc/passwd
COPY --from=base /etc/group /etc/group

# Command to run when container starts
CMD ["python3", "app.py"]
```
This example uses Alpine Linux as a base image and minimizes the modifications made to it. The `final` image is built on top of the `base` image, and unnecessary packages are removed. The `passwd` and `group` files are copied from the base image to maintain the same user environment.
