 # Best Practice: Implementing Health Checks in Docker Containers
<Ensure each Docker container has a defined health check to monitor its status>

# Explanation
A health check is a mechanism that allows Docker to periodically verify the status of a container and detect whether it is running properly. This is crucial for maintaining the overall health and reliability of containerized applications, as it enables automatic restarting of containers that may have failed or become unresponsive. The health check is defined using the `--heathcheck` flag during container creation or in the `Dockerfile` using the `HEALTHCHECK` instruction.

# Why It Matters
- Ensuring container availability: Health checks help maintain container availability by detecting and restarting unhealthy containers, minimizing downtime and preventing user-facing issues.
- Simplifying monitoring: Health checks simplify monitoring and management by providing a single point of contact for assessing the health of multiple containers in a given environment.
- Improving system resilience: By incorporating health checks into your Docker infrastructure, you can improve overall system resilience and ensure that your applications remain available, even in the face of potential failures.

# Example
```dockerfile
# Dockerfile with HEALTHCHECK instruction
FROM node:14.15.0

WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .

RUN apk add --no-cache --upgrade curl

RUN echo "HEALTHCHECK --interval=30s --timeout=5s CMD curl --fail http://localhost/ || exit 1" >> Dockerfile

CMD ["npm", "start"]
```

```bash
# CLI command to create container with health check
$ docker run --name myapp -d --restart=always --publish 80:80 --health-check myimage:latest
```
