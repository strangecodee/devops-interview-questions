 # Best Practice: Use Multi-Stage Builds for Performance and Reduced Image Size
Use multi-stage builds to minimize the final image size and improve build performance by separating the build and runtime environments.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple base images for different stages of the build. The first stage is used for building the application, and the subsequent stages are used to create a smaller runtime image. This approach reduces the image size by eliminating unnecessary files from the final image and improves build performance by avoiding the installation of unnecessary build tools and packages.

# Why It Matters
- Reduces image size: Multi-stage builds eliminate the need to carry unnecessary build tools and dependencies, thereby reducing the image size.
- Improves build performance: By separating the build and runtime environments, multi-stage builds improve build performance as the build environment can be optimized for the specific build tools and dependencies.
- Security: Multi-stage builds help minimize the attack surface by reducing the number of packages and dependencies present in the final image.

# Example
``` Dockerfile
FROM node:12.18.3 AS build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

FROM nginx:latest
COPY --from=build /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the first stage `node:12.18.3` is used to build the application, and the second stage `nginx:latest` is used to create the runtime image. The build environment installs the required dependencies using Yarn, and the final image only includes the compiled application and the Nginx server.
