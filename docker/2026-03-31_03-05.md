# Best Practice: Docker Images Should Have Minimal Base Images
<Docker images should be based on the smallest possible base image to reduce image size and attack surface area>.

# Explanation
Docker images are constructed by layering multiple filesystem changes on top of a base image. The larger the base image, the larger the resulting image size and the greater the attack surface area. By using a minimal base image, we can minimize both image size and the potential attack vector.

# Why It Matters
- Reducing image size can decrease build and deployment times, as well as lower storage requirements.
- Using a minimal base image reduces the attack surface area by limiting the number of packages and services included in the base image.
- By starting with a minimal base image, we can build upon it only the necessary components for our application, further reducing image size and attack surface area.

# Example
```
FROM alpine:3.12 as base
RUN apk add --no-cache --update ca-certificates

# ... other instructions for your application

FROM base
# Your application code goes here
```
Here, we use the Alpine Linux base image, which is one of the smallest base images available. We then install the necessary packages for our application in a separate layer, but our application code runs on top of the base image layer. This approach ensures that our application only includes the necessary components for it to run, and not any extra packages or services that might not be needed or could introduce security vulnerabilities.
