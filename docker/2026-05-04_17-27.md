# Best Practice: Use Multi-Stage Builds for Security and Efficiency
<Build Docker images using multi-stage builds to minimize the attack surface and reduce image size.>

# Explanation
Multi-stage builds allow you to create Docker images using multiple Dockerfiles in a single build process. The final image is based on a clean base image, while the build steps are executed in a separate intermediate image. This separation reduces the attack surface by not carrying unnecessary packages and configurations from the build environment to the final image. Additionally, multi-stage builds can help to reduce the final image size by not carrying the entire build toolchain and dependencies.

# Why It Matters
- Reduces the attack surface by minimizing the number of unnecessary packages and configurations in the final image.
- Helps to maintain image size by not carrying the entire build toolchain and dependencies.
- Enhances security by keeping sensitive build information out of the final image.

# Example
```Dockerfile
# Base image for the application
FROM node:alpine as app

# Set working directory and copy application source code
WORKDIR /app
COPY package.json yarn.lock .
RUN yarn install --frozen-lockfile

# Build the application
RUN yarn build

# Clean up the build environment
RUN rm -rf node_modules

# Use Amazon Linux as the base image for the runtime environment
FROM amazonlinux:latest

# Set working directory
WORKDIR /app

# Copy the final image from the previous build
COPY --from=app /app/dist .

# Expose the application port
EXPOSE 80

# Start the application
CMD ["npm", "start"]
```
