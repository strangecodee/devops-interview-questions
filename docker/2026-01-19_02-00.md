 # Best Practice: Use Multi-Stage Builds in Dockerfor SRE Efficiency
Create multi-stage builds in Docker to maintain a lean runtime image by separating the build and runtime environments.

# Explanation
Multi-stage builds allow you to have multiple build stages in a single Dockerfile. Each stage represents a distinct Docker image, and the output of one stage can be used as the input for the next stage. This approach ensures that only the necessary build tools and dependencies are included in the final runtime image.

# Why It Matters
- Minimizes image size: By separating the build and runtime environments, the final image size is significantly reduced since it does not include unnecessary build tools and dependencies.
- Improves security: Keeping your build and runtime environments separate maintains the security of your runtime environment.
- Enhances build reproducibility: Multi-stage builds provide consistent and predictable build results by using the same instructions for each build iteration.

# Example
```Dockerfile
# Use an official base image as the first stage
FROM node:14 as builder

# Set up the build environment and install dependencies
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Copy the source code
COPY . .

# Build the application
RUN yarn build

# Use an alpine-based image as the second stage for the runtime environment
FROM alpine:3.13

# Set up the application environment and copy the built artifacts
WORKDIR /app
COPY --from=builder /app/dist .

# Expose the application port
EXPOSE 8080

# Start the application
CMD ["node", "dist/index.js"]
```
