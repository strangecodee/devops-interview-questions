 # Best Practice: Use Multi-Stage Builds for Docker Images
Use multi-stage builds to keep your Docker images lightweight and reduce the attack surface by separating the build and runtime environments.

# Explanation
Multi-stage builds allow you to create Docker images using multiple FROM statements in a single Dockerfile. The first stage (build stage) is used for building the image, and the second stage (runtime stage) is used for running the application. This approach enables you to install only the necessary dependencies and tools during the build stage, minimizing the image size and potential security vulnerabilities.

# Why It Matters
- By using a separate build stage, you avoid installing unnecessary dependencies and tools within the final runtime image, reducing image size and optimizing resource utilization.
- Eliminating unused packages and configurations from the final image decreases the attack surface, minimizing potential vulnerabilities that could be exploited by attackers.
- Multi-stage builds improve the security and maintainability of your Docker images, ensuring that you are deploying only the required components needed to run your application.

# Example
```Dockerfile
# Stage 1: Build
FROM node:14 as build-env
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Stage 2: Runtime
FROM nginx:alpine
COPY --from=build-env /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, we use Node.js as the build environment and Nginx as the runtime environment. The build stage installs the required dependencies and builds the application, while the runtime stage serves the built application. This separation ensures a smaller, more secure runtime image.
