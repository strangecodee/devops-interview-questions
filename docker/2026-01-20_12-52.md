 # Docker Image Versioning Best Practice
Use semantic versioning for Docker image tagging to maintain a clear and consistent way of tracking changes and dependencies.

# Explanation
Semantic versioning allows for the separation of major, minor, and patch updates, making it easier to understand the impact of image updates and manage dependencies. By following a standard format, teams can communicate effectively about changes and ensure that all components remain compatible.

# Why It Matters
- Enables clear communication about the impact of image updates
- Facilitates dependency management across multiple components
- Helps maintain compatibility between services

# Example
```bash
# Use semantic versioning in your Dockerfile
FROM node:14.17.3

# ...

# When building the image, tag it with a version number
docker build -t my-image:1.0.0 .
```

# Alternatively, use a CI/CD pipeline to automate image versioning and tagging based on commit messages.
# For example, using Git Tags and Jenkins, the pipeline can automatically tag the image with the commit SHA or the semantic version specified in the commit message.
```bash
# Jenkinsfile
pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                sh 'docker build -t my-image:${env.GIT_COMMIT_SHA} .'
            }
        }
        stage('Tag') {
            steps {
                sh 'docker tag my-image:${env.GIT_COMMIT_SHA} my-image:${env.GIT_BRANCH}-${env.GIT_COMMIT_SHA}'
                sh 'docker push my-image:${env.GIT_BRANCH}-${env.GIT_COMMIT_SHA}'
            }
        }
    }
}
```

# In a GitHub Action, the YAML file can be configured to use the commit message to determine the image version.
# For example, using the standard GitHub commit message format, the image tag can be set to the major, minor, and patch version, respectively.

```yaml
name: Docker Build and Push

on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v2

      - name: Build Docker image
        uses: docker-dind@latest
        steps:
          - name: Build image
            run: |
              docker build -t my-image:${{ github.sha }} .
              docker tag my-image:${{ github.sha }} my-image:${{ github.ref.ref.split('/')[-1] }}

      - name: Login to Docker Hub
        uses: actions/docker/docker-login@v2
        with:
          registry: docker.io
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      - name: Push image
        uses: docker-dind@latest
        steps:
          - name: Push image
            run: |
              docker push my-image:${{ github.ref.ref.split('/')[-1] }}
```
