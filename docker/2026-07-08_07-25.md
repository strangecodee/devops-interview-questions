 # Best Practice: Use Multi-Stage Builds for Security and Efficiency
<Build Docker images using multi-stage builds to reduce image size and enhance security by separating build dependencies from runtime dependencies>.

# Explanation
Multi-stage builds allow you to create multiple build stages in a single Dockerfile, each with its own set of instructions. This results in smaller Docker images as unused build artifacts are discarded between stages. Additionally, multi-stage builds help improve security by keeping sensitive build tools and dependencies out of your final image.

# Why It Matters
- Reduces image size: By discarding build artifacts between stages, multi-stage builds help keep your final Docker image lean and efficient.
- Enhances security: Keeping build tools and dependencies separate from your runtime environment minimizes the attack surface area and reduces the risk of vulnerabilities.
- Saves resources: Multi-stage builds allow you to perform complex builds on a separate build environment, reducing the need for additional resources on your production environment.

# Example
```dockerfile
# Use a base image for building
FROM node:14 as builder

# Install dependencies
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Build the application
COPY . .
RUN yarn build

# Use a clean runtime image and copy the built application
FROM nginx:latest
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, we use a Node.js base image (builder) for building our application, and then switch to a clean runtime image (nginx) to run the application. This ensures that our final Docker image only contains the necessary dependencies for running the application, while the build dependencies are discarded.
