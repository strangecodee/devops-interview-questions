# Title: Implement Multi-Stage Builds for Image Optimization
<Use a performance-optimized approach by implementing multi-stage builds to reduce image size and improve build time.>

# Explanation
Multi-stage builds allow you to create Docker images using multiple FROM statements in a single Dockerfile. This technique enables you to separate the build environment from the runtime environment, thus reducing the image size and improving the build time. In each stage, you copy only the required files to the next stage.

# Why It Matters
- Reduces Image Size: By keeping intermediate build artifacts out of the final image, you minimize the image size.
- Improves Build Time: Multi-stage builds allow you to cache intermediate build steps, speeding up subsequent builds.
- Enhances Security: By excluding unnecessary dependencies and applications from your images, you minimize vulnerabilities.

# Example
```Dockerfile
# Use an official base image
FROM eclipse:jdk-openjdk-11-jre-alpine as build-env

# Set the working directory
WORKDIR /app

# Copy the source code
COPY . .

# Install dependencies
RUN apk add --no-cache \
    openjdk-11-jre \
    maven \
    && ln -s /usr/share/java/jre11 /usr/local/jre

# Build the application
RUN mvn clean package

# Use an alpine runtime image
FROM alpine:latest

# Set the working directory
WORKDIR /app

# Copy the built artifacts from the previous stage
COPY --from=build-env /app/target/. .

# Expose the application port
EXPOSE 8080

# Entry point to run the application
CMD ["java", "-jar", "app.jar"]
```
In this example, the first stage (`build-env`) is used for building the application, and the second stage (`alpine`) is used as the runtime environment. The `COPY --from=build-env` command is used to copy only the built artifacts to the runtime stage, without including the build environment.
