 # Use Multi-stage Builds for Performance and Reduced Image Size
Build Docker images using multi-stage builds to minimize image size and improve performance by separating the build and runtime environments.

# Explanation
Multi-stage builds allow you to create Docker images with multiple parents, each with a separate purpose. The first stage typically handles building and installing dependencies, while the second stage focuses on creating the final runtime image. This approach reduces the image size by eliminating unnecessary build tools and dependencies.

# Why It Matters
- Reduces image size: Multi-stage builds help minimize the size of your final Docker image by only keeping the essential runtime components.
- Improves performance: By separating the build and runtime environments, you can optimize the build process and improve overall system performance.
- Security: This best practice ensures that sensitive data and build tools are not included in the final runtime image, enhancing security.

# Example
```Dockerfile
# Use a base image for building and installation
FROM node:14 as builder

# Install dependencies
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Copy source code and build artifacts
COPY . .

# Use a lightweight base image for runtime
FROM node:14
WORKDIR /app
COPY --from=builder /app/node_modules ./
COPY package*.json ./
RUN yarn install --production
EXPOSE 8080
CMD ["yarn", "start"]
```
In the example above, the first stage utilizes a Node.js builder image to install dependencies, while the second stage uses a smaller Node.js runtime image. Multi-stage builds ensure a clean, optimized, and secure final image for production use.
