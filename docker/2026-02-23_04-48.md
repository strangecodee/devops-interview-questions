 # Use Multi-Stage Builds for Optimized Images
Use multi-stage builds to keep your final production image lightweight and optimized by separating the build and runtime environments.

# Explanation
Multi-stage builds consist of multiple `Dockerfile` stages, allowing you to perform build-time tasks in one stage and discard the artifacts from that stage in subsequent stages. This results in smaller, more efficient production images as you avoid carrying unnecessary components and dependencies.

# Why It Matters
- Reduces image size: By discarding unnecessary artifacts, you'll have a smaller production image, which in turn leads to faster image downloads and faster container starts.
- Improves security: Minimizing your image size also reduces the potential attack surface without compromising functionality.
- Faster builds: By separating build and runtime environments, you can significantly speed up your build times by only installing the necessary dependencies and tools for each stage.

# Example
```Dockerfile
# Use a base image for building the application
FROM node:alpine AS build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Use an optimized image for the runtime
FROM node:alpine
WORKDIR /app
COPY --from=build /app/dist .
EXPOSE 8080
CMD ["node", "dist/server.js"]
```
In this example, the first stage (`FROM node:alpine AS build`) is used for building the application, while the second stage (`FROM node:alpine`) is used as the production image for running the application. The first stage installs the dependencies, builds the application, and copies the built files to the second stage. The second stage only includes the optimized production image with the necessary runtime dependencies.
