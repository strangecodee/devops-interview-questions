# Best Practice: Use Multi-Stage Builds in Dockerfiles
Create multi-stage builds in Dockerfiles to keep the runtime image light and minimize attack surface.

# Explanation
Multi-stage builds allow you to create multiple build stages in a single Dockerfile, each with its own set of instructions. The last stage, which produces the final image, only includes the necessary files and dependencies for the application to run. Previous stages are discarded, leaving a clean and lightweight runtime image.

# Why It Matters
- Reduces image size: By discarding unnecessary build stages, you create a smaller image that requires fewer resources to store and distribute.
- Improves security: Fewer dependencies mean fewer potential vulnerabilities, reducing the attack surface of your runtime image.
- Enhances build efficiency: Multi-stage builds enable you to perform complex builds and caching in separate stages while keeping your final runtime image streamlined.

# Example
```Dockerfile
# Use an official base image for your first stage
FROM node:14.17.3 as build

# Set up the build environment
WORKDIR /app
COPY package*.json ./
RUN npm install

# Copy the application code and build the artifact
COPY . .
RUN npm run build

# Create a new stage for the runtime environment
FROM nginx:latest
COPY --from=build /app/build/production /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

# Final image uses the Nginx image with your application's build artifact
```
