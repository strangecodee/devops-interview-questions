# Best Practice: Minimize Docker Image Size by Using Multi-Stage Builds
<Use a smaller base image for the application and perform the build in a separate, larger image to minimize the final image size>

# Explanation
By using multi-stage builds in Docker, you can maintain a lean application image and keep sensitive build tools and dependencies out of your final image. In a multi-stage build, you can build your application in a larger image that includes all necessary build tools and then copy only the necessary artifacts to a smaller runtime image.

# Why It Matters
- Reduces image size: Minimizing image size can lead to faster download times for developers and smaller container sizes that are easier to manage and distribute.
- Increases security: By keeping sensitive build tools out of your final image, you reduce the attack surface for potential vulnerabilities.
- Improves consistency: Using multi-stage builds can help ensure that your development, testing, and production environments are consistent by using the same base image and application version.

# Example
```Dockerfile
FROM node:14-alpine as builder
WORKDIR /app
COPY package.json yarn.lock .
RUN yarn install

FROM nginx:latest
COPY --from=builder /app/dist /usr/share/nginx/html
```
In this example, we use a multi-stage build to build our Node.js application in the first stage with the `node:14-alpine` image and then copy only the necessary artifacts (the compiled application) to a smaller `nginx:latest` image for the runtime.
