 # Best Practice: Build Multi-Stage Docker Images
Build multi-stage Docker images to reduce image size and improve security.

# Explanation
Multi-stage builds allow creating multiple Dockerfiles in a single build process. In each stage, you can install only the necessary dependencies and packages for that specific stage. This results in smaller image sizes and eliminates unnecessary components, improving security.

# Why It Matters
- Smaller image sizes reduce the time and resources required for downloading and installing images, leading to faster build and deployment times.
- Reducing the attack surface by eliminating unused components enhances security.
- Adhering to this practice simplifies image management and upkeep.

# Example
```Dockerfile
# Stage 1: Build and Install Dependencies
FROM node:14 as build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Stage 2: Build Application
FROM node:14 as production
COPY --from=build /app .
RUN rm -rf node_modules
WORKDIR /app
RUN yarn build

# Stage 3: Production Image
FROM nginx:latest as production
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, three stages are defined: one for building and installing dependencies, another for building the application, and the final one for the production image. This allows each stage to only include the necessary components for their specific role.
