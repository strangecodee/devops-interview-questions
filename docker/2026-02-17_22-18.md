 # Best Practice: Use Multi-Stage Builds to Minimize Image Size and Increase Security

This practice involves creating Docker images using multiple `Dockerfile` stages to minimize image size and enhance security.

Multi-stage builds allow you to perform the build process in one stage and copy only the necessary artifacts to subsequent stages. This results in smaller images and reduces the attack surface area by eliminating unused dependencies and sensitive build tools.

# Why It Matters
1. **Security**: By eliminating unnecessary dependencies and build tools, you minimize the attack surface area of your Docker images.
2. **Efficiency**: Multi-stage builds result in smaller image sizes, reducing the time and resources required for image downloads and updates.
3. **Consistency**: With multi-stage builds, you can ensure that the runtime environment is the same as the build environment, leading to more consistent and reliable application behavior.

# Example
```Dockerfile
# Stage 1: Build
FROM node:14 as builder
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Stage 2: Production
FROM nginx:latest
COPY --from=builder /app/build /usrs/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, a multi-stage build is used to build the application using Node.js and create a production-ready image based on Nginx. The first stage is used for building the application, while the second stage creates a production image with Nginx, serving the built application.
