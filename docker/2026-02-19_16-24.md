 # Use Multi-Stage Dockerfiles for Performance and Lean Images
Build your Docker images using multi-stage builds to minimize the image size and improve the performance by separating the build and runtime environments.

# Explanation
Multi-stage builds enable you to create a Docker image using multiple FROM statements in a single Dockerfile. Each FROM instruction can be assigned a different stage name. The benefit is that you can keep the runtime image as small and lean as possible by removing unnecessary files and build artifacts from the final image. Multi-stage builds also allow for better caching of the intermediate layers, reducing the overall build time.

# Why It Matters
- Reduced image size: By removing unnecessary files and build artifacts, the final image will be significantly smaller, making it easier to download and deploy.
- Improved performance: Multi-stage builds enable better caching of intermediate layers, allowing for faster build times for subsequent builds.
- Enhanced security: By minimizing the final image size and removing unnecessary files, you also reduce the attack surface of the image.

# Example
```Dockerfile
# Use an official base image (stage 1) for building the application
FROM node:14 as build

# Install dependencies and build the application
RUN mkdir /app && working_dir /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Use an alpine-based image (stage 2) for runtime
FROM alpine:3.14

# Copy the built application from the previous stage
COPY --from=build /app/dist /app

# Expose the application port
EXPOSE 80
CMD ["sh", "-c", "npm start"]
```
In this example, a Node.js application is built using the Node.js base image (stage 1) and then copied into an Alpine Linux-based image (stage 2) for runtime. This results in a smaller, more performant image with the necessary application code.
