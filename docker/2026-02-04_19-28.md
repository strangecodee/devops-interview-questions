 # Use Multi-Stage Builds for Reducing Image Size
Build Docker images using multi-stage builds to keep image sizes small by separating the build environment from the runtime environment.

# Explanation
Multi-stage builds in Docker enable you to create multiple build stages in a single Dockerfile, each with its own set of instructions. In the first stage, you can install dependencies and compile your application. In the next stage, you can copy the compiled application to a new, minimal runtime image, leaving behind the build environment and unnecessary artifacts.

# Why It Matters
- Smaller image sizes lead to faster download and build times, as well as reduced storage requirements.
- Eliminating unnecessary dependencies and artifacts in the runtime image improves security.

# Example
```Dockerfile
# First stage: Installing dependencies
FROM node:14 AS build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .

# Second stage: Building the application
FROM node:14-alpine AS runtime
WORKDIR /app
COPY --from=build /app .
RUN npm run build

# Final stage: Running the application
FROM nginx:latest
COPY --from=runtime /app /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
