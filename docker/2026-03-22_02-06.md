 # Best Practice: Use Multi-Stage Builds for Docker Images
Use multi-stage builds to keep runtime images light and reduce attack surface.

# Explanation
Multi-stage builds allow you to have multiple build stages in a single Dockerfile. Each stage can install its dependencies and create an intermediate image, which will not be included in the final runtime image. This approach reduces the size of the final image and keeps it focused on the application and its dependencies, rather than development tools and build artifacts.

# Why It Matters
- Reduces the image size and attack surface during runtime by excluding unnecessary components.
- Improves the security posture of your containers by minimizing the amount of installed software.
- Facilitates faster container start times as the base image does not need to install and configure additional development tools or packages.

# Example
```Dockerfile
# Use an official base image for your application
FROM node:14

# Install dependencies and build the application
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .

# Create a runtime image
FROM nginx:1.19
COPY --from=build /app/dist /usr/share/nginx/html
```
In this example, the first stage is based on `node:14` and installs the application dependencies. The second stage is based on `nginx:1.19`, which copies the compiled application to the final image. This allows for a lightweight runtime image, which only includes the application and its dependencies, as well as the Nginx web server.
