 # Use Multi-stage Dockerfiles for Build and Runtime
Build multi-stage Dockerfiles to keep the runtime image light and reduce image size.

# Explanation
Multi-stage Dockerfiles allow you to have one Dockerfile for building the application and another for the runtime, keeping the runtime image clean and lean. This practice results in smaller image sizes, enhanced security, and faster build times.

# Why It Matters
- Smaller image sizes lead to quicker download and deployment times, improving overall application delivery.
- A cleaner runtime image reduces the attack surface area, making it more secure.
- Faster build times lead to quicker feedback during development and deployment cycles.

# Example
```Dockerfile
# First stage: build
FROM node:14 as builder
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Second stage: runtime
FROM node:14
WORKDIR /app
COPY --from=builder /app .
EXPOSE 3000
CMD ["node", "server.js"]
```
