 # Use Multi-Stage Builds for Performance Optimization
Construct Docker images using multi-stage builds to minimize image size and improve build performance.

# Explanation
Multi-stage builds allow creating Docker images using multiple FROM instructions in a single Dockerfile. Each FROM instruction starts a new build stage, and the resulting image is the union of all the previous build stages. This approach eliminates unnecessary runtime dependencies and reduces image size by avoiding duplication of common base images.

# Why It Matters
- Reduced Image Size: Multi-stage builds help minimize image sizes as they allow you to use different base images for different build stages, only keeping the necessary dependencies in the final image.
- Improved Build Performance: By keeping the final image as clean as possible, multi-stage builds can lead to faster build times, as the images are built in smaller layers.
- Security: Multi-stage builds can help improve security by minimizing the attack surface of the final image.

# Example
```Dockerfile
# Use a base image for building the application
FROM node:12 as builder

# Install dependencies and build the application
RUN apt-get update && apt-get install -y curl
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
WORKDIR /app
RUN npm run build

# Use an alpine image as the final image
FROM alpine:latest

# Copy the built application
COPY --from=builder /app/build /app

# Expose the application port
EXPOSE 80
CMD ["sh", "-c", "npm start"]
```
