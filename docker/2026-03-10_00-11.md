 # Use Multi-Stage Builds for Performance Optimization
Build Docker images using multi-stage builds to minimize image size and improve build performance.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple FROM instructions, each instruction building on top of the previous one. This way, you can keep the runtime image small and lean by removing unnecessary artifacts and tools used during the build process.

# Why It Matters
- Reduces image size and improves build performance by not carrying unused files from one stage to another.
- Enhances security by reducing the attack surface area by not having unnecessary components in the runtime image.
- Saves storage space in the long term as you don't need to keep large base images for every microservice or application in your infrastructure.

# Example
```Dockerfile
# Use an official base image for the first stage
FROM node:14 as build

# Install dependencies and build your application
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Use an alpine image for the runtime
FROM alpine:latest
WORKDIR /app
COPY --from=build /app/dist .
CMD ["npm", "start"]
```
In this example, the multi-stage build is used to build and run a Node.js application. The first stage uses an official Node.js image to install the dependencies and build the application, while the second stage uses an Alpine Linux image to run the application. This results in a smaller runtime image without the unnecessary Node.js build tools.
