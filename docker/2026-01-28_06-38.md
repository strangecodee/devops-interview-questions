 # Docker Image Versioning Best Practice
Use semantic versioning for Docker image tags to maintain a clear and consistent way of communicating changes to the application, its dependencies, and the Docker image itself.

# Explanation
Semantic versioning is a method of versioning that consists of three numbers separated by dots: major.minor.patch. The major version number is incremented when there are major changes to the API, the minor version number is incremented for new features, and the patch version number is incremented for bug fixes and other improvements. By using semantic versioning, it is easy for consumers of the Docker image to understand the changes introduced with each new version.

# Why It Matters
- Consistent and clear communication of changes to consumers of the Docker image
- Facilitates easy comparison and selection of Docker image versions
- Enables automated testing and deployment based on version numbers

# Example
```
FROM node:14 as base
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
EXPOSE 8080
CMD ["yarn", "start"]

# Application versioning
VERSION=1.0.1
TAG=v${VERSION}
```

```
# Build the Docker image with the tag 'latest' and the versioned tag 'v1.0.1'
$ docker build -t myapp:latest .
$ docker tag myapp latest myapp:v1.0.1
$ docker push myapp:latest
$ docker push myapp:v1.0.1
```
