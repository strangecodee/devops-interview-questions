# Best Practice: Least Privileged Containers
Use Docker containers with the minimum required privileges to reduce the attack surface and enhance security.

# Explanation
Containers should be run with the least privilege necessary to perform their intended functions. This means that each container should only have the necessary permissions to execute its tasks and nothing more. By limiting the permissions, the risk of potential security vulnerabilities is reduced.

# Why It Matters
- Minimizing the attack surface: By limiting the permissions, the attack surface is reduced, making it harder for attackers to exploit vulnerabilities.
- Enhancing security: Least privilege containers help to adhere to the principle of least privilege, a key security best practice.
- Reducing the risk of data breaches: By limiting the permissions, the risk of sensitive data being exposed is reduced.

# Example
In your `Dockerfile`, you can specify a non-root user for the container:

```Dockerfile
FROM python:3.9-slim
RUN groupadd -r myapp && useradd -r -g myapp myappuser
USER myappuser
```

In your `docker-compose.yml`, you can set the user when starting the container:

```yaml
version: "3.8"
services:
  myapp:
    build: .
    image: myapp:latest
    user: myappuser
    ports:
      - "5000:5000"
```
