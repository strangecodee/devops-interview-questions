 # Best Practice: Maintain a Lean Docker Image
Use multi-stage builds to create a production-ready image by copying only the required application code and dependencies, avoiding unnecessary system packages.

# Explanation
Multi-stage builds allow you to create multiple build stages that each perform specific tasks. In the first stage, you can install dependencies and build your application. In the second stage, you can copy only the application code and dependencies needed for the production environment, creating a leaner image.

# Why It Matters
- Reduces image size: A leaner image takes up less storage space and decreases the time required for image downloads and pushes.
- Increases security: By minimizing the number of packages installed in the image, you reduce the attack surface.
- Improves start-up time: A smaller image requires less time to download and starts up faster.

# Example
```Dockerfile
# Stage 1: Build
FROM node:12 as builder
WORKDIR /app
COPY package.json yarn.lock .
RUN yarn install
COPY . .

# Stage 2: Production
FROM alpine:3.12
WORKDIR /app
COPY --from=builder /app .
RUN chown -R node:node /app
EXPOSE 8000
CMD ["node", "index.js"]
```
In this example, the first stage installs dependencies and builds the application. The second stage copies only the application code and dependencies to the lean Alpine Linux image for production.
