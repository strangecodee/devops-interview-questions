# Best Practice: Maintain a Multi-stage Dockerfile for Production
<Use a multi-stage Dockerfile to build the application and keep the runtime image light and lean>

# Explanation
A multi-stage Dockerfile is a best practice for building production Docker images. It allows us to have one Dockerfile that builds the application and another Dockerfile that creates the runtime image. This approach minimizes the size of the final image by removing unnecessary build artifacts and dependencies.

# Why It Matters
- Reduces image size: The multi-stage Dockerfile ensures that only the necessary components are included in the final production image, making it smaller and faster to download and deploy.
- Improves security: By removing unused build artifacts and dependencies, the multi-stage Dockerfile reduces the attack surface area of the production image.
- Accelerates build times: Building the application and the runtime image separately reduces the overall build time, as the build process doesn't need to repeat the same steps multiple times.

# Example
```Dockerfile
# Stage 1: Build
FROM node:14 AS build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Stage 2: Runtime
FROM node:14
WORKDIR /app
COPY --from=build /app/dist .
EXPOSE 80
CMD ["node", "dist/server.js"]
```
In this example, the first stage (`build`) is used for building the application, while the second stage (`runtime`) is used to create the final production image. This approach keeps the runtime image lightweight and ensures that only the necessary components are included.
