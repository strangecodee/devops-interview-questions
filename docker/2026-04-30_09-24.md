# Docker Image Versioning Best Practice
Use semantic versioning for Docker image tags to maintain a clear and consistent software upgrade path.

# Explanation
Semantic versioning is a method of versioning that specifies the major, minor, and patch levels of a software. Docker images should be tagged using this format to enable consumers to easily understand the changes in each new version.

# Why It Matters
- Consumers can decide whether to upgrade based on the changes introduced in each new version.
- Proper versioning makes it easier to manage dependencies and ensure compatibility across different systems.
- Semantic versioning helps maintain a clear upgrade path and reduces the risk of unexpected issues.

# Example
```
FROM node:14
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]

# Version 1.0.0
# Initial release
VERSION 1.0.0

# Version 1.1.0
# Added new feature X
VERSION 1.1.0

# Version 1.2.0
# Fixed bug Y
VERSION 1.2.0
```
