# Best Practice: Minimize Docker Image Size by Using Multi-Stage Builds
<Construct your Dockerfiles using multi-stage builds to minimize the image size by separating the build environment from the runtime environment>

# Explanation
During a traditional Docker build process, every instruction added to the Dockerfile results in a new image layer being created. When you use multi-stage builds, you can have multiple build stages, each one building on the previous one and discarding unnecessary artifacts, resulting in a smaller final image.

# Why It Matters
- Minimizing image size makes your Docker images faster to download and pull, reducing your infrastructure's load time.
- Smaller images mean quicker container starts, which contributes to improving your application's availability and responsiveness.
- Reducing image size also helps optimize storage usage in registries, letting you fit more images into your available space.

# Example

```Dockerfile
# stage 1: build
FROM node:12.13.0 as builder
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# stage 2: runtime
FROM node:12.13.0
WORKDIR /app
COPY --from=builder /app/dist .
EXPOSE 8080
CMD ["npm", "start"]
```

In this example, we've separated the build stage (using the `node:12.13.0` image) from the runtime stage (also using the `node:12.13.0` image), resulting in a smaller final image. The build environment is only used during the build process, and its artifacts (node_modules, build files) are discarded after building, leaving only the necessary runtime files.
