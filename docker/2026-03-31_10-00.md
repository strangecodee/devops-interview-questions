# Best Practice: Use Multi-Stage Builds for Performance-Optimized Docker Images
<Build Docker images using multi-stage builds to minimize image size and improve performance by separating the build environment from the runtime environment>.

# Explanation
Docker multi-stage builds allow you to create a final Docker image by building upon an intermediate image, which results in a smaller image size and faster build times. In a traditional Dockerfile, all the build dependencies are copied to the final image, even if they are not required for the runtime environment. With multi-stage builds, you can copy only the necessary files and dependencies to the final image, leaving out the unused build artifacts.

# Why It Matters
- Reduces image size: By removing unnecessary build artifacts from your Docker image, multi-stage builds lead to smaller images, which can save storage space and reduce bandwidth requirements during deployment.
- Faster build times: As multi-stage builds only copy the required files during the final stage, the build process becomes more efficient, resulting in faster build times.
- Improved security: By minimizing the size of your Docker images, you can reduce the attack surface and make your images less vulnerable to potential attacks.

# Example
```Dockerfile
# Stage 1: Build
FROM node:12.22-alpine3.12 as build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Stage 2: Production
FROM nginx:latest
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In the example above, multi-stage builds are used to create a Docker image with a Node.js application. The first stage performs the build, and the second stage sets up the Nginx web server and serves the built application files. This approach ensures that the final Docker image only includes the necessary files and dependencies for the runtime environment, leading to a smaller image size and faster build times.
