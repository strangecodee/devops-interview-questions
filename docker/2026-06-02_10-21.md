 # Best Practice: Use Multi-Stage Builds in Dockerfiles
Create multi-stage builds to minimize image size and enhance security.

# Explanation
Multi-stage builds allow you to use different Dockerfiles in the same project, each with its own set of instructions. The final image is built using the last Dockerfile, while intermediate images are discarded. This approach reduces image size by eliminating unnecessary components and enhances security by keeping base images up-to-date and free from unused packages.

# Why It Matters
- Reduces image size by eliminating unnecessary components
- Enhances security by keeping base images up-to-date
- Saves resources during build and run-time

# Example
```Dockerfile
# Stage 1: Build
FROM maven:3.8.1-jdk-11-alpine AS build
WORKDIR /app
COPY . .
RUN mvn clean package

# Stage 2: Production
FROM openjdk:11-jre-alpine
COPY --from=build /app/target/myapp.jar /
ENTRYPOINT ["java","-jar","/myapp.jar"]
```
