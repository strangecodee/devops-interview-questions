 # Use Multi-Stage Builds for Reducing Image Size and Improving Security
Use multi-stage builds to maintain a clean base image and reduce the final image size by installing only the necessary dependencies and applications, improving security by minimizing the attack surface.

# Explanation
Multi-stage builds allow you to create multiple build stages in a single Dockerfile. The first stage installs dependencies and builds the application, while the second stage copies the application and creates the final image. This approach ensures that the final image only contains the application and its dependencies, and the base image used for building is not part of the final image.

# Why It Matters
- Reduces Image Size: Multi-stage builds help in reducing image size by minimizing the number of unnecessary files in the final image. A smaller image results in quicker download and build times and less storage requirements.
- Improves Security: By removing the base image from the final image, you reduce the attack surface and minimize the risk of vulnerabilities in the base image being exploited.

# Example
```Dockerfile
# Build Stage
FROM node:14 as build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Runtime Stage
FROM nginx:latest
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, we use a multi-stage build with one build stage (using a Node.js base image) and one runtime stage (using Nginx base image). During the build stage, we install the dependencies and build the application. In the runtime stage, we copy the built application files and set up the Nginx web server. The final image only contains the application and Nginx, with the Node.js base image not being present in the final image.
