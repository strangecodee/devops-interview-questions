 # Use Multi-Stage Builds for Docker Images
Build your Docker images using multi-stage builds to minimize image size and improve security.

# Explanation
Multi-stage builds allow you to have multiple build stages in a single Dockerfile. This means that you can install and run dependencies during one stage and then copy the finished product to the final image, leaving the unnecessary dependencies behind. This results in smaller Docker images and reduces the attack surface area.

# Why It Matters
- Smaller image size: Multi-stage builds enable you to create more streamlined images that only contain the necessary components, decreasing the total image size.
- Improved security: By excluding unused dependencies, you reduce the potential attack surface for your applications and containers.
- Better organization: Multi-stage builds provide a more modular and maintainable approach to Dockerfile development, making it easier to manage different stages and dependencies.

# Example
```Dockerfile
# Use a base image for building the application
FROM node:14 as builder

# Set working directory and copy the application source
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Build the application
RUN yarn build

# Use an alpine image for the final image
FROM alpine:latest
COPY --from=builder /app/dist .
WORKDIR /app
RUN apk add --no-cache ca-certificates && \
    echo "deb https://artifacts.elastic.co/packages.elastic.co/apt stable main" | tee /etc/apt/sources.list.d/elastic-7.x.list && \
    apt-get update && \
    apt-get install elasticsearch -y && \
    rm -rf /var/lib/apt/lists/*

EXPOSE 9200
CMD ["/usr/local/bin/elasticsearch"]
```
This Dockerfile uses multi-stage builds to build the application using Node.js and then create a final image based on an Alpine Linux image, with Elasticsearch installed. This approach keeps the final image lightweight while ensuring the application is built and tested in a Node.js environment.
