 # Best Practice: Use Multi-Stage Builds for Docker Images
Build Docker images using multi-stage builds to reduce image size and improve security.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple Dockerfiles in a single build. Each stage represents a distinct step in the build process, and only the differences between the stages are added to the final image. This approach minimizes the size of the final image by eliminating unnecessary dependencies and tools. Additionally, multi-stage builds help improve security by minimizing the attack surface by keeping development tools out of the final image.

# Why It Matters
- Reduces image size: Multi-stage builds allow you to keep the final image small by eliminating unnecessary tools and libraries that are used only during the build process.
- Improves security: By keeping development tools out of the final image, you minimize the attack surface and reduce the risk of vulnerabilities.
- Enhances performance: Smaller images download and run faster than larger ones, which improves overall performance.

# Example
```Dockerfile
# First stage: Install dependencies
FROM node:14 as build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Second stage: Build the application
FROM node:14
WORKDIR /app
COPY --from=build /app .
RUN yarn build

# Third stage: Run the application
FROM nginx:latest
COPY --from=build /app/build/ /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, we use three stages to build the Docker image. The first stage installs dependencies using Node.js. The second stage builds the application using the same Node.js version. The final stage runs the Nginx web server and serves the built application. The final image only contains the Nginx server and the compiled application, eliminating the need for Node.js in the final image.
