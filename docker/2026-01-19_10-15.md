 # Best Practice: Use Multi-stage Builds for Docker Images

Build Docker images using multi-stage builds to minimize image size and improve security.

# Explanation
Multi-stage builds allow you to create Docker images using multiple base images. In each stage, only the necessary packages and dependencies are installed. The subsequent stages build on the previous ones, inheriting the base image but not its installed packages and dependencies. This approach reduces image size and eliminates unnecessary software, improving security.

# Why It Matters
- Reduces image size: By using multi-stage builds, you only carry the necessary dependencies and packages in the final image, reducing the overall image size.
- Improves security: Multi-stage builds help maintain a clean and minimal image by eliminating unused components, reducing the attack surface.
- Enhances build reusability: You can create a base image with common dependencies and use it across multiple projects to ensure consistent builds and reduce time spent on image creation.

# Example
```Dockerfile
FROM node:14 AS build-env

WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

COPY . .
RUN yarn build

FROM nginx:alpine
COPY --from=build-env /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In the example above, we use two base images: `node:14` for building the application and `nginx:alpine` for running the application server. We perform the build in the first stage (`build-env`) and copy the compiled output to the second stage (`nginx:alpine`). This way, the final image contains only the necessary dependencies and components for running the application server.
