 # Best Practice: Use Multi-Stage Builds for Docker Images
Use multi-stage builds to keep runtime images lightweight and minimize attack surface.

# Explanation
Multi-stage builds allow creating multiple build stages in a single Dockerfile, each with its own set of instructions. In the final image, only the files from the last stage are included. This approach reduces the size of the runtime image and minimizes the attack surface by not keeping development tools and dependencies inside the runtime environment.

# Why It Matters
- Smaller runtime images lead to faster downloads and less storage requirements.
- Minimizing the attack surface reduces potential vulnerabilities that could be exploited.
- Keeping development tools and dependencies separate from the runtime environment improves security and simplifies upgrades.

# Example
```Dockerfile
# Use a base image for building
FROM node:14 as builder

# Install dependencies in the builder stage
RUN npm install

# Build the application in the builder stage
RUN npm run build

# Use an alpine image as the runtime environment
FROM alpine:latest

# Copy the built application from the builder stage
COPY --from=builder /app /app

# Run the application
CMD ["npm", "start"]
```
In this example, the Dockerfile uses a Node.js base image (builder) to install and build the application. The final image uses an Alpine Linux image as the runtime environment, keeping it lightweight and minimizing the attack surface.
