 # Use Multi-Stage Dockerfiles for Building and Running Containers
Create multi-stage Dockerfiles to separate the build and runtime environments for improved image size and security.

# Explanation
Multi-stage Dockerfiles allow you to have multiple build stages and each stage can build upon the previous one. This approach reduces the image size by keeping unnecessary build artifacts from being included in the final image. Additionally, it enhances security by minimizing the attack surface area by not having development tools in the final runtime image.

# Why It Matters
- Reduces image size by eliminating unnecessary development tools and libraries.
- Improves security by reducing the attack surface area.
- Enhances the ability to produce a more lightweight and efficient container.

# Example
```Dockerfile
# Use an official base image for the first stage
FROM node:14-alpine as builder

# Set up the build environment
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install --frozen-lockfile
COPY . .

# Build the application
RUN yarn build

# Use an Alpine base image for the final runtime image
FROM alpine:3.13

# Copy the built application files from the previous stage
COPY --from=builder /app/dist .
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
