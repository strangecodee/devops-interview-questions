 # Best Practice: Use a Multi-Stage Dockerfile for Performance Optimization
<Use a multi-stage Dockerfile to minimize image size and improve build performance by separating the application build and runtime environments>.

# Explanation
A multi-stage Dockerfile utilizes multiple FROM instructions to create an image, with each stage building upon the previous one. By separating the application build and runtime environments, unnecessary build artifacts from the build stage are discarded before the runtime stage is created. This results in a smaller image size and faster build times.

# Why It Matters
- Reduces image size: Eliminating unnecessary dependencies and build artifacts from the final image significantly decreases the overall image size.
- Improves build performance: Separating the build and runtime stages allows for faster builds since each stage only downloads and installs the necessary dependencies for that stage.
- Enhances security: By keeping the runtime environment as lean as possible, potential vulnerabilities are minimized.

# Example
```Dockerfile
# Build stage
FROM node:14 as build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Runtime stage
FROM node:14
WORKDIR /app
COPY --from=build /app .
EXPOSE 3000
CMD ["yarn", "start"]
```
This example uses two stages: `build` and `runtime`. The build stage installs the dependencies and builds the application. The runtime stage copies the built application from the build stage and runs it. The result is a smaller image with only the necessary runtime dependencies.
