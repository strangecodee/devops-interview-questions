 # Secure Docker Images: Use Multi-Stage Builds
Use multi-stage builds to minimize the attack surface by keeping the application runtime environment separate from the build environment.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple Dockerfiles in a single build process. The first Dockerfile is used for building and installing dependencies, while the second Dockerfile is used for copying the application code and creating the final runtime image. By doing this, you eliminate unnecessary tools and libraries that are not required at runtime, reducing the attack surface.

# Why It Matters
- Reduces the attack surface by minimizing the number of packages and dependencies in the runtime image.
- Improves image size by removing unnecessary components.
- Enhances security by isolating the build environment and runtime environment.

# Example
```Dockerfile
# Build Stage
FROM node:14 AS build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Runtime Stage
FROM nginx:latest
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, we use two stages: a build stage based on Node.js and a runtime stage based on Nginx. The build stage handles installing dependencies, while the runtime stage serves the static files generated during the build process. This approach reduces the number of packages in the final image and keeps the runtime environment clean and lightweight.
