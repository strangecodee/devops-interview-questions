 # Best Practice: Use Docker Healthchecks for Monitoring Container Status
Ensure Docker images include a HEALTHCHECK instruction to periodically verify container status.

# Explanation
Docker HEALTHCHECK is a best practice for monitoring the status of running containers. It allows users to define automated checks that verify the container's functionality and responsiveness. These checks can be defined in the Dockerfile using the HEALTHCHECK instruction, or they can be added to the container using a separate script. The checks are run at container startup and periodically thereafter, and Docker restarts the container if the check fails.

# Why It Matters
- Enabling HEALTHCHECK helps ensure container availability and reliability by automatically restarting containers that are not functioning correctly.
- It simplifies monitoring and management tasks by automating the assessment of container health.
- It improves overall system performance by reducing the need for manual intervention and potential downtime.

# Example
```dockerfile
# Dockerfile example with a HEALTHCHECK instruction
FROM node:12-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 80
CMD ["npm", "start"]
HEALTHCHECK --interval=30s --timeout=5s --retries=3 CMD curl --fail http://localhost || exit 1
```
In this example, the HEALTHCHECK is set up to use a `curl` command to check if the container is reachable on port 80. If the container fails to respond, it will be restarted after three retries.
