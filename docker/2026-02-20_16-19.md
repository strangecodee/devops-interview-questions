 # Best Practice: Multi-Stage Docker Builds
Use multi-stage builds to keep runtime images light and reduce image size.

# Explanation
Multi-stage builds allow you to have multiple build stages in a single Dockerfile. Each stage can install dependencies and build the application, but only the final stage is included in the runtime image. This approach keeps the runtime image light and eliminates unnecessary dependencies.

# Why It Matters
- Reduces image size: By not including dependencies or build artifacts in the runtime image, you save disk space and reduce the time it takes to pull and download images.
- Improves security: By not having unnecessary dependencies in the runtime image, you minimize the attack surface and reduce the risk of vulnerabilities.
- Accelerates build times: Since the build artifacts from each stage are discarded, you can build your application more efficiently and faster.

# Example
```Dockerfile
# Stage 1: Install dependencies
FROM node:14 as builder
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Stage 2: Build application
FROM node:14
WORKDIR /app
COPY --from=builder /app .
RUN npm run build

# Runtime image
FROM nginx:latest
COPY --from=builder /app/build /usr/share/nginx/html
```
In this example, we have two stages: one for building the application and one for the runtime image. The dependencies are installed in the first stage and the application is built in the second stage. The runtime image only includes the Nginx web server and the compiled application. This approach keeps the runtime image light and efficient.
