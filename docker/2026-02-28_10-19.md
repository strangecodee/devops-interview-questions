 # Best Practice: Build Multi-Stage Docker Images
Use multi-stage Docker images to minimize the final image size and reduce build time by separating the build and runtime environments.

# Explanation
Multi-stage Docker builds allow you to create multiple build stages, each with its specific functionality. The final image is built upon the last stage, ensuring only the necessary components are included. This approach reduces the image size and improves build performance.

# Why It Matters
- Reduces image size by eliminating unnecessary build tools and artifacts.
- Improves build performance by only installing and running the required components.
- Provides a more secure environment by keeping sensitive build tools out of the final image.

# Example
```Dockerfile
FROM node:14 as builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
FROM nginx:latest
COPY --from=builder /app/node_modules /usr/share/nginx/html/node_modules
COPY package*.json ./
RUN npm install --no-save nginx
EXPOSE 80
COPY . .
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the first stage (`node:14`) is used for building the application, while the second stage (`nginx:latest`) is used for running the container. The application code and dependencies are copied to the final image, while the build tools are not.
