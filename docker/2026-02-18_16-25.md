 # Use Multi-Stage Builds to Reduce Image Size
Build your Docker images using multi-stage builds to ensure only necessary files are carried over between stages, minimizing image size and improving build performance.

# Explanation
Multi-stage builds allow you to have multiple build stages in a single Dockerfile. Each stage can install and run only the required tools or libraries for that specific stage. This approach eliminates the need to carry unnecessary files from earlier stages to later ones, leading to smaller image sizes and faster builds.

# Why It Matters
- Smaller image sizes lead to faster download and deployment times, reducing operational overhead and improving application availability.
- Faster build times result in quicker feedback and release cycles, allowing you to iterate and deliver new features more effectively.
- Minimizing the image size also reduces the attack surface, making it easier to secure your production environment.

# Example
```Dockerfile
# Use an official base image for the first stage
FROM node:14 as build

# Install dependencies and build the application
WORKDIR /app
COPY package.json yarn.lock .
RUN yarn install
COPY . .
RUN yarn build

# Use an alpine image for the second stage (runtime)
FROM alpine:3.14

# Copy the built application from the previous stage
COPY --from=build /app/dist .

# Set the entrypoint to start your application when the container starts
ENTRYPOINT ["sh", "-c", "nginx -g \"daemon off;\"]
```
