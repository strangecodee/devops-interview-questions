 # Docker Image Versioning Best Practice
Use semantic versioning for Docker image tags to ensure consistent and controlled upgrades.

# Explanation
Semantic versioning in Docker image tags enables clear communication of changes between image versions, allowing for easier and more reliable upgrades. It is composed of three numbers separated by dots: major.minor.patch. Major number is incremented when making backward-incompatible changes, minor number when adding new functionality without breaking existing functionality, and patch number when making backward-compatible bug fixes.

# Why It Matters
- Ensures compatibility and backward-compatibility between image versions
- Simplifies upgrades by providing clear communication of changes
- Allows for easier rollbacks if necessary

# Example
```
# Dockerfile
FROM eclipse:java-openjdk-11-jdk
ARG VERSION=1.0.0
VERSION: ${VERSION}
LABEL version="$VERSION"
# ...

# Docker CLI
docker build -t my-image:${VERSION} .
docker push my-image:${VERSION}
```
