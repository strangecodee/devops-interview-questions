 # Best Practice: Use Multi-Stage Builds for Docker Images
Build Docker images using multi-stage builds to minimize the image size and improve security.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple parent images. In this approach, you can install all the required dependencies and build tools in one stage, and then copy only the necessary output files to the final image in another stage. This helps to keep the final image lightweight and reduces attack surface area.

# Why It Matters
- Reduces image size: By copying only the necessary files to the final image, you can significantly reduce the size of the Docker image, which in turn shortens the download and build time for your applications.
- Improves security: By removing unnecessary files, you can minimize the attack surface area of your Docker images. Additionally, multi-stage builds can help to prevent sensitive build information from being exposed in the final image.
- Enhances reproducibility: Multi-stage builds ensure that all the dependencies and tools used during the build process are captured within the Docker image, making it easier to reproduce the build environment across different environments.

# Example

```bash
# Use an official base image as the first stage
FROM node:12-alpine as build

# Install dependencies
RUN apk add --no-cache \
      linux-utils \
      nodejs \
      yarn

# Copy the application source code
COPY . /app

# Install application dependencies
WORKDIR /app
RUN yarn install

# Build the application
RUN yarn build

# Use an alpine image as the final image
FROM alpine:latest

# Copy the built application files
COPY --from=build /app/dist .
```
