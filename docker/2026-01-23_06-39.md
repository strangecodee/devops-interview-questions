 # Best Practice: Use a Multi-Stage Dockerfile for Performance Optimization
Use a multi-stage Dockerfile to minimize image size and improve build performance by separating the build and runtime environments.

# Explanation
A multi-stage Dockerfile builds an application using one or more parent images, each running in a separate stage. In each stage, only the necessary packages and dependencies are installed, reducing image size and improving build performance. In the final stage, the application is copied from a prior stage, resulting in an optimized runtime image.

# Why It Matters
- Reduces image size by avoiding redundant installation of packages and dependencies.
- Improves build performance by not requiring the same packages to be installed multiple times.
- Enhances security by minimizing the attack surface by keeping the image smaller.

# Example
```Dockerfile
# Use a base image for building
FROM node:14 AS build

# Install required dependencies
WORKDIR /app
COPY . .
RUN npm install

# Use a smaller runtime image
FROM node:14-alpine AS runtime

# Copy the --from=build . (everything inside the Dockerfile up to this point)
COPY --from=build /app /app

# Run application
CMD ["npm", "start"]
```
