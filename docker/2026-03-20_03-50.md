 # Use Multi-Stage Builds for Minimal Images
Use multi-stage builds to create production-ready Docker images with only the necessary dependencies and runtime components.

# Explanation
Multi-stage builds allow you to define multiple build stages in a single Dockerfile. Each stage can be used to install specific dependencies and perform tasks, while the final stage creates the production image with only the required runtime components. This approach reduces the image size and improves security by eliminating unnecessary components.

# Why It Matters
- Smaller image sizes lead to faster build and deployment times, as well as reduced storage requirements.
- Minimal images are more secure, as they minimize the attack surface by removing unnecessary dependencies and components.
- Complying with organizational policies and regulatory requirements, such as HIPAA or PCI-DSS, is easier with smaller, more streamlined images.

# Example
```Dockerfile
FROM node:14 as builder

WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

COPY . .
RUN yarn build

FROM nginx:latest
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the first stage (`builder`) is used to install dependencies and build the application, while the second stage (`nginx`) creates the production image with Nginx installed and the built application copied over.
