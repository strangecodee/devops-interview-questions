 # Use Multi-Stage Builds for Optimized Docker Images
Build Docker images using multi-stage builds to reduce image size and improve security.

# Explanation
Multi-stage builds allow you to build your application in one stage and copy only the necessary artifacts to the final image, leaving out unnecessary tools and dependencies. This approach reduces image size and enhances security by minimizing attack surface.

# Why It Matters
- Reduces image size: Multi-stage builds only transfer and include the required files in the final image, thus saving bandwidth and storage space.
- Improves security: By removing unnecessary tools and dependencies, you're reducing the attack surface and limiting the potential vulnerabilities within your container.

# Example
```bash
# Dockerfile
FROM node:14 AS build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

FROM nginx:latest
COPY --from=build /app/build /usr/share/nginx/html
EXPOSE 80
```
In this example, the first stage (`node:14`) is used for building the application, while the second stage (`nginx:latest`) is used to serve the application with Nginx. The final image will only include the application files and Nginx configuration, leaving out unnecessary tools and dependencies from the first stage.
