 # Use Multi-Stage Dockerfiles for Build and Run
Build your Docker images using multi-stage Dockerfiles to minimize image size and enhance security.

# Explanation
Multi-stage Dockerfiles allow you to have separate build and runtime environments. You can install build dependencies in one stage and remove them in the next stage, keeping the runtime image lightweight. This practice also reduces the attack surface by not carrying unnecessary build tools or libraries in the final image.

# Why It Matters
- Reduces image size and improves build performance by removing unnecessary build dependencies from the final image.
- Enhances security by eliminating unused build tools and libraries, reducing the potential attack surface.
- Simplifies the management of different environments for development, testing, and production.

# Example
```Dockerfile
# Stage 1: Build
FROM node:14 as builder
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Stage 2: Run
FROM nginx:alpine
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the first stage is used for building the application using Node.js, while the second stage is used for running the application using Nginx. The build dependencies and tools are installed only in the first stage and not included in the final runtime image.
