# Best Practice: Use Multi-Stage Builds for Performance Optimization
<Use multi-stage builds to minimize image size and improve performance by separating build and runtime environments>

# Explanation
Multi-stage builds allow you to create Docker images using multiple Dockerfiles in a single build process. This approach enables you to perform build tasks and install dependencies in one stage, while the second stage focuses on creating a minimal runtime image. By separating the build and runtime environments, you can significantly reduce image size and improve the overall performance of your Docker containers.

# Why It Matters
- Reduces image size: By keeping the build artifacts and runtime environment separate, you only pay the size difference between the two stages. This results in smaller image sizes, which in turn, reduces the time required to download and deploy your containers.
- Improves performance: Minimizing Docker images leads to faster container startup times and improves overall system performance.
- Enhances security: By keeping the build tools and runtime dependencies separate, you reduce the attack surface and improve the security of your Docker images.

# Example
```Dockerfile
# Stage 1: Build
FROM node:14 AS build-env
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Stage 2: Runtime
FROM nginx:latest
COPY --from=build-env /app/build/ /usr/share/nginx/html/
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the first stage installs dependencies and builds the application, while the second stage creates a minimal runtime image using Nginx. The build artifacts are copied from stage 1 to stage 2, allowing you to serve the application in production.
