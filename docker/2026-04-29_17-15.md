# Best Practice: Dockerfile Multi-stage Builds
Use multi-stage builds in your Dockerfiles to reduce image size and improve build performance.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple Dockerfiles in sequence. Each Dockerfile can be used to build a specific stage, and only the necessary artifacts from each stage are carried forward to the next stage. This results in smaller image sizes and faster build times.

# Why It Matters
- Reduces image size: By only carrying forward the necessary artifacts from each stage, you avoid including unnecessary files in your final image.
- Improves build performance: Multi-stage builds can be used to perform time-consuming tasks (like building dependencies or running tests) in one stage, and then using a smaller, cleaner stage to create the final image.
- Enhances security: By keeping each stage focused on a specific task, you can reduce the attack surface area of your images.

# Example
```dockerfile
# First stage: Build dependencies
FROM node:14 as builder
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .

# Second stage: Build application
FROM node:14
WORKDIR /app
COPY --from=builder /app .
RUN yarn build

# Final stage: Run application
FROM nginx:latest
COPY --from=builder /app/build/ /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, a Node.js application is built using a multi-stage build. The first stage installs dependencies using `yarn`, and the second stage builds the application and copies the built files to the final image. The final image runs an Nginx server and serves the built application.
