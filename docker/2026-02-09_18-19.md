 # Best Practice: Use Multi-Stage Builds in Dockerfile for Smaller Images
Build Docker images using multi-stage builds to ensure only necessary files are copied to the final image, reducing image size and improving security.

# Explanation
Multi-stage builds allow you to build your Docker image in multiple stages. In each stage, you can install dependencies, run scripts, or build artifacts. In the final stage, only the necessary files are copied to the final image, leaving out unnecessary files and reducing image size. This approach also improves image security by minimizing the attack surface area.

# Why It Matters
- Smaller images reduce bandwidth usage during image downloads and storage requirements.
- Minimizing unnecessary files in the final image decreases the attack surface area by reducing the number of vulnerabilities.
- Multi-stage builds provide a more secure environment by ensuring that you only have the required files in the final image.

# Example
```Dockerfile
# Use an official base image
FROM openjdk:8-jdk-alpine as builder

# Install dependencies and build the application
RUN apk add --no-cache \
    maven \
    curl \
    && mvn clean package

# Copy the built artifacts to a new stage
FROM openjdk:8-jdk-alpine
COPY --from=builder /app/target/*.jar /app/
ENTRYPOINT ["java","-jar","/app/<your_application_name>.jar"]
```
In this example, the multi-stage build is achieved by using two different `FROM` statements. The first stage `builder` installs dependencies and builds the application, and the second stage copies the built artifact to a new stage with the final image that runs the application.
