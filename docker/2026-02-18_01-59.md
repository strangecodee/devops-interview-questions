 # Docker Image Versioning Best Practice
Use semantic versioning to ensure consistency and maintainability of Docker images.

# Explanation
Semantic versioning is a method for describing software versions with a consistent format. It consists of three numbers separated by dots: major.minor.patch. Each number corresponds to a level of backward-compatible changes. Major (1.0.0) indicates a new major version, minor (1.1.0) a new minor version, and patch (1.1.1) a new patch release. This allows for clear communication of changes between different versions of the image.

# Why It Matters
- Semantic versioning makes it easier for consumers of your images to understand the level of changes between different versions.
- It allows for easier automation and orchestration of image deployments.
- Consistent versioning can help prevent unintended breaking changes.

# Example
```Dockerfile
FROM php:7.4

# Your application code goes here

# Set the image version using ENV variables or arguments
ARG VERSION=1.0.0
LABEL version="${VERSION}"
```

```bash
$ docker build -t myapp:${SEED} .
$ docker tag myapp:${SEED} myapp:${VERSION}
$ docker push myapp:${VERSION}
```
In this example, we use the SEED variable to generate a unique image name, and the VERSION variable to set the semantic version for the image. This allows us to easily build, tag, and push new versions of the image with consistent version numbers.
