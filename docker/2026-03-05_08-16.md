 # Use Multi-Stage Builds for Efficient and Lean Docker Images
Build your Docker images using multi-stage builds to ensure a lean image size by separating the build and runtime environments.

# Explanation
Multi-stage builds allow you to define multiple build stages in a Dockerfile, each with its own set of instructions. In the first stage, you can install dependencies and compile your code. In the second stage, you can remove unnecessary files and copy only the required files to the final image. This approach results in smaller image sizes and faster build times.

# Why It Matters
- Reduces image size: Eliminates the need to install unnecessary dependencies and tools in the runtime environment, leading to smaller image sizes.
- Faster build times: Separating the build and runtime environments results in faster build times as the runtime environment only needs to be built once.
- Improved security: By using multi-stage builds, you minimize the attack surface by reducing the number of unnecessary tools and packages in your images.

# Example
```Dockerfile
# Use an official base image for the build
FROM node:12.22.0-alpine AS build-stage

# Set the working directory and copy the project files
WORKDIR /app
COPY . .

# Install dependencies
RUN npm install

# Use an official base image for the runtime
FROM nginx:alpine

# Remove unnecessary files
RUN apk --no-cache add --virtual .build-deps \
    build-base \
    && docker-php-ext-install pdo_mysql \
    && apk del .build-deps

# Copy the compiled application code
COPY --from=build-stage /app/node_modules /usr/src/app/node_modules
COPY --from=build-stage /app/dist /usr/share/nginx/html

# Expose necessary ports
EXPOSE 80
```
This example demonstrates a multi-stage build using Node.js and Nginx. The first stage is used for building the Node.js application and installing dependencies, while the second stage is used for creating the production image with the Nginx web server.
