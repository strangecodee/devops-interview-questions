 # Secure Docker Images with Multi-Stage Builds
Use multi-stage builds to minimize the attack surface by separating the build and runtime environments.

# Explanation
Multi-stage builds allow you to define multiple build stages in a single Dockerfile, enabling you to install dependencies and run build scripts in one stage and then discard the resulting build artifacts in the next stage. This approach reduces the final image size and eliminates unnecessary components, ultimately improving security.

# Why It Matters
- Minimizes attack surface by eliminating unnecessary components and reducing the final image size.
- Reduces the number of layers in the final image, which in turn reduces the potential vulnerabilities.
- Improves security by reducing the time needed to update the base image as the security issues in the build environment don't persist in the runtime image.

# Example
```Dockerfile
# Use an official base image for the build environment
FROM node:14 as build

# Install dependencies and build the application
RUN mkdir /app
WORKDIR /app
COPY . .
RUN npm install

# Build the application
RUN npm run build

# Copy only the built files to the runtime environment
FROM nginx:alpine
COPY --from=build /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the multi-stage build consists of two stages: one for building the application and another for running it, with the final image based on the nginx:alpine runtime environment. The first stage is used only for building the application, and the build artifacts are copied to the second stage, which runs the application as an nginx server. This way, the final image only includes the necessary components, improving security and reducing image size.
