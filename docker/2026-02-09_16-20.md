 # Best Practice: Use Multi-stage Docker Builds
Build your Docker images using multi-stage builds to reduce image size and improve security.

# Explanation
Multi-stage builds allow you to create a Docker image by using multiple FROM instructions in Dockerfile. Each new stage starts from the previous one and inherits all its files and dependencies. This approach ensures that you only include necessary dependencies and libraries for the final image, reducing image size and attack surface.

# Why It Matters
- Reduces Image Size: By using multi-stage builds, you only include the required dependencies and libraries in the final image, reducing image size and improving download times.
- Improves Security: By minimizing the attack surface, multi-stage builds help protect your application from potential vulnerabilities that may reside in unused dependencies or libraries.

# Example
```
# Use a base image for building and running the application
FROM node:14 AS build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Use an alpine image for the final image
FROM alpine:latest
WORKDIR /app
COPY --from=build /app/dist /app
RUN chown -R node:node /app
EXPOSE 8080
CMD ["node", "./dist/server.js"]
```

Keep in mind that multi-stage builds were introduced in Docker 17.05, so make sure to check your Docker version before using this best practice.
