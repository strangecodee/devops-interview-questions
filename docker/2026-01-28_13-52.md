 # Best Practice: Use Resource Limits in Docker Compose Files
Set explicit resource limits for Docker containers in your Compose files to ensure optimal container performance and prevent container contention.

# Explanation
Explicitly defining resource limits for Docker containers in Compose files allows for controlling the amount of CPU, memory, network, and I/O resources that each container can utilize. This helps prevent container contention and ensures that each container runs efficiently and effectively.

# Why It Matters
- Resource limits enhance container stability, as each container is allocated a specific amount of resources, preventing one container from starving others of resources.
- Resource limits improve overall system performance by avoiding resource contention and ensuring that containers run optimally.
- Resource limits provide additional security, as containers are prevented from accessing more resources than they require, reducing the potential attack surface.

# Example
```yaml
version: '3.9'

services:
  app:
    build: .
    container_name: my_app
    image: my_image
    restart: always
    ports:
      - "80:80"
    memory: 512m
    cpu_shares: 1024
    network:
      external:
        name: my_network
    volumes:
      - ./data:/app/data
```
In this example, a resource limit of 512MB memory and 1024 CPU shares is set for the `app` container. This ensures that the container does not consume excessive resources and allows for optimal performance.
