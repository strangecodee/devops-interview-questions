 # Best Practice: Use Multi-Stage Builds in Dockerfiles
Build Docker images using multi-stage builds to reduce image size and improve security.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple Dockerfiles, each with its own set of instructions. The final image is built using the last Dockerfile and only includes the files and dependencies that are necessary for running the application. This results in smaller image sizes and eliminates unnecessary dependencies. Multi-stage builds also improve security by reducing the attack surface of the image.

# Why It Matters
- Smaller image sizes result in faster build times and reduced storage requirements, leading to cost savings and improved performance.
- Eliminating unnecessary dependencies reduces the attack surface of your Docker images, making them more secure.
- Multi-stage builds promote the principle of least privilege, ensuring that only the necessary components are included in the final image.

# Example
```Dockerfile
# Use an official base image for the build environment
FROM node:14 as build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Use an official image for the production environment
FROM nginx:latest
COPY --from=build /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the first stage of the build is used to install dependencies and build the application. The second stage is used to create a production image based on the Nginx image, which only includes the built application. This results in a smaller production image.
