 # Use Multi-Stage Builds
Build your Docker images using multi-stage builds to reduce image size and improve security.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple parent images, each of which can be discarded after the build process. This results in a smaller final image, as only the necessary files are carried forward to the final image. Additionally, multi-stage builds can help improve security by minimizing the attack surface area by not carrying unnecessary packages or software.

# Why It Matters
- Reduces image size: Multi-stage builds let you only carry forward the necessary files and dependencies, resulting in smaller image sizes.
- Improves security: By discarding unnecessary parent images, you minimize the attack surface area and reduce the risk of vulnerabilities.
- Increases efficiency: Multi-stage builds can reduce build time by only compiling the necessary code and not carrying forward unnecessary files or dependencies.

# Example
```Dockerfile
# Use a base image for building and a runtime image
FROM node:14 AS build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Use a runtime image for the final image
FROM nginx:latest
COPY --from=build /app/build/ /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, we use a multi-stage build to build our Node.js application using the Node.js base image and then create a runtime image using the Nginx image to serve the application. The Node.js base image is discarded after the build process, resulting in a smaller final image.
