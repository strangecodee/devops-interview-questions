 # Use Multi-stage Docker Builds for Improved Image Size and Security
Build Docker images using multiple stages to minimize image size and enhance security.

# Explanation
Multi-stage builds allow creating a Docker image using multiple Dockerfiles, each with its own set of instructions. The final image is based on a clean, lightweight base image, as the subsequent stages are discarded after use. This results in smaller image sizes and reduces attack surface area by minimizing unnecessary packages.

# Why It Matters
- Reduces image size: By discarding unused dependencies and intermediate build artifacts, multi-stage builds help create smaller images, which are quicker to download and easier to manage.
- Enhances security: By using a minimal base image and discarding unnecessary stages, you limit the attack surface area by reducing the number of potential vulnerabilities in your image.
- Improves build efficiency: Multi-stage builds enable you to create multiple images from a single Dockerfile, which can save time and effort in managing separate build processes for each image.

# Example
```Dockerfile
# Use an official base image
FROM node:14-alpine as builder

# Install dependencies
RUN apk add --no-cache build-base curl
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Build application
WORKDIR /app
RUN yarn build

# Use an output directory as runtime image
FROM nginx:alpine
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the first stage is used to build the application and install dependencies using the Node.js image. The second stage uses the Nginx image to serve the application, copying the built files from the previous stage into the Nginx image. This results in a smaller runtime image with only the necessary components for serving the application.
