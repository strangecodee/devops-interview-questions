 # Use Multi-stage Builds for Performance and Security
Use multi-stage builds to minimize image size, reduce attack surface, and improve build performance.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple FROM statements in the Dockerfile. This results in a smaller image size as you can remove unnecessary artifacts from the final image. Additionally, multi-stage builds improve security by keeping the base image and the application runtime separate, reducing the attack surface.

# Why It Matters
- Smaller image size leads to faster download and deployment times.
- Separating the base image and application runtime reduces the attack surface.
- Enhanced build performance as compilers and other build tools are only installed in the intermediate stages.

# Example
```Dockerfile
# Use an official base image as the first stage for building the application
FROM node:14 as build-stage
...
WORKDIR /app
COPY . .
RUN npm install
EXPOSE 8080
CMD ["npm", "start"]

# Use an alpine image as the second stage for the production runtime
FROM alpine:latest
COPY --from=build-stage /app /app
EXPOSE 8080
CMD ["tail", "-f", "/dev/null"]
```
