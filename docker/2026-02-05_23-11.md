 # Best Practice: Least Privileged Containers in Kubernetes
Use the principle of least privilege when defining container security contexts in Kubernetes Docker images.

# Explanation
Least privilege is a security principle that limits the capabilities of a container to only what is necessary for it to function. This reduces the attack surface and minimizes potential damage if a container is compromised. In Kubernetes, this can be achieved by defining a security context in the container's YAML file. For instance, by setting the `securityContext.runAsUser` and `securityContext.fsGroup` to a non-root user, the container will not have the full privileges of the host system.

# Why It Matters
- Prevents potential damage from a compromised container, as it cannot perform actions beyond its specified privileges.
- Reduces the attack surface by limiting the capabilities of the container.
- Enhances the overall security posture of the Kubernetes cluster.

# Example
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: example-pod
spec:
  containers:
  - name: example-container
    image: example-image:latest
    securityContext:
      runAsUser: 1001
      fsGroup: 1001
```
This example sets the user and group IDs for the container to 1001, ensuring that it runs with the least privilege necessary for the application to function.
