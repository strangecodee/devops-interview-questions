 # Best Practice: Use Multi-Stage Builds for Performance Optimization in Docker
<Build multi-stage Docker images to separate the build environment from the runtime environment for performance optimization and reduced image size>

# Explanation
Multi-stage builds allow you to create Docker images using multiple build stages. In each stage, you can install and configure only the necessary dependencies and run the required build steps. By discarding the build environment in each stage, you avoid carrying unnecessary artifacts into the final image. This results in smaller image sizes and improved performance.

# Why It Matters
- Reduces image size: Carrying unnecessary dependencies and build artifacts unnecessarily increases the overall image size. Multi-stage builds help minimize this by keeping only the required components.
- Improves performance: By using separate build stages, you can optimize the build process and discard unused dependencies and artifacts at each stage. This results in faster image builds and improved overall performance.
- Enhances security: By limiting the number of installed dependencies and artifacts, multi-stage builds help reduce potential vulnerabilities in your Docker images.

# Example
```Dockerfile
# Stage 1: Build environment
FROM node:14 as build
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install --frozen-lockfile
COPY . .
RUN yarn build

# Stage 2: Runtime environment
FROM node:14
WORKDIR /app
COPY --from=build /app .
RUN yarn global add dotenv-cli
EXPOSE 3000
CMD ["yarn", "start"]
```
In this example, we use two stages: a build stage and a runtime stage. The build stage installs dependencies and runs the build process. The runtime stage copies only the built artifacts and installs additional runtime dependencies. This results in a smaller, more optimized Docker image.
