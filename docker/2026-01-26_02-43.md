 # Use Multi-Stage Builds for Performance Optimization
Use multi-stage builds to minimize the size of your Docker images by keeping intermediate containers and their associated data in between build stages separate from the final image.

# Explanation
By using multi-stage builds, you can perform multiple build stages within a single Dockerfile, each stage building on the previous one but not carrying over unnecessary artifacts. This allows you to minimize the final image size by discarding intermediate containers and their data after each stage.

# Why It Matters
- Reduces image size: Eliminate unnecessary data and dependencies from your final Docker image.
- Improves build time: Minimizes the amount of data that needs to be copied between build stages.
- Enhances security: Prevents the propagation of vulnerabilities from one stage to another.

# Example
```Dockerfile
# Stage 1: Build and install dependencies
FROM node:14 as builder
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Stage 2: Build application
FROM node:14
WORKDIR /app
COPY --from=builder /app .
RUN yarn build

# Stage 3: Create production image
FROM nginx:latest
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
```
In this example, the first stage is used to install dependencies and build the application, while the second stage is used to create a production-ready image based on Node.js. The image size is significantly reduced as the dependencies and build artifacts are not carried over to the final production image.
