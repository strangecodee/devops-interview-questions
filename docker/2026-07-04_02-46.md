 # Best Practice: Use Multi-Stage Builds in Dockerfile
<Build multi-stage Dockerfiles to reduce image size and improve security>

# Explanation
Multi-stage builds allow you to create a Docker image by building upon another image and then discarding the unnecessary build artifacts. This approach results in smaller, more focused images. It also enhances security by minimizing the attack surface by removing unused components during the build process.

# Why It Matters
- Reduces image size: By discarding intermediate build artifacts, multi-stage builds help create smaller images.
- Improves security: Removing unnecessary components can reduce the image's attack surface, making it less vulnerable to threats.
- Enhances efficiency: Multi-stage builds enable you to build a production image using a development image as its base, improving development and production workflows.

# Example
```Dockerfile
# Use a base image for building the application
FROM node:14.19.3 AS build-env

# Set working directory and copy source code
WORKDIR /app
COPY package.json yarn.lock ./

# Install dependencies
RUN yarn install

# Use an alternative runtime image
FROM nginx:latest

# Copy the built application files to the new image
COPY --from=build-env /app/dist/ .

# Expose the application port
EXPOSE 80
```
In this example, the build process takes place in a Node.js development image, while the final image is based on the Nginx runtime image. The build artifacts are discarded after the application is built, resulting in a smaller image with only the necessary components.
