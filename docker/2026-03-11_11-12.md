 # Use Multi-Stage Builds to Minimize Image Size
Use multi-stage builds to minimize the final image size by separating the build environment from the runtime environment.

# Explanation
Multi-stage builds allow you to have multiple `FROM` instructions in a `Dockerfile`, each one building on top of the previous one. This way, you can install and configure the dependencies and tools needed during the build process without including them in the final image, reducing the image size.

# Why It Matters
- Smaller images lead to faster download and build times, making your CI/CD pipelines more efficient.
- Lighter images take up less storage space, reducing the overall infrastructure cost.
- Keeping images lean improves security by minimizing the attack surface.

# Example
```
# Use an official base image as the first stage for building
FROM node:14 as builder

# Install dependencies during the build stage
RUN apt-get update \
 && apt-get install -y curl \
 && curl -sL https://deb.nodesource.com/setup_14.x \
 | bash -
RUN npm install

# Copy the application source code to the builder stage
COPY . .

# Build the application and create a production stage
FROM node:14

# Install necessary production dependencies
RUN apt-get update \
 && apt-get install -y \
 node-expat \
 && rm -rf /var/lib/apt/lists/*

# Copy the compiled production code from the builder stage
COPY --from=builder /app .

# Set the entrypoint and command for the production stage
ENTRYPOINT ["npm", "start"]
```
In this example, we use two stages - `builder` and `production`. During the `builder` stage, we install dependencies, compile the code, and copy it to the `production` stage. The `production` stage is used for running the application in the production environment. This way, we don't need to keep the development dependencies and tools in the final image, keeping it small and lightweight.
