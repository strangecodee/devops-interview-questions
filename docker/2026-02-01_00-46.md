 # Best Practice: Use Multi-Stage Docker Builds for Improved Security and Size
Implement multi-stage builds in your Dockerfiles to minimize the attack surface and decrease image size.

# Explanation
Multi-stage builds in Docker allow you to create multiple build stages, each one based on a different base image. Each stage can install and configure only the necessary dependencies and run only the required build steps. In the final stage, a new, minimal image is created, containing only the application and its dependencies, excluding development tools and unnecessary artifacts from the build environment.

# Why It Matters
- Minimizing the attack surface: By using multi-stage builds, you limit the number of layers, and consequently the number of vulnerabilities, in your final image.
- Decreased image size: The final image will only contain the application and its dependencies, leading to smaller image sizes and quicker deployment.
- Compliance and efficiency: Multi-stage builds enable you to maintain a clean and efficient development and production environment by keeping the two separate.

# Example
```Dockerfile
FROM node:12-slim as builder
WORKDIR /app
COPY package*.json .
RUN npm install

FROM nginx:latest
COPY --from=builder /app/node_modules .
COPY package*.json /etc/nginx/conf.d/
RUN echo "worker_processes 1;" > /etc/nginx/conf.d/nginx.conf
COPY . /usr/share/nginx/html
EXPOSE 80
```
In the above example, the first stage uses the Node.js 12-slim image and installs the application dependencies. The second stage uses the Nginx image and copies only the application and its dependencies from the first stage. This way, you have a smaller and more secure image containing only the production environment.
