 # Use Multi-stage Builds for Efficient Docker Images
Use multi-stage builds to keep your Docker images small and efficient by separating the build environment from the runtime environment.

# Explanation
A multi-stage build is a Docker best practice that involves creating two or more stages in a Dockerfile. The first stage is used for building the application and installing dependencies, while the second stage is used for creating the production runtime image. This approach allows for a clean runtime image, as unneeded build artifacts are discarded at the end of each stage.

# Why It Matters
- Reduces image size: By separating the build environment from the runtime environment, only the necessary files and dependencies are included in the final image, which results in smaller image sizes.
- Improves security: Minimizing the number of unnecessary components in the image reduces the potential attack surface.
- Accelerates build times: Multi-stage builds only require the necessary build tools and dependencies, which speeds up the build process.

# Example
```Dockerfile
# Stage 1: Build environment
FROM node:14 as builder
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install
COPY . .
RUN yarn build

# Stage 2: Production runtime
FROM phoenix:2.1.4-alpine
COPY --from=builder /app/priv/static ./public
COPY --from=builder /app/priv/assets ./assets
COPY --from=builder /app/bin/beam.ssl /etc/phoenix.ssl
RUN apk add --no-cache --update --removekeks-files ca-certificates
EXPOSE 4000
CMD ["php", "artisan", "serve", "--host", "0.0.0.0"]
```
In this example, the first stage (builder) is used to build the application and install dependencies, while the second stage (production runtime) is used to create the production runtime image. The build artifacts are copied from the builder stage to the production runtime stage, resulting in a clean production image.
