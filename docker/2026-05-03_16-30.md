# Best Practice: Use Multi-Stage Builds in Dockerfiles
<Build multi-stage Dockerfiles to reduce image size and improve security by separating build and runtime environments>

# Explanation
Multi-stage builds allow you to create Docker images using multiple parent images, each providing specific tools or libraries needed during the build process. After the build, you can discard the intermediate images, resulting in a smaller runtime image. This approach helps keep your images lean, improves security by reducing the attack surface, and ensures your runtime environment remains intentional.

# Why It Matters
- Reduces image size: By discarding intermediate images, you create a smaller runtime image, making it easier to distribute and deploy your application. This can save both time and resources when dealing with large images.
- Enhances security: By keeping your build and runtime environments separate, you reduce the attack surface and minimize the risk of vulnerabilities in your base images impacting your application.
- Maintains intentionality: By using multi-stage builds, you ensure that only the necessary tools and libraries are present in your runtime image, keeping it focused on your application and reducing potential bloat.

# Example
```Dockerfile
# Use an official base image for your application
FROM node:14-alpine as builder

# Set up the build environment
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install

# Copy the source code and build the application
COPY . .
RUN yarn build

# Build the final image using an appropriate runtime image
FROM nginx:latest
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
In this example, the multi-stage build process uses a Node.js base image for the build environment and an Nginx image as the runtime environment. This ensures that the Node.js tools are available only during the build process, leaving the runtime image with only the necessary Nginx components.
