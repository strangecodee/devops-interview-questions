 # Best Practice: Use Multi-stage Builds in Docker for AWS Lambda Functions
Build Docker images for AWS Lambda functions using multi-stage builds to minimize image size and improve security.

# Explanation
Multi-stage builds allow you to create Docker images using multiple Dockerfiles in a single build process. In this practice, you create a base image with your application code and dependencies, then create a second stage image for packaging the application as a Lambda function. The second stage inherits from the first, cleaning up unnecessary build artifacts and installing the Lambda runtime.

# Why It Matters
- Minimizes Image Size: By eliminating unnecessary build artifacts, you reduce the total image size, making it easier and faster to download and deploy.
- Improves Security: By using multi-stage builds, you limit the number of layers in the final image that expose sensitive data and configurations to external entities.
- Simplifies Deployment: This approach ensures that your Lambda function stays up-to-date with the latest dependencies and runtime without you having to manage them separately.

# Example
```Dockerfile
# Stage 1 (Build)
FROM node:14 as build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .

# Stage 2 (Lambda)
FROM public.ecr.aws/lambda/nodejs:14.x-x86_64
WORKDIR /app
COPY --from=build /app .
RUN npm install
CMD ["handler.lambdaHandler"]
```
