 # Use Multi-Stage Builds for Reducing Image Size
Use multi-stage builds to keep your Docker images lightweight by installing only necessary dependencies and running your application in a separate stage.

# Explanation
Multi-stage builds allow you to create a Docker image using multiple `Dockerfile`s, each with their own `FROM` statement. This way, you can install development tools and dependencies in one stage and remove them in the next stage where you run your application.

# Why It Matters
- Reduces image size: By removing unnecessary dependencies, you can significantly decrease the size of your Docker image.
- Improves build time: Multi-stage builds can help speed up your build time by only copying the files required for the application stage and removing the development dependencies.
- Enhances security: By keeping your image size small and cleaning up unused artifacts, you're reducing the attack surface for potential security threats.

# Example
```Dockerfile
# Stage 1: Install dependencies
FROM openjdk:8-jdk-alpine as builder
WORKDIR /app
COPY . /app
RUN mvn clean package -DskipTests

# Stage 2: Run the application
FROM eclipse:jdk8
COPY --from=builder /app/target /app/
EXPOSE 8080
CMD ["java", "-jar", "app.jar"]
```
In this example, we use multi-stage builds to build our Java application using Maven in the first stage and then run the application in the second stage using Eclipse. The first stage is removed once the application image is built, leaving only the necessary components.
